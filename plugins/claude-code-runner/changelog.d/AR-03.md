### Added

- Turn handover behind `runner.turn_handover` (off by default, 09 18.19.3 to 18.19.7). With the
  key every Claude Code process runs under a small keeper in its own session with a named pipe
  as its input, and a restart of the runner no longer ends a turn: SIGTERM hands every live turn
  over (exit code 75, no heartbeat after it) and the next runner adopts it with full rights. It
  replays what the turn's stream said before the restart, takes follow-ups, keeps the input open
  while background work runs, stops a failed turn after its grace, and handles the end of an
  adopted process like its own, with compaction and session recovery within their once-per-run
  limits. Every process of a run starts through a launch handshake whose steps are written to the
  turn record first, so a crash at any point leaves one recorded Claude Code process or none, and
  never an input answered twice. Before it launches a process of a run it did not accept, the
  runner asks the server (`run.launch.check`). The heartbeat reports the capability
  `turn_handover` while the key is on.
- `claude-code-runner stop --turns` ends every turn on purpose: each is stopped as a stop by a
  person is, its run ends `cancelled` with `adapter_stopped`, and the command exits 0.
