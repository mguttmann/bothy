# Entscheidungen (Ruling-Log)

Kleine Festlegungen mit Datum und Grund (ADR 0001). Tragende Entscheidungen stehen als ADR unter docs/adr/, Rulings eines Kapitels in seinem Abschnitt "Rulings" bzw. "Entscheidungen".

## M1-01 Server-Gates

| Nr | Datum | Festlegung | Grund |
|---|---|---|---|
| M1-01/1 | 2026-10-10 | Die Unveränderlichkeit gemergter Migrationen hält `<modul>/migrations.sha256`; neue Zeilen schreibt nur `make migrations-lock`, das nie eine bestehende Zeile ändert. Von Hand entfernt ein Branch nur seine eigene, noch nicht gemergte Zeile, wenn er umnummeriert. | ADR 0007 Regel 5 und "Confirmation"; einen Diff gegen einen entfernten Ausgangsbranch gibt es vor dem ersten Push nicht. |
| M1-01/2 | 2026-10-10 | Die Server-Gates verlangen go, eine Docker-kompatible Laufzeit und die Pins, sobald ein Go-Modul getrackt ist, auch Gates ohne Tests. | R-QA-02 und PLAN P-09: Ein Rechner, der die Integrationstests nicht ausführen kann, meldet nie einen halb grünen Server-Stand. |
| M1-01/3 | 2026-10-10 | `codegen-check` erkennt Drift über Schnappschüsse vor und nach dem Generator statt über `git diff`. | Handänderungen in einem schmutzigen Arbeitsbaum sind keine Drift des Generators. |
| M1-01/4 | 2026-10-10 | `make perf` hat das Zeitlimit `quality.perf.timeout`. | Das Standardlimit von `go test` würde Dauertests vorzeitig beenden; der Wert ist eine benannte Schwelle wie alle anderen in Kapitel 23. |
| M1-01/5 | 2026-10-10 | `tools/bin/tools.lock.json` steht im Layout, das `make tools-lock` schreibt (JSON mit Einrückung 2); `tools/bin/tests/test_fetch_tools.py` hält das. | Im früheren kompakten Layout schrieb jeder Re-Pin die ganze Datei um, und die geänderten Prüfsummen gingen im Diff unter. |
| M1-01/6 | 2026-10-10 | `make migrations-lock` verweigert bei einer unlesbaren Zeile oder einem doppelten Namen in `migrations.sha256` und schreibt nichts; Reihenfolge und Zeilenende am Schluss stellt es beim Schreiben her. | Bei einer unlesbaren oder doppelten Zeile müsste es eine Zeile verwerfen oder auswählen, also eine bestehende Zeile ändern. |
| M1-01/7 | 2026-10-10 | `migrations-lint` überspringt ein Go-Modul nur, wenn weder `migrations/` noch `migrations.sha256` existiert; eine Prüfsummen-Datei ohne Verzeichnis scheitert. | Wird `migrations/` gelöscht, während die Prüfsummen-Datei bleibt, fällt das auf. Werden beide zusammen gelöscht, wird eine Migration samt ihrer Zeile von Hand geändert oder wird die neueste Migration samt ihrer Zeile entfernt, sieht das Gate es nicht; diese Grenze steht in `docs/quality/gates.md` unter "Was die Gates nicht abdecken". |
| M1-01/8 | 2026-10-10 | Die Rezepte der Server-Gates brechen nach jedem fehlgeschlagenen Schritt ausdrücklich mit `exit 1` ab, statt sich auf `.SHELLFLAGS` zu verlassen. | GNU make 3.81 (macOS) kennt `.SHELLFLAGS` nicht und liefe nach einem Fehler weiter. |
| M1-01/9 | 2026-10-10 | Die Go-Abdeckung rechnet über eine Kopie von `coverage.out` ohne die Zeilen der Pakete unter `test/` und `perf/`; `coverage.out` selbst bleibt unverändert. | SonarQube liest `coverage.out` in `make check` und im CI-Job, der nur `make sonar` ausführt; nur so sieht es an beiden Orten dieselbe Datei. Bis M1-72 `services/server/perf/**` in `sonar.test.inclusions` aufnimmt (Brief M1-72, Scope 8), zählt SonarQube die Dateien unter `perf/` ohne `_test.go` (etwa `perf/internal/report` ab M1-16) als Produktionscode. |
| M1-01/10 | 2026-10-10 | `go_prereqs.py` meldet jeden Fehler beim Lesen der Lock-Datei oder beim ersten Laden eines Pins (Netzfehler, abgebrochener Download, kaputte Lock-Datei) als Problem des Gates (`<gate>: <werkzeug>: <fehler>`). | Ein Abbruch mit Traceback sagt nicht, welches Werkzeug fehlt, und verliert die schon gesammelten Probleme. |
| M1-01/11 | 2026-10-10 | `tools/conftest.py` (neu, außerhalb der Dateiliste des Briefs) entfernt für jeden Test die Variablen, mit denen Git-Hooks auf ein Repository zeigen (`GIT_DIR` und verwandte); `codegen_check.py` gibt sie nicht an `git ls-files` weiter. | Der pre-push-Hook ruft `make check`; aus einem verknüpften Worktree erbt pytest ein absolutes `GIT_DIR`, und die Git-Fixtures der Tests hätten das echte Repository umkonfiguriert und einen Commit erzeugt, der alle Dateien löscht. Die Fehlerklasse steckte schon in älteren Git-Fixtures unter `tools/`; behoben ist sie an einer Stelle, `tools/ci/tests/test_git_env_isolation.py` hält das. |
