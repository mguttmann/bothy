# Accessibility checklist of the phone apps

Status: M5-10 filled. This page is the checklist of exit criterion 3 of milestone M5 (PLAN 11):
every rule of [01 Product, section 8](../spec/01-product.md#8-accessibility) (WCAG 2.2 level AA)
for every phone screen of M5 on iOS with VoiceOver and on Android with TalkBack, each with how it
is checked. The desktop app has its own page,
[accessibility-checklist.md](accessibility-checklist.md), with the same columns. The terminal
screens M8 and M9 are checked by M5-13 and the live views M10 by M6-16; they have their rows
below with that state.

## How to read this page

Each screen has a table with one row per rule of 01 section 8 (contrast, screen reader, live
content, font size, focus, targets, motion, color, language) and the columns:

- **Where**: what of the screen the row is about.
- **Platform**: iOS, Android or both.
- **Automated evidence**: the test file and the test names that check the rule; they run on
  every pull request (`flutter test` of `apps/client`, `packages/admin_ui` and
  `packages/design_system`) or in the platform jobs `apps (iOS)` and `apps (Android API 26)` and
  `apps (Android API 36)` (`make apps-platform`, `apps/client/platform-tests.json`).
  `tools/docs/tests/test_accessibility_checklist.py` fails when a named test does not exist.
- **State**: `automated` (the evidence decides), `manual before release` (a person with the
  screen reader on a physical device checks it before every app release, PLAN 5 row
  "Accessibility") or `not applicable` with the reason. A row can be both automated and
  manual: the tests check what a machine can, the person checks how it sounds.
- **Manual pass**: the assistive technology of the manual pass.

`apps/client/test/a11y/phone/routes_checklist_test.dart` fails when a kind of page of the phone
router (`PhonePageKind`) has no row in the table "Routes of the phone".

## Automated checks per screen

Every phone screen runs the five tests of `dsPhoneAccessibilityTests`
(`package:design_system/testing.dart`), in the density `touch`:

1. **Screen reader**: the audit `dsSemanticsProblems` finds no control without a name, no
   tappable node without a role, no enabled button a screen reader cannot press, no empty stop
   and no name read twice; the semantics snapshot (every node a screen reader stops at, in
   reading order, with role, label, value, state and actions) equals the checked-in file
   `test/a11y/semantics/<screen>.txt`, so a lost label or a changed reading order fails.
2. **Contrast and targets**: `labeledTapTargetGuideline`, `androidTapTargetGuideline` (48 by
   48, also `density.target-min` of `touch`) and `iOSTapTargetGuideline` (44 by 44) in light
   and dark; the text contrast (`textContrastGuideline` without inactive controls) is measured
   on macOS hosts (D-M4-07-10), and the token gate checks every color pair on every host
   ([contrast.md](../design/contrast.md)).
3. **Font size**: text scale 2 (200 percent) in German and English without an overflow, every
   named control still reachable by a finger.
4. **Motion**: with reduced motion (the system setting, `MediaQuery.disableAnimations`, and
   `motion.reduced`) no animation runs after the first frame.
5. **Language**: the application locale of the semantics tree is the app's language, and no
   node carries a locale in another language, in German and English.

The platform audits check what VoiceOver and TalkBack receive from the same screens
(integration_test/a11y_audit/audit_app.dart shows one screen per run):

- **iOS**: `AccessibilityAuditTests.swift` runs `performAccessibilityAudit` with every audit type
  (contrast, element detection, hit region, sufficient element description, Dynamic Type, text
  clipped, traits, actions) on the iOS simulator (`tool/run_ios_a11y_audit.sh`); it starts each
  screen with the launch argument `--route=/<screen>`.
- **Android**: `AccessibilityChecksTest.kt` runs every check of the latest preset of the
  Accessibility Test Framework (touch target size, text and image contrast with a screenshot,
  speakable text, duplicate descriptions, clickable spans, traversal order, redundant
  descriptions and the rest) on the accessibility tree TalkBack reads, on the emulator
  (`tool/run_android_a11y_checks.sh`).

## Settings of the manual pass

The manual pass runs before every app release on one physical iPhone and one physical Android
phone, in German and English, light and dark:

| Setting | iOS | Android |
|---|---|---|
| Screen reader | VoiceOver (Settings, Accessibility, VoiceOver) | TalkBack (Settings, Accessibility, TalkBack) |
| Larger text | Larger Accessibility Sizes at the largest step | Font size and display size at the largest step |
| Reduce motion | Reduce Motion on | Remove animations on |
| Bold text | Bold Text on | Bold text on |
| High contrast | Increase Contrast on | High contrast text on |
| Switch and keyboard | Full Keyboard Access with a Bluetooth keyboard | Switch Access with a Bluetooth keyboard |

Steps for every screen: swipe through the screen from the first to the last element and check
that every element is read once, with its role, its name and its state, in the order of the
screen; activate every control with a double tap; check that the live content of the screen is
announced as the row says and not more often; repeat with the largest text and with reduced
motion.

## Platform audits: known limitations

An issue of the platform audit that comes from the Flutter engine and not from the app is listed
here and in the test (`knownLimitations`) with its reason; it matches by the issue and the
element, the test prints every issue it lets pass, and none is ignored silently. Both audits also
run on a screen made to have gaps (`known_gaps` of the audit entry: a tappable square of 20 by
20 without a name, grey text on grey), so a green screen is no empty run; that screen also shows
which rules the platform audits do not measure on Flutter elements.

| Audit | Issue | Reason | Where the rule is checked instead | Follow-up |
|---|---|---|---|---|
| iOS `performAccessibilityAudit` | "Element has no description" on a scroll view without a name | the engine presents every scrollable list as a scroll view of its own (`FlutterSemanticsScrollView`), and Flutter offers no name for it; VoiceOver reads the items of the list | the screen reader tests of every screen above name every item | none while the engine has no name for scroll views |
| iOS `performAccessibilityAudit` | no issue for the contrast and the hit region of Flutter elements | the audit reported neither for the grey text and the square of 20 by 20 of the self-check screen (Xcode 27) | the contrast and target tests of every screen above and the token gate | when the audit starts to report them, every screen above fails on them, and the rows here change |
| Android Accessibility Test Framework | "may not have a label readable by screen readers" on an empty text field, below API 28 | the engine sets the label of a text field as its hint text only from API 28 on (its Android embedding), so on Android 8 and 8.1 an empty field reaches the accessibility tree without a name; the framework reported it on API 26; the app cannot set it | the screen reader tests of every screen above name every field | none while the engine sets the hint text only from API 28 on |
| Android Accessibility Test Framework | no result of the text contrast check for Flutter text | the check measures text views, and the engine presents Flutter text as plain views; the self-check screen got no contrast result | the contrast tests of every screen above and the token gate | none while the engine presents text as plain views |

The touch target size, labels, duplicate descriptions and the other checks of the framework do
run on Flutter elements: the self-check screen fails them (`theChecksFindKnownGaps`).

## Gaps found and fixed by M5-10

- The banner (`DsBanner`) squeezed its note into a column of a few characters when its action
  was wide (German at text scale 2, the denied microphone): the action goes below the note.
- The badge of the Running tab was read as a bare number before the tab's name: it says "2
  active runs".
- The "As list" toggle of the run graph had its state on an unnamed node around the button: the
  button carries the state.
- Empty gaps of the share sheet of Android, the emergency pages and the Me page were empty stops
  for VoiceOver and TalkBack.
- The group of a space in the sidebar (phone and desktop), which the list gives the actions to
  move it, had no name, and the move actions of the space row sat on an unnamed node of their
  own (found by the audit of Xcode; the audit `dsSemanticsProblems` now fails on a node with
  custom actions and no name).
- The preview of the share sheet read the bare file name, which the audit of Xcode reports as no
  human-readable label: it says "Shared file screenshot.png, 1.2 MB".
