# M3-09: Voice messages and transcript

Status: ready | Depends on: M1-47, M2-31, M3-05, M3-06, M3-07 | Milestone: M3

## Goal

After this ticket a person sends a voice message: a message with `kind = voice` and exactly one attachment, an AAC-LC recording in an MP4 container (`audio/mp4`, `.m4a`), and an agent may also send MP3 (`audio/mpeg`). `createMessage` and `createThread` (`first_message`) accept `MessageCreate.kind = voice` (until now `400 validation_failed` with `errors[].code` `not_enabled`, M1-56) and check the audio before they store anything: the file must be checked and deliverable, its detected type must be a voice format (otherwise `400 validation_failed` with `errors[].code` `voice_format_unsupported`), and its duration read by the server from `mvhd` must not exceed `voice.max_duration` (otherwise `400 validation_failed` with `errors[].code` `voice_too_long`). The transcript comes from one of two places, chosen by `voice.transcription_mode`: in mode `agent` (the default) the operator agent of the thread transcribes the audio itself and stores the text with `submitTranscript` (action `file.transcript.submit`; any other agent gets the same `404` as an unknown file when it cannot see the file); in mode `service`, and only while the switch `voice.enabled` is on, the worker sends the audio through the egress client to the one configured, OpenAI-compatible transcription service (port `Transcriber`, adapter `openai_compatible`) and reports the result through `file.updated`, and a person can start it again with `requestTranscription` (action `file.transcribe`). Agents are routed by 09 "Voice messages": a voice message that triggers an agent without a transcription path is rejected at acceptance with `voice_unsupported` (AG-25), and in mode `service` the agent invocation waits until the transcript is `done` or `failed`, at the latest `voice.transcript_hold_max`, using the hold of M3-07 (`runs.invocation_held_until`, R-DM-44). No transcript text ever appears in an event, a log line, a span, a metric, an audit entry or a problem body. This is the voice part of the M3 goal that files, images and voice messages reach people and agents only after they are checked, R-FI-10, R-AG-16 and the server side of plan ticket M5-07.

Product requirements implemented here:

11. A voice message is a message with `kind = 'voice'` and exactly one attachment (12 8.1). `createMessage` and `createThread` (`first_message`) accept `MessageCreate.kind = voice` and no longer answer `400 validation_failed` with `errors[].code` `not_enabled` for it (06 5 point 3, M1-56 D2); `card` keeps that answer.
12. Formats (12 8.1): AAC-LC in an MP4 container (`audio/mp4`, extension `.m4a`) for every author; `audio/mpeg` (MP3) in addition for agents. Any other format gives `400 validation_failed` with `errors[].code` `voice_format_unsupported`; the same file can still be sent as a normal attachment.
13. Duration (12 8.1): the server reads it for MP4 from `mvhd` (timescale and duration) with its own box reader in the worker, never in the API process (SEC-UP-5, 12 7.3); above `voice.max_duration` the answer is `400 validation_failed` with `errors[].code` `voice_too_long`.
14. Transcription mode `voice.transcription_mode` with `off`, `agent` (default) and `service` (12 8.2, R-FI-10, D-FI-09). Mode `agent`: the operator agent of the thread stores the transcript with `submitTranscript` (`file.transcript.submit`, "agent-self: operator of the thread whose message the file is attached to, and read", `rl.agent_runtime`, `If-Match`), `transcript_source = 'agent'` (05 4.8, 09 4.7, 09 13).
15. Mode `service`: after the virus scan the worker calls the port `Transcriber` with the adapter `openai_compatible` at `voice.transcription_url`, the key from the secret provider (`voice.transcription_api_key_ref`), the time limit `voice.transcription_timeout` and a language hint from `users.locale`; `transcript_source = 'service'` (12 8.2, 09 13). Audio leaves the server only while `voice.enabled` is on (02 2) and only to the configured address, never to an address from user data, and only through the egress client (SEC-NET-1, SEC-NET-2, T-NW-01).
16. `requestTranscription` (`file.transcribe`, `write`, `rl.upload`, `Idempotency-Key`) starts the job in mode `service`; with `voice.enabled` off the answer is `403 feature_disabled`; in the other modes `409 conflict` with `reason` `transcription_unavailable` (12 8.2, 06 5 point 5).
17. Result: `transcript_status` `pending` to `done` or `failed` with `transcript_text` and `transcript_language`; every change of the transcript writes the durable event `file.updated` (receive action `file.read`) without the text (12 2, 12 8.2, 05 6, 04 2.2). The transcript is searchable through `files.search_vector` (03 5, 14 2) and visible to everybody with `file.read` (09 13).
18. Routing (09 13, R-AG-16): mode `agent` with the effective capability `voice_input` of the candidate (owner permission `supports_voice` and adapter report, 09 2.2), or mode `service` with `voice.enabled` on for the author, is a transcription path; otherwise a triggering voice message is rejected at acceptance with `trigger_state = failed` and `voice_unsupported` (09 3.5, AG-25).
19. In mode `service` the `agent.invocation` of a voice message is written only when the transcript is `done` or `failed`, at the latest after `voice.transcript_hold_max`, exactly once, with the marker `runs.invocation_held_until` (04 15.3 point 1, 03 R-DM-44 and R-DM-47, 12 10, D-K-G6).
20. A service failure is retried by the job, then the transcript is `failed` (02 14.4 row "transcription service").
21. An agent that may not see the file gets the same `404` as for an unknown file id (PLAN row; 12 1 point 2, AZ-P4, ADR 0017).
22. Transcripts and file names never appear in logs, spans, metrics, audit details, problem bodies or events (SEC-LOG-4, 12 14, 20 "No contents", SEC-T10); no JSON `null` (ADR 0053).
23. No call to the object store or the transcription service inside a database transaction (02 8.5); every job run repeats without double effect (02 12.4 rule 1).
24. The deferred conformance lines `AG-20 attachment M3-07`, `AG-20 transcript M3-09` and `AG-25 voice M3-09` of M2-31 are closed: their parts run in the conformance suite and the lines leave `testdata/deferred.golden` (PLAN row M3-09, D-W-108, 09 16.2).

## Design notes

1. **Dependencies and placement** (02 4.3, 4.4; ADR 0008, ADR 0050). Everything about the audio and the transcript lives in `files` (02 4.3 row `files`: port `Transcripts`, event `FileFinalized` "scan and, if applicable, transcript final"); `messaging` passes the kind of the message to `files.Attachments.Attach` (edge `messaging -> files` exists); `runs` asks `files` for the effective mode and the pending reason (edge `runs -> files` exists since M3-07) and `agents` for `voice_input`. No new module edge: `files` reads `voice.enabled` through its outgoing port `VoiceSwitch` (note 15) and the locale through `identity.Directory` (edge `files -> identity` exists). The transcription adapter is an adapter of `files` and uses `platform/egress` (02 4.4 "`platform` only in `adapters`"). Ruling for docs/DECISIONS.md: the switch is an outgoing port bound in `internal/wire`, not an edge `files -> instance`, because only the composition root needs to know where flags live (note 15).

2. **Effective mode** (12 8.2, 02 2, 06 5 point 5). `Transcripts.Mode(ctx, subjectID, subjectKind)` returns `voice.transcription_mode`, except that `service` is returned as `off` while `VoiceSwitch.Enabled` is false for the subject. Ruling for docs/DECISIONS.md: the subject is the author of the voice message (for routing and the automatic start), the caller (for `requestTranscription`) and the uploader (in the job); reason: the flag supports a rollout to people and groups (M1-47), and audio may leave only while the switch is on for the person whose voice it is (02 2 row "Transcription service"). Mode `agent` and `off` do not depend on the switch.

3. **Ports** (doc comments say every method runs inside the caller's unit of work where it writes, and that `Request` and `Submit` authorize themselves):

    ```go
    // Mode is the effective transcription mode (12 section 8.2).
    type Mode string // ModeOff "off", ModeAgent "agent", ModeService "service"

    // Transcripts answers the transcription mode and stores transcripts (12 8.2, 09 13).
    type Transcripts interface {
        Mode(ctx context.Context, subjectID ids.ID, subjectKind string) (Mode, error)
        Request(ctx context.Context, a actor.Actor, fileID ids.ID) (TranscriptView, error)
        Submit(ctx context.Context, a actor.Actor, cmd SubmitCmd) (TranscriptView, error)
    }
    type SubmitCmd struct { FileID ids.ID; IfMatch, Text, Language string }
    type TranscriptView struct { FileID ids.ID; Status, Text, Language, Source, ETag string }

    // PendingReason tells why the attachments of a message are not final (12 2, 12 10).
    type PendingReason uint8 // PendingNone, PendingFiles, PendingTranscript
    ```

    `TranscriptView` is the type of M3-05's port method `Transcript` (`getTranscript`), extended with `ETag`; do not add a second one. `AttachCmd` gets `Voice bool` (the message has `kind = voice`) and `AuthorKind string` (`user`, `agent`, `app`). `Attachments.Pending(ctx, messageID)` returns `(PendingReason, error)` instead of `(bool, error)`: `PendingFiles` when an attachment is not final in the sense of M3-04's `domain.Final`, else `PendingTranscript` when an attachment has `transcript_status = 'pending'`, else `PendingNone`; adapt the callers of M3-07 (`invokeOrHold`, `ReleaseInvocation`, the follow-on run).

4. **Voice formats and the voice check** (12 8.1, 12 7.3; Ruling for docs/DECISIONS.md for b to d).

    a. `domain.IsVoiceFormat(mimeType, authorKind)`: true for the detected names that M3-06's `domain.HasContainerMetadata` treats as MP4 audio (the pinned type detector of M3-04 reports an `.m4a` with brand `M4A ` and an MP4 whose only track is audio; pin the exact names in a table test with generated fixtures), and additionally for `audio/mpeg` when `authorKind` is `agent`. People and apps send only MP4 audio (12 8.1 "`audio/mpeg` (MP3) is also accepted for agents").

    b. `domain.VoiceCheck(VoiceFacts{UploadState, ScanStatus, MimeType, AuthorKind, HasWidth, HasHeight, DurationMs, HasDuration, MaxDuration})` returns the first failing verdict in this order: not final (`upload_state` or `scan_status` still `pending`) gives `NotReady`; final but not deliverable gives `Blocked`; not a voice format gives `FormatUnsupported`; an MP4 with width or height (it has a video track) or without a duration (the box reader found no `mvhd` duration) gives `FormatUnsupported`; a duration above `voice.max_duration` gives `TooLong` (equal passes); otherwise `OK`. MP3 has no duration and passes the duration rule (Out of scope; spec gap).

    c. The codec inside the MP4 (AAC-LC) is not verified: the API process must not parse audio (SEC-UP-5) and `files` stores no codec fact; a wrong codec only fails playback on a device. The type, the absence of a video track and the duration are checked, which is what 12 8.1 requires the server to read.

    d. The file must be deliverable at send time. Reason: the detected type and the duration are written by the worker after the read pass (12 3.4, 12 7.3), and the plan row demands a synchronous `400 validation_failed`; a client keeps the voice message in its outbox until `file.updated` reports the file ready (15 13).

5. **MP4 audio is complete only after the container phase** (change to M3-06 Design note 1 a and 10 d; Ruling for docs/DECISIONS.md). `domain.DeferContainerComplete(mimeType)` is true exactly for the MP4 audio names of note 4 a. For these types the final transaction of `files.scan` (verdicts `clean` and `skipped`) leaves `upload_state = 'pending'` and inserts `files.thumbnail`, as M3-06 does for images; the container phase of `files.thumbnail` then runs on the pending row and its transaction T3 sets `duration_ms` (when the box reader found one) and `upload_state = 'complete'` together through `recordFileChange`, which makes the file final and publishes `files.FileFinalized` (M3-07 Design note 10 b). A box reader error leaves `duration_ms` absent and still sets `complete`, so the file stays usable as a normal attachment. Reason: without this a voice file would be deliverable for a moment without its duration, and a send in that moment would be refused as unsupported. Video and QuickTime keep the order of M3-06. Change the M3-06 test expectation for MP4 audio, never delete it.

6. **Attaching a voice message** (`Attach` with `Voice = true`, inside the unit of work of `createMessage` or `createThread`, after the checks of M3-07 Design note 4 on the locked file row):

    a. M3-07's checks run first, so a foreign, deleted or already attached file answers `409 conflict` with `reason` `file_not_attachable` as before.

    b. `domain.VoiceCheck` on the locked row: `NotReady` gives `409 file_not_ready`; `Blocked` gives `409 file_blocked`; `FormatUnsupported` gives `400 validation_failed` with `errors[].code` `voice_format_unsupported`; `TooLong` gives `400 validation_failed` with `errors[].code` `voice_too_long`; the pointer is `<Pointer>/0` (`/attachment_file_ids/0`, in `createThread` `/first_message/attachment_file_ids/0`). The unit of work rolls back, so neither message nor attachment row stays and the thread sequence is given back.

    c. `Transcripts.Mode(author)`: for `ModeService` set `transcript_status = 'pending'` through `recordFileChange` (one `file.updated` in the scope of the message) and insert `TranscribeArgs{FileID}` with `jobs.Inserter.InsertTx` in the same transaction. For `ModeAgent` and `ModeOff` the file keeps `transcript_status = 'none'`.

    d. The message keeps `kind = 'voice'` (M1-56 writes the column); `MessagePosted.Kind` is `voice`, which is what `runs` reacts to (note 12).

7. **Body rules** (`messaging/domain`, M1-56 D2; Ruling for docs/DECISIONS.md for the codes). `kind = voice` is no longer `not_enabled` (`card` keeps it). A voice message needs exactly one attachment: none gives `400 validation_failed` with `errors[].code` `required` and pointer `/attachment_file_ids`, more than one gives `errors[].code` `limit_reached` with the same pointer (prefix `/first_message` in `createThread`). `content_md` may be empty, as for every message with an attachment (M3-07 Design note 5 a); a caption is allowed and its mentions trigger as in a text message. `components` stay card-only.

8. **`submitTranscript`** (`Transcripts.Submit`; 05 4.8, 09 4.7, 09 13; Ruling for docs/DECISIONS.md for the ETag and the checks).

    a. Load the file by id with `deleted_at IS NULL` and its attachment row; `authorize(actor, file.transcript.submit, fileResource(f, ref))` (M3-07 Design note 9). Unknown, foreign and invisible files give the same `404` (AZ-P4); a visible caller who is not the operator agent of the thread gets the denial of the requirement (note 14).

    b. `voice.transcription_mode` other than `agent` gives `409 conflict` with `reason` `transcription_unavailable` (the same reason as 12 8.2 for `file.transcribe`; a transcript of the agent would overwrite the service or contradict mode `off`).

    c. Lock the file row `FOR UPDATE`. Not deliverable: `409 file_not_ready` or `409 file_blocked` by M3-04's `domain.Final`; not a voice format (`IsVoiceFormat` with the uploader's kind) gives `409 conflict` with `reason` `transcription_unavailable`.

    d. Precondition: `files` has no `version` column, and the transcript's ETag is derived (03 R-DM-48, 06 8 point 1): `domain.TranscriptETag` is the strong ETag `"<first 22 characters of the base64url SHA-256>"` over `transcript_status`, `transcript_source`, `transcript_language` and `transcript_text`, each followed by one zero byte (the same form as the ETag of `getInstance`, M1-46). The operation uses `IfMatchRequired`: a missing or `*` `If-Match` gives `428 precondition_required` in `StagePreconditions` (M1-18); a value that is not exactly the current ETag gives `412 version_conflict` with `current` (the `Transcript` view) and the current `ETag` header. Compare the raw header value, because `ParseIfMatch` accepts only decimal versions. `getFile` and `getTranscript` (M3-05) send the same value in the header `ETag`.

    e. Body: `text` must not contain U+0000 (`errors[].code` `invalid`, pointer `/text`) and must not exceed `message.max_content_bytes` in UTF-8 bytes (`too_long`); an empty `text` is allowed (a silent recording). `language` is optional and must pass `domain.ValidLanguageTag` (a BCP 47 tag of the form primary subtag of two or three letters, then subtags of two to eight letters or digits; `pattern_mismatch` through the schema pattern of note 18).

    f. Write `transcript_status = 'done'`, `transcript_text`, `transcript_language` (absent when not sent), `transcript_source = 'agent'` through `recordFileChange` (one `file.updated` without text); answer `200` with the `Transcript` view (`text`, `language`, `source` only when `done`, no JSON `null`) and the new `ETag`. A later submit with the new ETag replaces the transcript (a correction). No audit entry (05 4.8 column Audit "no").

9. **`requestTranscription` and the job `files.transcribe`** (12 8.2, 02 12.3 row `files.transcribe`, 02 12.4, 02 14.4 row "transcription service"; Ruling for docs/DECISIONS.md for the states, the failure rule and the language).

    a. `Request`: load and `authorize(actor, file.transcribe, fileResource(...))` (unknown or invisible: `404`); `VoiceSwitch` off for the caller gives `403 feature_disabled` (the operation's description); `voice.transcription_mode` other than `service` gives `409 conflict` with `reason` `transcription_unavailable`; lock the row; not deliverable gives `409 file_not_ready` or `409 file_blocked`; not a voice format gives `409 conflict` with `reason` `transcription_unavailable`. Status `none` or `failed`: set `pending` through `recordFileChange` and insert the job (`InsertTx`); status `pending` or `done`: change nothing. Answer `202` with the `Transcript` view. The idempotency stage of M1-20 replays a repeated `Idempotency-Key`.

    b. Job args `TranscribeArgs{FileID ids.ID}`, kind `files.transcribe`, queue `files`, `HandlerOptions.MaxAttempts` = `voice.transcription_max_attempts`, River's default backoff. One run: read the row outside a transaction; return `nil` when it is gone, deleted or not `pending` (02 12.4 rule 1). When `Mode(uploader)` is no longer `service` or the file is not deliverable, write `failed` (step e) and return `nil`. Otherwise read the locale with `identity.Directory.User(uploaded_by)` (a principal that is not a person has no locale) and compute `domain.LanguageHint(locale)` (the primary subtag in lower case, empty when invalid); open the object with `ObjectStore.Get` and call `Transcriber.Transcribe` outside any transaction (02 8.5).

    c. Success: one unit of work locks the row and requires `pending`, `deleted_at IS NULL` and the same `object_key` as read; otherwise it writes nothing and returns `nil`. It sets `done`, `transcript_text`, `transcript_language` (the response's language when `ValidLanguageTag`, else the hint, else absent) and `transcript_source = 'service'` through `recordFileChange`, which publishes `files.FileFinalized` (note 10), so the held invocation is released in the same transaction (M3-07 Design note 13 a).

    d. Errors: `ErrTranscriptionPermanent` from the adapter writes `failed` at once; any other error returns the error so River retries, and on the last attempt (`job.Attempt >= voice.transcription_max_attempts`) writes `failed` instead. A database error never writes `failed`.

    e. `failed`: lock the row as in c, set `transcript_status = 'failed'` with `transcript_text`, `transcript_language` and `transcript_source` absent, through `recordFileChange` (it publishes `FileFinalized` as well, so the held invocation goes out with the transcript `failed`).

10. **Final for the invocation** (12 2 "final", 12 10; M3-04 Design note 6, M3-07 Design note 10). `domain.InvocationFinal(f) = domain.Final(f) && f.TranscriptStatus != "pending"`; `StateFacts` gets `TranscriptStatus`. `domain.BecameFinal(before, after)` (M3-07) compares `InvocationFinal`, so `recordFileChange` publishes `FileFinalized` exactly when the last condition for an invocation is met: the scan result, the container phase of note 5, or the end of a pending transcript. `domain.Final` and `domain.Deliverable` keep their meaning for delivery, so a deliverable file with a pending transcript is still served (M3-05 maps only `Final` and `Deliverable`). Ruling for docs/DECISIONS.md: one function decides "final for the invocation", and setting `pending` on a final file publishes nothing.

11. **Adapter `openai_compatible`** (12 8.2, 09 13, SEC-NET-1 to SEC-NET-3, T-NW-01; Ruling for docs/DECISIONS.md for the request form and the error classes).

    a. One `egress.Client` built by `internal/wire` with `Options{Purpose: "transcription", Hosts: <exactly scheme, host and port of voice.transcription_url>, Redirects: RedirectNever, Timeout: voice.transcription_timeout}` and `MaxResponseBytes` from `egress.max_response_bytes`. A self-hosted service on a private address needs an operator entry `host[:port];allow_private` in `egress.allowed_hosts` (M1-22 Design note 4); say so in 12 8.2. The URL is instance configuration only; no request field, file name or user value ever reaches the request line.

    b. Request: `POST <voice.transcription_url>` with `multipart/form-data`, streamed from the object through an `io.Pipe` (no spool file): part `file` with the file name `audio.m4a` or `audio.mp3` (never `original_name`) and the stored `mime_type`; `model` only when `voice.transcription_model` is set; `language` only when the hint is not empty; `response_format` = `json`. `Authorization: Bearer <key>` only when `voice.transcription_api_key_ref` is set, the key resolved per call through `secrets.Provider.Resolve` (cached by `secrets.cache_ttl`, M1-09) and held in the redacting secret type.

    c. Response `200` with a JSON object: `text` (string, required), `language` (string, optional); other members are ignored. `text` must be valid UTF-8 without U+0000 and at most `message.max_content_bytes` bytes.

    d. Error classes: transient are timeouts, connection errors, `408`, `429` and `5xx`; permanent (`ErrTranscriptionPermanent`) are `egress.BlockedError`, `egress.ErrResponseTooLarge`, every `3xx` (never followed), every other `4xx`, a malformed or invalid body. Log one Warn line per failed call with `bothy.file.id`, the class and the status code; never the URL path or query, the key, a response body or text.

12. **Routing at acceptance** (09 3.4, 3.5, 13; M2-04 Design notes 2 to 6; M2-05 Design note 6; M2-08 Design note 10).

    a. `runs.OnMessagePosted` accepts `Origin = human` with `Kind` `text` or `voice` (M2-05 step 1 and M2-08 note 10 a said "voice comes with M3").

    b. For a voice message only: `MessageTrigger.Voice = true`, `VoiceMode` from `files.Transcripts.Mode(author)`, and `VoiceInput` of every `AgentFacts` built for the decision (thread operator, channel operator, mentioned agents) from `agents.EffectiveCapabilities(agent).VoiceInput`. A text message reads neither, so the text path costs no extra statement.

    c. The decision function decides (M2-04 note 6, `D-M2-04-2`): without a transcription path `reject` with `voice_unsupported`, which the merged mapping of M2-08 note 10 d turns into `trigger_state = failed` with that reason and no audit entry (a decision-function rejection); with a path, `Decision.Transcript` is `agent` or `service`. `agent`: the invocation is written at once (the audio is final since note 6 b), the adapter reads the file with `file.read` and calls `submitTranscript`. `service`: the invocation is held (note 13).

    d. In the run context of M2-13, `RunContextAttachment.transcript` is `transcript_text` when `transcript_status = 'done'` (absent otherwise) and the element keeps the `trust` of its message (09 4.6, ADR 0054 point 4); `ForMessages` carries the text internally, the API `File` never does. The AG-25 case and the AG-20 attachment and transcript cases of the conformance suite follow note 20.

13. **Hold and release** (04 15.3 point 1, 03 R-DM-44 and R-DM-47, 12 10; M3-07 Design notes 11 to 13). In `invokeOrHold`: `reason := files.Attachments.Pending(messageID)` when `HasAttachments` (and unconditionally on the follow-on run, as M3-07 note 11 d); hold when `reason != PendingNone`; the window is `domain.HoldWindow(reason == PendingTranscript, file.invocation_hold_max, voice.transcript_hold_max)`, so a voice message waiting for its transcript waits at most `voice.transcript_hold_max` and one waiting for a scan `file.invocation_hold_max`. The release time stays fixed at acceptance. `ReleaseInvocation` with cause `ReleaseFinal` releases only when `Pending` is `PendingNone`; `ReleaseTimeout` releases with the transcript still `pending`. Follow-ups (`agent.followup`) are not held. Ruling for docs/DECISIONS.md: the transcript is a reason to hold only through `transcript_status = 'pending'`, which only mode `service` sets.

14. **Authorization** (05 4.8; M1-28 requirement mapping; 07 4.1). A visible caller who is not the operator gets the reason of the merged `ThreadOperator` atom (`subject_kind_not_allowed`, 07 4.1) as `403 forbidden`. Remove the action from the golden deferred list; `TestDeferredActionsGolden` and AZ-P3 stay green. `file.transcribe` keeps the requirement `Level(write)` of the text mapping (if the merged code lists it as deferred, replace it the same way). Ruling for docs/DECISIONS.md: "foreign agent" of the plan row is an agent that cannot read the file; it gets the same `404` as an unknown id.
