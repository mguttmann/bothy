# M4-06: Localization with ARB lint

Status: ready | Depends on: M4-01 | Milestone: M4

## Goal

After this ticket `packages/l10n` holds every interface text of the apps and the console in German (default) and English as ARB files (`app_de.arb`, `app_en.arb`), generated with `flutter gen-l10n` into a typed `AppLocalizations` with ICU plurals and selects, plus the pure helpers that every screen needs: the translation of server problem codes with a generic fallback that shows the code, number, date, time and currency formatting per locale, and the fixed term table of 01 9 so that German and English mean the same. The build breaks on a missing translation, and a test over the ARB files rejects en and em dashes (U+2013, U+2014) and emoji and checks the term table. Why: 01 9 makes German and English first-class, D-W-94 keeps every other repository text English, and the ban list of the design README forbids dashes and emoji in interface texts; these rules must be gates before the first screen ticket writes a string.

## Design notes

1. **Generator setup.** `l10n.yaml`: `arb-dir: lib/l10n`, `template-arb-file: app_en.arb`, `output-dir: lib/src/generated`, `output-localization-file: app_localizations.dart`, `output-class: AppLocalizations`, `synthetic-package: false`, `nullable-getter: false`, `required-resource-attributes: true` (every message has an `@key` with a `description`), `untranslated-messages-file` in a temporary path only during the check. Ruling for docs/DECISIONS.md: English is the template because the code and its reviewers read English (D-W-94), while German stays the default locale of the app (01 9); `supportedLocales` lists `de` first. Key names are `lowerCamelCase` with a screen or component prefix (`e1ServerAddressLabel`, `liveBoxStateRunning`, `problemFallback`).

2. **Missing translation breaks the build.** `test/completeness_test.dart` parses both ARB files and fails on a key that is missing in one of them, on a key whose ICU placeholders differ between the two (name and type), on an `@key` without `description`, and on an empty message. In addition the gate runs `flutter gen-l10n` with the `untranslated-messages-file` option into a temporary copy and fails when that file lists anything, and compares the generated output with the checked-in `lib/src/generated/` (a stale generation fails). Put the generation check into `make codegen-check` for Dart members (one loop over members that have `l10n.yaml`, SKIP when none); record the ruling.

3. **ARB lint.** `test/arb_lint_test.dart` scans every message value (not the keys or descriptions, which are English prose and fall under the repository rules): U+2013 and U+2014 fail; emoji fail, defined as any code point with the Unicode property `Extended_Pictographic` plus the regional indicators `U+1F1E6` to `U+1F1FF` and the variation selector `U+FE0F` (keep the ranges in one constant with the Unicode version and source in a comment); a deliberately inserted U+2014 and a deliberately inserted emoji in a test fixture ARB file must fail (`test/fixtures/bad_dash.arb`, `test/fixtures/bad_emoji.arb`). The same scan covers the `description` texts for dashes only.

4. **Term table.** The table of 01 9 between its language-check markers is the source. A generator reads its rows (German, English, Code) and writes `lib/src/term_table.dart` (`const List<TermPair> termTable`, generated code); the gate compares. `test/term_table_test.dart`: for every English message that contains an English term of the table as a whole word (case-insensitive, plural with `s` included), the German message of the same key contains the German term of the row (word stem match: the German term or its stem without a final `e`, `en`, `n` or `s`); a list of explicit exceptions with a reason per key is allowed in the test and starts empty. Ruling for docs/DECISIONS.md: the check direction English to German, because the template is English. Implement the generator in Python in `tools/l10n/` (standard library, ruff `D`, pytest) so the Markdown parsing runs in the tool environment; or, if a Dart test can read `docs/spec/01-product.md` reliably from the package (walk up to the repository root as M2-38 does for its vectors), as a Dart test with `--check`; record which.

5. **Problem codes.** `String problemText(AppLocalizations l, String code, {String? reason})`: a switch over every code of `x-problem-codes` in `docs/api/openapi.yaml` to an ARB message (`problem<Code>`), with `reason` selecting a more specific message where 01 or 07 names one (for example `forbidden` with `capability_missing`); any other code gives `problemFallback(code)` ("Something went wrong ({code})"). `test/problem_text_test.dart` reads the code list from `docs/api/openapi.yaml` (walk up to the repository root) and fails for a code without an ARB message, so a new code in the spec needs a text in the same change.

6. **Formatting.** `L10nFormat(Locale locale)` with `money(num amount, String currency)` (de: `1,84 USD`; en: `USD 1.84`, as 01 9 shows), `count(int)`, `percent(num)`, `durationShort(Duration)` ("4:12", "28 min", "2 h 5 min" per locale), `time(DateTime, {required String timeZone})` and `relativeDay` ("today", "yesterday", weekday) using `intl` with the IANA time zone given by the caller (`users.time_zone`); no clock inside, the caller passes `now`.

7. **Locale resolution.** `Locale resolveAppLocale({String? userLocale, required List<Locale> systemLocales})`: `users.locale` `de` or `en` wins; otherwise the first system locale whose language is `de` or `en`; otherwise `de`.

8. **First keys.** Add the keys that M4-07 and M4-18 need first: the trigger labels (components.md 5), the live box state words and translated reasons (components.md 2.1), "Not found or no access", "No access anymore", "Sending", "Sending delayed", "Offline", the problem texts. German texts of components.md 5 are given there verbatim; take them from that table.

9. **Rulings for docs/DECISIONS.md** (`D-M4-06-<n>`): English template and German default (note 1); generation check in `codegen-check` (note 2); the emoji definition (note 3); term check direction and generator place (note 4); the allow-list entry for the German ARB file (D-W-94).

## Tests (write them first)

`packages/l10n/test/`:

- `arb_lint_test.dart`: the real files pass; `bad_dash.arb` (a value with U+2014) fails naming key and code point; `bad_emoji.arb` (a value with U+1F680) fails; an en dash U+2013 in a description fails.
- `completeness_test.dart`: the real files pass; a fixture pair with a missing German key fails; a placeholder `{count}` typed `int` in English and `String` in German fails; an `@key` without description fails.
- `problem_text_test.dart`: every code of the spec has a text; `forbidden` with `capability_missing` gives the specific text; `future_code` gives the fallback containing `future_code`, in both locales.
- `formatting_test.dart`: `money(1.84, 'USD')` gives `1,84 USD` in de and `USD 1.84` in en (the non-breaking space that `intl` may produce is normalized in the assertion and documented); durations; times in `Europe/Berlin` and `America/New_York` across a daylight saving change.
- `locale_resolution_test.dart`: user `en` with system `de` gives `en`; no user locale with system `fr`, `en` gives `en`; system `fr` only gives `de`.
- `term_table_test.dart`: the generated table equals 01 9; an English message with "Space" whose German text lacks the German term fails (fixture); the real files pass.
