# M2-12: Agent sessions per thread

Status: ready | Depends on: M2-09 | Milestone: M2

## Goal

After this ticket every thread has at most one current agent session and a history of earlier ones, kept by the module `agents` in the table `agent_sessions` (03). People read the history (`listAgentSessions`), start a new session (`resetAgentSession`, the built-in `/new`) and bind an existing external session with a compare-and-swap over the current session (`bindAgentSession`, the built-in `/resume`, with `take_over` for a session that is current in another thread); the adapter reports the external reference, the model, `started` and a failed binding (`reportAgentSession`) under `If-Match`. The run path carries the session: every invocation of the thread's operator names its session mode (`new`, `resume` or `bind`) and its session row, `run.start` with a reference creates the row, otherwise the first report creates it, and an imported earlier session is bound exactly once at the first trigger and fails open with exactly one system line when the runtime no longer knows it (AG-18). A stale `expected_current_session_id` and a take-over without `take_over` give `409` (AG-17); two concurrent reports never both succeed; an external session is current in at most one thread. Why: a thread is the unit of an agent's conversation (01 section 1 point 2; REUSE L01 and L14). Without sessions an adapter could not continue a conversation after a restart, people could neither start over nor resume, and the import could not carry earlier sessions over (22 section 9).

11. At most one current session per thread, and an external session (`agent_id`, `external_session_ref`) is current in at most one thread; both are partial unique indexes and hold under concurrency (03 `agent_sessions`; PLAN row M2-12).
12. `listAgentSessions` returns the current and the earlier sessions of a thread with reference, model, cost, period and end reason; permission `read` on the thread, `rl.read`, no audit (09 9.3, 05 4.6).
13. `resetAgentSession` ends the current session with `end_reason = 'reset'`, writes `agent_session.changed`, and the next run gets `session.mode = new`; it never disturbs a run that is active (09 9.2). Permission `trigger` and `agent.invoke` (05 4.6, rule 1.6), `rl.trigger`, `Idempotency-Key`, no allow audit.
14. `bindAgentSession` binds an external session to the thread with `expected_current_session_id` as compare-and-swap and `take_over` for a session current elsewhere: `409 conflict` with `reason` `session_bound_elsewhere` or `session_changed`, nothing changes on a `409`; the old rows end with `rebind`, the new row has `started = true`, the next run gets `bind`; permission `trigger` and `agent.invoke` here and, when taking over, also there; audited (09 9.4, 05 4.6, 07 4.2, AG-17).
15. `reportAgentSession` lets the adapter report reference, model, `started` and `bind_failed` for the session of its own active run in the thread, as compare-and-swap over `agent_sessions.version` with `If-Match`; the first report creates the row when `run.start` carried no reference; permission `agent-self`, `rl.agent_runtime`, SR9 exception (05 4.6, 09 4.7, 9.1, 9.5, 04 15.3 step 4, 07 SR9).
16. Every operator invocation carries its session: mode `new`, `resume` or `bind` and the session row; a guest run carries neither (09 9.1, 3.6, R-AG-04). `run.start` with `external_session_ref` creates the row (`is_current`, `started = false`) and sets `runs.agent_session_id`; otherwise the first report sets it (09 9.1, 03 `runs.agent_session_id`, E-AG-19).
17. An imported earlier session is bound at the first trigger in the run's transaction, exactly once (compare-and-swap over the partial indexes), with audit `agent_session.bind` and `agent_session.changed`, never after the thread had a current session; when the runtime no longer knows it, the adapter reports `bind_failed: session_missing`, the bound row ends with `rebind`, a new row starts and exactly one system line `agent_session.resume_failed` with the run's agent as author is written, which does not reopen a closed thread (03 `messages`, R-DM-42); the run continues (09 9.5, 22 section 9, AG-18).
18. After an operator change in a main thread the session of the former operator ends with `agent_changed` at the next run (03 `end_reason`, R-AG-02).
19. `agent_session.changed`: resource `thread` without `resource.version`, receive action `thread.read`, payload `AgentSessionChangedPayload` (05 section 6, 04 9 point 3, openapi).
20. No read permission gives `404`, `403` only with read permission (R-AZ-01); every denial is audited by `authz` (R-AZ-04, AZ-P13); audit details carry only IDs and codes, never the reference (SEC-AUD-5).
21. Versioned answers carry `ETag`; no JSON `null` (06 8, ADR 0053); unknown request fields give `400 validation_failed` (06 2 "Unknown values").

## Design notes

1. **The code of the fail-open system line** (03 `messages`, R-DM-34, R-DM-42, D-W-104). 09 9.5 point 4 and 22 section 9 step 5 require exactly one system message when an imported or rebound session is missing. A system message is `kind = 'system'` with a code in `messages.system_code` (SEC-OUT-3). The core contract has the rule: the CHECK of `messages.system_code` in 03 lists `agent_session.resume_failed`, and 03 states that when the server accepts an `agent_session.report` with `bind_failed`, it writes in the same transaction exactly one such line with the run's agent as author, and that a system line does not reopen a closed thread (also 00 "Done" and 01 6.1). Use exactly that code; the enum `Message.system_code` in `openapi.yaml` lists it as well. Before writing any code, read the CHECK on `messages.system_code` in the merged migration of M1-56 (never edit that file). If it already lists both codes of 03 (M1-56 builds its CHECKs as 03), add no migration for it. If it lists only `thread.reopened` (M1-56 was built from a 03 before R-DM-42), the migration `<next free number + 1>_messaging_system_code_resume_failed.sql` drops that CHECK (its name from the merged migration, or the PostgreSQL default name when that migration names none) and adds it again with exactly the two codes of 03 as `NOT VALID`, and `<next free number + 2>_messaging_system_code_validate.sql` validates it (upgrade.md M5 and M8, M6 through the runner of M1-12). Any other content of that CHECK is a deviation of M1-56 from 03: stop with `Verdict: BLOCKED <reason>` as the Boundaries say for merged M1 code (D-W-100). Never write the note as text, as another code or as a normal message.

2. **Module boundaries** (02 4.3, 4.4, 8.3).
    - `agents` owns `agent_sessions`, the four operations and every session rule; no other module reads or writes the table (03 principle 12).
    - `runs` calls the port `agents.Sessions` in its own unit of work: `ForInvocation(ctx, InvocationSessionQuery{ThreadID, AgentID, TriggeredBy ids.ID}) (InvocationSession, error)` with `InvocationSession{Row *Session}` (Design note 9) and `AttachOnStart(ctx, AttachOnStartCmd{ThreadID, RunID, AgentID ids.ID; ExternalSessionRef, Model string}) (sessionID ids.ID, err error)` (Design note 10).
    - `agents` declares the source `RunSource` with `ActiveRun(ctx, threadID ids.ID) (ActiveRun, bool, error)`, `ActiveRun{RunID, AgentID, SessionID ids.ID; State string}`: the run of the thread in `queued`, `running` or `waiting_input` (R-DM-14), its row locked `FOR UPDATE`. `runs` implements it in its postgres adapter; `internal/wire` wires it (an empty source answers "no run" until wiring, 02 4.4).

Reuse the port function the trigger path of M2-04 and M2-05 uses; add a read-only port method to `chat` only if none exists.

Reason: a report must find the reporting agent's active run and the row of `runs.agent_session_id` belongs to `runs` (03), while `agents` may not use `runs` (02 4.4); a declared source and an In-Tx event keep every edge downward, as the `authz` sources and `agents.AgentDisabled` do. 7. **`resetAgentSession`** (09 9.2), one unit of work:
    a. Load the thread (unknown gives `404`) and its operator; authorize (Design note 5).
    b. Lock the thread's current row `FOR UPDATE`. None: `409 conflict` with `reason` `no_current_session`. Ruling for docs/DECISIONS.md, documented in 09 9.2: there is nothing to end, and a `201` without a session would have no body that fits `AgentSession`.
    c. End it: `ended_at = now()`, `is_current = false`, `end_reason = 'reset'`, `version + 1`; append `agent_session.changed`; answer `201` with the ended row and its `ETag`.
    d. Ruling for docs/DECISIONS.md, documented in 09 9.2: a reset during an active run ends the current row at once and leaves the run alone; the run keeps `runs.agent_session_id`, its reports still reach that row (Design note 11), and the next run gets `new`. Reason: 03 has no column for a pending reset, and "waits until it ends" means the active run is not switched; the visible effect (the next run starts a new session, the command answers "after the run") is the same.

8. **`bindAgentSession`** (09 9.4), in this order:
    a. Load thread T (unknown gives `404`) and its operator A.
    b. When A is set, find the current row of `(A, external_session_ref)` in another thread T2 (no lock yet).
    c. Authorize with `TargetThreadID = T2` (zero when none) (Design note 5).
    d. Validate the body (Design note 13); `expected_current_session_id` and `take_over` as in `AgentSessionBind`.
    e. T2 set and `take_over` false: `409 conflict` with `reason` `session_bound_elsewhere`; nothing changes.
    f. Unit of work: lock T's current row and, if taking over, T2's row `FOR UPDATE` in ascending `id`. Compare-and-swap: the ID of T's current row (or none) must equal `expected_current_session_id` (or its absence), else `409 conflict` with `reason` `session_changed` and nothing changes (09 9.4 point 3; `412` belongs to `If-Match`). If T2's row is no longer current, continue without a take-over.
    g. End T's current row with `rebind`; when taking over, end T2's row with `rebind`; insert the new row (T, A, reference, `started = true`, `is_current`, cost baseline of Design note 14) with `INSERT ... ON CONFLICT DO NOTHING`. No row inserted: re-read and answer `409 conflict` with `reason` `session_changed` (T got another current row) or `session_bound_elsewhere` (the reference became current in a third thread).
    h. Events (Design note 15), the allow audit entry, `201` with the new row and its `ETag`. The next run gets `bind` (Design note 9). A bind during an active run leaves that run on its row, like a reset.

9. **Session of a new run** (09 9.1, 9.5; 22 section 9). `runs` calls `ForInvocation` in the transaction that appends `agent.invocation`, only for a run of the thread's operator; a guest run gets no session (09 3.6, R-AG-04). `ForInvocation`:
    a. Lock the thread's current row `FOR UPDATE`.
    b. Current row of another agent: end it with `agent_changed` and append `agent_session.changed` (03 `end_reason`, R-AG-02).
    c. Current row of this agent: return it.
    d. No current row: when the thread has no row other than rows with `end_reason = 'import'` and has an import row of this agent, take the newest (`created_at`, then `id`, descending) and insert a current row with the same reference, `started = true`, its `model`, `cost_baseline_micros` and `currency` (`ON CONFLICT DO NOTHING`). Inserted: audit `agent_session.bind` with the triggering human as actor and `cause` `import`, append `agent_session.changed`, return the row. Not inserted because the thread got a current row concurrently: re-read and return it (exactly one of two concurrent first triggers binds, 22 section 9 step 3). Not inserted because the reference is current in another thread: return none (fail open, 22 section 9 steps 3 and 5). Ruling for docs/DECISIONS.md: "has had no current session since the import" means the thread has no row other than import rows, so a later reset never binds again (09 9.5 point 5).
    e. Otherwise return none.
    The mode is decided in `runs/domain` (`runs` owns the table that tells whether a run used a row): no row gives `new` without `agent_session`; a row with `started = false` gives `new` with the row (the adapter reuses its reference, REUSE L14); a started row that some run already used (`runs.agent_session_id`) gives `resume`; a started row no run used gives `bind`. The payload carries `agent_session` and the new member `session_mode`; a guest run has neither. Ruling for docs/DECISIONS.md: `session_mode` is the openapi name of `session.mode` in 09 9.1 (Design note 17). The single constructor of `AgentInvocationPayload` takes the session decision as a required argument, so every writer of `agent.invocation` (acceptance, a released held invocation, follow-up runs, interactions without a waiting run, model commands, whichever are merged) carries it.

10. **`run.start`** (09 9.1, 4.7, 04 15.3 step 4). The `queued -> running` path of `startRun` calls `AttachOnStart` after its token checks and its compare-and-swap succeeded; `resumeRun` (`waiting_input -> running`) does not, because the run keeps its row. `AttachOnStart`:
    - Guest run (the agent is not the thread's operator): return zero; the reference is ignored.
    - Lock the current row. A current row of this agent: attach it, unchanged even if the reference or model in `run.start` differ.
    - No current row of this agent and a reference given: the most recent row of this thread and agent with that reference (a reset or bind ended it after the run was queued): attach it, unchanged. Otherwise insert a current row with the reference, `model` and `started = false` (`ON CONFLICT DO NOTHING`), append `agent_session.changed`, attach it; when nothing was inserted, attach nothing and log the run and thread IDs (no reference).
    - No reference: attach nothing; the first report creates the row.
    `runs` writes `runs.agent_session_id` in the same transaction. Ruling for docs/DECISIONS.md: `run.start` never changes an existing row, so the version the adapter got with the payload stays valid for its first `If-Match`, and a new row starts at version 1 (03 default); a changed reference or model of an existing row comes only through `agent_session.report`. The reference is validated as in Design note 13; an invalid one fails `startRun` with `400 validation_failed` and pointer `/external_session_ref`.

11. **`reportAgentSession`** (05 4.6, 09 4.7, 9.1, 9.5):
    a. Load thread T. Read the active run through `RunSource` (locks its row). No active run, a run of another agent, a state other than `running` or `waiting_input`, or a run whose agent is not T's operator (a guest run has no session): `404 not_found` with the body of an unknown thread.
    b. Authorize (Design note 5).
    c. Validate the body (Design note 13); unknown members give `400 validation_failed`.
    d. Let R be the row of `runs.agent_session_id`, locked `FOR UPDATE`.
    - R exists: `If-Match` must equal R's version; absent or different gives `412 version_conflict` with `current` = R. With `bind_failed`: Design note 12. Otherwise apply: a different reference replaces R's reference (if R is current and the new reference is current in another thread: `409 conflict` with `reason` `session_bound_elsewhere`); a given, different `model` replaces it; `started: true` sets it; `started: false` never resets it. Nothing changed: `200` with R, no version change, no event. Changed: `version + 1`, `agent_session.changed`, `200`.
    - No R: `If-Match` present gives `412 version_conflict` without `current`; `bind_failed` gives `409 conflict` with `reason` `session_not_bound`. Insert a current row (T, A, reference, `model`, `started` as given, absent is false) with `ON CONFLICT DO NOTHING`. Inserted: `agent_session.changed`, publish `SessionAttached`, `200`. Not inserted: `409 conflict` with `reason` `session_changed` (the thread got a current row, for example by a bind during the run) or `session_bound_elsewhere`.
    e. Answer with `ETag`. Because step a locks the run row, the second of two concurrent first reports sees the row the first created and gets `412 version_conflict` with `current`; two reports with the same `If-Match` give one `200` and one `412` (PLAN acceptance "two concurrent reports yield exactly one success").
    Ruling for docs/DECISIONS.md: `If-Match` is the compare-and-swap of the report (`IfMatchOptional`): absent means "this run has no session row yet", so a missing header where a row exists is a version conflict, not `428`; `started` only moves forward; a reference change of a started row is the same session under a resolved reference (09 9.5 point 3, 18.9 "Session missing in Claude Code" reports the new reference without `bind_failed`). Reasons `session_not_bound` and `no_current_session` are new and documented in 09.

12. **`bind_failed: session_missing`** (09 9.5 point 4, 03 `end_reason` `rebind`). Allowed when R exists and `started = true`, else `409 conflict` with `reason` `session_not_bound`. In the unit of work: when R is current, end it with `rebind` and insert a new current row N (reference, `model` and `started` from the body, cost baseline 0); when R is no longer current (a reset or bind ended it during the run), insert N already ended with R's `end_reason` and `ended_at = now()`, so that human decision stays in force (03 `ended_at`: "or was never current"). Events R then N; publish `SessionAttached{SessionID: N, ReplacedSessionID: R, BindFailed: true}`. `runs.OnSessionAttached` sets `runs.agent_session_id = N` and calls `messaging.Messages.AppendSystemLine` once with the code of Design note 1, author the agent, after M1-56 D6 (`kind = 'system'`, `origin = 'system'`, empty `content_md`, server `client_msg_id`, silent, no mentions, no `trigger_state`), through `AppendToThread` with `ReopenIfClosed = false` (a note does not reopen a closed thread). A system line never triggers (SR4). The run continues; the answer is `200` with N. "Exactly once": a retry with the same `Idempotency-Key` returns the stored answer (06 7), a concurrent duplicate fails the `If-Match` compare-and-swap. Ruling for docs/DECISIONS.md: N ended when R was ended (author and reopen rule of the note are in 03, R-DM-42).

14. **Cost baseline** (03 `cost_baseline_micros`, 22 section 9 step 7). An import binding copies `cost_baseline_micros` and `currency` of the import row. A bind (Design note 8) sets the new row's baseline to `cost_baseline_micros + cumulative_cost_micros` of the most recent row of the same agent and reference in any thread, with its currency; none gives 0 and the default currency. Rows created by `run.start`, by a report or by `bind_failed` start at 0. Ruling for docs/DECISIONS.md: a runtime that reports sums per session would otherwise book the earlier amount a second time after a rebind (03, "the server books only the part above it"; booking itself is M2-22).

15. **Events and audit.**

Envelope: scope `{space_id, channel_id, thread_id}` of the row's thread, resource `{kind: thread, id: thread_id}` without `version` (04 9 point 3), receive action `thread.read`, actor the principal of the request (for changes made by `ForInvocation`, the triggering human), payload `AgentSessionChangedPayload{thread_id, agent_session}`. 16. **Locks and concurrency** (02 8.2, 03 6.3). Rows of `runs` before rows of `agent_sessions`; several rows of `agent_sessions` in ascending `id`. Report: the run row through `RunSource`, then R. Acceptance and start: the run row (in `runs`), then the session rows. Bind and reset: session rows only. Deadlocks and lock timeouts are retried by the unit of work (`database.tx_retry_max`). The partial unique indexes are the final guard: every insert uses `ON CONFLICT DO NOTHING` and maps the outcome, so no unique violation reaches a client as `500`.
