# M2-43: Control connection between host service and server

Status: ready | Depends on: M1-67, M2-42 | Milestone: M2

## Goal

After this ticket a paired host service holds exactly one outgoing control connection to the server at `wss://<instance>/api/v1/hosts/connect` (asyncapi channel `hostControl`), and the server knows at every moment which host is connected, what it reports and whether it may receive sessions. The server opens with `hello` (challenge, server time, heartbeat interval, protocol versions, JWKS of purpose `terminal`); the host service logs in with `identify`, a compact EdDSA proof over the challenge made with the Ed25519 key it registered at pairing, within `terminal.host_auth_timeout`; an unknown or replaced key closes with `4110`, a disabled or retired host with `4111`, a second live connection with the same keys with `4112` and a disabled host, a bad or missing proof with `4113`, a protocol version below the supported one with `4114` (24 "Errors", 18 "Host service and server"). `identify` lists `live_sessions`, and every other session of the host in `active` or `detached` ends with `host_restarted` (24 "Detach and reattach", D-W-90, TM-T16). After `ready` the host service sends `report` before it accepts any `session.open`, and the server sends `session.open` only after that `report`; the report writes the profiles, the session users with their working directories after HD7 (TM-T29 (c)), the self-checks with one entry per affected account and the server-host flag (24 "Host service `bothy-host`" points 5 and 6). Heartbeats keep the connection alive; `terminal.host_heartbeat_miss_limit` missed heartbeats close it. Presence travels as the ephemeral `host.presence_changed`; the server closes the connection on disable, retirement and re-pairing; a host whose `doctor` refused the start logs in, sends exactly one `report` and stops (D-W-91). This ticket builds both ends: the server side in `internal/terminal/adapters/wsrelay` and the client side in `services/host/internal/control`, and it makes the deferred authorization entry `host.connect` of M1-28 a real requirement with the right `host-self`. Without it the server cannot reach a host, a stolen key pair stays invisible (T-TM-05), and a host that stops for all people because of one account names nobody (T-TM-14). Sessions, the session token and both stream relays follow in M2-44 and M2-45.

Product requirements implemented here:

11. One control connection per host at `/api/v1/hosts/connect`, opened only by the host service, outgoing, over TLS; JSON text frames `{op, d}` of at most `sync.ws_max_frame_bytes`; the first frame is `hello` with `protocol_versions`, `challenge`, `server_time`, `heartbeat_interval_ms` (`terminal.host_heartbeat_interval`) and the JWKS of purpose `terminal` (24 2.2 last bullet, 5.3; asyncapi `hostControl`; `HostChannelHello`).
12. Login only with a valid signature over the challenge of `hello` (`HostIdentify.proof`: compact JWS, `alg = EdDSA`, `typ = host-auth+jwt`, over `{challenge, host_id, iat}`, with the key registered at pairing) and within `terminal.host_auth_timeout`; otherwise `4113`; unknown or replaced keys `4110`; host `disabled` or `retired` `4111`; a protocol version the server does not support `4114` (24 13, D-W-24, 18 9.1, D-T38).
13. `host.connect` is `host-self` (05 2.1, 4.14; 07 3; D-T25): only the host itself, authenticated with its key, passes; Audit `denials`, plus one allow entry on a change of `reported_is_server_host`, `reported_doctor` or `reported_session_users` and one entry per second control connection (24 10.1); Permissions `no`; class `rl.host`.
14. `heartbeat` is answered with `heartbeat_ack`; after `terminal.host_heartbeat_miss_limit` missed heartbeats the server closes with `4009` (asyncapi `hostControl.receive.heartbeat`).
15. `identify` on the control connection always carries `live_sessions`; the server ends every other session of the host in `active` or `detached` with `close_reason = host_restarted` (24 6.2, 10.3, D-W-90, R-TM-27, TM-T16).
16. After `ready` the host service sends `report` before it accepts any `session.open`, and the server sends `session.open` only after that `report` (24 2.2 point 5, asyncapi `hostControl` description). `report` writes `hosts.reported_profiles`, `hosts.reported_session_users` (the lists after HD7, TM-T29 (c)), `hosts.reported_doctor` (one entry per affected session user under the rule for names), `hosts.reported_is_server_host`, `hosts.reported_require_local_confirm` and `hosts.reported_os_version` (03 `hosts`, D-W-63, D-W-64, D-W-69, D-W-109).
17. When `doctor` refused the start, the paired host service logs in, sends exactly one `report`, closes the connection without accepting `session.open` and ends with the exit code after which the service manager does not restart it (24 2.2 "Message on a refused start", D-W-91, TM-T21 (g)).
18. A second control connection with the same keys makes the server probe the older one with a WebSocket ping: no answer within `terminal.host_duplicate_probe_timeout` closes the older with `4009` and accepts the new one; an answer closes both with `4112`, disables the host with `disabled_reason = duplicate_connection`, ends all sessions (`host_disabled`), audits `host.connect` with code `duplicate_connection` and sends `host.updated` (24 3.4, D-T13, R-TM-13, TM-T23).
19. The server closes the control connection when the host is disabled or retired (`4111`) and when it is re-paired (`4110`) (24 3.1, 3.3, 13).
20. Presence: the connection state lives only in the memory of the server (03 `hosts`) and travels as the ephemeral `host.presence_changed {host_id, connected}` to everyone with `host.read` (05 6, 24 10.2).
21. A report that no longer names the session user of a person ends that person's sessions on the host with `access_revoked` in the same transaction (07 SR12, 24 8.3); a report that turns `reported_is_server_host` on ends the sessions of people who are not owners (07 SR10, 24 8.3).
22. Every frame of both sides conforms to `docs/api/asyncapi.yaml` and its body schema in `docs/api/openapi.yaml` (G9); no JSON `null` (ADR 0053); no proof, challenge, key, terminal content or path in logs, audit details, events, problem bodies or test output (24 10.1, 10.4, SEC-LOG-2).

## Design notes

1. **Placement.** The connection, its op handlers and the registry live in `terminal/adapters/wsrelay` (02 4.3: `Relay` only in that adapter); every decision is a pure function in `terminal/domain`; every database effect is a use case in `terminal/app` with `authorize`, unit of work, audit and events. Only `terminal/adapters` imports `github.com/coder/websocket` (02 5 rule 4). `terminal` uses `instance` (JWKS), `identity` (owner status), `authz` and the kernel; it never imports `gateway`: presence goes through `kernel/eventlog.EphemeralPublisher`, bound in `internal/wire`.

2. **Endpoint and frames.** Route `GET /api/v1/hosts/connect` on the public listener for the roles `api` and `all`, registered like M1-64 registers `/api/v1/gateway` (same chain steps, bound to `host.connect` for AZ-P1). Accept with the library's default origin check (a host service sends no `Origin`; never `InsecureSkipVerify`). Text frames only, read through a reader limited to `sync.ws_max_frame_bytes` plus one byte; strict decoding as in M1-64 (duplicate keys, invalid UTF-8, unknown members, missing `op`, a `d` that does not match its schema). One reader goroutine handles ops in order; one writer goroutine drains a queue bounded by `sync.outbound_queue_max` with the deadline `gateway.write_timeout` per write. Close codes outside the login: a binary frame, invalid JSON, a frame over the limit (reason `frame_too_large`), an unknown op, a server-to-host op from the host or a second `identify` close with `4002`; queue overflow or a missed write deadline with `4014`; a panic or an internal error with `4000` (added to `hostControl` and `hostData` in note 14). Ruling for docs/DECISIONS.md: `4002` covers unknown ops on this channel because `hostControl` names no `4001`.

3. **Login.** `hello` right after the upgrade: `protocol_versions` = `SupportedProtocolVersions` (today `[1]`; a test holds it equal to `x-protocol-versions` of `hostControl`), `challenge` = 32 bytes from `crypto/rand` in base64url without padding, `server_time`, `heartbeat_interval_ms` from `terminal.host_heartbeat_interval`, `heartbeat_miss_limit` from `terminal.host_heartbeat_miss_limit` (new member, note 14), `jwks` = the `next`, `active` and `retiring` keys of purpose `terminal` only. `IdentifyOutcome` decides in this order, first match wins:
   a. No frame within `terminal.host_auth_timeout` after `hello`, or a valid host-to-server op other than `identify`: `4113`. A frame that fails decoding: `4002`.
   b. `protocol_version` not in `SupportedProtocolVersions`: `4114`, before the proof is looked at (18 9.1).
   c. `live_sessions` absent or `session_id` present on the control connection: `4002`.
   d. Proof (`CheckHostProof`): compact JWS with exactly three parts; header `alg` exactly `EdDSA`, `typ` exactly `host-auth+jwt`, `kid` present; payload exactly the members `challenge`, `host_id`, `iat`. No host row with `identify.host_id`, a host in `pairing` (keys discarded) or `kid` different from `hosts.auth_jkt`: verdict `HostAuthUnknownKey`, close `4110`. Signature that does not verify with `hosts.auth_public_jwk` through `kernel/jose`, `challenge` different from this connection's, `host_id` claim different from `identify.host_id`, `iat` before `hello.server_time` minus `auth.clock_leeway` or after now plus `auth.clock_leeway`, any malformed part: verdict `HostAuthInvalid`, close `4113`. Ruling for docs/DECISIONS.md: `kid` is the RFC 7638 thumbprint of the host's Ed25519 key (`hosts.auth_jkt`), so the server tells a replaced key (`4110`, "run `pair` again") from a forged signature (`4113`); the claim set is closed and `iat` must lie within `auth.clock_leeway` of the exchange.
   e. `authorize(host principal, host.connect, {kind: host, id, HostAuth})` (note 4): `principal_inactive` for `disabled` or `retired` closes with `4111`.
   f. Duplicate check (note 5), then the login unit of work: reconcile `live_sessions` (note 6), store `identify.host_version` in `reported_host_version` (a change raises `hosts.version` and writes `host.updated`), set `last_seen_at` (note 9).
   g. Register the link (note 7), re-read `state` and `auth_jkt` once and close yourself with the mapped code if they changed in between (a state change committed between e and the registration found no link to close), then send `ready {host_id, state, llm_credentials}` (`confirming` or `active`; `HostReady` after M2-42; `llm_credentials` from the row re-read in this step).
    `identify.host_version` must match SemVer 2.0.0 and `os_version` in `report` must pass `textcheck.DisplayText`; otherwise `4002` for `identify` and note 8 for `report`. Keep `hello`, the timeout and the proof check in one function with a parameter for the channel, so that M2-44 reuses it for `hostData` (`session_id` instead of `live_sessions`).

4. **Authorization.** `actor.Principal{Kind: host, ID: host_id}` (07 3, D-T25); never looked up in `principals`. `authz` changes: requirement `host.connect`: `HostSelf`, mapping row `host-self` -> `HostSelf`; the atom passes for kind `host` with `r.ID` equal to the principal and fails with `subject_kind_not_allowed` for every other kind (05 4.14 last paragraph, as TM-T17 for the terminal actions); visibility of resource kind `host` for a host principal: only its own row (another host gives `not_found`). Liveness for kind `host`: `Resource.HostAuth` must be set (missing is an internal error); `HostAuthUnknownKey` or `HostAuthInvalid` gives `unauthenticated` with reason `host_auth_failed`; a host state from `authz.HostSource` other than `confirming` or `active` gives `unauthenticated` with `principal_inactive`; the snapshot of a host principal is empty (no grants, not owner). Replace the deferred entry and remove `host.connect` from the golden list in the same change (07 4.2, AZ-P3); `VerifyRegistrations` then accepts the channel ops (M1-25 rule 3a).
   a. Every op after the login calls `authorize` again with `HostAuthValid` and closes on a denial with the code of note 3 (`4110` for a host now in `pairing`, `4111` for `disabled` or `retired`): a state change on another node still ends the connection at its next op, fail closed.
   b. Denials are recorded by the authz layer as for every action (aggregated per `audit.deny_aggregate_window`, R-AZ-04, AZ-P13); a denial without an existing host row has no resource. The actor columns of `host.connect` entries stay empty and the host is the resource. Ruling for docs/DECISIONS.md: audit actor IDs point to principals with a row; a host is named as resource.
   c. Changes of `reported_session_users` are rights state (03 4.3, 07 SR12, M2-40 Design note 8). `ApplyReport` writes them only through M2-40's in-transaction `ApplySessionUserReport` (the function `RecordSessionUserReport` wraps), inside its own unit of work declared as `txn.RightsChange{Action: host.connect, Resource: host, Targets: [host], Principals: people with a valid assignment on the host}` (not a second unit of `RecordSessionUserReport`). When `SameReport` is false, that unit raises `permission_version`, ends the sessions of vanished names with `access_revoked` and writes the one `host.updated`; the other `reported_*` columns are written in the same unit. Only `reported_is_server_host`, which 03 does not list, is read per decision through `authz.HostSource` (M2-40 Design note 3). Login, heartbeat, session reports and reports without a change of `reported_session_users` never raise the version; the other rights-version change of this ticket is the host transition of note 5 b, which 24 3.1 requires for every transition out of `active`. Ruling for docs/DECISIONS.md: Permissions `no` of `host.connect` (05 4.14) does not exempt a report from 03 4.3; a changed list of session users raises the rights version, the server-host flag does not.

5. **Second control connection (24 3.4, TM-T23).** Before the login unit of work, under a per-process lock per host: if the registry holds a live link for the host, call `Ping` on it with a context limited by `terminal.host_duplicate_probe_timeout`.
   a. No answer: close the older with `4009`, run `ConnectionLost` for it (note 11), continue the new login; audit `host.connect` allow with details `code: stale_connection_replaced`.
   b. Answer, host `active`: in one unit of work disable the host through M2-39's transition with `disabled_reason = duplicate_connection` (it ends all sessions with `host_disabled`, raises `permission_version` as every transition out of `active` does, writes `host.updated`), audit `host.connect` deny with reason `host_duplicate_connection` and details `code: duplicate_connection`; after the commit close both connections with `4112`.
   c. Answer, host `confirming`: 03 allows `disabled` only after confirmation. Use M2-41's fallback from `confirming` to `pairing` that discards the keys (the one after `terminal.fingerprint_max_attempts`), with the same audit entry and `host.updated`; close both with `4112`. Ruling for docs/DECISIONS.md and update 24 3.1 and 3.4: for an unconfirmed host the only state from which only a new pairing helps is `pairing` with discarded keys.
   d. Ruling for docs/DECISIONS.md: the reason `host_duplicate_connection` (decision `forbidden`) joins 07 4.1, because the closed list has no reason for a denial with valid credentials.

6. **`live_sessions` (24 6.2, D-W-90).** In the login unit of work, the host's sessions not `closed` are locked `FOR UPDATE` in ascending `id`. `ReconcileLiveSessions(sessions, live)`:
   a. Every session in `active` or `detached` not in `live` ends with `host_restarted` through the session-ending function (note 10). `opening` sessions stay; `terminal.open_timeout` ends them (M2-44).
   b. Every listed ID that is `closed` for this host, unknown, or of another host gets `session.close {session_id, close_reason}` right after `ready`: the stored `close_reason`, else `access_revoked`. Ruling for docs/DECISIONS.md: a PTY the server no longer allows ends at the next login (8.3 "instructs the host service"), fail closed for IDs the server does not know.
   c. Listed sessions that are `opening`, `active` or `detached` stay unchanged; their end comes with `session.ended`.

7. **Links, readiness and presence.** The registry maps host ID to one link (connection, writer queue, `reported` flag, key generation). `ControlLinks` (app port):
   a. `OpenSession(ctx context.Context, hostID ids.ID, cmd HostSessionOpen) error`: `ErrHostNotConnected` without a link, `ErrHostNotReady` before the first applied `report` after `ready` (M2-44 maps both to `409 host_unavailable`); otherwise enqueue `session.open`.
   b. `CloseSession(ctx context.Context, hostID, sessionID ids.ID, reason string) error`: enqueue `session.close`; without a link nothing happens (note 6 b catches it at the next login).
   c. `CloseHost(hostID ids.ID, code int)`: close the link with the code after the caller's commit. `setHostState` (disable, retire: `4111`), `issueHostPairingCode` for an existing host (`4110`), M2-41's fallback to `pairing` after `terminal.fingerprint_max_attempts` (`4110`) and the duplicate paths call it.
   d. `Connected(hostID ids.ID) bool`: true from the first applied `report` after `ready` until the link ends. `Host.connected` in `getHost`, `listHosts` and `host.updated` reads it. `host.presence_changed {host_id, connected}` is published on each change of that value (resource `{kind: host, id}`, no scope, no actor, no `seq`). Ruling for docs/DECISIONS.md and 24 10.2: "connected" means usable for sessions, so a client that retries after `409 host_unavailable` on `connected: true` does not race the first `report`.
    If the merged gateway drops ephemeral events without a space or channel scope, add the rule "no scope: every live connection is a candidate, admitted with the receive action in delivery mode" to its candidate selection with a test.
   e. `SendReady(hostID ids.ID)`: after the commit of `confirmHost` (M2-41), `setHostLlmCredentials` (M2-40) and any other change of `hosts.llm_credentials`, the registry re-reads the row and sends `ready` again on the open link (M2-42 Design note 15); without a link nothing happens (the next login carries it).

8. **`report`.** `ValidateReport` (failure answers `host.error {op: "report", code: "validation_failed"}`, stores nothing and keeps the connection): every check `hd1_user` to `hd11_shared_locations` appears at least once; `check` and `session_user` unique together; `session_user` only on entries with `ok = false`; `os_user` names unique without regard to case; profile names unique; `display_name`, `workdirs[]` and `os_version` pass `textcheck.DisplayText`; each `session_users[].os_user` and each `doctor[].session_user` through M2-39's `domain.NewOSUser` (pattern of 03, at most `host.os_user_max_chars`); profile names, `display_name`, each `workdirs` entry and `os_version` at most `terminal.report_label_max_chars` characters; `profiles`, `session_users` and the `workdirs` of one session user each at most `terminal.report_max_entries` entries. These are M2-41 Design note 4 c to f, reused through its validator where the merged code exposes one; unlike `pairHost`, an empty `session_users` is allowed, because a refused start must still report HD1. `ApplyReport` in one unit of work, host row `FOR UPDATE`:
   a. `DiffReport(stored, new)`: nothing changed: no write, no event, no audit (06 2 "No effect"). Otherwise update the changed `reported_*` columns, `hosts.version + 1`, one `host.updated` through M2-39's writer (when `reported_session_users` changed, the one that `ApplySessionUserReport` writes, note 4 c). The lists are stored exactly as reported, in their order (TM-T29 (c)).
   b. Audit allow `host.connect` only when `reported_is_server_host`, `reported_doctor` or `reported_session_users` changed. Details: `changed` (list of codes `is_server_host`, `doctor`, `session_users`), `is_server_host` (bool), `failed_checks` (codes `<check>` or `<check>:<code>`), `hd6_users`, `hd9_users`, `hd10_users`, `hd11_users`, `session_users_added`, `session_users_removed` (lists of names). Session user names enter audit details only through a value kind that accepts exactly the pattern of `HostSessionUserAssign.os_user` and at most `host.os_user_max_chars` characters; if M2-39 has none, add `auditing.OSUser(name string) Value` and extend SEC-AUD-5 in 19 with this form (19 allows the ticket that needs a value form to add it). Ruling for docs/DECISIONS.md.
   c. `SessionsEndedByReport` (SR10 part only): when the new `reported_is_server_host` is true, every session not `closed` of a person who is not an active owner (owner status through `identity`) ends with `access_revoked` in the same unit of work, without a rights-version change. The sessions whose session user (`host_session_user_id` -> `os_user`) is missing from the new list end in M2-40's `ApplySessionUserReport` (SR12, note 4 c). After the commit `CloseSession` for each session ended by either path (if the merged `ReportOutcome` of M2-40 carries only their number, extend it with the ended session IDs).
   d. The first applied report after `ready` sets the link's `reported` flag and makes `Connected` true.

9. **Heartbeat and liveness.** `heartbeat {active_sessions}` (`minimum: 0`, note 14) is answered with `heartbeat_ack {server_time}`; `active_sessions` is informational and changes nothing. The server closes with `4009` when no `heartbeat` arrived for `terminal.host_heartbeat_interval` times (`terminal.host_heartbeat_miss_limit` + 1) since `ready` or the last `heartbeat`; the extra interval absorbs the first delay, as M1-64 rules for the gateway. `last_seen_at` is written at login and on a heartbeat when older than `identity.last_active_granularity`, without event and without `version`. JWKS refresh: `heartbeat_ack` carries `jwks` (new optional member) whenever the set of purpose `terminal` differs from the last set sent on this link. Ruling for docs/DECISIONS.md and 24 5.3: a scheduled rotation publishes the `next` key `agent.jwks_max_age` before use, so a long-lived connection learns it in time; after an emergency rotation the window is at most one heartbeat interval plus `signing_key.cache_ttl` (honest limit in 24 5.3).

10. **`session.started` and `session.ended`.** Both act only on a session of this host. `session.started`: `opening -> active`, `started_at`, `terminal_session.changed`; already `active` or `detached`: no change; `closed`: answer `session.close` with the stored reason. `session.ended`: `ValidateHostSessionEnd` accepts from the host only `client_closed`, `process_exited`, `idle_timeout`, `detach_expired`, `open_failed` and `host_policy_violation`; `close_detail` is required exactly for `open_failed` (any value of `TerminalCloseDetail`) and `host_policy_violation` (`subscription_login_detected`, `helper_untrusted`, `shared_location`); `exit_code` only with `process_exited`. A session that is already `closed` gives no change (the host confirms a `session.close`). An unknown session or one of another host gives `host.error {op, code: "not_found"}` and `session.close` with `access_revoked`; an invalid end gives `host.error` with `validation_failed`. Ruling for docs/DECISIONS.md: these sets. Every end goes through one session-ending function of the module (expected from M2-39): state `closed`, `closed_at`, `close_reason`, `close_detail`, `exit_code`, `version + 1`, `terminal_session.changed` to the person, audit `terminal.terminate` with `session_id`, `close_reason`, `close_detail`, `bytes_in`, `bytes_out` and the duration (24 10.1). If the merged function lacks the event or the audit entry, add them there, so M2-44 and M2-46 reuse one end path.

11. **Connection loss and shutdown.** When an authenticated link ends for any reason other than a close that comes with a host state change (`4110`, `4111`, `4112`), `ConnectionLost` sets every `active` session of the host to `detached` with `detached_at` and `terminal_session.changed` (24 6.2), unless a newer link of the same host is registered in this process; then the presence turns false. Shutdown of the roles `api` and `all`: a `StopStep` in `PhaseConnections` (M1-11) runs `ConnectionLost` for every link and closes it with `4013` within the remaining `shutdown.total_timeout`; update 02 15.3 step 3. Ruling for docs/DECISIONS.md.

12. **Host side (`services/host/internal/control`).** `Config{ServerURL, HostID, AuthKey, HostVersion, BackoffBase, BackoffCap, RootCAs, Clock}` from M2-42's state and configuration. `internal/control` implements M2-42's `startup.Control` (`Login(ctx) (Ready, error)` returning the declaration of `ready`, `Report(ctx, Report) error`, `Close() error`) on top of `Client`; `cmd/bothy-host run` replaces `NoControl` with it. `Report` hands the report to `ReportSource` (c). Every later `ready` is passed to `internal/startup` as the current declaration (the path the merged `internal/startup` offers for a second `ready`, M2-42 `TestDeclarationFromReady`). The refused-start path stays M2-42's `Login`, one `Report`, `Close`, exit `78`, over one connection (g). `Run(ctx)`:
    a. Dial `wss://<server>/api/v1/hosts/connect` (scheme only from an `https` server URL; system roots unless `RootCAs` is set; proxy from the environment); refuse `ws://` and never skip verification.
    b. On `hello`: pick the highest version in both its own list and `protocol_versions` (none: stop, log "update the host service or the server"); sign the proof (header `alg`, `typ`, `kid` = RFC 7638 thumbprint; payload `challenge`, `host_id`, `iat`); send `identify` with `live_sessions` from `Sessions.Live()` and `host_version`; store the JWKS.
    c. On `ready`: send `report` from `ReportSource` as the first frame, before handling any other frame; resend on every change of the source. `is_server_host` is M2-42's HD5 result or-ed with `PeerIsLocal(remote, own addresses)` of this connection (24 2.3).
    d. Send `heartbeat` every `heartbeat_interval_ms`; close and reconnect when no frame arrived for `heartbeat_interval_ms` times (`heartbeat_miss_limit` + 1). Replace the JWKS on a `heartbeat_ack` with `jwks`. A `session.open` before the own `report`: close with `4002` and reconnect.
    e. `session.open` and `session.close` go to `Sessions`; `Notifier` sends `session.started` and `session.ended`. Until M2-45 binds its session manager, `run` binds `RefuseSessions` (empty `Live()`; every `session.open` answered with `session.ended {open_failed, pty_failed}`; `session.close` ignored, there is no PTY); its doc comment names M2-45.
    f. Close codes: `1000`, `1001`, `4000`, `4002`, `4009`, `4014`, `4113` and any unknown code: reconnect with exponential backoff and full jitter from `host_service.reconnect_backoff_base` to `host_service.reconnect_backoff_cap` (new keys, note 14), reset after a `ready`; `4013`: reconnect after a uniform delay below `host_service.reconnect_backoff_base`; `4008`: wait `retry_after=<seconds>` from the close reason, else the cap; `4111`: end all PTYs through `Sessions`, wait the cap before each attempt; `4110`, `4112`, `4114`: end all PTYs, return `ErrStop` with the code. `run` exits on `ErrStop` with M2-42's exit code for a refused start, the one exit code the service definitions do not restart. Ruling for docs/DECISIONS.md.
    g. Refused start (M2-42 Design note 15): `run` calls `Login` before it decides, M2-42 replaces `declaration.json` with the declaration of `ready` and evaluates HD6 again, and on a finding that refuses the start it sends exactly one `Report` with all checks and `Close` (code `1000`) over the same connection, then exits with the refused-start code. `Login` here logs in with empty `live_sessions` and retries with the backoff for at most `host_service.reconnect_backoff_cap` in total; after that it returns `ErrUnreachable` and the stored declaration decides (24 2.2; the local `doctor` output names the accounts). No separate report connection: M2-42's `Control` covers the refused-start path.
    h. Frame types are hand-written structs (the host module has no generator) decoded with `DisallowUnknownFields` and a required-member check; note 13 keeps them equal to the contract. No log line contains a proof, the challenge, a key or report content beyond codes.

13. **Cross-implementation recordings.** `services/host/testdata/control/host_frames.json` is written by a host test (fixed key from SHA-256 of `control-recording/host-auth`, fixed clock, the challenge and server time of the recording), with one frame per host-to-server op and the public JWK; `server_frames.json` is written by a server test with one frame per server-to-host op, `heartbeat_ack` with and without `jwks`, and `error`. `UPDATE_RECORDINGS=1` writes, otherwise each test compares byte for byte. The server test validates every host frame with `specschema.ValidateChannelFrame("hostControl", false, ...)` and verifies the recorded proof with the server's `CheckHostProof`; the host test decodes every server frame strictly. Ruling for docs/DECISIONS.md: recordings in both directions hold the hand-written host frames to the contract, as M2-38 does for Noise.

14. **Specification text (spec first; chapters English).** 24: new 3.5 "Control connection" with the login order and proof rules of note 3, `connected`, report validation and `host.error`, the accepted end reasons of note 10, the reconciliation of note 6 and the client reactions of note 12 f; 3.1 a transition `confirming --> pairing: second control connection (3.4)`; 3.4 the `confirming` case, the probe only within one node until M2-47, the audit of both outcomes; 5.3 the JWKS refresh and its limit; 6.2 `session.close` for listed sessions closed on the server; 13 `4000` on `hostControl` and `hostData`; 17 the rows `host_service.reconnect_backoff_base` (Default `1s`) and `host_service.reconnect_backoff_cap` (Default `5m`). 07 4.1: row `host_duplicate_connection`. 19 SEC-AUD-5: the value form of note 8 b. 02 15.3 step 3: control connections of host services. `openapi.yaml`: `HostChannelHello.heartbeat_miss_limit` (required integer, minimum 1); `HostHeartbeatAck.jwks` (optional `Jwks`); `HostHeartbeat.active_sessions` `minimum: 0`; `HostIdentify.host_version` with a SemVer pattern and `proof` naming `kid`; `Host.connected` description. `asyncapi.yaml`: `4000 unknown_error` ("reconnect with backoff") in the `x-close-codes` of `hostControl` and `hostData`; the `hostControl` description names the JWKS refresh and report validation.

## Acceptance criteria

- [ ] Missing heartbeats close the connection with `4009` after `terminal.host_heartbeat_miss_limit`.
- [ ] `identify` names `live_sessions`, and every other session of the host in `active` or `detached` ends with `host_restarted` (TM-T16, D-W-90).

- [ ] After `ready`, `report` comes before any `session.open`; `report` writes `hosts.reported_session_users` with the lists after HD7 (TM-T29 (c)) and `hosts.reported_doctor` with one entry per affected session user.

- [ ] TM-T23: a second live connection disables the host with both closed by `4112`; a dead older one is replaced after `4009`.
- [ ] A host service below the supported protocol version gets `4114` (18 "Host service and server").

- [ ] Frames of both sides are checked against `asyncapi.yaml` (G9, recordings in both directions).
