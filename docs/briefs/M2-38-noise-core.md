# M2-38: Host service module and Noise core in Go and Dart

Status: ready | Depends on: M1-01 | Milestone: M2

## Goal

After this ticket the host service has its own Go module `services/host` (module path `github.com/OWNER/bothy/services/host`) with `VERSION`, `CHANGELOG.md`, a component `Makefile` whose `release-build` builds the unsigned `bothy-host` binaries for the five platforms of 18 "Components", and the three packages every later terminal ticket builds on: `internal/noise` (the handshake `Noise_NK_25519_ChaChaPoly_SHA256` over `github.com/flynn/noise`, initiator and responder, the prologue `"bothy-terminal/1" || session ID || host ID`, transport states with the 65535-byte limit of the Noise specification), `internal/frame` (the frames `start` to `replay_end` of 24 "Frames") and `internal/fingerprint` (24 "Fingerprint"). The pure Dart package `packages/bothy_noise` implements the same handshake, transport, frames and fingerprint on the primitives of the package `cryptography`, for the desktop app, the mobile app and the web console. Both implementations produce the same bytes for the public test vectors of cacophony and noise-c (TM-T01) and for each other's checked-in recordings in both directions (TM-T02), and in both a wrong prologue, a wrong static key or a swapped host ID make the handshake fail. Why: the terminal stream must keep its content from relay, proxy, logs and a database dump (24 "Protection goal", SEC-TERM-1, T-TM-01) with a small, checked standard instead of own cryptography (ADR 0068, R-TM-02), and device (Dart) and host (Go) must agree byte for byte before any session, relay or view is built on them (M2-42 to M2-48, M4-35). The Go library is little maintained (RK-28); the vectors hold it, and the report states its version and its advisories.

Product requirements implemented here:

11. 5. **`internal/noise` (Go).** Package comment: purpose, the protocol name, the source sections of 24, that the package does no I/O.
    - Constants: `ProtocolName = "Noise_NK_25519_ChaChaPoly_SHA256"`, `PrologueLabel = "bothy-terminal/1"`, `MaxMessageLen = 65535`, `TagLen = 16`, `MaxPlaintextLen = MaxMessageLen - TagLen`, `KeyLen = 32`, `IDLen = 16`, each with its source in a comment.
    - `ParseID(s string) ([IDLen]byte, error)`: only the canonical 36-character form 8-4-4-4-12, hex digits in either case; the 16 bytes in the octet order of RFC 9562 (the bytes as the string reads left to right); no version check, because the prologue binds bytes and the server validates its own IDs. Errors wrap `ErrInvalidID`. Ruling for docs/DECISIONS.md (byte order of the IDs in the prologue).
    - `Prologue(sessionID, hostID [IDLen]byte) []byte`: `PrologueLabel` (16 ASCII bytes) || session ID || host ID, 48 bytes.
    - `EphemeralKeyHash(public []byte) (string, error)`: SHA-256 of the 32-byte X25519 public key, base64url without padding (openapi `client_ephemeral_key_hash`, claim `cek`, 24 5.3); another length gives `ErrInvalidKey`.
    - `KeyPair{Private, Public [KeyLen]byte}`; `GenerateKeyPair(random io.Reader) (KeyPair, error)` (production passes `crypto/rand.Reader`); `KeyPairFromPrivate(private [KeyLen]byte) (KeyPair, error)` for recordings and tests.
    - `InitiatorConfig{HostStatic [KeyLen]byte; SessionID, HostID [IDLen]byte; Ephemeral KeyPair}`: the ephemeral key is required, because the device computes `cek` from it before the session is opened (15 23.2 step 2). `NewInitiator(cfg) (*Initiator, error)`; `(*Initiator).WriteMessage1(payload []byte) ([]byte, error)`; `(*Initiator).ReadMessage2(msg []byte) (payload []byte, t *Transport, err error)`.
    - `ResponderConfig{Static KeyPair; SessionID, HostID [IDLen]byte; Ephemeral *KeyPair; Random io.Reader}` (nil `Ephemeral`: generated from `Random`, default `crypto/rand.Reader`). `NewResponder(cfg) (*Responder, error)`; `(*Responder).ReadMessage1(msg []byte) (payload []byte, initiatorEphemeral [KeyLen]byte, err error)` (M2-45 compares the hash of `initiatorEphemeral` with `cek`); `(*Responder).WriteMessage2(payload []byte) ([]byte, *Transport, error)`. Both types have `HandshakeHash() []byte` after completion. An unexported constructor with a raw prologue serves the vector tests.
    - `Transport`: `Encrypt(plaintext []byte) ([]byte, error)` and `Decrypt(msg []byte) ([]byte, error)` with the cipher states of `Split` (initiator to responder, responder to initiator). One goroutine may encrypt while another decrypts; neither method is safe for concurrent calls of itself (doc comment).
    - Limits, checked by the wrapper before the library is called, so that the behaviour does not depend on the library version: a handshake message longer than `MaxMessageLen` or a payload that would make one longer gives `ErrMessageTooLong`; `Encrypt` with more than `MaxPlaintextLen` bytes gives `ErrMessageTooLong` without using a nonce; `Decrypt` with more than `MaxMessageLen` or fewer than `TagLen` bytes fails.
    - Ruling for docs/DECISIONS.md: after the first failed `Decrypt`, or any failed handshake step, the object refuses every further call with `ErrBroken`, because a failed authentication means manipulation (24 5.3 "hard warning", `4104`) and continuing would let a relay probe; the wrapper keeps its own message counter per direction and refuses at 2^64 - 1 (`ErrNonceExhausted`, Noise revision 34 section 5.1 reserves that nonce); calls in the wrong order give `ErrState`.
    - Ruling for docs/DECISIONS.md: a Diffie-Hellman result of 32 zero bytes (low-order public key) fails the handshake in both languages. Verify that the pinned library's `DH25519` already returns an error for it; if not, use a `DHFunc` that wraps it and rejects the zero result. Reason: the Dart side must behave the same, and an all-zero shared secret means a key that an attacker chose.
    - Use `Config.EphemeralKeypair` of the library for a fixed ephemeral key if the pinned version has it, otherwise a deterministic `Config.Random` reader; `PeerEphemeral()` and `ChannelBinding()` (or their equivalents) give the initiator's ephemeral key and the handshake hash.

6. **`internal/frame` (Go).** `type Type byte` with `TypeStart 0x01`, `TypeData 0x02`, `TypeResize 0x03`, `TypeClose 0x04`, `TypeExit 0x05`, `TypeReplayBegin 0x06`, `TypeReplayEnd 0x07`; `type Sender uint8` with `FromDevice` and `FromHost`; `type Frame struct{Type Type; Cols, Rows uint16; Data []byte; ExitCode int32}`; constructors `Start`, `Data`, `Resize`, `Close`, `Exit`, `ReplayBegin`, `ReplayEnd`; `Encode(f Frame) ([]byte, error)`; `Decode(b []byte, from Sender) (Frame, error)` (the returned `Data` aliases `b`, documented); `(Frame).IsInput() bool`; `MaxLen = 65519` with the comment "largest plaintext of a Noise transport message: 65535 minus the 16-byte tag (24 5.2, 5.4)" and a test that it equals `noise.MaxPlaintextLen`. The package does not import `noise`; the local channel of M2-42 uses the same frames.
    - Ruling for docs/DECISIONS.md (update 24 5.4), because 24 5.4 names field widths but no byte order or body rules: all integers big-endian; `start` and `resize` carry exactly 4 bytes, columns then rows, each 1 to 65535 (as `TerminalSessionOpen`); `data` carries 1 to 65518 bytes (an empty `data` would count as input without input, 24 6.3); `close`, `replay_begin` and `replay_end` carry no body; `exit` carries exactly 4 bytes, a signed 32-bit two's complement integer.
    - Directions: `start`, `resize` and `close` only from the device; `exit`, `replay_begin` and `replay_end` only from the host; `data` both ways. A type byte outside `0x01` to `0x07` gives `ErrUnknownType`; a known type in the wrong direction gives `ErrWrongDirection`; a wrong body gives `ErrMalformed`; an empty input `ErrEmpty`; more than `MaxLen` bytes `ErrTooLong` (also in `Encode`). Ruling for docs/DECISIONS.md: every decode error ends the session like an unknown type (`4104`, 24 5.4, asyncapi `terminalStream`); M2-45 does the mapping.

9. **Noise state machine in Dart.** Implement `CipherState`, `SymmetricState` and the `NK` handshake of revision 34: `h` is the protocol name itself (exactly 32 bytes), `ck = h`, `MixHash(prologue)`, the pre-message `MixHash(rs)`; message 1 `e` (`MixHash(e.public)`), `es` (`MixKey(DH(e, rs))`), `EncryptAndHash(payload)`; message 2 `e`, `ee`, `EncryptAndHash(payload)`; `Split` with the Noise HKDF (HMAC-SHA-256: `temp = HMAC(ck, ikm)`, `out1 = HMAC(temp, 0x01)`, `out2 = HMAC(temp, out1 || 0x02)`), first cipher initiator to responder. ChaChaPoly nonce: 4 zero bytes then the 64-bit counter little-endian (section 12.3); associated data `h` during the handshake, empty in transport; ciphertext and tag concatenated. Primitives: `X25519`, `Chacha20.poly1305Aead()`, `Sha256` and `Hmac.sha256()` of `cryptography`. The same limits, the zero-result rejection, `broken` after a failure and the nonce limit as in note 5. `encrypt` takes its nonce synchronously when called, so results belong to the call order (doc comment: send them in that order).
