# M1-05: Server skeleton, module register and architecture gate

Status: ready | Depends on: M1-01 | Etappe: M1

## Goal

After this ticket `services/server` is a buildable Go module: every module of chapter 02 exists as
a port package with its README, the cross-cutting packages live in `internal/kernel`, and
`architecture/modules.yaml` is the single source of module boundaries. A generator
(`tools/archgen`) turns the register into `.go-arch-lint.yml`, so `make arch` rejects every import
that breaks the layer and module rules from the first Go commit on. The kernel packages `ids`,
`clock` and `errs` are complete now, because every later ticket builds on them.

## Fixed requirements that apply

1. No MVP. Built from scratch directly in its final state; etappen are only the build order.
2. Strictly modular: clear module and service boundaries, dependencies only through defined
   interfaces, no cross access.
3. Documentation in code: every public module, class, function and interface has a docstring or doc
   comment (purpose, parameters, return value, errors, example where useful); comments explain why,
   not what. API documentation is generated from code (OpenAPI from the routes, dartdoc, Python API
   docs in the docs site).
4. Documentation in the repo: README per module/service, an ADR for every architecture decision, a
   CHANGELOG entry per release, docs site kept current. A change without matching documentation is
   not done.
5. Quality gates (SonarQube, linters, type checks, security scanners, test coverage) block the merge.
6. Test first: write the failing test, run it and keep its red output for the report, make it green,
   then clean up.
7. No en dash (U+2013) or em dash (U+2014) in any file you write; `grep -nP "[\x{2013}\x{2014}]"`
   over your changed files prints nothing.
8. White label: no company, person, host or instance names, no paths of a personal machine, no real
   data. Examples use example.com and the people Alex, Sam and Robin.
9. Configuration values only through named keys from `docs/operations/configuration.md`. This ticket
   adds no configuration key.
10. Module rules 1 to 7 of 02 "Regeln" and the layer table of 02 "Schichten im Modul" (ADR 0008): a
    module is `internal/<module>`, its port is the root package, other modules import only the
    port, the dependency graph is acyclic, `kernel` is usable by all, `platform` and `api` only in
    `adapters`.
11. The register is the only source of module boundaries; the go-arch-lint configuration is
    generated from it and never edited by hand (02 "Modulregister als Quelle", R-AR-19, ADR 0050).
12. IDs are UUIDv7 (RFC 9562) generated by the application; the API writes them in lower case and
    accepts upper case on input (03 "Grundsätze" 1, 06 "Grundregeln").
13. Every error has a kind with a fixed HTTP status and a stable snake_case code; internal details
    never reach a response (02 "Fehlerarten", 06 "Fehler", ADR 0015).
14. The product name appears in code only at the listed places: Go module path, binary `bothy`,
    environment prefix `BOTHY_`, image name (02 "Code-Layout", 18).
15. `go.mod` sets the older maintained Go line as `go` directive and the built version as
    `toolchain` (ADR 0005). Module path `github.com/OWNER/bothy/services/server` until V1 (P-05).
16. A gap in the core contract (00, 03, 04, 05) ends the ticket with `Verdict: BLOCKED` (P-11). This
    ticket needs "modules without tables" in 03 "Module" (`gateway`, `search`, `stats` with
    `keine`); verify it is there before you start.

## Design notes

### go.mod

- `module github.com/OWNER/bothy/services/server` (P-05).
- `go 1.26.0`: the older of the two maintained Go lines on 2026-10-10 (ADR 0005). `toolchain` is the
  exact version that `go version` prints on the host, at least `go1.27.2`.
- Only dependency: `go.yaml.in/yaml/v3` (the maintained continuation of `gopkg.in/yaml.v3`; MIT and
  Apache-2.0), used by `tools/archgen` with `Decoder.KnownFields(true)`. Pin the newest v3 release.
  The kernel packages use the standard library only.

### Register `architecture/modules.yaml` (normative format; later tickets extend it)

```yaml
# SPDX-License-Identifier: Apache-2.0
# Module register: docs/spec/02-architektur.md "Modulregister als Quelle", ADR 0050.
version: 1
exclude: [tools]            # directories go-arch-lint ignores (repository tools, not product code)
kernel:
  core: [ids, clock, errs]  # usable by every package
  ports: [actor, authorize, txn, eventlog, auditing, idempotency, personaldata]
platform: {}                # <name>: {depends_on: [<platform names>], vendors: [<vendor groups>]}
wire: {vendors: []}
cmd: {vendors: []}
# api: {vendors: [...]}     # added by M1-17 together with api/
testsupport: {paths: [test, perf]}   # test code across modules (02 "Code-Layout"); nobody may use it
modules:
  instance:
    tables: [instance, instance_settings, server_signing_keys, feature_flags, sequence_counters]
    actions: [instance.discovery.read, instance.read, ...]
    events: [instance.updated]
    ephemeral_events: []
    ws_ops: []
    depends_on: []
    adapter_vendors: []
  # ... all 19 modules
vendors: {}                 # <group>: [<import path>, <import path>/**]
```

- Modules appear in the order of the line "Ebenen (von unten)" in 02 "Erlaubte Abhängigkeiten":
  instance, billing, audit, authz, identity, chat, agents, files, messaging, status, runs, search,
  importer, privacy, sync, stats, notify, apps, gateway.
- `tables` from 02 "Modulliste", `actions` from 02 "Aktionen je Modul", `events`,
  `ephemeral_events` and `ws_ops` from 02 "Ereignistypen und WebSocket-Ops je Modul", `depends_on`
  from 02 "Erlaubte Abhängigkeiten", each list in the order of the chapter. Copy them exactly; M1-06
  checks them against 02, 03 and `docs/spec/actions.yaml`.
- `adapter_vendors`, `platform` and `vendors` start empty. The ticket that adds the first adapter or
  platform package adds its entry and vendor group (for example M1-07 adds `platform.config` with
  vendor group `yaml`, M1-12 adds `pgx`). A new package without a register entry fails `make arch`
  ("not attached to any component"); that is intended.
- Name patterns: module and platform `^[a-z]+$`, vendor group `^[a-z0-9]+$`.
- `tools/archgen` validates and exits 1 with file and YAML path on: unknown field, wrong `version`,
  duplicate module, `depends_on` naming an unknown module or itself, a dependency cycle (message
  lists the cycle, for example `chat -> agents -> chat`), a table, action, event type or op in two
  modules, an undefined vendor group, a platform `depends_on` that is unknown or cyclic, empty or
  overlapping kernel lists.

### Generator `tools/archgen`

- `go run ./tools/archgen -register architecture/modules.yaml -out .go-arch-lint.yml` (paths
  relative to `services/server`; these are the flag defaults). Output is byte-for-byte deterministic
  and starts with `# SPDX-License-Identifier: Apache-2.0` and
  `# Code generated by tools/archgen from architecture/modules.yaml. DO NOT EDIT.`
- `tools/archgen/main.go` carries
  `//go:generate go run . -register ../../architecture/modules.yaml -out ../../.go-arch-lint.yml`.
- `make codegen-check` (M1-01) must catch a stale `.go-arch-lint.yml`. Read its recipe: if it runs
  `go generate ./...` in every Go module and then `git diff --exit-code`, the directive is enough.
  Otherwise add exactly one line that runs this generator before the diff, and change nothing else.
- Generated content (go-arch-lint config version 3, the shape of 02 "go-arch-lint" with one
  component per platform package, because M1-14 must restrict River to `platform/jobs`):
  - `version: 3`, `workdir: .`, `allow: {depOnAnyVendor: false}`, `exclude:` from the register,
    `excludeFiles: ["^.*_test\\.go$"]`.
  - `vendors`: one entry `v-<group>: {in: [...]}` per register vendor group.
  - `components`: `kernel-core` (exact paths `internal/kernel/<core>`), `kernel-ports` (exact paths
    `internal/kernel/<port>`), `platform-<p>` (`internal/platform/<p>` and `.../**`) per platform
    package, `wire` (`internal/wire`, `internal/wire/**`), `cmd` (`cmd/**`), `api` (`api/**`) only
    if the register has `api`, and per module `<m>` (`internal/<m>`), `<m>-domain`
    (`internal/<m>/domain`, `.../**`), `<m>-app` (`internal/<m>/app`, `.../**`), `<m>-adapters`
    (`internal/<m>/adapters/**`).
  - `commonComponents: [kernel-core]`.
  - `deps`: `<m>: {mayDependOn: [kernel-ports]}`; `<m>-app: {mayDependOn: [<m>, <m>-domain,
    kernel-ports, <dependency ports>]}`; `<m>-adapters: {mayDependOn: [<m>, <m>-app, <m>-domain,
    kernel-ports, every platform-*, api if declared, <dependency ports>], canUse: [v-<adapter
    vendors>]}`; `platform-<p>: {mayDependOn: [kernel-ports, platform-<depends_on>], canUse:
    [...]}`; `wire: {mayDependOn: [all module components, every platform-*, kernel-ports, api if
    declared], canUse: [...]}`; `cmd: {mayDependOn: [wire, every platform-*, kernel-ports],
    canUse: [...]}`. `<m>-domain` and `kernel-ports` get no `deps` entry: go-arch-lint rejects an
    empty `mayDependOn`, and without an entry a component may use only the common component. Omit
    empty `canUse` and omit a whole entry whose lists are both empty.
  - `testsupport` (`in: [test/**, perf/**]` from `testsupport.paths`): `deps` entry with
    `anyProjectDeps: true` and `anyVendorDeps: true` (verify both keys against the pinned
    go-arch-lint; if they differ, use its equivalent and record it); it appears in no other
    component's `mayDependOn`. Reason: shared test harnesses and load tests use the real wire graph
    (M1-16 creates `perf/internal/report`, M1-71 `test/harness`), and production code must never
    import them (02 "Code-Layout").
- If the pinned go-arch-lint reports an error for a component whose `in` matches no package, add a
  `doc.go` (package comment only) to `domain` and `app` of every module and record it in
  DECISIONS.md; never make the generator drop declared components.

### `internal/kernel/ids`

- `type ID [16]byte`; `func New() ID` (process-wide generator: system clock, `crypto/rand`);
  `type Generator`; `func NewGenerator(c clock.Clock, random io.Reader) *Generator`;
  `func (g *Generator) New() ID`; `func Parse(s string) (ID, error)`; `func MustParse(s string) ID`
  (panics; for tests and constants); `func (ID) String() string` (lower case, 8-4-4-4-12);
  `func (ID) IsZero() bool`; `func (ID) Time() time.Time` (UTC, millisecond); `MarshalText` and
  `UnmarshalText`; `var ErrInvalid` (wrapped by `Parse` errors).
- Layout per RFC 9562 section 5.7: 48-bit Unix milliseconds, version nibble `0111`, 12 bits
  `rand_a`, variant `10`, 62 bits `rand_b`.
- Monotonic per process (RFC 9562 section 6.2, method "Monotonic Random"), guarded by a mutex: in the
  same millisecond as the last ID, add a random value in `[1, 2^32)` to the 74 bits of `rand_a` and
  `rand_b` taken as one counter; on overflow advance the timestamp by one millisecond and draw fresh
  random bits; if the clock goes backwards, keep the last timestamp. A failing random reader is a
  programming error: panic with a message naming the package.
- `Parse` accepts upper and lower case, requires version 7 and variant `10`, and rejects the nil
  and max UUID, braces, the `urn:uuid:` prefix and any other length.

### `internal/kernel/clock`

`type Clock interface { Now() time.Time }`; `func System() Clock` (returns UTC);
`type Fake` with `func NewFake(t time.Time) *Fake`, `Now`, `Set`, `Advance(d time.Duration)`; safe
for concurrent use. The fake lives in the same package so that `kernel-core` keeps exact paths.

### `internal/kernel/errs` (aligns 02 "Fehlerarten" with 06 "Fehler")

- `type Kind uint8` with `Status() int` and `String() string` (snake_case). Kinds and status:
  `bad_request` 400, `unauthenticated` 401, `step_up_required` 401, `forbidden` 403, `not_found`
  404, `method_not_allowed` 405, `conflict` 409, `invariant_violation` 409, `gone` 410,
  `precondition_failed` 412, `too_large` 413, `unsupported_media_type` 415,
  `range_not_satisfiable` 416, `unprocessable` 422, `precondition_required` 428, `rate_limited`
  429, `internal` 500, `unavailable` 503. The zero value `KindNone` has `Status() == 0`.
- `type Code string` with one constant per code of the 06 block (for example
  `CodeVersionConflict = "version_conflict"`), and `func AllCodes() []Code`. Each code has exactly
  one kind; the kind follows from the code, never from the caller. Mapping: `validation_failed`,
  `malformed_request`, `cursor_invalid`, `webhook_host_not_allowed` to `bad_request`;
  `unauthenticated`, `token_expired`, `session_revoked`, `use_dpop_nonce`, `invalid_dpop_proof` to
  `unauthenticated`; `step_up_required` to `step_up_required`; `forbidden`, `scope_missing`,
  `device_pending`, `channel_read_only`, `feature_disabled`, `agent_invocation_denied`,
  `invocation_token_invalid` to `forbidden`; `not_found`; `method_not_allowed`; `conflict`,
  `request_in_progress`, `already_started`, `billing_mode_mismatch`, `tool_class_mismatch`,
  `invalid_state_transition`, `base_version_conflict`, `component_used`, `operator_mismatch`,
  `file_not_ready`, `file_blocked`, `title_manual` to `conflict`; `i1_violation`, `last_owner` to
  `invariant_violation`;
  `resync_required`, `message_deleted`, `gone` to `gone`; `version_conflict` to
  `precondition_failed`; `payload_too_large` to `too_large`; `unsupported_media_type`;
  `range_not_satisfiable`; `idempotency_key_reuse` to `unprocessable`; `precondition_required`;
  `rate_limited`; `internal_error` to `internal`; `unavailable`, `maintenance`, `setup_required` to
  `unavailable`. The code list follows `x-problem-codes`; a code added there later gets its kind
  in the same change (the test over `AllCodes()` compares both).
- `type Error struct` with fields `Code Code`, `Detail string`, `Reason string`, `Hint string`,
  `Cause string`, `Fields []FieldError`, `Current any`, `RetryAfter time.Duration` and an unexported
  wrapped error; `type FieldError struct{ Pointer, Code, Detail string }`. Constructors
  `New(code Code, detail string) *Error` and `Wrap(code Code, err error, detail string) *Error`
  (both panic on a code without kind: programming error), setters `WithReason`, `WithHint`,
  `WithCause`, `WithFields`, `WithCurrent`, `WithRetryAfter` returning the receiver;
  `Kind() Kind`, `Unwrap() error`; `Error()` returns `<code>` or `<code>: <detail>` and never the
  cause or the wrapped error; `LogValue() slog.Value` (package `log/slog`) adds kind, cause and the
  wrapped error for logs. Package functions `As(err error) (*Error, bool)` and
  `KindOf(err error) Kind` (`KindNone` for nil, `internal` for any error that is not an `*Error`).
- `Cause` is an internal label for logs and metrics, never serialized into a response. Constants for
  the internal causes 02 names: `CauseAuthzNotChecked = "authz_not_checked"`,
  `CauseUnknownAction = "unknown_action"`, `CauseDBPoolExhausted = "db_pool_exhausted"`,
  `CauseShuttingDown = "shutting_down"`, `CauseDeadlineExceeded = "deadline_exceeded"`,
  `CauseDependencyUnavailable = "dependency_unavailable"`. Reason: 06 defines the closed set of
  public codes, and 02 forbids internal details in responses.

### `cmd/bothy`

- `main` calls `os.Exit(run(ctx, os.Args[1:], os.Stdout, os.Stderr))`.
- `commands.go` holds `type command struct { name, summary string; run func(ctx context.Context,
  args []string, stdout, stderr io.Writer) int }` and the table `commands`. This ticket registers
  no command; M1-07 adds `config`, M1-11 `serve`, and so on (02 "Befehle des Binarys" is the
