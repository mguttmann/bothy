# FIX-hermes-adapter-main1118 Hermes adapter ready for Hermes Agent main f7e2898aae

Owner order of 2026-11-18: the Hermes installation moves from upstream main `a8b0bc15053c` to
upstream main `f7e2898aaefc8f967dbf7345e3999a65672fe60e`, and the adapter must work on both. A
read-only analysis of the new commit found three runtime changes that reach the adapter without
breaking its import: Hermes removed its old session store (be3d6affc8 "refactor(state)!: remove
the old session store"), lowered `agent.clarify_timeout` from 3600 s to 90 s (migration 53), and
offers Deny only on an approval whose command preview it had to cut, unless the adapter confirms
a send of the whole command first. Normative text: 09 17.3 (rows `send_clarify`,
`_send_exec_approval_prompt`, interaction and title) and 17.10.

## Open minors

- `cards._duration` rounds: a clarify wait of 210 s reads "4 minutes" on the card although the question expires after three and a half; round down for waits that are not whole minutes.
- With a small `hermes_adapter.max_message_bytes` the approval preview budget of D-HAM-3 falls below Hermes' own 3000 characters (about 1000 characters at 8192 bytes, none below the reserve), so an old Hermes shows less of the command than before; keep at least Hermes' default when the card still fits.
- `CLARIFY_EXPIRED` says the agent went on; after a restart of the gateway the question is gone without the turn going on, so the wording is not exact there.
