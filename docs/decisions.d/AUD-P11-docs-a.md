# AUD-P11-docs-a Documents held to what is built: API contract, operations, product promises, quality pages

Work package P11-docs-a of the audit of 2026-11-11: findings about documents that promise more
than is built, or describe it wrongly. Each finding was checked against the code of 2026-11-23.
The documents now say what is built and mark the rest as not built where the text stands; a
missing product part is a plan row of V3 (V3-20 to V3-45), not built here. Small gates hold the
corrected texts (`test_description_ratchet.py`, `test_unpaginated_lists.py`,
`test_bothy_commands.py`, `test_table_ownership.py`, `test_architecture_tiers.py`) and rule D6 of
`make config-doc-check` now refuses a planned key of a finished milestone.

## Open

For the next run in each area. None of these is a known wrong result of the product.

- The description gaps of the API contract counted by the ratchet are not filled; the next runs per
  tag lower the ceilings. The ratchet does not count parameters, headers or nested inline
  properties.
- No lint binds new operations to the method rule of 06 section 2.
- The channel export dialog does not say that the files are not part of the export; `exportDone`
  is shared with the data export and the audit export, so a new text key is needed.
- No arch check holds the list of direct writes of 15 section 1 item 3.
- The client shows the channel switch for autonomous runs while no runner reports `wakes`; 01
  6.21 says that it has no effect.
- `trace-propagation.mmd` still draws the adapter steps; the text below it in 17 marks them as not
  built.
- `install.sh --offsite` accepts any string; `bothy-backupd` rejects a wrong form only later.
- `make demo` runs in no CI workflow; the Android step of `demo.md` for the demo CA is not checked
  on a device.
- `test_bothy_commands.py` checks command names, not argument forms.
- The order of the modules in `modules.yaml` does not follow the tiers of 02 4.4; the test holds
  the edges.
- Dockerfile heads and ADRs still say that Renovate updates digests; `docs/quality/toolchain.md`
  "Updates" says what that means today.
- The status of the roadmap is maintained by hand, not generated from the plan.

Left open on purpose (owner or devices): the real screen reader pass, real recordings per
platform, the activation of Renovate (step 16 of the publishing checklist), the paid probe turns
of A1-05, closed schemas for the `*.v1` sub-contracts, a register of problem reasons and derived
required error responses.
