# AUD-docs-spec-01 Status lines, backup state without a view, functions of the API alone, WCAG criteria

Work package of the audit of 2026-11-11 for the entry point and two chapters of the specification
(`docs/SPEC.md`, `docs/spec/01-product.md`, `docs/spec/16-operations.md`). Findings:
`docs-accuracy-3` (rulings 1 to 3), `docs-accuracy-6` (rulings 4 to 6), `fn-chat-messages-2`
(rulings 7 to 9), `a11y-5` (rulings 10 and 11). All four are differences between what a document
says and what is built; this package changes documents and adds the tests that hold them, and
no product code.

## Open

For the next run in each area. None of these is a known wrong result of the product.

Questions for the owner:

- V3-18 (channel settings in the apps): before the first release or after it? Today a person
  with `manage` cannot change the tags of a post, an owner cannot give a channel an operator
  outside the four flows, and nobody can delete a template in an app. Recommendation: build the
  operator and the tags before the first release to third parties, because "No agent answers
  here" and a wrong tag cannot be repaired without the API; the rest can follow.
- V3-19 (backup state in the admin console): before the first release or after it?
  Recommendation: before it, at least the warning for owners, because an installation without
  the profile `observability` learns of a failed backup only from the log.
- A conformance report for accessibility: publish one with the first release, and in which form?
  Recommendation: decide with the first release; until then close the rows of the states `open`
  and `partly` of `docs/quality/wcag-criteria.md` in the order of level A first.

Documents:

- The READMEs of single modules and packages (under `services/`, `packages/`, `apps/client`,
  `plugins/`, `sdk/`) open with the list of tickets that built them, some still with "skeleton
  (M1-05) plus ..."; the audit asked to move these lists to the changelogs. They are not held by
  `test_status_lines.py`.
- `docs/roadmap.md` lists A1 as planned (audit finding `docs-accuracy-16`); once it says "in
  progress", chapter 26 can use `built (A1-01 to A1-09), planned (A1-10)`.
- `docs/glossary.md` keeps "Status: draft M0" as an example of the translation of the planning
  documents.
- The comment of the migration `00050_status_backup_runs.sql` says that the admin console and
  the status page read the table; a merged migration is never changed.
- `apps/client/lib/menus/autonomous_runs_dialog.dart` cites D-AR-08-4 for the place of the
  switch; the ruling is D-AR-08-9.

Product, with the plan rows above:

- `bothy-backupd` has no command that prints the newest runs or writes the manifest of a run to
  a file; the guides use `psql` (ruling 5).
- The rows of the states `open` and `partly` of `docs/quality/wcag-criteria.md` are the work
  list for the goal of 01 section 8. The console's own pages (login, step-up, the shell) have no
  accessibility test.
- `test_feature_list_callers.py` judges an action by "at least one operation is called". Other
  operations that no app calls (for example `deleteProjectBinding`, `listRunSteps`) belong to
  actions the apps use and are not named by a row of the feature list.
