# M7-26 Plugin in the Compose stack, portability and release

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M7-26-1 | 2026-10-26 | Delivery path (Design note 1): the product bundle carries the plugin build. The product's `make release-build` first runs `make -C plugins/grafana-bothy-live release-build` for `plugins/grafana-bothy-live/VERSION` and hands the ZIP to `tools/ci/product_release.py build --plugin-zip`, which checks it (`plugin_release.read_zip`: only members below `bothy-live-panel/`, no link, no `..`, no backslash, `plugin.json` with this ID, type `panel` and the version of the commit's `VERSION` file) and adds its files to `infra/observability/grafana/plugins/bothy-live-panel/` of the bundle with the commit's time, mode `0644` and owner 0 (18 2.1 rule 5). `compose.yaml` mounts that folder read-only into Grafana; in the repository the folder holds only a `.gitignore`, and `make -C plugins/grafana-bothy-live stack-install` fills it in a checkout. No download at install time. | The bundle is already downloaded, checked against the SHA-256 in `install.sh` and signed in `SHA256SUMS`, so the plugin needs no second download address, checksum or failure path in `install.sh`, and an installation without network access to the release page after the bundle still gets the plugin; the bundle stays reproducible and keeps rules 1 to 4 of 18 2.1. |
| D-M7-26-2 | 2026-10-26 | Gate check (requirement 13): the check `grafana-unsigned-plugins` of `make ops-check` (`tools/opscheck/opscheck.py`) reads `services.grafana.environment` of `infra/compose/compose.yaml` (mapping or list form) and fails unless `GF_PLUGINS_ALLOW_LOADING_UNSIGNED_PLUGINS` is exactly `bothy-live-panel`: another ID, a placeholder or variable, `*`, a list (also with a trailing comma), a value with spaces, an empty value and a missing setting are findings. Any other line under `infra/` outside a comment that names `allow_loading_unsigned_plugins` (case-insensitive: an overlay, `.env.example`, a Grafana ini file) is a finding too; the plugin builds under `infra/observability/grafana/plugins/` are skipped, they are code Grafana loads, not settings, and the plugin's README quotes the setting. | SEC-VZ-5, T-VZ-05: the check holds the exact ID and also closes the paths next to the checked line (Grafana reads the setting from the environment and from ini files). |
| D-M7-26-3 | 2026-10-26 | VZ-T13 through the Grafana API (requirement 14): every storage run of the portability test starts `grafana` after the telemetry scan and asks its HTTP API on the loopback address inside the container with `curl` (`docker compose exec`): the admin password is read there from the secrets volume and handed to `curl -H @-` on stdin, so it never appears in an argument list or a log. Checked: `/api/plugins?type=panel` lists `bothy-live-panel` with the signature `unsigned`, `/api/plugins/errors` is empty, `/public/plugins/bothy-live-panel/module.js` is served, `/api/dashboards/uid/bothy-live` is provisioned and every panel type in it (also inside rows) is a loaded panel plugin; in `docker compose logs grafana` every line that says unsigned and names a plugin ID (`id=`, `pluginId=`) names `bothy-live-panel`, at least one does, and `logger=provisioning.dashboard` logs no `level=error`. The report lists the unsigned lines. | The published port is not reachable from the host when Docker runs in a VM, the container's loopback is; the plugin error list and the log together show that no other unsigned plugin was loaded or refused. |
| D-M7-26-4 | 2026-10-26 | Release of the component `grafana-bothy-live` (requirement 15): `release.yml` installs Node.js 24 in the job `build` for `bothy` and `grafana-bothy-live` (no package manager cache in a release job), the plugin's `release-build` runs `npm ci` from `package-lock.json` before the build, and the new job `plugin-signing` (environment `release`) runs `release_chain.py sbom`, `sign` and `verify` over `--binary dist/bothy-live-panel-${VERSION}.zip`, keyless in the public phase with the identity of `refs/tags/grafana-bothy-live/v`; `publish` takes that set by artifact id and skips its generic SBOM and checksum steps for the component. The SBOMs are those of the ZIP file (`syft scan file:`), like the bundle and `install.sh` of the product. `make release-trial COMPONENT=grafana-bothy-live` runs the same functions with a throwaway key and two probes (changed ZIP against `SHA256SUMS`, `sign` without the SBOM). | One signing path for every release file (D-W-127, ADR 0062); a missing SBOM stops the release before anything is signed. |
| D-M7-26-5 | 2026-10-26 | Names that differ from the brief (D-W-100): the gate check is the ops check `grafana-unsigned-plugins` in `tools/opscheck/opscheck.py`; the VZ-T13 step lives in the runner `tools/portability/portability_run.py` (D-M7-14-6), so `portability.yml` and `tests/portability/` need no change but the README; the plugin's release code is `tools/ci/plugin_release.py`.
