# AUD-PKG-P03-admin-console Audit package of the administration and the web console: live period, waiting devices, step-up, lists, grants, apps, agents, hosts, console terminal, shell and session, distribution crash target

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-PKG-P03/A1 | 2026-11-23 | Until the API has an instance-wide list of waiting devices, the shell counts them one pass at a time (a count asked for while one runs runs once after it) and counts again only after a change on People or Devices, not after every change of any screen. The per-person assembly of `waitingDevices` stays. | A group, grant or agent change never touches a waiting device, and parallel or repeated full passes spent the read rate limit of a large instance. A list operation is a contract change and stays open (issues of the waiting-device count). |
| AUD-PKG-P03/A2 | 2026-11-23 | The page "Live" computes its 24-hour period again on a tab change and at the end of TV mode; TV mode moves the period by the whole minutes since it started at every rotation (`VizHostOptions.withRange`). No period picker is built; specification 25 6.5 states the built state. | Whole minutes keep the period on full minutes, which `getStatsTimeline` requires. A picker is a new control with its own design and stays open. |
| AUD-PKG-P03/A3 | 2026-11-23 | When the page "Live" has spaces to offer, it asks `getStatsLive` once without a space; a `403` moves it to the first space and removes "All spaces" from the selector, without a further note. | The same rule as the statistics A7 (`StatsController._refuse`); one extra read per opening is cheaper than a first view that shows a refusal to a space manager. |
| AUD-PKG-P03/A4 | 2026-11-23 | The step-up flow of `auth` maps any failure of the step-up key's signer that is not an `AuthException` to `StepUpCancelled`, as its port promised; the desktop signer adapter is unchanged, and an invalidated step-up key keeps ending the account through the apps' key watcher (08 5.4). No new `AuthException` subtype is added. | A cancelled confirmation read as "No connection". Mapping `key_invalidated` to an auth error in the adapter would hide it from the watcher that signs the lost device out (device_key_lost_test), so the account end stays the visible answer there. |
| AUD-PKG-P03/A5 | 2026-11-23 | `admin_ui` keeps its state in `StatefulWidget`s with `AdminActionState` and a few `ChangeNotifier` controllers, which deviates from ADR 0029 and 15 section 4 (Riverpod). Lists that reload on a filter now drop older answers by a generation counter. Aligning the package is left to a refactor ticket. | The deviation is a package-wide architecture change without a user-visible defect of its own; the reproduced defect (out-of-order answers) is fixed where it occurred. |
| AUD-PKG-P03/A6 | 2026-11-23 | The changelog fragment of the `admin_ui` fixes is the root fragment `changelog.d/AUD-PKG-P03-admin-console.md`, as earlier `admin_ui` tickets did. | `packages/admin_ui` is no release component (`RELEASE_COMPONENTS`); it ships in the client and the console. |
| AUD-PKG-P03/B1 | 2026-11-23 | `admin_ui` keeps the `Idempotency-Key` of `installApp`, `createGrant`, `createGroup` and `createAgent` per request content while no final answer arrived (no answer, `401`, `429`, `5xx`, `409 request_in_progress`) and drops it on any final answer (`RequestKeys`, at most `maxOpenRequestKeys` kept). Creates whose answer carries a one-time secret (tokens, host and enrollment codes, incoming webhooks, HMAC subscriptions) keep one key per call, and state changes and PATCH writes are not covered. | A lost answer turned a repeat into a second grant or a `409` on the slug the first install took; a repeat of a one-time secret answers `409 conflict` with `reason` `one_time_secret` (06 7), and state changes are protected by content or `If-Match`. |
| AUD-PKG-P03/B2 | 2026-11-23 | A `412 version_conflict` on the host and agent pages reads the record again and shows a warning to repeat the change; the change is not sent again by itself. | The other device's change may make the person's change wrong; the person decides again on the current state. |
| AUD-PKG-P03/B3 | 2026-11-23 | A failed step of the app install offers "Close" besides "Try again" and "Uninstall" (deviation from the two options of D-M6-08-1; 11 4.1 updated); the token follows on the app page. | A token refused for its last day forced the uninstall of a working app. |
| AUD-PKG-P03/B4 | 2026-11-23 | The app page has "Change consent" over the current manifest (required scopes fixed, optional scopes and events changeable, reason, `setAppScopes`); it issues no token. | `setAppScopes` had no other caller than the update dialog, so "Later" was a dead end; 11 4.2 already says a newly granted scope needs a new token. |
| AUD-PKG-P03/B5 | 2026-11-23 | The interview offers "Try again" only after `builder_timeout` and `builder_offline`, with the same turns; re-entering an interview that delivered a draft takes that draft. | Both fallbacks can pass; `builder_invalid` and `builder_not_configured` would fail again, and a second builder call costs money for a draft the person already has. |
| AUD-PKG-P03/B6 | 2026-11-23 | `AgentPage` listens to the first presence stream of its agent and listens anew only when the agent changes or a presence appears or goes; the shell's `agentPresence` API is unchanged. | The desktop hands a new stream per build; the stream is a view of one store per agent, so the first subscription stays valid. |
| AUD-PKG-P03/C1 | 2026-11-23 | The console's terminal binds Ctrl+Shift+F6 (Cmd+Shift+F6 on Apple systems) through `TerminalPane.shortcuts`; it moves the focus to the first enabled button above the terminal, and the view names the keys. No plain key is bound. | Tab, Shift+Tab and F6 belong to the shell; app shortcuts in the terminal need the platform modifier (R-PR-10). F6 matches the column switch of the desktop app. |
| AUD-PKG-P03/C2 | 2026-11-23 | When a stored "View as person" exists, the console's step-up adapter reads the session on `step_up_required` first; if the view is gone, the request repeats without a step-up. The server keeps its answer (no new reason code). | The browser clock decided when a view ended, and a request that hit the server's end first opened a step-up dialog. A new reason is a contract change; the console can tell the two cases apart with one session read. |
| AUD-PKG-P03/C3 | 2026-11-23 | The action step-up confirms over the challenge it created before the dialog when the person answered within half of its lifetime; after that it creates a new challenge and confirms over it. The lifetime is `expires_at` as read on arrival, at most `ConsoleActionStepUp.challengeLifeCap` (the default of `auth.step_up_challenge_ttl`). | `auth.step_up_challenge_ttl` ran while the person typed. A second challenge on every step-up doubled the requests in `rl.public_auth` of the client address and ran the administration suites of `console-e2e` into `429`; the cap keeps a browser clock that runs behind from keeping an expired challenge. |
| AUD-PKG-P03/C4 | 2026-11-23 | The console's HTTP client gets no request timeout in this change. | Dio's browser adapter sets `xhr.timeout` to connect plus receive timeout, a cap on the whole request, which would cut a large audit export; per-request values belong to the `admin_ui` repository. Left as a minor. |
| AUD-PKG-P03/C5 | 2026-11-23 | The console keeps without a session list (24 12 notes the build state); a reload leaves the session detached until it ends on the host. | Listing, adopting and ending sessions of other tabs is a feature of its own (FIX-terminal-session-lifecycle left the console out). |
| AUD-PKG-P03/C6 | 2026-11-23 | `crash_reports.target` of `distribution.yaml` reaches the build as `crash_dsn` of the release branding and the define `CRASH_DSN`; `dart_defines.json` names `CRASH_DSN` only when set. | The key was read by no step, so a publisher's target sent nothing. A define that is always written would override a `--dart-define=CRASH_DSN` of a manual build. |
