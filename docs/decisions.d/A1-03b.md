# A1-03b Server: hosting runners visible to owners

Follow-up of [A1-03](A1-03.md) for the entry of [A1-08](../briefs/A1-08-new-agent-clients.md).
Normative text: [26-builtin-agents.md](../spec/26-builtin-agents.md) 8.1 and 9,
[09-agents.md](../spec/09-agents.md) 2.2 and 4.8.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-A1-03b-1 | 2026-11-07 | The stored capability is the member `hosts_agents` of `AgentRuntimeStatus`, the `presence` of `Agent`, with the values of `ToolClass`; absent when the runner does not report it. | A1-08 reads the agent list it already has (design note 2 of its brief); `presence` already holds what the runtime reports, so neither a new operation nor a member of `Agent` is needed. |
| D-A1-03b-2 | 2026-11-07 | Only `getAgent` and `listAgents` set it, and only for a caller with an active owners row (`identity.Directory.User`); `agent.read` keeps its right. | `agent.read` also admits readers of a served channel and the agent itself; they see nothing more than before. `agent.updated` (receive action `agent.read`), the `412` body and the heartbeat answer never carry it, because their audience is not owners only. |
| D-A1-03b-3 | 2026-11-07 | The value is the stored one (`agents.reported_details`), not the in-memory presence. | The ceiling the server enforces is the one of the last stored heartbeat (26 3.1 item 3, A1-03 design note 5), and a change of it is stored at once, so the list shows exactly what `createAgent` will accept. |
