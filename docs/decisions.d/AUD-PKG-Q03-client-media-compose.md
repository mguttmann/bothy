| AUD-PKG-Q03/1 | 2026-11-28 | The permission of a card is decided per component from its own `required_capability` and `restricted_to`; a component the reader may not use is locked on its own (`DsMessageComponents.lockedCustomIds`) with the note of the first locked component, and the card counts as not permitted only when every component is locked. The header keeps the fields of the first component. | On the approval card of 09 11.5 the first button decided for all: "Always allow" (owner) was open for a run starter and "Deny" was locked for a starter without `approve_actions`. |
| AUD-PKG-Q03/2 | 2026-11-28 | The video dialog does not start by itself and has Play and Pause, Mute and Sound on, a position slider and the position in words. A failure of the player after the start fetches a new ticket and goes on at the position and in the playing state of before; a failure without progress since the last renewal, or without a way to renew, shows "Playback failed". No renewal ahead of the expiry. | WCAG 1.4.2 and 2.1.1; the server checks the ticket on every range request (12 9.2), and a renewal on the failure needs no clock of the ticket's expiry in the app. The progress rule keeps a broken file from renewing for ever. |
| AUD-PKG-Q03/3 | 2026-11-28 | "Play" of an audio attachment after "Pause" continues with `resume`; when that fails (the ticket expired during the pause) the app fetches a new ticket and plays from the start. | `play` starts from the beginning by the interface. |
| AUD-PKG-Q03/4 | 2026-11-28 | Removing a composer attachment whose upload an attempt of this run started enqueues `releaseUpload` (12 12: deletes the completed file or aborts the open session); "Upload again" releases the session the failed upload kept before the new entry. Both run in the uploads' lane, so after an attempt under way and after being offline. A removal before any attempt writes nothing for the server. | The same rule as for a discarded new post (FEAT-NEW-CHAT-ATTACH, FNCA/4). An open session counted against `file.upload_max_open_sessions` until it expired. Attachments of an earlier run are not in the composer, so the upload progress of this run is enough to know what the server holds. |
| AUD-PKG-Q03/5 | 2026-11-28 | `AttachController.add` and `addText` run one after another, and `add` is all or none: a copy that fails after earlier files of the same call were attached removes them again with their copies. Restoring the attachments of a composer after a restart is plan row V3-65 together with the draft attachments (`file_ids`). | Two adds at once (a drop and a paste) could both pass the count check; the restore needs the draft attachments of #657 to be useful. |
| AUD-PKG-Q03/6 | 2026-11-28 | The thread's outbox view leaves out the draft writes (`putThreadDraft`) and gives a list only when it differs from the one before; the forum's waiting posts and the unsent draft text of a new post give a value only when it changes. No new `client.perf` target for typing. | The composer writes the draft on every key press (D-M4-20-2); the history, the composer chips and the sidebar rebuilt on each one although no reader shows a draft entry. | AUD-PKG-Q03/7 | 2026-11-28 | The three reads of the share sheet's targets are `ShareTargetsDao` of `local_store` with bound values and a test against the schema; the app no longer writes SQL. | A rename in `local_store` broke the share sheet only at run time. |
| AUD-PKG-Q03/8 | 2026-11-28 | The iOS share extension writes its inbox entry at Send, before the first network call, uploads the files from the entry, records the completed uploads in it on a transient failure and deletes it after a confirmed send or a refusal. When the app reads the inbox it deletes staging folders and half-written entries older than `ShareInbox.staleAfter` (one day). An app that takes over an entry while the extension still sends it may upload the files a second time; the message is created once (same `client_msg_id`) and the extra files expire unattached. | iOS may end the extension during an upload without any error path running; the share was lost and its copies stayed until logout. A background `URLSession` would need its own delegate and process lifetime handling for a case the inbox now covers. |
