# A1-07 Interview (2026-11-06)

Brief: [A1-07-agent-interview.md](../briefs/A1-07-agent-interview.md). Normative:
[26-builtin-agents.md](../spec/26-builtin-agents.md) 6, 7.4, 9, 12 (BA-T15), 13 (R-BA-09) and 14;
ADR 0076, ADR 0054. The rulings settle what chapter 26 leaves open; none is weaker than the
chapter.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-A1-07-1 | 2026-11-06 | Request shape (`AgentInterviewRequest`): `turns[]` of `{role: builder or owner, text}` oldest first and the optional `want_draft`. No turn is the start of an interview. Each turn, the builder's earlier questions included, is at most `agents.interview.answer_max_chars` characters of display text with line breaks; more turns than `agents.interview.max_turns` is `too_many_items` on `/turns`, an interview whose event payload reaches `sync.event_payload_max_bytes` is `too_large` on `/turns`. | The client keeps the interview (26 6.1 item 1); the server never cuts the person's text, so a payload that does not fit is the person's input to shorten. |
| D-A1-07-2 | 2026-11-06 | Answer shape (`AgentInterviewAnswer`): `outcome` (`questions`, `draft`, `fallback`), `questions`, `draft` (`AgentDraft`: the members of `agent_definition.v1` plus `name`, `handle`, `description` and the optional `channel_suggestion {space_name, channel_name}`, flat), `errors` (the draft's findings as `FieldError`, pointers into the draft), `fallback_reason` and `cost_estimate {amount_micros, currency}`. | One flat object maps one to one onto the preview of 26 8.2; the pointers of `errors` are the pointers `putAgentDefinition` gives later. |
| D-A1-07-3 | 2026-11-06 | Builder answer (`AgentInterviewBuilderAnswer`): `kind` `questions` (one or two non-empty questions of at most `agents.interview.answer_max_chars` characters, no draft) or `draft` (no questions), and `costs`. The contract stays closed at every level (W7): a member outside it is refused by the request validation with `400`, and the request stays open until `expires_at`. The use case decodes the body strictly again; a draft finding of a surface of 26 5.5 (`unknown_member`, `skill_frontmatter`, `inline_shell`, `import_outside_folder`), of a shape the typed answer cannot carry (`invalid_type`, `invalid_enum`, a missing member) or of a character (`invalid_utf8`, `control_character`, `bidi_control`) refuses the whole answer: `400 validation_failed` to the builder and the fallback `builder_invalid` for the person, so such a draft never reaches the preview. Every other finding of 26 4.3 and `mcp_not_in_catalogue` goes back with the draft. | The answer is model output (26 6.1 item 3); a refused surface must not reach the person's preview, while a too long text or a missing secret reference is something the person can ask the builder to fix. |
| D-A1-07-4 | 2026-11-06 | The class a draft is checked for is its `settings.tool_class_wish` (26 8.2 sets it before the definition is stored), so a `stdio` server with a lower wish is `tool_class_too_low` in `errors`. | The creation flow sets that class first; a draft valid here is stored. |
| D-A1-07-5 | 2026-11-06 | Catalogue check (26 7.4): equal transport, for `stdio` command, package and the argument list in order and count, for `http` the URL; `env[]` and `headers[]` equal as sets by name, each with the same `value` or the same `secret_ref` (a switch is a difference). Until the templates of A1-06 bind `app.CatalogueSource`, the catalogue is empty and every drafted server is `mcp_not_in_catalogue`. | The order of named entries carries no meaning; every value that can carry an endpoint or a key is compared. |
| D-A1-07-6 | 2026-11-06 | Deadline: the route of `interviewAgent` runs under `agents.interview.timeout` plus `http.request_timeout` (`httpserver.Operation.Timeout`, set by `wire.InterviewDeadline`), the wait for the builder is `agents.interview.timeout`. The console's backend for frontend is the same route with the cookie session, so it gets the same deadline. No cross-check against `http.request_timeout`. 02 14.2 and 26 14 name the sum. | With both equal the request context would end with the wait and turn a timeout into an error; the rest of the request (authorize, audit) keeps the normal budget. |
| D-A1-07-7 | 2026-11-06 | `interviewAgent` is `x-idempotency-exempt: read_only`, `answerAgentInterview` `agent_runtime`. | A stored response of an Idempotency-Key would store the interview, which 26 6.1 item 3 forbids; the builder answers once (409 for a second answer). |
| D-A1-07-8 | 2026-11-06 | Answer refusals: unknown or forgotten request `404` before authorize; `agent.interview.respond` refused (another agent, a person) `404`; after `expires_at` `410 gone`; a second answer after an accepted or refused one `409 conflict` with `reason: already_answered`. A request is remembered until `expires_at` plus `agents.interview.timeout`. | The pattern of the search assistant (14 4.10), with the "answers once" of 26 6.1 item 2 made visible instead of a silent `204`. |
| D-A1-07-9 | 2026-11-06 | Audit and log (R-BA-09): every request that passed authorize and the turn check writes one allow entry `agent.interview` on the instance with `outcome`, `fallback_reason` (only for a fallback), `turns`, `draft_errors` and `cost_micros`, and one log line `agents: interview` with the same values under `bothy.agents.interview.*`; written after the outcome in a unit of work of its own that outlives a cancelled request, which is recorded as `builder_timeout`. | The builder may have spent money even when the person left; nothing of the text reaches audit or logs (canary in the app tests and the canary scenario). |
| D-A1-07-10 | 2026-11-06 | Runner: the builder sends nothing for any finding of 26 4.3, also for those the server would answer as field errors, and does not check the catalogue (the server does). Model default `sonnet` (`runner.agent_builder_model`, 26 14); at most two builder calls at once; the one-shot call is shared with the search assistant (`oneshot.py`); the instruction file of a call is named `builder.md`. | 26 6.2 item 3 ("sends nothing for an answer that fails"); a model that drafts an invalid definition should not cost the person a round trip with a draft they cannot store. |
| D-A1-07-11 | 2026-11-06 | The runner's copy of the rules (`definition.py`) treats a lone surrogate of a JSON string as `invalid_utf8`, where Go decodes it to U+FFFD and lets it pass; every other rule equals the server's, held by the whole corpus. | Python keeps lone surrogates in a `str`; refusing them only makes the runner stricter, never weaker. |
| D-A1-07-12 | 2026-11-06 | Placement: `agents/domain/interview` (pure rules), `agents/app/interview.go` (`Interviewer`, its own collaborators next to `Service`), the port `agents.InterviewRelay` implemented by `gateway/adapters/interviewrelay` over `Hub.AskBuilder`, the handlers `agents/adapters/httpapi/interview.go`, and `agent.interview_requested` registered by `agents`. | The search assistant pattern (`search.AssistRelay`) within the module that owns the definitions and the catalogue port. |
