# AUD-pkg-plugins-sdk-01 Audit findings of the plugins and SDKs: run ends, loop failures, log lines and the reference apps

Findings of the audit of 2026-11-11 against the Python and TypeScript SDKs, the Hermes adapter, the
Claude Code runner and the reference apps (GitHub app, Jira app, cost reconciliation app, Grafana
panel), handled as one work package. Each finding was read again against the code of `main`; the
pull request lists which were fixed, which were already resolved and which wait for a later package.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-P9P/1 | 2026-11-23 | The generated `Idempotency-Key` header gets its text form through a deterministic rewrite step in `make generate` (`str(idempotency_key)`), not through custom generator templates. | Same pattern as the em dash rewrite (M2-23/5); a copied template would have to follow every generator update, the one-line rewrite matches exactly the 104 lines and a test holds every operation. |
| AUD-P9P/2 | 2026-11-23 | A `finishRun` without an answer, or answered `5xx`, `401` or `429`, leaves the end pending in memory; the adapter resends the first end asked for with the reconnect backoff until the server stores or refuses it; after a stop the run is left to the server. No durable store of the pending end. | Same behaviour as the TypeScript SDK (AUD-ST1); a durable end would need a new inbox state and restart path, while the server ends an unattended run itself (09 5.5). |
| AUD-P9P/3 | 2026-11-23 | A stored event of a known type that does not decode is turned into `UnknownEvent` in `envelope_from` and acknowledged without reaching the handler. | One place for all decode errors and both sources; leaving it unacknowledged would bring it back forever, stopping the adapter would crash-loop. |
| AUD-P9P/4 | 2026-11-23 | `WebhookKeyCache` bounds the fetch through a generated core client with `asyncio.timeout(sdk.http_timeout)` and adds no retry. | The hang is the harm (one shared fetch for every caller); a failed fetch is already tried again by the next call. |
| AUD-P9H/1 | 2026-11-23 | A report or a control command reply above `hermes_adapter.max_message_bytes` is cut at a UTF-8 boundary and ends with the session mirror's note `(cut)` (shared helper `cut_with_note`), logged with `report_cut` or `message_cut`; the rest is not attached. | A report carries text only (the standalone sender refuses attachments, 09 17.9); the note tells the reader that text is missing, as the mirror already does. Attaching the rest would be a new upload path for reports. |
| AUD-P9H/2 | 2026-11-23 | When the SDK loop raises after `connect` returned, the adapter reports a retryable fatal error `bothy_adapter_loop_failed` to Hermes (`_set_fatal_error` plus `_notify_fatal_error`, spawned so that Hermes' handler can await `disconnect`); a stop with a close code (4015, instance mismatch) and a stop after `disconnect` are not reported. | Hermes at the pin reconnects only platforms that reported a fatal error, with its own backoff; an own restart loop in the adapter would duplicate it. A close code is final until the operator acts. |
| AUD-P9H/3 | 2026-11-23 | A control command Hermes fails gets a fixed notice of the agent without a run (`COMMAND_FAILED`, the command's name only) instead of a failure state on the server. | The server has no failure state for a command; the error's text could carry content and stays out of the thread. |
| AUD-P9H/4 | 2026-11-23 | `get_chat_info` stays an answer from the ID alone; 09 17.3 now describes that instead of a `thread.read`. | Hermes' base class asks only for `name` and `type`, and no caller at the pin needs the thread's title; a server read per call would add latency and a failure path for no user. |
| AUD-P9H/5 | 2026-11-23 | The job and stage helpers run in a durable install through a starter `run.py` that `install` writes into the plugin directory; it loads the plugin entry (which serves `packages.json`) and runs `python -m bothy_hermes_adapter`. | Hermes' environment holds nothing of the adapter (D-HERMES-INSTALL-DURABLE-1), so `python -m bothy_hermes_adapter` alone cannot work there; the starter reuses the entry's finder instead of a second copy of the package list logic. |
| AUD-P9H/6 | 2026-11-23 | Unexpected failures of the adapter loop and of handler tasks are logged with `traceback.format_tb` (frames only), not with `exc_info`. | An exception's text can carry content (SEC-LOG); its frames name only code. |
| AUD-P9R/1 | 2026-11-23 | A live turn the runner adopts at its start takes a slot of `runner.max_parallel_runs` without waiting, also above the bound; turns the runner starts itself wait until fewer than `total` slots are held; the heartbeat reports `run_slots.used` at most `total`. | An adopted turn already runs: making it wait or stopping it would lose work. Counting it keeps the bound for new turns. The server refuses a `run_slots` with `used` above `total` (heartbeat.go), so the report is capped. |
| AUD-P9I/1 | 2026-11-23 | The GitHub app keeps its PID lock file; README and 11 10.1 require one instance per `state_dir` instead of moving the state to SQLite with a kernel lock. | The store move is a redesign of the app's persistence (also #1322); the rule closes the documented harm for every operator who follows the README. |
| AUD-P9I/2 | 2026-11-23 | Lost `503` deliveries are documented with the manual redelivery path of GitHub (Recent Deliveries or the REST endpoints); no automatic redelivery job. | A redelivery job needs a GitHub App or hook admin rights and runs against the live GitHub API, which no test here may call. |
| AUD-P9I/3 | 2026-11-23 | Mirrored replies stay attempted once (D-M2-49-11, D-M2-50-12); the READMEs now limit "the person is told to check" to `/issue` and say a refused mirror is only logged. | A retry of a write to GitHub or Jira without a confirmed outcome can post twice; the at-most-once rule is deliberate. |
| AUD-P9I/4 | 2026-11-23 | The cost reconciliation app gets its own key `reconciler.pass_interval` (default `1h`) between passes; skipping unchanged days is not added. | Daily buckets change at most a few times a day; one key removes the per-minute audit no-ops without a new local state of submitted days. |
| AUD-P9I/5 | 2026-11-23 | The panel's timeline starts at the start of the period and plays from the start at the end; the start position differs from the app (which starts at the end) and 25 8.2 says so. | Starting at the start is tested behaviour of the panel; only the dead Play button at the end was a defect. |
| AUD-P9T/1 | 2026-11-23 | The parity gap to the Python SDK (#1339) is documented as a table "Differences from the Python SDK" in `sdk/typescript/README.md`, and 11-extensions.md 11.2 points to it; the missing handler hooks, modules and the costs fallback are not ported in this package. | The only user of the TypeScript SDK in the repository is `plugins/github-app`, which uses the client and webhook keys only; porting search assist, interview, runtime status, uploads and six hooks is new feature work without a consumer, while the false "same modules" claim was the harm. |
| AUD-P9T/2 | 2026-11-23 | The half-wired adapter parts of #1343 (empty degraded reasons, the gateway error path for `run.update`, reconciliation without a command store) stay and are deferred, not removed. | The Python adapter has the same three parts in the same state; removing them in one SDK would widen the gap of AUD-P9T/1, and wiring them is the parity work (runtime status, gateway patches, file command store). |
| AUD-P9T/3 | 2026-11-23 | The outbox age or attempt limit (#1340) is deferred like its Python counterpart #1174. | Both SDKs share the outbox contract; a limit with `onFailed` and `discard` in one SDK only would split it, and the deliverer with backoff and a limit is a new concept. |
