| D-CU-06-1 | 2026-11-26 | Probes of 27 16 (`plugins/claude-code-runner/tests/real_cli/test_computer_probe.py`, part of `make runner-real-cli`): the CLI starts the `stdio` server of `--mcp-config` with the file's `env` in print mode and in a background session under `host`, and the image an MCP tool returns lies only in `<config>/projects/<folder>/<session>.jsonl` and `<config>/projects/<folder>/<session>/tool-results/`; deleting both leaves no file under the configuration folder or `HOME` with it. Run on 2026-11-26 against 2.1.332 (the version `ci_cli.py` installs; the code's pin is 2.1.326, which was not at hand): print mode on macOS, both modes in a throwaway Linux container. No fallback of 27 16 is taken. | Both probes hold; the CI job runs the background part with every change, so a later CLI that breaks either fails there. |
| D-CU-06-2 | 2026-11-26 | Branch `feat/CU-06` (the coordinator's name), not `feat/CU-06-runner-computer-use` of the brief; the branch merges `origin/main` (FIX-RUNNER-BG-NO-PROMPT, #1791) so the settings file of a background session keeps `permissions.denyInsteadOfPrompting` and the real-CLI job `make runner-real-cli` exists. | The probes run in that job, and a background session of the stage must keep the refusal of prompts. |
| D-CU-06-3 | 2026-11-26 | The request folder lives in `claude_code_runner.computer` (`RequestFolder`), which takes the server call as a function, so the folder of `bothy-wake` (09 18.19.8), which is not built yet, can share it. The runner answers each request once, never one whose answer file stands, and passes only the members of 27 12.2 in `result`; a failure of the network or the server, or an answer without a member of 12.2, is answered with `status` 0 and `code` `request_failed`, which C1 maps to `host_offline`. | C1 decodes the answer strictly (D-CU-05-1), so a member the server adds later must not reach it; `request_failed` is a code of the runner like `request_refused`, not a problem code of the server. |
| D-CU-06-4 | 2026-11-26 | The runner learns that a run opened a session from the answers it relayed: an `open` answered `ok` leaves the mark file `opened` in the run's request folder, which C1 never reads and a runner that adopts the run reads too. The mark names the session's configuration folder, session id and thread, so the sweep after the start's adoption and after every run deletes the files of a run whose record a start removed (left, stopped, a handover record of another runner) and that therefore never reached the end of a run again. A failed deletion leaves a mark per thread (`<runner.state_dir>/computer/left/<thread_id>.json`); the thread's next run tries again and names the leftover in its status line with the cause `computer_transcript_left`. | The answer is the only place the runner sees the open; a status line is the existing way to name something in the live box (26 5.9), and a new box note code would change 09 18.9. |
| D-CU-06-5 | 2026-11-26 | At the end of a computer run in background mode the runner stops the session and removes its entry (`claude stop`, `claude rm`) before it deletes the files, also when the release already stopped it; in print mode it deletes once the process is gone. A run that stays for a next runner (a live turn, a handover) keeps its per-turn file, its request folder and its session; the adopter keeps the nonce of the file. | 27 10.5 item 2; deleting under a live session would let it write the transcript again. |
| D-CU-06-6 | 2026-11-26 | The start, `stop --turns` and the hosted leftover check read only `turns/<run_id>.json` as turn records (`adoption.record_paths`). | The per-turn file of 27 10.1 lies in the same folder, and a reader of `*.json` logged it as `turn_record_unreadable` and counted it as a record of a handover. |
| D-CU-06-7 | 2026-11-26 | Computer use applies to every `host` turn of the process, the turns of a hosted agent included (their state folder holds the files), because a hosted configuration is the runner's with its own state folder and class. A hosted `host` turn keeps its own `--strict-mcp-config`, which then loads its servers and the computer file. | 27 10.1 says "every turn under tool class `host`"; SR13 on the server decides who may open a session. |
| D-CU-06-8 | 2026-11-26 | CU-T24 lives in `services/server/test/terminal/e2e/computer` (build tag `computere2e`) on the Compose stack of the terminal suite (the server image, PostgreSQL, the `termhost` service of `compose.terminal.yaml` with an image variant that adds Xvfb, `python3-xlib`, `python3-pil` and `python3-tk` through `ARG EXTRA_PACKAGES`), not under `tests/e2e/` with a profile of `infra/compose/e2e.sh`; it runs through `make computer-e2e` (first the Fake-Claude client test `plugins/claude-code-runner/tests/computer_mcp` against the real `bothy-computer-mcp`) as a step of the CI job `test-adapters-e2e`, which `tools/ci/components.py` also selects for a change of the computer packages of the host, `bothy-computer-mcp`, the test backend and `infra/compose/test/host/`. | The terminal suite already pairs real host services in systemd containers and builds the server image; a second stack would fork it (brief rule 2, D-W-100: follow the code). |
| D-CU-06-9 | 2026-11-26 | In CU-T24 the runner runs from source in a second container of the host image on the network `termhosts` (as an unprivileged user, its Python dependencies from `uv export`), because the instance origin `https://chat.example.com:8443` resolves only there and the DPoP `htu` must equal it; `bothy-computer-mcp` and Fake-Claude are root-owned files of mode `0755`. | `runner.computer_mcp_bin` must not be writable by group or others, and the origin is part of every proof. |

| D-CU-06-11 | 2026-11-26 | The sentinel check of CU-T24 searches windows of the images the agent really received (offsets a multiple of 3, so their base64 form is a substring), raw, hex, base64 and base64url, in the database dump, the Compose logs, the collector exports and the desktop's journal; a positive control finds them on the runner side. | A synthetic pattern would not prove that the images of the session itself stay off the server. |
