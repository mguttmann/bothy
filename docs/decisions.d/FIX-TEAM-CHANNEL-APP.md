# FIX-TEAM-CHANNEL-APP Mention labels, add form and member completion of team channels

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-TEAM-FIX-1 | 2026-11-22 | An owner's text message in a team channel that mentions handles of current members shows "to @a, @b" (`ToMembers`, l10n `teamToMembers`), the members in the order of their first mention; without such a mention it shows "to all members" as before. The app reads mentions with the server's rule of 09 3.9.4, ported from Go `MentionedHandles` (`mentionedHandles` in `team/team_model.dart`, unit tests mirror `TestMentionedHandles`); a handle of no member narrows nothing. This replaces the "to all members" part of D-TEAM-APP-5. | Owner ruling of 2026-11-22: a message that mentions members goes only to them, one without a member mention goes to every member; the server side is built separately. The label uses the team as read now, so a message written before a member was added or after one was removed is labelled by today's members, like the known minor that "to all members" shows under messages from before team mode. |
| D-TEAM-FIX-2 | 2026-11-22 | The add form takes its agents from the existing `listAgents` (`agent.read`, every page, active agents only) through `TeamPort.agents`, read beside the team when the dialog opens; a failed read falls back to the stored agents without a failure text. The agent field stays the design system's `DsDropdownField` with `enableFilter`, which filters the list from the first typed letter. Home channels still come from the channels the person sees (`visibleChannelsProvider`); a channel in which the agent is already a member is not offered, and an agent whose every home channel is taken is not offered either (an agent that operates no channel is, with the existing note). No new server endpoint. | Owner wish of 2026-11-22: when adding, a picker of all agents with type-ahead, then the home channel among the channels that agent operates, and a sensible handle. The stored principals hold only the agents the device has met, `listAgents` holds all the owner sees. The pairs the server would refuse with `team_member_exists` are not offered. |
| D-TEAM-FIX-3 | 2026-11-22 | The handle is filled in when a home channel is chosen (also the one chosen at once): the home channel's name lower-cased, every run of characters outside `[a-z0-9_-]` a `-`, leading characters other than a letter or digit and trailing `-` dropped, at most 32 characters (the default of `team.handle_max_chars`), unique among the members in any letter case with `-2`, `-3` and so on; the agent's handle when the name leaves nothing. A handle the owner typed or brought with `/team add <handle>` is never replaced; a suggestion is cleared when the agent changes to one without a chosen home. | The home channel names the project the member works on and tells two memberships of the same agent apart; the server checks length and uniqueness again. |
| D-TEAM-FIX-4 | 2026-11-22 | In the composer of every thread of a team channel the existing mention suggestions (`ComposerController`, `mention_suggestions.dart`, `DsComposer` keys) offer the team's members instead of the stored people and agents: right after `@` all members, sorted by handle and without the usual limit of 8, each with its agent's name; further letters filter by handle or agent name. The members come from `channelTeamProvider`, so only an owner gets them, and a choice inserts `@handle `. | Owner, 2026-11-22: "When I press the @ key, I want a choice of all agents." In a team channel a mention addresses a member by its team handle, which is no principal handle, and only owners read the channel, so people are no useful target there. Extending the one mention mechanism keeps the keyboard behaviour of `DsComposer` (arrow up and down, Enter or Tab, Escape) and the tap on the phone. |
