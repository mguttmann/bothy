| D-M7-13-1 | 2026-10-27 | Version gate placement (Design note 1): the rule is pure Dart in `packages/domain` (`SemVer` with the precedence of SemVer 2.0.0 item 11, `decideClientVersion`); only the first rule of the app's platform counts, a rule value that is no SemVer counts as absent and is logged once per key and value, an app version that is no SemVer is never blocked, the minimum wins over the recommendation. The app asks `getDiscovery` at the start and on E1 "Connect" (as before) and before every gateway attempt: the sync engine got the port `ConnectGate` (`GatewayConnection`, `SyncEngine.create(connectGate:)`), which the app fills with `VersionWatch.admit` of the instance; a refusal ends the attempt without a socket in `updateRequired` with the reason `belowMinimumVersion`, which never reconnects; a gate without an answer admits the attempt, so the server stays the second line with `4007` for protocol versions. When the gate refuses while the app runs, `OnboardingController` closes the instance's services without deleting anything (the outbox and the local data stay) and shows E1 "App too old" with the update path, so no authenticated request leaves the app. The gate's time counts against `client.sync.connect_timeout` of the attempt. | 18 9 item 2 and brief requirement 13: the gate runs before `identify`, so an old app never reaches `4007`; closing the services is the one place that stops every authenticated request, not only the socket. |

| D-M7-13-5 | 2026-10-27 | iOS release (`ios.py`, job `build-apple`, environment `release-apple`): the archive is built unsigned and signed afterwards inside out with `codesign` (frameworks and libraries, then the extensions, then the app) with the Apple Distribution identity in a keychain of the run and the App Store profiles of the app and both extensions (secrets `APPLE_DISTRIBUTION_P12`, `APPLE_DISTRIBUTION_P12_PASSWORD`, `APPLE_IOS_PROVISIONING_PROFILE`, `APPLE_IOS_NOTIFICATION_PROFILE`, `APPLE_IOS_SHARE_PROFILE`); each profile must name the team's application identifier of its bundle; the entitlements are the build's plus the application identifier, the team identifier, `get-task-allow` false and `aps-environment` production. The IPA (`Payload/`, `ditto`) goes up with `xcrun altool --upload-app` and the App Store Connect API key that `release-apple` already holds for notarization (`APPLE_NOTARY_KEY`, base64 of the `.p8`, with its key and issuer ID); the App Store Connect API then waits for the processed build (bound `storeapi.PROCESSING_PATIENCE_SECONDS`) and adds it to the TestFlight group `beta`; `ios.py promote --build N` adds it to `stable`. The app record and both groups are created by the publisher; the release names a missing one. The export compliance declaration (`ITSAppUsesNonExemptEncryption`) is not set by the build: it is a statement of the publisher (owner, OQ-08). | One signing path for app and extensions with checks we control; a team API key with the App Manager role serves notarization and uploads alike. |
| D-M7-13-6 | 2026-10-27 | Android release (`android.py`, new job `build-android`, new environment `release-android`, `ubuntu-24.04`): Gradle signs the release build with the publisher's upload key when the properties `uploadStoreFile`, `uploadStorePassword`, `uploadKeyAlias`, `uploadKeyPassword` are set (passed as `ORG_GRADLE_PROJECT_<name>`, the key store in the run's temporary folder), otherwise with the debug key as before, which no release uploads because the signer check refuses it.
