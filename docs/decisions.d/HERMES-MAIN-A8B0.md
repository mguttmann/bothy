# HERMES-MAIN-A8B0 Hermes adapter on Hermes Agent main a8b0bc1505

Hermes installations that follow upstream main at commit `a8b0bc15053c1d71fb2bfea39007847c9e1c5673`
(2026-11-06, no release tag; 528 commits after `v0.23.0`) must keep working, and so must those on
`v0.22.5` (`bf0203a794a0`). This ticket pins, records and checks the adapter against that commit (spec 09 section 17).

## Open minors

- In the fail-open case of D-HERMES-MAIN-4 the box says "Previous session not found, new session started", although the session exists and is only live in another thread; a distinct text or `system_code`.
- Restart hazard, already present on `v0.22.5`: after a gateway restart `_ran_here` is empty, so a bind sends `/resume` and the session moves; a later `/new` in the old thread ends it in Hermes, and the bound thread silently gets a fresh session. A Fake-Hermes test first (bind after restart, a run in the old thread, a second run in the bound thread). Then either resend `/resume` when the Hermes ID differs from the server's reference, or derive the guard from the server's `rebind` row. This is also the precondition for using the upstream move for bind (option b) from a tagged release.
- Approval cards resolve by session key only (`platform.py` `resolve_gateway_approval(request.session_key, ...)`), so a stale card can answer the next queued approval of the same session. `a8b0bc15053c` offers `ExecApprovalPrompt.request_id` and `tools.approval.resolve_gateway_approval_card` (upstream 5ab58da1f6). This needs a fallback for `v0.22.5` and is not reproduced for Bothy.
- `send_draft` returns `success=True` when no thread or run matches, so the draft is dropped silently (the final `send` still carries the text).
- `a8b0bc15053c` strips image tags and a trailing silence marker in `_clean_for_display`; `send_draft.last_equals_answer` is not recorded for such replies.
- A Fake-Hermes or unit test that calls `switch_session` directly with `_ran_here` naming another thread; today only the end-to-end Fake-Hermes test holds D-HERMES-MAIN-4, because `platform.py` imports Hermes and the unit tests run without it.
- `config:best-practices` turns on digest updates for the second regex manager of `renovate.json`; once `v0.23.0` is older than `deps.min_release_age`, Renovate may propose a "digest" update to the commit of `v0.23.0`, which would move the pin back. The ancestry note says to close it and the recording test fails on it; not checked with Renovate itself.
- `tests/pin_rules.py` `_RULING` accepts any `D-...-n` ID in a row that names the commit, also one that only mentions it in passing.
