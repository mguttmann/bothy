# AUD-misc-misc-01 Platform runs of the host service, the SQL rule of Semgrep, native code in CodeQL

Work package of the audit of 2026-11-11 for the workflows and rules outside one component
(`.github/workflows/host-platform.yml`, `.github/workflows/codeql.yml`, `.github/workflows/ci.yml`,
`.semgrep/`). Findings: `fn-terminal-hosts-2` (rulings 1 to 6), `quality-tools-2` (rulings 7 and
8), `config-devex-2` and `client-native-3` (one cause, rulings 9 to 11), `config-devex-5`
(ruling 12).

| AUD-MISC-MISC-01/1 | 2026-11-11 | On Linux `host-platform.yml` gives `/opt` the owner root and the mode `0755` before the platform suite, the folder alone and not its content. `tools/ci/tests/test_host_platform_workflow.py` reads the program folder of the install plan, the folder of the suite and `PLATFORM_OUT` of the workflow and fails when a Linux step before the suite does not reset the folder above each. | Cause of every failed test of the Ubuntu job (run 42556146760 of 2026-11-09 and the runs before): the image of the hosted Ubuntu runner opens `/opt` to every user while it is built (`chmod -R 777 /opt` in [`images/ubuntu/scripts/build/configure-system.sh`](https://github.com/actions/runner-images/blob/main/images/ubuntu/scripts/build/configure-system.sh) of actions/runner-images, retrieved 2026-11-11). The product installs to `/opt/bothy-host/bin`, the suite keeps its programs under `/opt/bothy-platform`, and `bothy-host` refuses a helper or a program below a folder a session user can write (HD10 `helper_untrusted`, HD11 `program_location_untrusted`, exit `78`), so `pair` met a service that had ended and a crash was not restarted. Reproduced with the Linux bundle of the suite in the host image of the terminal suite: with `/opt` at `0777` `TestPlatform_TMT29g_Token`, `TestPlatform_ExitPolicy` and `TestPlatform_PTYRunsAsSessionUser` fail with the messages and journal lines of the hosted run, with `0755` the same three pass. The refusal is the product working as specified, so the runner is brought to the state of a stock system and the product is left alone. |
| AUD-MISC-MISC-01/2 | 2026-11-11 | The entry scan of HD11 reads the owner and the type of an entry without its ACL: `hostos.LstatOwner` asks a `Security` that is an `OwnerReader` for exactly that and falls back to `Lstat`. Only the reader of macOS implements it (lstat alone); Linux and Windows read as before. Every other check keeps the full `Lstat`. | Cause of the macOS job: `TestPlatform_EntryScanMeasurement` scans a home of one million entries, and the reader of macOS starts `/bin/ls -led` once per path for the extended ACL. The scan compares only the owner of each entry with the other session users and follows folders, it never judged the ACL; with one program start per entry the run ended at the test bound of one hour inside `doctor`. A real home on macOS met the same cost in every full run of the checks. `TestEntryScanStartsNoProgramPerEntry` walks a real tree with the reader of macOS and counts the programs (one per entry before, none now); `TestEntryScanStillFindsAForeignEntry` holds that the owner read this way is the real one. |

| AUD-MISC-MISC-01/7 | 2026-11-11 | The Semgrep rule `bothy-go-sql-string-building` runs in taint mode: a text built with `fmt.Sprintf` or by joining a string literal (on either side) is a source, every argument of `Query`, `QueryRow`, `Exec`, `Prepare`, their `Context` forms and `SendBatch` is a sink. The method list and the excluded test paths are unchanged. The fixture gains the forms through a variable, a list and a function literal and two cases that stay allowed. | The rule matched only a statement built inside the argument list, so SQL built in a variable first passed the gate of ADR 0007; three places in the server did. Taint mode follows the built text through assignments, lists and function literals of the function, and a statement built inline is still found, because source and sink are then the same expression. A rule that refuses every statement that is not a literal was tried and dropped: it reported the pass-through methods of `platform/pg` and other wrappers that build nothing. |
| AUD-MISC-MISC-01/8 | 2026-11-11 | The nine places the widened rule finds keep their code and carry `nosemgrep` with the reason on the line: the queue count and the pending read of the job runtime, the bootstrap of the database roles, and six statements of the test database helper `pgtest`. | Each builds its text from sanitized identifiers (`pgx.Identifier`) and constants only, in positions where SQL takes no parameter (a schema-qualified table of River, `ALTER`, `CREATE`, `DROP` and `COMMENT ON DATABASE`, `GRANT`); every value is passed as a parameter. Checked per place at its source. `pgtest` is not excluded as a folder, so a new statement there is judged again. |
| AUD-MISC-MISC-01/9 | 2026-11-11 | The CodeQL matrix gains `c-cpp` with `build-mode: none` on the Linux runner. The guard `tools/ci/tests/test_codeql_workflow.py` derives the native languages from the tracked sources (`NATIVE_SOURCES`) and allows `c-cpp` only without a build. | The C++ of the Windows runner and of the plugin `device_key` had no analysis but the compiler warnings of its Windows targets. CodeQL infers the compilation units of C and C++ from the source files ([build options of CodeQL](https://docs.github.com/en/code-security/reference/code-scanning/codeql/build-options-for-compiled-languages), retrieved 2026-11-11), so the entry needs no toolchain and no step the guard does not know. Tried with the CodeQL bundle the pinned action uses, in a Linux container over the tracked files: the database is created from every compilation unit, `security-extended` runs and reports nothing. Without the Windows headers the extraction is partial; a Windows runner would see more and is not used, because the job has one fixed runner. |
| AUD-MISC-MISC-01/10 | 2026-11-11 | Swift and Kotlin stay outside the CodeQL matrix as named exceptions (`NOT_ANALYSED` of the guard, each with its reason). The header of `codeql.yml` no longer claims every supported language and names both; a test fails when an exception is in the matrix after all or when no tracked source needs it any more. 23 section 3 gains the row "Native code of a Dart package" with the gates that cover this code and those that do not. | CodeQL extracts Swift and Kotlin only while it watches a build (same source as ruling 9): an Xcode build on a macOS runner and the Gradle build of the Android app, each with the Flutter toolchain, in every pull request, because `codeql.yml` may carry no path filter. That is a second full app build per pull request next to the platform jobs. SonarQube Cloud analyses both languages in every pull request (`quality/sonar/profiles.json`), so they are not without a gate; the false sentence in the header was the defect that could be fixed at once. |
