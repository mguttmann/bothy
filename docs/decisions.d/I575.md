# I575 Secret scope minors of the A1-05 delta red team (2026-11-08)

Issue #575. Normative: [26-builtin-agents.md](../spec/26-builtin-agents.md) 4.2, 5.1 item 3,
R-BA-08, [threat-model.md](../security/threat-model.md) T-BA-02. The rulings settle what the
chapters left open; none is weaker than them. The paid probe turns of 26 5.7 are not part of this
issue (issue 577).

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-I575-1 | 2026-11-08 | No `url`, `args[]` entry or plain `value` of `headers[]` or `env[]` of an MCP server holds `${`; the finding is `invalid` on that pointer, beside `secret_value_not_allowed` when the name looks like a secret. All three writers check it (`definition.ExpandsVariable` in Go, `definition.py` `_expands_variable`, `definition_rules.py` `expands_variable`), held equal by the corpus files `invalid/invalid-variable-expansion.json` and `valid/dollar-lookalikes.json`. A `$` without a following `{` stays allowed. This extends D-A1-02-6 (`url`). `secret_ref` targets are not covered: they are paths the runner reads itself, and a resolved value comes from a file of the operator. | The CLI substitutes `${VAR}` and `${VAR:-default}` in `url`, `headers`, `args` and `env` of its MCP configuration (reproduced with CLI 2.1.288 for header values and URLs; the CLI documentation names all four). The runner writes the values unchanged (`materialize.py` `_entries`), so the only guard of the organization API key was the allow-list environment plus undocumented blanking by the CLI. `args[]` and `env[]` are the same class of value and are refused with it. |
| D-I575-2 | 2026-11-08 | `own_credential_files` stays the three `file:` keys of the runner (`agent_token_ref`, `dpop_key_ref`, `anthropic_api_key_ref`); 26 5.1 item 3 now names them as "credential of the runner" and says why the CLI configuration folder needs no own start check: under `organization` it lies in `<runner.state_dir>/claude-config/`, which the folder may not overlap; under `personal` the host user's CLI folder enters the scope only through a file the operator places there. | The resolver reads only below `<hosted_secrets_dir>/<agent_id>/` by real path and, since D-I575-3, without links and with one hard link; a start check for the `personal` CLI folder would need the runner's environment at config load and would refuse nothing a definition can reach. |
| D-I575-3 | 2026-11-08 | The resolver opens the file one path name at a time from the agent's subfolder (`O_NOFOLLOW`, `dir_fd`), then `fstat` on the open file: more than one hard link is `secret_out_of_scope`; a link met in any step is `secret_unavailable`; both end the run with `mcp_reference_unavailable`. `secrets.read_open_file` applies the checks of `resolve` (regular file, owner, mode, UTF-8) to the open file. 26 5.1 item 3 and the runner README name the operator's duty to keep copies or links of the runner's or the CLI's credentials out of the folder. | Red team of A1-05: a hard link resolves inside by path, and the open after the check followed links (TOCTOU). Both need write access to the folder, which only the operator has, so the check closes the race and the hard link case at the place of the read; a copy placed by the operator is undetectable and stays the operator's responsibility. A legitimate file with a second hard link inside the scope is refused too; the operator stores one name per secret. |
| D-I575-4 | 2026-11-08 | The OpenAPI descriptions of `AgentDefinitionMcpServer.url` and `AgentDefinitionEntry.value` are not changed. | They summarize the rule; 26 4.2 and the corpus are normative (A1-02), and a description change would regenerate four clients for no behaviour change. |
