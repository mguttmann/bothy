| D-M4-31-1 | 2026-10-19 | Histogram path: the app histograms reach the Collector as own cumulative OTLP histogram data points. `metrics.AggregatedSet` (a `sdkmetric.Producer` on the OTLP metric reader) keeps one histogram per name and attribute set with the bounds of signals.md 4.7 and adds the client's bucket counts unchanged; count and bucket counts are exact, the sum is an upper bound (each value at its bucket's upper bound), minimum and maximum are absent. An entry with a bound outside the 4.7 row, a repeated bound or a negative count is discarded; discarded entries count in `bothy.client_metrics.discarded` by reason (added to signals.md). The app clamps a value above the top bound into the top bucket (`le` 10). | ADR 0057 left the path open; one measurement per bucket count would let the SDK re-aggregate and could not keep the counts exact. | D-M4-31-2 | 2026-10-19 | The sender takes the collected entries every `client.metrics.flush_interval` and when the app quits or signs out, sends them with `submitClientMetrics` outside the outbox, split at `maxItems` (200), only while `privacy.client_metrics` is on (off: the entries are dropped, nothing waits). A network error keeps the newest batch for the next interval and drops older ones; any other error drops the batch; `403 feature_disabled` stops the sender until the setting changes. | Telemetry is not user data and the operation is idempotency-exempt; never more than one batch waits (brief Design note 2, 01 11). |
| D-M4-31-3 | 2026-10-19 | The crash target comes from the build configuration only (define `CRASH_DSN`); `BuildBranding.hasCrashTarget` is true when it is set, replacing the stand-in define `BRANDING_CRASH_REPORTS` of D-M4-25-4. Sentry starts only with a target and `privacy.crash_reports` on (default on with a target) and closes when the switch is turned off. | D-M4-31-4 | 2026-10-19 | `tools/ci/dart_sdk_denylist.py` runs in `make licenses` over the root `pubspec.lock` and fails on a package matching an OpenTelemetry, analytics or monitoring pattern; `sentry_flutter` and its Dart core `sentry` are exempt by name, because the lock file has no dependency graph. | ADR 0057 "Confirmation"; brief Design note 6. |
