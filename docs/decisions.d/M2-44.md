| D-M2-44-5 | 2026-10-19 | Relay: the first message of each direction since a grant is the handshake and is not counted; every later message adds its length to `bytes_in` or `bytes_out`, a device message sets the time of the last device frame; when a pairing ends for another reason than the end of its session, the counts are written in one update without event or version; the end path takes the live counts (`RelayControl.Counters` takes and clears them, so they are written once). The deadline of a slot is met by `session.started` before the PTY runs and by the pairing afterwards; on a host that reports `require_local_confirm` the pairing meets the deadline of an opening, and a pairing that ends before `session.started` gives the slot a new deadline of `terminal.open_timeout`. | D-M2-44-6 | 2026-10-19 | The host service refuses a handshake by closing its data connection with `4101` (`token_expired`, `token_replayed`) or `4104` (every other detail of 24 5.3) and the `close_detail` as close reason; the relay hands the same code and reason to the device; an opening, and a started session refused with `4104`, end `open_failed` with the detail; a started session refused with `4101` is `detached`.
