| D-M4-38-3 | 2026-10-26 | The generator `clientstack/termgen` (Go, built for the Docker host's architecture and copied next to `bothy-host`, owner root, mode 0755) runs as two `command` profiles of the host service: `termgen-rate` writes `TERMGEN <seq>` lines of 64 characters, one per 100 ms on an absolute schedule, 1100 lines; `termgen-burst` writes 16 chunks of 256 KiB in 64 KiB writes, each followed by `TERMGEN-END <chunk> <bytes>`, and waits for a typed line feed before each chunk. "Full speed for a fixed byte count" is kept per chunk; the acknowledgement bounds what is in flight, because the terminal has no flow control toward the PTY and the host's send queue (256 messages) and the relay buffer disconnect a reader that falls behind (24 6.2, D-M6-18-9), so an unacknowledged burst larger than those buffers would measure the buffers and fail on a slow machine. | Brief Design note 2; deterministic tests. |
| D-M4-38-4 | 2026-10-26 | Measurement points: frame to paint per line of `termgen-rate` from the decrypt of the `data` frame that completes the line (`TerminalPerfProbe.dataDecrypted`, `Timeline.now`) to the end of the rasterization (`FrameTiming` `rasterFinish`) of the first drawn frame whose visible text shows the line; the drawn frame is the post-frame callback after new output (`frameDrawn`) and pairs with the frame timing whose build ended last before it, within 50 ms (a larger gap drops the sample instead of guessing); p95 by nearest rank over at least 1000 lines. Throughput: per chunk from its first decrypted byte to the rasterization of the frame that shows its end line; all decrypted bytes over the sum of the chunk times, so the acknowledgement round trips do not count. "Without backlog": the renderer writes each decrypted frame into the model at once, so its backlog is the output decrypted since the last drawn frame (reported as `terminal_backlog_max_bytes`); a queue that grows lies before the decrypt and ends in a disconnect by the host, so the throughput counts only when the burst ran without a detach. Both values and the generator settings go to `build/perf/summary.json`; `PERF_SUMMARY_MERGE=1` (the terminal part of `make perf-desktop`) joins them with the chat targets, the chat part starts a fresh file. | Brief Design note 2; 15 19; D-M4-34-5. |

| D-M4-38-6 | 2026-10-26 | Two product defects the terminal E2E found are fixed with tests, as M4-34 did (D-M4-34-4): the pairing wizard of M4-37 confirmed with the version it read on "Next", but the host service reports while the host waits for its confirmation and each report raises the version, so "Confirm" failed with `412 version_conflict` (with the default `host_service.credential_check_interval` after a minute on step 3); it now reads the host again and resends the same answers, at most `confirmVersionAttempts` times, as long as the host still offers every chosen session user, else the conflict is shown. And the exit code did not reach the tab on the real stack: the server closes the stream with `4100 process_exited` right after the session ended, and the `exit` frame did not arrive first (in the E2E runs never), so the tab showed "ended" instead of the code. Depending on the order, the close came through the stream (`4100`) or first through the host events (`terminal_session.changed`), and both paths ended the tab. Both now go through one place of the controller (`_endWith`): it keeps `exited` when the frame came, and otherwise reads the session (`getTerminalSession`, a new method `getSession` of the port `TerminalServerApi`, in the app and the console) and shows the `exit_code` the server stored with the end (15 23.2 item 5); without a code it stays ended. Why the frame is lost (the host's send queue or the relay's device queue is dropped when the session ends) is not fixed here; any output written right before the end may be lost the same way, which the report names for the server and host. Each was reproduced first (`packages/admin_ui/test/hosts/pairing_test.dart`, `packages/terminal_ui/test/controller_flow_test.dart`). | Brief fixed requirement 11 (the real path); owner rule: Majors of the own work are fixed in the same ticket. |
