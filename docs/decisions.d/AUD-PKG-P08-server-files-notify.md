# AUD-PKG-P08-server-files-notify Server findings of the audit of 2026-11-11 in files, notify, terminal, apps and importer

Work package of the audit of 2026-11-11 for the modules `files`, `notify`, `terminal`, `apps`
and `importer` of the server. Each finding was read again on the current `main` first; findings
already fixed or decided since the audit are closed with their evidence and have no row here.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-P08/1 | 2026-11-23 | This ruling supersedes the "no new index" of D-M3-08-15 for these two reads. `files` gets the partial index `(deleted_at, id) WHERE deleted_at IS NOT NULL` (migration 00123) for the catch-up step `DeletedRows` and the gauge `PurgeBacklog` of `files.cleanup_pending`, held by `TestHotPathIndexes`. Steps b and c (`UnattachedCandidates`, `FailedRowCandidates`) get no index. Supersedes the "No new index" part of D-M3-08-15 for the deleted rows. | The deleted rows are few and leave the index with their purge, so the index is small and both reads of every run stop scanning the whole table; an index for steps b and c would cover most rows and needs a measurement on a large instance first (srv-files-adapters-7, srv-files-core-7). |
| AUD-P08/2 | 2026-11-23 | `ExportPackages.Store` inserts the `gdpr_export` row `pending` before it writes the object and sets it `complete` (`CompleteExportFile`) after length and SHA-256 match; `Open` hands out only a complete package; a refused package is marked deleted through `Delete` (redaction and `files.purge_objects`); step c of `files.cleanup_pending` deletes a package left `pending` after `file.failed_row_ttl`. Not built: a maintenance command that compares storage and rows. Tests: `TestExportPackagesRefused`, `TestCleanup_StaleExportPackage`. | An object written before its row could stay in storage with personal data and no row that names its key, and the module never lists the storage (D-FI-11) (srv-files-core-8). With the row first every object of a package is reachable by the purge; a storage scan is a new concept. |
| AUD-P08/3 | 2026-11-23 | The scan pass completes an open S3 multipart upload (`completeOpenUpload`) before it pings clamd; the spec asks for a lifecycle rule age longer than `file.upload_session_ttl`. Not built: an end state for a pass whose source object or upload is gone (it still retries; deferred with the reconciliation of hanging files). Test: `TestScanPassCompletesMultipartBeforePing`. | During a clamd outage every confirmed S3 upload stayed an incomplete multipart upload that the recommended lifecycle rule may abort (srv-files-core-2); completing it first costs one `HEAD` per pass of an S3 upload and changes no delivery rule, because the file stays pending until the scan. |
| AUD-P08/4 | 2026-11-23 | 12 5.2 no longer promises that the uploader sees the reason of a failed or blocked upload: the owner sees the malware reason in the audit log, the API does not deliver the session's `failure_reason` yet (planned). | Delivering the reason needs a new member of `File` in openapi.yaml, a contract test and failure texts in all clients, beyond a server audit package (fn-files-voice-3); the spec now states what is built. |
| AUD-P08/5 | 2026-11-23 | The local signals of `cluster.mode = single` (`terminal.host_close`, `terminal.session_open`) are handed to the handler through `txn.AfterCommit` of the outermost unit, with a context outside the finished unit, as `sendReady` already did; outside a unit they run at once. Test: `TestUseCasesStageSignals/outer_unit`. | With an `Idempotency-Key` the whole request runs in one unit, so the handler closed the control connection before the outer commit and a failed commit left the row `active` while the host had stopped (srv-terminal-5); the same rule as the `NOTIFY` of several nodes keeps one behaviour for both modes. |
| AUD-P08/6 | 2026-11-23 | Not built: giving the live relay counts back when the unit of an end rolls back or is retried (srv-terminal-7). `finish` keeps taking them inside the unit. | The unit of work has only `AfterCommit`, no rollback hook, and reading without taking races with the relay's own progress writes (double count); both are a design change of the relay counters (D-M2-46-22), not a small fix. |
| AUD-P08/7 | 2026-11-23 | Not built: switching the control connection and `Hub.holdOpen` to the injected `app.Timers` and clock (srv-terminal-11). | Production runs real timers and the system clock on both paths, so behaviour does not change; the switch moves the tests of 4113, 4009 and the probation to the fake clock and belongs with the relay state work of srv-terminal-3. |
| AUD-P08/8 | 2026-11-24 | This ruling supersedes the lease length of D-M2-26-3: an attempt of `apps.webhook_deliver` takes a lease of twice `webhook.delivery_timeout`, and the job timeout is the same, so the lease and the job outlast the send limit. | With a lease equal to the send limit, the lease wake-up could claim the head again while a send that hung until the limit was still recording its result, so its backoff and the disabling of the subscription were lost (srv-apps-billing-1). |
