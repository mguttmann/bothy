# FIX-delete-releases-binding The project binding of a deleted forum gives its folder free

Fix of a Major found in operation: a project forum deleted without the folder box
kept its project binding after the purge, so its folder could never be bound to a new forum
(`putProjectBinding` answered `409 conflict` "bound to another forum", and
`deleteProjectBinding` on the deleted forum `409 conflict` "the channel is archived"). It closes
D-DEL-SRV-10 (e) of [FEAT-delete-spaces-chats.md](FEAT-delete-spaces-chats.md). Design note:
[delete.md](../design/delete.md) D-DEL-17. Normative text: 03 `project_bindings`, R-DM-57,
R-DM-56; 07 4.5 point 2 and 4.5a point 7; 02 `messaging.purge_deleted`; 09 18.15.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-DEL-REL-1 | 2026-11-02 | A deleted forum keeps its binding during the undo window and releases it when the deletion is final: the purge of the forum or of its space sets `project_bindings.released_at` in the same transaction; the row stays. The unique index on `lower(workspace_ref)` covers only rows with `released_at` NULL, and `BoundProjectFolders` (R-DM-56) leaves released rows out. Release at delete with a re-binding on restore was not chosen. | A restore within the window always gets its binding back, because nobody can take the folder meanwhile, so there is no "folder taken" case to explain; the cost is that a new forum can take the folder only after the window plus at most one `chat.delete_purge_interval`. The row keeps the folder outcome readable for `getChannelDeletion` (D-DEL-15). |
| D-DEL-REL-2 | 2026-11-02 | A binding whose folder move is still `requested` is not released at the purge; the runner's outcome (`trashed` or `refused`) releases it in the transaction that stores the outcome. | A new forum must never take a folder the runner is about to move to the trash. |
| D-DEL-REL-3 | 2026-11-02 | `deleteProjectBinding` is allowed on an archived or deleted forum and on a forum of an archived space (still `channel.project.bind`: owner with step-up); `putProjectBinding` there stays `409 conflict`. On a deleted forum the row goes with a requested folder move, and `channel.updated` carries `deleted_at`, so no client reads it as an undo. This replaces the DELETE part of D-M2-03-7. | Giving a folder free changes no frozen history; it is the owner's way out when a runner never reports the outcome of a folder move. |
| D-DEL-REL-4 | 2026-11-02 | The repair of bindings purged before this fix is the job `messaging.purge_deleted`: every run (also the one at worker start) first releases every binding of a purged forum or of a forum of a purged space that is not released and has no requested folder move. No data change in a migration. | upgrade.md rule M7 forbids backfills in migrations; the job runs at every start, so the first start of the new server frees the folder of the forum deleted in operation. |
| D-DEL-REL-5 | 2026-11-02 | The new index is built CONCURRENTLY next to the old one and takes its name `project_bindings_workspace_ref_key`, so the conflict mapping of this and of the previous server version stays the same. No event and no audit entry for a release. | upgrade.md rules M1 and M4; the release has no actor, like the purge (D-DEL-9). |
| D-DEL-REL-6 | 2026-11-02 | The runner needs no change: a deletion takes the forum out of its served channels (`access.changed`, `channel.archived`), and a new binding reaches it with `agent.config_changed`; a scenario test holds that the new forum is ready with an ok folder check, not `contains_other_project`. | 09 18.1 already reloads the served channels on these events. |
| D-DEL-REL-7 | 2026-11-02 | Minors, open for the next run in this area: (a) during the undo window, and while a folder move waits, `putProjectBinding` of the same folder still answers the generic "bound to another forum" without saying that the holder is a deleted forum; (b) the OpenAPI still lists `409` for `deleteProjectBinding`, which now has no 409 case; (c) unbinding a deleted forum while its runner moves the folder ignores the later outcome, which is then not audited. | No reproduced harm; (a) and (b) are wording, (c) needs a runner that reports after the owner gave up waiting. |
