# M2-43 Control connection between host service and server

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M2-43-1 | 2026-10-18 | On `hostControl` an unknown op, a server op sent by the host, a second `identify`, a binary frame, invalid JSON and a frame over `sync.ws_max_frame_bytes` (reason `frame_too_large`) close with `4002`. | `hostControl` names no `4001`; every one of these is a frame the server cannot take in this order. |
| D-M2-43-2 | 2026-10-18 | The proof of `identify` is a compact JWS with `alg` exactly `EdDSA`, `typ` exactly `host-auth+jwt` and `kid` the RFC 7638 thumbprint of the login key (`hosts.auth_jkt`), over exactly the claims `challenge`, `host_id` and `iat`; `iat` lies in [`hello.server_time` minus `auth.clock_leeway`, now plus `auth.clock_leeway`]. An unknown host, a host in `pairing` or another `kid` closes with `4110`; every other failure with `4113`. | The `kid` lets the server tell a replaced key ("run `pair` again") from a forged signature; a closed claim set and a short `iat` window keep a proof from being reused outside its exchange. |
| D-M2-43-3 | 2026-10-18 | Audit entries of `host.connect` have empty actor columns and name the host as the resource; a denial for a host without a row has no resource. | Audit actor IDs point to principals with a row; a host is no principal row (07 section 3). |
| D-M2-43-4 | 2026-10-18 | A `report` whose session users changed is the rights change `host.connect` on the host with the people of its valid assignments; its session users go through M2-40's `ApplySessionUserReport` (next `permission_version`, sessions of vanished names end with `access_revoked`, one `host.updated`), the other `reported_*` columns in the same unit. The server-host flag raises no rights version; when it turns on, the sessions of people who are not active owners end with `access_revoked` in the same unit. | Permissions `no` of `host.connect` (05 4.14) does not exempt a report from 03 4.3, which counts the session users as rights state; 03 does not list the flag, which SR10 reads per decision through `authz.HostSource`. |
| D-M2-43-5 | 2026-10-18 | `Host.connected` and `host.presence_changed` mean "usable for sessions": true from the first applied `report` after `ready` until the control connection ends. | A client that retries after `409 host_unavailable` on `connected: true` must not race the first `report`, before which the server sends no `session.open`. |
| D-M2-43-6 | 2026-10-18 | A live duplicate of a host in `confirming` puts it back into `pairing` with its keys dropped (the fallback of M2-41 with a fresh code that is never shown, `host.updated` with `key_changed`); both connections close with `4112`. The life cycle draws `confirming --> pairing` for it (24 3.1, 3.4). | 03 allows `disabled` only after the confirmation; for an unconfirmed host `pairing` without keys is the only state from which only a new pairing helps. |
| D-M2-43-7 | 2026-10-18 | The deny reason `host_duplicate_connection` (decision `forbidden`) joins 07 4.1; a live duplicate writes one deny entry `host.connect` with it and `code: duplicate_connection`, a dead older connection that is replaced one allow entry with `code: stale_connection_replaced`. Until M2-47 the probe runs within the node of the older connection. | The closed list of reasons had no reason for a denial with valid credentials; both outcomes of 24 3.4 must be traceable. |
| D-M2-43-8 | 2026-10-18 | Every session listed in `live_sessions` that is closed for this host, unknown or of another host gets `session.close` right after `ready`: the stored `close_reason`, else `access_revoked`. | A PTY the server no longer allows ends at the next login (24 8.3 "instructs the host service"), fail closed for IDs the server does not know. |
| D-M2-43-9 | 2026-10-18 | Session user names enter the audit details of `host.connect` only as lists of the value kind `auditing.OSUserNames` under the members `hd6_users`, `hd9_users`, `hd10_users`, `hd11_users`, `session_users_added` and `session_users_removed`, each name in the form of `host_session_users.os_user`; those members take nothing else (19 SEC-AUD-5). | M2-39's `OSUserName` is accepted only under `os_user`; a closed set of members with their own form keeps free text out of the details while naming the accounts T-TM-14 needs. |
| D-M2-43-10 | 2026-10-18 | The host service may report only `client_closed`, `process_exited` (with `exit_code`), `idle_timeout`, `detach_expired`, `open_failed` (with any `close_detail`) and `host_policy_violation` (with `subscription_login_detected`, `helper_untrusted` or `shared_location`); `close_detail` exactly with the last two, `exit_code` only with `process_exited`. | The other reasons are decisions of the server (revocation, limits, host state); a host that reports them is wrong or forged and gets `validation_failed` without a change. |
| D-M2-43-11 | 2026-10-18 | The server closes with `4009` when no `heartbeat` arrived for `terminal.host_heartbeat_interval` times (`terminal.host_heartbeat_miss_limit` + 1); `heartbeat_ack` carries `jwks` whenever the set of purpose `terminal` changed since the last set sent on the connection. | The extra interval absorbs the first delay, as M1-64 rules for the gateway; a scheduled rotation publishes the `next` key `agent.jwks_max_age` before use, so a long-lived connection learns it in time (limit after an emergency rotation in 24 5.3). |
| D-M2-43-12 | 2026-10-18 | When a control connection ends without a state change of the host (not `4110`, `4111`, `4112`) and no newer connection of the host is registered on the node, its `active` sessions become `detached`; at shutdown a stop step of `PhaseConnections` detaches and closes every connection with `4013`. | 24 6.2: the PTYs keep running until `terminal.detach_grace`; a close that comes with a state change already ended the sessions. |
| D-M2-43-13 | 2026-10-18 | The host service reacts per close code: `1000`, `1001`, `4000`, `4002`, `4009`, `4014`, `4113` and any unknown code reconnect with exponential backoff and full jitter between `host_service.reconnect_backoff_base` and `host_service.reconnect_backoff_cap`, reset after `ready`; `4013` after a random delay below the base; `4008` after `retry_after`, else the cap; `4111` ends all PTYs and waits the cap; `4110`, `4112` and `4114` end all PTYs and stop with exit code `78`. | The codes of 24 13 name the client action; `78` is the one exit code no service definition restarts (D-M2-42-14). |
| D-M2-43-14 | 2026-10-18 | On a refused start the host service logs in through the same `Control` with empty `live_sessions`, retries for at most `host_service.reconnect_backoff_cap` in total (then `startup.ErrUnreachable`, and the stored declaration decides), sends exactly one `report` and closes with `1000` over the same connection. | D-W-91: the console must name the accounts of a refused start; a separate report connection would be a second login with the same keys. |
