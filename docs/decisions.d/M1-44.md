| M1-44/5 | 2026-10-13 | A found but revoked or expired token is not refused by the Authenticator: it returns the actor of the token's principal with the token id and `CredentialInactive` (new field of `kernel/actor.Actor`), and `authorize` refuses it in `check_active` with `401 unauthenticated` and the audit reason `token_revoked`. | M1-44/6 | 2026-10-13 | Revoking a token is a rights change: `revokeToken`, `Tokens.Revoke` outside a unit and every caller of `RevokeAllForPrincipal` raise `permission_version`; `Revoke` inside a unit that is no rights change and `RevokeAllForPrincipal` outside one fail with `internal_error`. `access.changed` is appended only where the M1-29 path computes a difference; a token changes no grant, so a revocation appends none. | authz caches token liveness with the rights snapshot per version (M1-28/12); without the new version a revoked token would stay live in the cache of every process. 05 marks `token.revoke` as a rights change; the brief says "as the path computes it". |
