| D-TEAM-11 | 2026-11-21 | A member's reply is mirrored and handed on only when the run it answers was started and fed only by active owners (`runs.triggered_by`, the authority of a team input, the person of every follow-up of the run and the principal of every interaction with the run's components; the interactions were added after the red team's round 3), checked in the job (since red team round 4 against the record of D-TEAM-12, not against the input rows); since red team round 7 the job reads the run of the reply from its link in `run_answers` (D-TEAM-12), which exists only when the reply was sent with the invocation token of that run; the `run_id` the agent names is never passed on. | D-TEAM-12 | 2026-11-21 | Who fed a run is recorded when an input is stored or given to the run, in the append-only table `run_feeders` (R-DM-63), and the check of D-TEAM-11 reads only that record: database triggers on `runs`, `run_followups` (insert and move to the follow-on run) and `interactions` record the stored inputs, `runs.Delivery.Prepare` records the person of every allowed delivery into a run (`domain.FeedSourceOf` for every invocation-bearing event type, so also a control command and a wake input), and the run context records the writers of the messages it gives the run, every element of any origin and author (`domain.ContextFeeders`: the authority of a team input, the author of a person's message, the whole record of the run an agent's message answers, linked in `run_answers` (R-DM-64, migration 00109) by the acceptance for every checked answer whose request carried the invocation token of exactly the named run (`actor.ActingFor` bound to it, passed as `MessagePosted.ActingRunID`) and for every live box anchor the server writes, NULL for every other message such as an agent's note written outside a run of its thread or without the token of the run it names, an agent's message of any kind (answer, team copy, card) edited after it was written, whose edit no run vouches for, or an app's; a live box anchor cannot be edited (`updateMessage` answers `403`, like a system line); since red team rounds 5 to 7), plus what the run takes over with its session: in mode resume the record of every earlier run of the session row in the thread, in mode bind NULL (a bound session holds history no record names). `bothy_app` may only read and insert the table; a run without its trigger row (older than the record) and a recorded input that speaks for no person fail. Tests: the round 2 to 4 reproductions, a test per source of `run_feeders` that fails for a source without a case, a test that every invocation-bearing event type has a source, a table test of `domain.ContextFeeders` over every author kind, the round 5 reproduction (another agent's note in the context), the round 7 reproductions (a reply and a note naming a concurrent owner run without its token, a reply with the token of another run, an edited live box anchor), the round 6 reproduction (the member's own note written in a run a non-owner started in another channel), an own answer of an earlier non-owner run, an own answer of an earlier owner run that still hands on, the same answer edited in a run a non-owner started elsewhere, the session carry-over in modes resume, new and bind, down tests of 00108 and 00109, and a schema test that every column referencing `runs` is classified as an input with its trigger or as no input. | The red team reproduced the same class three times, each time through a row the check derived the persons from: a revoked grant (round 2), an interaction (round 3), an interaction whose card was deleted (round 4). Round 5 found the context recording an allow list (persons and team inputs) that skipped another agent's message, and round 6 the exception for the run's own agent, whose text a non-owner can steer in another channel. Both are one class: text an agent wrote carries no person, only the run that wrote it does. So an agent's text now speaks for the record of the run it answers and for nobody without one, the session speaks for the record of its runs, and every author kind or origin without a rule is recorded as NULL and refused by default. Recording at the moment of the input and never deriving from deletable rows closes the class at one place; the triggers make it impossible to store an input without recording it. Not covered: what the agent reads on its own through the API during a run (a message of a person with a grant that is no input of the run), and what the agent's runtime keeps outside the session row of the thread (its memory files or profile, written in runs elsewhere), including two runs of the same agent active at once. Since red team round 7 the attribution is bound to the token: an agent steered by a non-owner in another run named a concurrent owner run in `run_id`, and the answer check (same agent, same thread, run active) accepted it; now such an answer is accepted without a link, so it speaks for no person in a later context and is refused in a team channel. The Hermes adapter and the Claude Code runner send their answers through the SDK outbox, which binds every entry to the newest token of its own run (`Outbox` `token_for`, `Adapter._token_for_run`); other runners must do the same, else their answers never hand on (fail closed). The binding is only as strong as the separation of tokens inside the agent's runtime: the SDK keeps the tokens of every run of the process in memory and in its inbox store (mode 0600, the runner's user), so a runtime that lets a steered turn read those files or that process could take the token of a concurrent owner run; this belongs to the documented limit of what the agent's runtime keeps outside the server. Fail closed by design: a message without a person or a run (an agent's note outside a run of the thread, a command reply without a run, a wake note, an app's post) refuses every later run that reads it in its context window until it leaves the window (an owner can delete it), a session that carries a non-owner's run refuses until the owner resets it (`/new`), and a bound session refuses until `/new`; the channel configuration that rides every turn (the channel prompt and skills of the home channel, 09 17.6, set by a person with `manage`, R-AZ-09, and the profile's own bindings), which is no input of a run and records no editor: such a person reads the home channel, so the readers rule refuses while the grant lasts, and an owner who revokes a `manage` grant on a home channel checks its prompt. Checked and recorded by the author: attachments (only the author's own uploads can be attached) and their transcripts, a person's edits (only the author edits; an edit of any message whose author is no person records NULL), the backfill windows, and team copies (the authority); the readers rule keeps non-owners out of work threads. |
