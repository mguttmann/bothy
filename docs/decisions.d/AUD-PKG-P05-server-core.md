# AUD-PKG-P05-server-core Server core findings of the audit of 2026-11-11

Work package of the audit of 2026-11-11 for the core of the server: `internal/platform`
(jobs, pg, otel, testkit, httpserver), `internal/instance`, `internal/status`, `internal/stats`,
the retention and index paths of billing, authz, notify, apps and agents, `sqlc.yaml`,
`cmd/bothy`, `cmd/bothy/importtool`, `cmd/bothy-backupd` and the API generators. Each finding
was read again on the current `main` first; findings already fixed or decided since the audit
are closed with their evidence and have no row here.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-P05/1 | 2026-11-23 | `pg.PurgeEach` deletes in transactions of at most 32 candidates (`purgeChunk`), each candidate in its own savepoint as before; an error rolls back only its own transaction, earlier ones stay committed and count. Test: `TestPurgeEach_ShortTransactions`. | One transaction of up to `retention.batch_size` savepoints overflowed the backend's cache of 64 subtransactions and made other sessions read `pg_subtrans` (data-layer-4). Skipping a candidate that times out is not built. |
| AUD-P05/2 | 2026-11-23 | `UnitOfWork` checks the context before COMMIT (an ended context rolls back as before) and then sends COMMIT with `context.WithoutCancel`, bounded by `database.statement_timeout`, like the rollback. Test: `TestUnitOfWork_CancelDuringCommitStillCommits`. | A COMMIT aborted in flight could leave a durable transaction while `Do` reported an error and skipped `txn.AfterCommit` (srv-platform-data-16). |
| AUD-P05/3 | 2026-11-23 | `bothy.outcome` of a job attempt is `cancelled` only for a canceled context with a cancellation error (stop, cancellation); River's job timeout is `failed`. Test: `TestOutcomeOf_TimeoutIsFailed`. | A timeout uses up an attempt like any failure; as `cancelled` it was invisible to a failure rate (srv-platform-data-9). |

Not built: an alert rule per job kind, and the JSON logger for `bothy-backupd`. | River's error line lost kind and cause to the allowlist handler and its routine lines filled the worker log (errors-observability-2, srv-platform-data-2, errors-observability-11). |
