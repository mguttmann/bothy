# A1-06 Templates and their gate (2026-11-06)

Brief: [A1-06-agent-templates.md](../briefs/A1-06-agent-templates.md). Normative:
[26-builtin-agents.md](../spec/26-builtin-agents.md) 7, 9 and 14, 07 2.13; design notes D-A1-14 to
D-A1-16 of [builtin-agents.md](../design/builtin-agents.md). The rulings settle what chapter 26
leaves open; none is weaker than the chapter.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-A1-06-1 | 2026-11-06 | Person names: the gate checks capitalized words in a person position: after a cue word (`for`, `by`, `from`, `to`, `with`, `ask`, `tell`, `thanks`, `thank you`, `dear`, `hi`, `hello`, `hey`, `cc`, `ping`, `contact`, `assign to`, `assigned to`) and the names joined to it by a comma, `&`, `and` or `or`; the value of a field line such as `Owner:`, `Author:`, `Reviewer:`, `Attendees:`, `From:`, `To:` or `Cc:`; and an `@` mention. A word other than Alex, Sam and Robin is a finding unless it is on the short list of capitalized non-names (`NON_PERSON_WORDS`, weekdays, languages, tool names). A name in any other position, a lower-case name and a name that is also a common word stay unseen; review and the private deny list hold them. Frontmatter author fields cannot occur: any `SKILL.md` key other than `name` and `description` and any `template.yaml` key outside the schema is already a finding. | A list of common first names is no proof and would flag ordinary words; positions keep the false findings low enough that the shipped texts pass without exceptions, and the limits are stated instead of hidden (brief design note 2). |
| D-A1-06-2 | 2026-11-06 | CI trigger: `make templates-check` runs in the job `gates` of `ci.yml` (and of `build-verify.yml`), which runs on every pull request, so every change to `templates/`, `tools/templates/` or `tests/agent-definitions/` runs it; in the component map `tools/templates/` is a tool folder without component, and `templates/agents/` selects `server`, whose embedded copy `make codegen-check` holds equal. | The gate is Python only and takes about a second, so a path filter would save nothing; the parity test of the gates jobs requires every target of `make gates` in one job. |
| D-A1-06-3 | 2026-11-06 | Topics and tool classes of the shipped templates: `writing-helper` (`chat`, no MCP server), `code-reviewer` (`scoped`, works on the files of its agent folder, no MCP server), `research-summarizer` (`scoped`, one `http` MCP server `https://search.example.com/mcp` with the header `Authorization` as `secret_ref` `env:SEARCH_MCP_TOKEN`), `meeting-notes` (`chat`, no MCP server). None uses `stdio`, so none needs `host`. | The four example topics of 26 7.5; the lowest class that does the job, and one template shows how a template names a secret without holding it. |
| D-A1-06-4 | 2026-11-06 | Schema `agent_template.v1`: `name`, `description`, `version`, `tool_class_wish` and `skills` are required; `model_hint` (becomes `settings.model`), `required_secrets` (environment names, unique) and `mcp_servers` are optional; no other key. `name` and `description` are one line of display text; `version` matches the pattern of `origin.template_version`. A `secret_ref` in a template is `env:<NAME>` with `NAME` in `required_secrets`. YAML with a key twice in one mapping is refused (Go's decoder refuses it too). | 26 7.1 lists the members without saying which are optional; a template without MCP servers needs neither list. A `file:` reference would be an absolute path of one host, and an undeclared name would leave the operator guessing which secret to provide. |
| D-A1-06-5 | 2026-11-06 | The draft of a template is checked with the rules of 26 4.3 for its `tool_class_wish` (`chat` when the wish is no class), with the limits of `tests/agent-definitions/limits.json`, the defaults of the server keys. The skill body is the text after the closing frontmatter line. | The wish preselects the class of the preview (26 4.4 item 1); a template that only passes above its wish would fail at creation. |
| D-A1-06-6 | 2026-11-06 | The Python rules of 26 4.3 (`tools/templates/definition_rules.py`) are a port of the Go validator and are held equal by running the whole corpus `tests/agent-definitions` in `test_definition_rules.py`; the Go loader of the server is held to the gate by running the gate's failing fixtures of the rules `layout`, `schema`, `frontmatter` and `definition` (`TestGateFixturesOfTheSchemaAreRefused`). The content rules (`host`, `path`, `ip`, `person`, `secret`, `denylist`) run only in the gate. | One conformance set for every writer (D-A1-02-8); a private template is the operator's data and is checked for its structure and safety, not for white-label terms. |
| D-A1-06-7 | 2026-11-06 | The deny rule of the gate matches each template file under its path `templates/agents/<slug>/...`; the repository-wide scan skips the gate's failing fixture of that rule (`@exclude-path: tools/templates/tests/fixtures/denylist/*` in `tools/denylist/generic.rules`). The fixture of the secret rule uses this product's token format with the `EXAMPLE` marker, which gitleaks allows and the gate refuses. | A fixture that must fail a deny rule would otherwise fail `make denylist` of the repository; the gate never sees the fixture path, so the exclusion cannot hide a template. |
| D-A1-06-8 | 2026-11-06 | Names that differ from the brief: the worktree branch is `feat/A1-06-v4` (launcher); the generated copy and its `go:generate` directive live in `services/server/internal/agents/adapters/templates/` instead of `internal/agents/templates/`, because go-arch-lint attaches only the layers of a module and refused an unattached package that `wire` imports; the loader is `internal/agents/adapters/templatefs` (it reads YAML, a vendor of the adapters); the generator is `services/server/tools/templatecopy`. A skipped private template is logged with the attribute `bothy.reason` only (the log handlers keep only the keys of signals.md 5.3), so the log names the reason and not the slug. | D-W-100: follow the code and the module rules; no dependency names differ. |
