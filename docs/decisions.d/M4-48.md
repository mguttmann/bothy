# M4-48 Copy single blocks of a message

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M4-48-1 | 2026-10-29 | Every code block (fenced and indented) and every quote block copies exactly itself. On the desktop (density `comfortable` or `compact`, macOS and Windows alike) through a text button at the top right of the block, "Copy code" or "Copy quote", always visible, a button for keyboard and screen reader and kept out of the system selection; a click on the text copies nothing. On the phone (density `touch`) the whole block is one tap target without a button. The renderer tells the two apart by the density, as the sidebar rows do, not by the platform. | Owner request 2026-10-29 (01 6.12, R-PR-25). The desktop already had "Copy code" on code blocks; a text button needs no new icon in the token build and reads the same in both languages. |
| D-M4-48-2 | 2026-10-29 | Trailing line break rule of a code block: the copy is the text between the fences with LF line breaks; only the line break that ends the last content line is dropped. Blank lines at the end stay, an unclosed fence copies to the end of the message, an indented fence removes only its own indentation, tabs and every other character stay as the parser gives them. | The rendered block already drops that one break; a command copied with a final line break would run on paste in some terminals. Keeping trailing blank lines is what "byte exact" means for the rest. |
| D-M4-48-3 | 2026-10-29 | A quote copies without its `>` markers. Plain text: source line breaks kept, inline Markdown as its text, blocks separated by an empty line, list items with "- " or their number, tasks with "[x] " or "[ ] ", code blocks raw, table cells separated by a tab, a nested quote as text of its parent. HTML: the same content with emphasis, code, lists, tables, headings and the `https`, `http` and `mailto` links; inactive links, internal paths and images become text, so a paste loads nothing and has no link that only works inside the app. The HTML is not wrapped in a `blockquote`, because the plain form drops the quote too. | 01 6.12 item 4; SEC-OUT-1 and SEC-OUT-2 hold for what leaves the app as well. |
| D-M4-48-4 | 2026-10-29 | Rich text goes through an own method channel `bothy/clipboard` of the four runners (`write` with `text`, `html` and on Windows `cf_html`): NSPasteboard with `.html` and `.string` (macOS), one UIPasteboard item with `public.html` and `public.utf8-plain-text` (iOS), `ClipData.newHtmlText` (Android), CF_UNICODETEXT plus the registered format "HTML Format" (Windows). Dart builds the CF_HTML document with its byte offsets (`windowsClipboardHtml`), so the offsets are unit tested. A missing or failing channel falls back to plain text through Flutter's clipboard; a code block always goes through Flutter's clipboard, which holds plain text only. | Flutter's `Clipboard` has no HTML flavor and the `pasteboard` dependency only writes files and images; a channel per runner is the pattern of `bothy/deep_links` and `bothy/start_at_login`. The macOS and Windows runners also answer `readHtml`, used by the platform test. |
| D-M4-48-5 | 2026-10-29 | On the phone a long press on a message opens the message menu (`MessageTile.longPressMenu`, set from the form factor); a tap stays with the content. Before this ticket the phone had no way to reach the menu, because the hover bar needs hover or keyboard focus. | The owner's flow "long press keeps the message menu with Copy text for the whole message" needs the menu on the phone; a tap is now the block copy. |
| D-M4-48-6 | 2026-10-29 | The message history offers no system text selection today (no `SelectionArea` around messages); this ticket does not add one. The copy targets are built so that a selection keeps working where a view offers one: on the desktop the buttons are `SelectionContainer.disabled` and a drag selects across blocks (widget test), on the phone the block claims only the tap, so a long press and drags stay with the widgets around. | Adding selection to the history changes its long press and focus behavior on every platform and is outside this ticket; the owner's requirement is that selection is not broken, which the tests hold. |
| D-M4-48-7 | 2026-10-29 | The confirmation is the snack bar "Copied" (`messageCopied`, the text of "Copy text") of the nearest scaffold; on the phone with `HapticFeedback.lightImpact`. Without a scaffold (a bare dialog, a test) the copy happens without the snack bar. Platform coverage: the widget tests run each desktop behavior under macOS and Windows and each phone behavior under iOS and Android; the integration test `integration_test/copy_blocks_test.dart` runs on the real clipboard in the CI jobs `apps-macos` and `apps-windows` (`platform-tests.json`). | One confirmation for every copy of the history; no GUI test on a maintainer's machine. |
