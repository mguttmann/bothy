| D-M7-17-6 | 2026-10-23 | Presence writes and TTL (Design note 2): `app.PresenceWriter` flushes every `cluster.presence_flush_interval` in one transaction: the upsert of one row per counted live connection of the hub (gateway session, person, device, focus, idle) with `updated_at` = now, the delete of the node's rows whose connection ended and the delete of every node's rows older than `cluster.presence_ttl`; its stop step after the connections closed deletes all rows of the node. A failed write is logged (`gateway presence not written, retrying at the next interval`) and counted (`bothy.gateway.presence.write_failures`) and never blocks a connection. The reader keeps, per person, the newest fresh row of each device and ignores rows older than `cluster.presence_ttl`. A configuration check requires `cluster.presence_ttl` above twice `cluster.presence_flush_interval`; defaults `2s` and `10s`. Place: `internal/gateway/app/presencewriter.go`, `adapters/postgres/presence.go`, `internal/wire/configkeys_cluster.go`. | Changes of focus or idle reach the worker within one interval without a write per op; one upsert of all rows brings back rows lost with the `UNLOGGED` table after a database crash; a node that crashed stops refreshing, so its rows age out without a coordinator. |

| D-M7-17-10 | 2026-10-23 | Agent presence across nodes is decided from the stored row (the newest heartbeat of every node), never from one node's memory alone, at one place, the presence tracker: (1) a heartbeat that takes the agent over on this node (the entry was not fed here since it was filled, the row holds a newer heartbeat of another node, or the agent was offline or unknown here) is stored at once with the monotone `PersistHeartbeat` and announces its state again even when the published pair is unchanged; (2) before the deadline timer sets an agent `offline` it reads the row outside the entry lock; a row with a newer heartbeat is adopted (report, state, last heartbeat) and the deadline moves to that heartbeat plus `agent.presence_timeout` plus `agent.heartbeat_persist_interval`, the most the feeding node's row can lag; nothing is published before; a failed read keeps the verdict of this node; (3) `Statuses`, `getAgent` and `listAgents` use the entry only when the row holds no newer heartbeat. Spec 09 notes the immediate store. Found by the red team and the delta red team; `TestPresenceAcrossNodes` moves an agent between two trackers on one store with a fake clock. Place: `internal/agents/app/presence.go` (`expire`, `memory`, `Statuses`), `heartbeat.go` (`takeover`, `persistNow`). | Since M7-17 an `offline` of one node reaches the clients of every node (`gateway.agent_presence`); the node the agent left must see the new node's heartbeat before its own deadline, independent of the flush phase, and a node's stale entry must not answer reads; the grace of one persist interval makes the verdict independent of the ratio of persist interval and timeout, so no new configuration check is needed. |
