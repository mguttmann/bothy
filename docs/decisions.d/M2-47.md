| D-M2-47-1 | 2026-10-20 | Scope: besides `session.open` over `NOTIFY ephemeral` and the hash rule of the edge, M2-47 builds the probe of an older control connection across nodes (24 3.4), the closing of a host's connections on every node at a transition or re-pairing (24 3.1, 3.3) and the check "host connected" across nodes behind `409 host_unavailable` (24 6.1 point 2, 13). The end of a session needs no signal: it reaches every api node through the event log tail (M2-44 Design note 11), which M2-47 proves with two nodes. The code stays node-neutral; with `cluster.mode = single` none of it runs. | Without these paths `cluster.mode = multi` would keep the control connection of a disabled or re-paired host open on another node, hide a copied key and answer `409 host_unavailable` by chance of the node; no other ticket builds them (M7-17 covers gateway, `runs` and `agents`). Place: 24 section 9, `internal/terminal`. |

| D-M2-47-3 | 2026-10-20 | Kinds and payload: `terminal.session_open` (`host_id`, `session_id`), `terminal.host_close` (`host_id`), `terminal.host_present` and `terminal.host_gone` (`host_id`, `conn_id`), `terminal.session_paired` (`host_id`, `session_id`); compact JSON with exactly these members, each a UUID string, never `null`. | D-M2-47-4 | 2026-10-20 | Port `app.Signals` (`Stage` in the unit of work, `Committed` after it, `Send` outside any unit) with one `SignalHandler` for both modes: `LocalSignals` (`single`) calls the local handler in `Committed`; `NotifySignals` (`multi`) executes `NotifyEphemeral` on the unit's transaction in `Stage` and does nothing in `Committed`, because every node, the sender included, receives the notification through its listener. | D-M2-47-5 | 2026-10-20 | Listener: `EphemeralListener` opens its own connection (`bothy-terminal-ephemeral`), executes `LISTEN ephemeral`, hands each signal in order to the handler, logs a loss once, retries at once and then every `database.listen_reconnect_backoff_cap`, and after `LISTEN` succeeded again runs the reconciliation (host states of all its control and data connections by `HostStatesByIDs`, close what is no longer `active`, announce every eligible control connection at once). | D-M2-47-7 | 2026-10-20 | Second control connection across nodes: every accepted control connection gets a `conn_id` (UUIDv7 on the clock of its node); a node ignores announcements of its own connections; the node of the older connection probes it with M2-43's probe (`4009` without answer, else the duplicate verdict in one unit that stages `terminal.host_close`, so every node closes with the code of the state); the node of a newer connection announces it at once when it hears an older one.
