| D-M5-13-0 | 2026-10-27 | Built on main after M4-38, M5-11 and M5-12. Names and layout that differ from the brief: the terminal suite runs against the terminal stack of the Go helper `services/server/test/terminal/clientstack` (the stack of M2-48 with its TLS front and one host container) in the new mode `mobile`, not against `infra/compose/test/compose.e2e-mobile.yaml`, which stays unchanged; `make e2e-mobile` (`tools/e2e/mobile_e2e.py`) starts that helper after the stack of `infra/compose/e2e.sh` is gone and runs `tool/mobile_e2e_suite.sh <platform> terminal` per platform (`MOBILE_E2E_SUITES` names `terminal` like the suites of M5-11); the helper runs that stack with the profile `mobile` of `services/server/test/terminal/profiles.yaml` (the default profile with a `terminal.quick_reattach_window` of at least three patiences of the test kits, longer than the bounds of the return from the background together, a floor the profile loader checks against the patience the client suites wait by), so the return within the window depends on no machine's speed, and the half after the window waits it out once per platform; it writes the terminal windows of the profile (`terminal_windows`) into the connection data, so the suite waits by `terminal.quick_reattach_window` and checks against `terminal.detach_grace` without a number of its own. The physical-device measurement of the terminal targets is the one of M4-38 (`perf_test/terminal_perf_test.dart`) with the evaluation of M5-11; nothing new is built for it. | Brief Boundaries (D-W-100, D-W-120): the merged code of M4-38 and M5-12 already holds the pairing helper the brief allows to reuse (Scope "or reuses the pairing helper of M2-48"); a second pairing seed in the Compose overlay would duplicate it. |
| D-M5-13-1 | 2026-10-27 | Host in the stack: the host service container is the `termhost` of M2-48 on its internal network, which reaches only the TLS front of the stack over TLS with the stack's test CA (24 2.2, SEC-TLS-1); the helper pairs it through the public API with an owner session (createHost assigned to Alex, `bothy-host pair` with the code inside the container, confirmHost with the first characters of the fingerprint and Alex's session user) and renames it "Build host" with updateHost. Alex is an owner and holds `terminal` implicitly (24 8.1). The host is not declared the server host: it does not share the server's network here, and SR10 (a non-owner refused with `terminal_denied` `server_host_owner_only` on the server host) is covered on the real server and host container by TM-T08 of the conformance suite. The network cut of the suite is the in-process tunnel of `e2e_test/support/e2e_network.dart` and affects only the app's connections, never the host container's. | Brief Design note 1: the brief's topology (the host next to `api` on the Compose network) is what made the server-host declaration necessary; with the stack of M2-48 the host sits on its own network as a real host would, and the SR10 case already has its test. |
| D-M5-13-2 | 2026-10-27 | The app switcher picture per platform: on iOS the suite moves the app to the background with the home button and asserts, without pumping, that the privacy cover is in the tree and the terminal view is offstage, so the picture iOS takes after `inactive` shows only the cover; on Android it asserts that the window asked for `FLAG_SECURE` when M8 opened and that nothing lifted it on the way to the background, so the system takes the recent apps picture blank (the instrumented `RecentsProtectionTest` of M5-12 checks the window flag itself). A pixel check of the system snapshot is not made: patrol offers no access to the app switcher picture, and on iOS the snapshot file of the system is a compressed texture whose text cannot be read without an OCR the repository does not have. | Brief Design note 2 ("where patrol can"); R-PR-12, D-M5-12-3. |
