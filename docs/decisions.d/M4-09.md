| D-M4-09-3 | 2026-10-15 | Persist before publish: a rotated refresh token is written to the `SecretStore` and the write awaited before the new access token is published; refreshes of one family run as a single flight (`RefreshCoordinator`), and a request that failed with an older token repeats with the current one instead of refreshing again. `401 session_revoked` signs out with `sessionRevoked`, unless the request or the refresh was sent in an earlier session (before a logout and a new login), whose late answer must not end its successor, clear the store or emit an event, and is never resent with the successor's token; a refresh rejected with `unauthenticated`, `token_expired` or `invalid_dpop_proof` signs out with `refreshRejected`; a network or other error keeps the state and emits `RefreshFailed`. | Brief Design note 4: a crash between rotation and storage falls into the server's `auth.refresh_reuse_grace` (08 7.4) instead of a lost token; two refreshes of one family would look like theft. |
