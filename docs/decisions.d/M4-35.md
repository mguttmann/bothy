# M4-35 Package terminal_ui and terminal view

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M4-35-1 | 2026-10-20 | The controller is the only owner of the ephemeral X25519 key: it creates the pair right before `openTerminalSession` or `attachTerminalSession` (only its hash leaves), hands it to `NkInitiator` and calls `destroy()` of `cryptography` (the private bytes are zeroed) right after message 2 and on every abort (cancelled step-up, refused request, key mismatch, closed stream). `ephemeral_key_test.dart` checks that the pair is destroyed and no longer extractable. | Brief Design note 1, R-CL-15; a weak reference cannot be checked reliably in a VM test, zeroing can. |
| D-M4-35-2 | 2026-10-20 | The escape filter (`render/escape_filter.dart`) sits in `terminal_ui` in front of `xterm` on the byte stream before UTF-8 decoding. Allow list: text and C0 controls pass; ESC sequences pass except DCS, SOS, PM and APC (dropped with their content); CSI passes except window operations and reports (final `t`), status reports other than CPR (`n` unless `6`), DA3 (`c` other than DA1 and DA2), every `$` intermediate (DECRQM and the report family), DECREQTPARM (`x`) and XTVERSION (`> q`); every OSC is dropped except OSC 8, which becomes inert text plus a link record. The only answers left are CPR, DA1 and DA2. On top, sequences that make `xterm` 4.0.0 throw or hang are dropped (a parameter above `EscapeFilter.maxParameterValue`, SGR 38 or 48 without sub-parameters or with a palette index above 255, REP above `EscapeFilter.maxRepeatCount`, `CSI 0 X`), and `TerminalScreen` catches any renderer exception so hostile output cannot end the session as tampering. | Brief Design note 2, 24 11.2, SEC-TERM-6, TM-T14; the blocks must not depend on the renderer's version. |
| D-M4-35-3 | 2026-10-20 | Pins compare the key bytes only (base64url decoded): no pin opens and pins `noise_public_key`, `key_generation`, fingerprint and first seen after the first successful handshake; the same key writes nothing; a different key shows the warning whatever `key_generation` says, and a confirmed change sends `pin_changed = true` (open and attach) and writes the new pin only after message 2. | Brief Design note 3, 15 23.3, TM-T18. |
| D-M4-35-4 | 2026-10-20 | `lib/testing.dart` holds `FakeHost` (static X25519 key, `NkResponder` of `bothy_noise/testing.dart`, checks the token of message 1, records the device frames, sends `data`, `exit`, the replay and any close code) and `FakeTerminalTransport` (in memory, `hello` and `identify`). The fakes of the server API, the pins, the step-up, the clock, the links and the prompts are test support of the package (`test/support/`). | Brief Design note 4; M4-36 and M4-38 test against the real host service. |
| D-M4-35-5 | 2026-10-20 | `xterm` 4.0.0 (2024-02-27, MIT) is adopted: no advisory in OSV or the GitHub advisory database on 2026-10-20, no security issue in its tracker. Its own handlers are the second layer: the view leaves `onTitleChange`, `onIconChange` and `onPrivateOSC` unset (OSC 52 and OSC 8 reach only `onPrivateOSC`; there is no clipboard handler). | D-M4-35-7 | 2026-10-20 | Close codes: no reaction retries by itself. `4100` ends (blocked with a danger banner when `close_reason` is a revocation: `access_revoked`, `i6_violation`, `user_disabled`, `device_revoked`, `session_revoked`, `host_disabled`, `host_retired`, `host_rekeyed`), `1000` ends, `4104`, `4002` and `4012` block, `4101` detaches and the next "Reattach" asks for a step-up before the request, `4102`, `4103`, `1001`, `4013`, `4014`, `4004`, `4008` and a broken stream without a code detach with their own text and offer "Reattach" as a manual action. | 15 23.2 item 8, asyncapi `x-close-codes`; an automatic reattach on mobile foreground or network return is M5's wiring. |
| D-M4-35-8 | 2026-10-20 | Attach runs its own step-up: on `401 step_up_required` it runs one step-up and repeats the request once. | D-M4-35-9 | 2026-10-20 | Superseded by D-M4-35-18. | D-M4-35-16 | 2026-10-20 | Red team round 1 (`NEIN`, seven Majors), fixed with a test each: pasted text loses ESC, DEL and the C0 and C1 controls other than tab, line feed and carriage return before the confirmation and the send (a single line with `ESC[201~` and Ctrl-O ran a command without a dialog); an OSC 8 target must be printable ASCII and the confirmation shows its host first in a scrolling dialog (a target with U+2028 hid the real host); dropped link records dispose their xterm anchors (the view froze); "End", a revocation or a closed tab during a pending attach are no longer overwritten; a closed stream stops its frame pump, so a stale resize tick neither sends nor blocks, and an older stream loop leaves the key of a newer attach alone; CPR answers count from 1; the cursor is an opaque underline (D-M4-35-9). | `docs/quality/red-team-gate.md`; red team report of M4-35. |
| D-M4-35-17 | 2026-10-20 | Class fix of the delta red team (findings M4 of round 1, N2 and N3): one ownership token for every flow of a terminal tab. An opening, an attach and the stream loop it starts own the generation they began with; End, Detach, a revocation, a block and dispose start a new one. The state has one writer, `_set(epoch, state)`, which ignores a flow that lost the tab; every await of a flow goes through `_owned`, which stops it there; the stream, the pump and the ephemeral key change only under the same check. Proof: a model test interrupts the opening and the attach after every microtask with End, Detach, a revocation and dispose, for a normal handshake, a failing connect and a broken message 2, and checks that a final state of the action stays, that only a connected or exited tab holds a stream, that every key is destroyed, that no frame but `close` follows the action and that a disposed tab notifies nobody. | Owner rule of 2026-10-17 (the same class a second time is fixed at one place with a test over the class); red team reports of M4-35 (round 1 and delta). |
| D-M4-35-18 | 2026-10-20 | Class fix of the delta red team (round 1 M7, N1 and N4): what xterm 4.0.0 paints for the cursor and the selection is not what components.md 12 pairs (a block over the character, a translucent selection over the text, underline and bar in row 0). xterm now gets a transparent cursor and selection, and one painter of the view, `TerminalMarksPainter`, paints every marked cell opaque in its token pairing, snapped to whole device pixels: the cursor cell in `cursor` with its character in `cursor-text`, a selected cell in `selection-bg` with its character in `fg`, without the focus a frame in `cursor`. Proof: a pixel test over light and dark, device pixel ratios 1, 1.25 and 2, three cursor cells, focus on and off and three kinds of cell checks the cell (nothing painted elsewhere), the pairing and the contrast, and a selection test checks the selection in both themes and all three ratios. Supersedes D-M4-35-9. | components.md 12 (block cursor with `cursor-text`, selection `selection-bg`); 01 accessibility (AA in light and dark). |
