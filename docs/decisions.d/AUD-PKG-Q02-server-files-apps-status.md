# AUD-PKG-Q02-server-files-apps-status Files, apps and status findings of the audit of 2026-11-11

Work package of the audit of 2026-11-11 for `internal/files`, `internal/apps` (with the
reconciliation log of `internal/billing`), `internal/status` and `internal/stats`. Each of the 18
issues was read again on the current `main`; all 18 still applied. Twelve are fixed here, six are
closed with a plan row in `docs/PLAN.md` (V3-66 to V3-71), and V3-65 records the follow-up of the
refusal in AUD-Q02/1.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-Q02/1 | 2026-11-28 | `ValidateManifest` refuses `delivery.mode: gateway` (code `invalid` on `/delivery/mode`) when events, or commands or components without `interactions_url`, would reach the app over the gateway; stored manifests are only parsed, so existing installations keep working. A commands-only app with `interactions_url` keeps the mode, because the contract requires `mode` with only `gateway` or `webhook`. App delivery over the gateway is plan row V3-65. Tests: `TestValidateManifest_Rules` (cases "gateway mode with events" and "gateway mode for commands without interactions_url"), `TestValidateManifest_GatewayWithoutGatewayDelivery`, `test/integration/apps` (Linker seeded as an earlier gateway installation), `TestUpgradeAppliesCommandDiff` (now upgrades Tracker). | fn-extensions-sdks-3 (#655): the gateway closes every app at `ready` with 4018 (D-M2-25-24), so such a manifest installed and never received anything. |
| AUD-Q02/2 | 2026-11-28 | `app.uninstall` ends the pending deliveries of every subscription of the installation as `dead` with `event_expired`. The participant of `retention.transient` first runs `WebhookService.ExpireLost`: the gap rule (D-M2-26-5) for every subscription with a pending row whose event left the log, without waiting for its next delivery; an active or paused subscription becomes disabled with cause `gap` and an audit entry, a disabled one only gets its lost rows ended. The catch-up of a paused subscription (D-M2-26-2) is unchanged. Tests: `ScenarioUninstallDisablesSubscriptions`, `ScenarioRetentionSweepEndsLostDeliveries`, `TestPurgeOnlyExpired`. | srv-apps-billing-3 (#893): pending rows had no end after an uninstall or once their event left `sync.event_retention`, and retention never deletes a pending row. |
| AUD-Q02/3 | 2026-11-28 | Counters `bothy.webhook.delivery` (outcome `succeeded`, `retrying`, `failed`, `dead`) and `bothy.webhook.transition` (cause `gone`, `max_consecutive_failures`, `retry_max_age`, `gap`, `max_pending`), recorded after the commit through the port `WebhookMetrics` (adapter `apps/adapters/otelmetrics`), series start at 0; the alert `BothyWebhookSubscriptionStopped` (ticket) fires on a system transition within 24 hours. A cost reconciliation logs `cost reconciliation entry unmatched` with `bothy.run.id` and `bothy.reason` (`no_entries`, `personal`, `provider`, `currency`) per unmatched run, after the commit. Supersedes "no new metric" of D-M2-26-17. The alert rule lives in `infra/observability`, the area of another package, because the finding asks for it. Tests: `TestMetrics_RecordsTheWebhookSignals`, `TestNew_SeriesStartAtZero`, the signal checks of the 410, quota, sweep and uninstall scenarios, the promtool rule test, `TestReconcile_Unmatched`. | srv-apps-billing-11 (#925): system stops of subscriptions and unmatched reconciliations were invisible to the operator. |
| AUD-Q02/4 | 2026-11-28 | `app.ObjectStore` keeps Put, Get, Head and Delete; multipart is the port `app.MultipartStore` of the S3 driver only (wire refuses driver s3 without it, the scan pass gets it as `ScanDeps.Multipart`). Removed: the fs multipart code, `PresignUploadPart` with `PresignedPart`, `ErrNotSupported` and the S3 presign client (the start check `presigned_mode_unavailable` stays; V3-32 brings presign back), `PutPart.ContentLength` (the verifying reader checks the length, D-M3-03-22), `domain.CheckTransition` (wrong anyway: the import reopens aborted or expired sessions, M8-11) and the sniffer fields read only by tests. `VariantPoster` stays, reserved by the key schema (12 4.4, V3-32). The conformance suite holds the real part layout `uploads/<id>/<n>`. Tests: `TestObjectStoreHasExactlyThePortOperations`, `RunObjectStoreConformance/PartLayout`, `RunMultipartConformance` in `TestS3Conformance`, `TestDeleteOfOriginalRemovesLeftParts`. | srv-files-adapters-5 (#955), srv-files-core-12 (#974): half the port had no production caller while the suite certified it. |
| AUD-Q02/5 | 2026-11-28 | `ProcessImage` takes an image slot without waiting and otherwise returns `app.ErrImageSlotsBusy`; the handler snoozes the job for 5 seconds (`jobs.Snooze`, River `JobSnooze`): no attempt used, no failure line, outcome `snoozed` (02 12.4 rule 7). Tests: `TestProcessImageSlotsBusy`, `TestWorker_SnoozeHoldsTheJob`, `TestJobsMetrics_SnoozeIsSnoozed`. | srv-files-core-13 (#975): a job waiting for a slot used up its timeout and an attempt and held a worker that scans needed. |
| AUD-Q02/6 | 2026-11-28 | New queue `files_text` (`jobs.queue.files_text.max_workers`, default 2) for `files.transcribe` and `files.extract_text`; `files` keeps scan and thumbnail. The default of `file.scan.max_concurrent` is 2, the workers of `files`, instead of a start cross-check. Jobs queued before the deploy still run (River finds the worker by kind). Tests: `TestJobsConfigBindsDefaults`, `TestScanConfigsBind`, the voice and extract registration tests (queue `files_text`). | srv-files-adapters-12 (#961): two slow transcriptions held both workers and kept new uploads pending (`409 file_not_ready`). |
| AUD-Q02/7 | 2026-11-28 | Files are read through two row shapes: `GetFileByID` and `LockFileByID` (mapping `fileOf`), and `GetSessionByID`, `LockSessionForUpdate`, `LockSessionForShare`, `LockScanTarget` (mapping `sessionOf`, reusing `fileOf`); the duplicate `LockVoiceFile` and seven other reads are gone. `digest()` returns an internal error for a length other than 32. Tests: `TestDigestRefusesWrongLength`, `TestSessionRowCarriesTheFileRow`, `TestMappingsFillEveryField`. | srv-files-adapters-18 (#964): about eleven queries repeated the column list with hand mappings, and a wrong-length digest was read as zeros. |
| AUD-Q02/8 | 2026-11-28 | The s3 object mirror retries list, head, get and put on a network error, 408, 429 or 5xx with a doubling pause (named values `attempts`, `firstBackoff`; the SDK client keeps `aws.NopRetryer`, D-M3-02-3); an object that still fails is skipped and the run ends with `s3_mirror_objects_failed_<n>`, a list that still fails with `s3_mirror_failed`. Not built: comparing against a listing of the target. Tests: `TestMirror_RetriesTransientErrors`, `TestMirror_FailedObjectDoesNotStopThePass`, `TestMirror_ListFailsAfterRetries`, `TestMirror_ErrorIsCode`. | srv-stats-status-7 (#1068): one HTTP error failed the whole run, and a permanently failing object blocked every key behind it. |
| AUD-Q02/9 | 2026-11-28 | `bothy-backupd` starts a failed run again `retryDelay` (15 minutes) after it ended, at most `retryLimit` (2) times per due time; the next due time of the kind replaces a pending retry and a `pg_full` drops a pending `pg_diff` retry. At start, after `CloseInterrupted`, `Scheduler.RetryFailed` plans the same retry for the newest run of each kind when it is failed, canceled or interrupted and no later due time has passed. Times missed during a standstill are still not caught up; amends D-M7-02-2. The restore test is not retried (its failures are check results). Tests: `TestFailedRunRetried`, `TestRunNotRecordedRetried`, `TestRetryFailedAfterRestart`, `TestRunsLatestRun`. | srv-stats-status-8 (#1069): a short database error or a restart at backup time meant waiting for the next cron time, a week for the full run. |
| AUD-Q02/10 | 2026-11-28 | The memory of `status.probe` (`domain.Track`) lives in the table `status_component_probe` (migration 00128); the round reads and writes it in its transaction after locking every component, and a round older than the stored one changes nothing. Amends D-M7-09-3: several workers no longer break the memory. Tests: `TestProbe_TwoWorkersShareTheMemory`, `TestMigrationStatusComponentProbe`. | srv-stats-status-11 (#1071): with a per-process memory a flapping check could turn degraded too early. |
