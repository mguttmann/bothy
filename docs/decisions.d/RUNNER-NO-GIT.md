# RUNNER-NO-GIT Every runner forum is a Claude Code chat

Owner expectation of 2026-10-30: every development forum works as a Claude Code chat, also when
its folder is not a Git repository and also when the forum has no project folder. Before, a
binding to a folder without `.git` was not ready (`not_a_git_worktree`, three forums in live
operation), and a forum with the runner as operator but without a binding failed at once with a
bare "Error in the adapter". Normative text: 09 18.1, 18.9, 18.12, 18.13, 5.4, 21, R-AG-35;
01 section 4, 6.9 item 5, R-PR-27.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-RUNNER-NO-GIT-1 | 2026-10-30 | Readiness no longer asks for `.git`: a bound folder that resolves under the root and that the runner user may read, write and search is ready. `not_a_git_worktree` is no longer sent; the code stays in the reason table and the app's mapping for older runners. | The runner uses no Git feature in a turn (R-AG-28: no worktree per post; it reports no branch, diff or commit), so Git never was a precondition of a turn, only of the readiness check. |
| D-RUNNER-NO-GIT-2 | 2026-10-30 | No note "Git features skipped" in the session column. | There is no Git-dependent feature in the runner to skip; a note would need a new readiness member through the server, the API and the app for a message that says nothing happened. If a Git feature is added later, its ticket adds the note. |
| D-RUNNER-NO-GIT-3 | 2026-10-30 | `runner.default_workspace` (default empty, off) is the folder of a forum without a binding: `.` is `runner.projects_root` itself, any other value a reference resolved as a `workspace_ref` (strict descendant, symbolic links resolved), refused at configuration load when it leaves the root. It must exist and be writable when a run starts, else the run ends `adapter_error` with a cause that names the key. A bound forum never falls back to it. | The owner chooses the projects root or a dedicated folder; keeping the value under the root keeps the confinement of 18.1. Falling back for a bound forum would silently run a project's chat in the wrong folder. |
| D-RUNNER-NO-GIT-4 | 2026-10-30 | A forum without a binding has no `project_readiness` entry, also with a default folder; such a run uses `runner.default_model` and `runner.scoped_allowed_tools`. | The server applies readiness only to bindings; without a binding there are no runner settings to narrow the runner's own. |
| D-RUNNER-NO-GIT-5 | 2026-10-30 | Every run the runner ends without a turn or with `adapter_error` names its cause in the `summary` of `finishRun`: a fixed English sentence per log code (`causes.py`) with the code in backticks, never a path, user or value of the host. The SDK's `RunRefused` takes the summary; an unexpected handler error gets a summary that names only the error's kind. An adopted turn repeats the stored summary. | The reason codes are fixed by the server (5.2) and a new code would be stored as `adapter_error` anyway; `summary` already exists in `finishRun` and in the run document, so no API change is needed. English like every adapter text; the reason word next to it stays translated. |
| D-RUNNER-NO-GIT-6 | 2026-10-30 | The app shows the `summary` of a failed or cancelled run as the cause next to the reason: in the live box under the reason line and in the collapsed line after it; for such a run the summary is no longer shown as the last text. | The person saw only "Error in the adapter"; the collapsed line of an ended run showed no reason at all. |
| D-RUNNER-NO-GIT-7 | 2026-10-30 | The project folder report (18.13) still lists only Git work trees. | The dialog "Add forums for existing folders" checks every listed folder for a new forum; a projects root also holds folders that are no projects. A folder without Git is bound by name ("Existing folder"). |
| D-RUNNER-NO-GIT-8 | 2026-10-30 | Only a channel in the runner's served cache gets `runner.default_workspace`; a run in a channel the runner does not operate (a guest mention, 09 3.6), bound or not, ends `adapter_error` with the cause `channel_not_served`. A text channel the runner operates without a binding is treated like a forum. | Red team finding: the cache answered "no binding" also for a channel it does not hold, so any guest mention ran in the default folder, a bound forum of another agent included; before this ticket such a run was refused with `project_not_bound`. |
