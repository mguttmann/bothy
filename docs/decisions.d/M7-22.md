| M7-22/3 | 2026-10-14 | Write once and key form (D-M7-22-2, D-M7-22-3): the object is `[<prefix>/]<instance_id>/<seq with 20 digits, leading zeros>.jws`, the layout of the file sink. `Put` reads the oldest version of the key first (the same bytes count as stored, other bytes are `ErrCheckpointConflict`), then writes with `If-None-Match: *` and an SHA-256 checksum; on `412` or `409` of a concurrent writer the stored bytes decide the same way. `List` pages through `ListObjectVersions` below `[<prefix>/]<instance_id>/` (page size 1000, the tests 10), takes the oldest version of every checkpoint key, skips delete markers and other names, and returns the checkpoints in `seq` order. | The brief suggested `checkpoints/<seq>.jws`; the instance ID keeps two instances in one bucket apart, as the file sink does, and the same width keeps the key order the `seq` order.
