| No | Date | Ruling | Reason |
|---|---|---|---|
| D-A1-04-1 | 2026-11-06 | Until A1-05 a hosted run takes its thread lock (under the agent's state folder) and a slot of the shared pool before it ends `failed` with `adapter_error` and the cause `definition_missing`, without `run.start`; it waits with `thread_busy` or `slots_full` like a turn. | 26 5.6 lists the definition check among the steps before a turn, and the slot is what a hosted turn will hold; taking it now makes the shared slots of 26 3.2 item 3 real and testable before the turns exist (BA-T09), and A1-05 replaces only the refusal by the turn. |
| D-A1-04-2 | 2026-11-06 | A hosted agent's loaded class is the lower of the `tool_class` of its `Agent` record in `listHostedAgents` and `runner.hosted_max_tool_class`; the runner lists the set again on `agent.updated` of a hosted connection and on the timer, instead of an `agent.read` of itself. | The API token of a hosted agent carries no `tool_class` claim (it is an opaque `ApiTokenCreated` secret, A1-03), and the list already returns the agent's record; the invocation token's claim stays the check of every run (SR2). |
| D-A1-04-3 | 2026-11-06 | The next hosted token is fetched when the share `TOKEN_REFRESH_FRACTION` (`hosting.py`) of the token's lifetime is left (the lifetime read from `created_at` and `expires_at`); the agent then reconnects with the new token, because the issue revokes the old one and the server closes its connection with `4012`. A `4012` while the runner fetches the next token is that renewal; any other `4012` drops the agent until the next list. | The runner cannot read `agents.hosted_token_ttl`; the token row names its lifetime. The share leaves many backoff attempts when the server is briefly unreachable. Swapping the token inside a running SDK client would need an SDK change the revocation closes anyway. |
| D-A1-04-4 | 2026-11-06 | `runner.hosted_agents` without `runner.dpop_key_ref` is a configuration error naming `runner.dpop_key_ref`. | The server issues a hosted token only to a DPoP-bound caller (`dpop_required`, D-A1-03-4); failing at the start names the cause instead of a hosted agent that never connects. |
| D-A1-04-5 | 2026-11-06 | The hosted set is listed first once the runner's own connection is ready and its first heartbeat was answered, and again on every reconnect of that connection; a failed token issue (also the `404` of a runner whose stored heartbeat lacks `hosts_agents` yet) is retried with the SDK's backoff until the list no longer names the agent. | `issueHostedAgentToken` requires the stored capability (26 3.3 item 1, D-A1-03-6 stores it at once); listing before the heartbeat would answer every issue with `404`. |
| D-A1-04-6 | 2026-11-06 | The SDK's heartbeat builder accepts the capability `hosts_agents` (`chat`, `scoped`, `host`) as the last key of its closed set. | The builder refused every key outside its closed set, so no runner could report the capability; as the last key the capabilities of an adapter without it keep their order and bytes (26 11 item 3). |
| D-A1-04-7 | 2026-11-06 | The runner tests reach each hosted agent on a FakeServer of its own through the test seam `hosted_url` of `Runner` (default `runner.server_url`); the real-server test runs the same path against one server. | The FakeServer models one agent principal; a second principal needs a second server, and a routing front cannot route the gateway's `hello`, which comes before the token. |
| D-A1-04-8 | 2026-11-06 | The baseline fixtures replace values that differ between two runs of the same scenario (the temporary folder, UUIDs, the runner's release version) by stable names, and the heartbeat bodies are taken from the runner once its first folder check ran. | The first heartbeat on the wire goes out before or after that check by timing, also on the base; a fixed point keeps the comparison byte-equal and stable. |
