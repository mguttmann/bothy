# FIX-cost-display Costs of personal runs and of running runs

| No | Date | Ruling | Reason |
|---|---|---|---|
| FIX-COST/1 | 2026-11-01 | Cause 1, reproduced read-only on the live instance: `cost_entries` holds valid `personal` bookings (`adapter_reported`, estimates) and `stats_minutes` the same sums, but the server runs with the default of `billing.show_personal_estimates`, `false` (`services/server/internal/wire/configkeys_billing.go`), so `CostStats` and `CostCurrencies` (`services/server/internal/billing/adapters/postgres/queries/stats.sql`, filter `show_personal OR billing_mode <> 'personal'`) and the backend view (`services/server/internal/stats/app/backends.go`) drop every row of an instance whose agents all run on personal subscriptions: "Costs per agent", "Costs per space" and the executive tile "Costs per billing mode" read "No data". The default becomes `true`: amounts of mode `personal` are shown, labeled "information only" (the apps already label them so); an operator who wants them hidden sets the switch to `false`. 10 12.2 and 17 change; D-BR-01 keeps the booking rule and points here for the display. | Owner bug of 2026-11-01: the owner read "nothing cost money" although the runs had costs at API prices. The label keeps the rule that a personal amount is never an invoice. Removing the switch was not needed; flipping its default fixes every view at once (`getCostStats`, `getStatsBackends`, `getThreadCosts`). |
| FIX-COST/2 | 2026-11-01 | One cost source: the bookings (`cost_entries`) are the amounts of statistics and executive page; `runs.cost_micros` is the run's live estimate while it works and the booked sum after `run.finish` (10 12.1 step 6), so run card, run header and statistics agree once the run ended. A run that ends without a `result` keeps its last live estimate on the run and has no booking (unchanged rule for server-ended runs, RK-16). | The statistics must not count estimates of running runs twice or lose them at a crash; the run card must not sit at zero for an hour. |
| FIX-COST/3 | 2026-11-01 | Cause 2: the Claude Code runner reported costs only in `run.finish`; the pinned CLI states amounts only in a `result` (verified in a live session transcript: one `cost-state` line per turn end, none during a turn of 30 minutes). The runner now patches `/cost` during the run (09 4.10 already allows it): each `assistant` message's `message.usage` priced with the server's start prices, settled on the exact difference at every `result` (09 18.7 addendum). The runner ships `prices.json` as a byte copy of the start file, held equal by `test_price_file_is_the_server_start_file`, because the price table of the server is owner-only (`price.read`) and may be empty on an instance. | The spec names `run.update` on `/cost` as the path for intermediate values; the start file is the documented price list (10 12.3). |
| FIX-COST/4 | 2026-11-01 | The live topology card (25 6.1) shows the cost of a `personal` run too, labeled "information only", like the run cards of the apps. | Same rule in every run card; the live frame already carries the amount. |
| FIX-COST/5 | 2026-11-01 | Not covered: the live estimate uses base prices; a long-context or other surcharge model (for example a `[1m]` variant) is estimated low until the next `result` corrects it. | 10 12.3 names surcharges as outside the estimate. |
