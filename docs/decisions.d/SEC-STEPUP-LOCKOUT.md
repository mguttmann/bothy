# SEC-STEPUP-LOCKOUT A locked password path does not count as a failed step-up

| No | Date | Ruling | Reason |
|---|---|---|---|
| SEC-SL/1 | 2026-11-01 | `stepUpWithPassword` answers a locked password path with `401 step_up_required` and reason `password_locked`, and a password changed during the attempt with reason `password_changed`. Neither fails the challenge or counts toward `auth.step_up_fail_limit` or `auth.login_fail_limit`; the challenge stays issued and expires by its TTL; the refusal is audited as `auth.step_up` deny with reason `step_up_required` and cause `locked` or `credential_changed` (08 6.2 and 13). | The lockout is a rule of the login, not a wrong confirmation. Counting it let anyone who knows the login name lock the password path with wrong logins and revoke the session of a Windows app, whose only step-up is the password (D-M4-11-2), with the correct password typed; this broke R-ID-10. The code stays `step_up_required` because the list of problem codes is closed (06 5 item 7) and a `reason` is the defined refinement; the status stays `401` so that a client that does not know the reason still sees a refused step-up and not an authorization denial. |
| SEC-SL/2 | 2026-11-01 | `StepUpService.confirm` of `packages/auth` stops asking on reason `password_locked` and throws the `DioException` of the answer; the screens show it through `problemText` ("Password sign-in is locked ... Try again later or confirm on another device"), so the web console shows the same text. Reason `password_changed` asks again like a wrong password, since nothing was counted and the current password succeeds. Amends FIX-SU/3. | Asking again during a lockout can only fail; the reason already reaches every screen through the existing problem text, so no new exception type is needed, and `AuthException` stays the type of a lost session for the sync engine. |
| SEC-SL/3 | 2026-11-01 | `StepUpUnavailable` (no step-up method in this session) reads as `403 forbidden` with reason `step_up_not_possible` in the new project dialog (`newProjectFailureOf`), in `selfFailure` and in `loadProblem` of `admin_ui`, with the text "This action cannot be confirmed in this session. Use another device." instead of a cancel or a revoked session. | Red team minor of FIX-stepup-macos; the same error class appeared in three places, so all three map it to the one problem text. |
| SEC-SL/4 | 2026-11-01 | The fake server of `sync_engine` counts the terminal's fresh step-up only for `terminal.step_up_max_age` (60 s, constant `terminalStepUpMaxAge`), older ones answer `401 step_up_required` with reason `terminal_step_up_not_fresh` like the server (07 section 4.2 step 8). | Red team minor of FIX-stepup-macos: the fake used the five-minute window of `auth.step_up_max_age` for the terminal too. |
