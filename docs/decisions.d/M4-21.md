| D-M4-21-1 | 2026-10-24 | The newest active run of the thread by `queued_at` gets the pinned box (R-DM-14 allows one; a late event may show two for a moment). The anchor message of an active run draws nothing; an ended run draws the collapsed line from its summary, the step counts of the summary count as tools until the document is loaded. | D-M4-21-2 | 2026-10-24 | Follow-ups are decided by the server: the composer's send path does not change during a run; it only reads "Follow-up to <agent>" while the thread has an active run, and the message's `trigger_state` shows `followup_delivered` from the event. | D-M4-21-3 | 2026-10-24 | Pending interaction lock: a card with an interaction in the outbox that is not confirmed and not failed ignores further activations (also between the tap and the stored entry), and `DsMessageComponents` keeps its own lock until the card's state changes; a failed interaction shows as the card's error (`problemText`), not as a failed-write row, and the card is operable again while it is `active`. Whether the reader may use a card follows only the server's reports: the channel level `trigger`, the capabilities of the `ChannelView`, `restricted_to` with the run's `triggered_by`, and the owner flag of `getMe` (owners meet every rule); the server checks again. | D-M4-21-4 | 2026-10-24 | Autocomplete: a request goes out after `ui.autocomplete_debounce` without a newer input; when it goes out, the request still in flight is cancelled (`CancelToken`) and a late answer of an older request is dropped by a generation counter; the list shows only the server's choices. Command syntax in the composer: `/name` or `/handle:name` (09 10.3), the option values in order or as `option:value`, the last option takes the rest of the line. The built-ins come first in the suggestions, then the operator's commands, then the others; a name of a built-in is always the built-in, an unqualified name of another agent's command that clashes is reached only qualified (`/handle:name` also names the operator's command). A built-in the server's answers do not allow here is not offered and, when typed, is not sent at all: the text stays and the composer says it is not available here, because a reserved name sent as a message would reach the model or a running turn (09 10.1, 09 7). A refused `invokeCommand` belongs to the thread it was sent from, so it shows there as a failed write with its reason; the composer's autocomplete compares requests by value, so an answer or another rebuild never asks the agent again (Stop needs an active run the person may stop, `/new` and `/resume` the level `trigger`, `/title` the title right, `/close` write access in an open thread). | 09 10.1, 10.3, 10.5; components.md 9; brief Design note 4. |
