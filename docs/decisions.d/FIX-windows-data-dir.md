# FIX-windows-data-dir Data folder of the Windows app after the brand name in the version resource

| No | Date | Ruling | Reason |
|---|---|---|---|
| FIX-WDD/1 | 2026-11-26 | Before Flutter starts, the Windows runner copies `%APPDATA%\com.example\client` to `%APPDATA%\<company>\<product>`, the folder path_provider_windows derives from the version resource (`BRANDING_APP_NAME` for both since AUD-PKG-P02/16, sanitized the same way), when the old folder is this app's (it holds `flutter_secure_storage.dat` and the folder `instances`) and the new folder does not exist (`apps/client/windows/runner/legacy_data_dir.h`, called in `main.cpp` after the single-instance check). The copy goes to `<product>.migrating` and is renamed when complete; the old folder stays unchanged as a fallback; an existing new folder is never overwritten. | AUD-PKG-P02/16 changed `CompanyName` and `ProductName` from `com.example` and `client` to the brand name. path_provider_windows puts the application support folder under these two names, and flutter_secure_storage_windows keeps its DPAPI file (`flutter_secure_storage.dat`, user scope) and the local databases there, so on 2026-11-26 the updated app on a Windows 11 test machine found an empty folder and showed the pairing screen while its device stayed active on the server. The AES key of the secure storage in the Credential Manager (`key_client_...`, from `BINARY_NAME`) and the CNG device keys did not change, so a copy of the folder is the whole repair; the same copy made by hand brought the device back the same day. Copying, not moving, keeps the data if the new build has to be rolled back. |
| FIX-WDD/2 | 2026-11-26 | Not covered: an installation that already started a build with the new names has the new folder and keeps it, even if it only shows the pairing screen; its data stay in the old folder and are copied by hand (stop the app, move the new folder aside, copy the old one). The macOS, iOS and Android apps are not affected: their data folders come from the bundle or application ID, which AUD-PKG-P02/16 did not change. | The runner cannot tell a fresh folder from one where the person paired again, and overwriting a new pairing would lose it. |
| FIX-WDD/3 | 2026-11-26 | The header has no Windows dependency and is tested with the host C++ compiler on real folders in a temporary stand-in for `%APPDATA%` (`apps/client/windows/runner/test/legacy_data_dir_test.cpp`, run by `run_tests.sh`, `make runner-test`, the CI job `test (apps)`). | As FIX-WD/3: the CI job `apps (Windows)` only builds the runner. |
