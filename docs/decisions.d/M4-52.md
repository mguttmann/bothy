# M4-52 Status dots for unseen agent news

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M4-52-1 | 2026-10-31 | The status of a chat comes from its newest run by `queued_at`: `queued` and `running` are working (yellow), `waiting_input` is waiting for the person (blue), `completed` is done (green), `failed` is failed (red); `cancelled` and a state of a newer server give no status. Blue covers the open question, the approval card and the input request, because each is a card message after which the run waits (09 5). | The owner names four colours; the run state the client already syncs separates exactly these four, and a cancel is the person's own act or a stop, not news. |
| D-M4-52-2 | 2026-10-31 | A status is seen when any of these holds: (a) the chat is open on this device; (b) this device's seen mark names the same run and status; (c) the person's read state was written at or after the change (`read_states.updated_at` against `queued_at` for working and `finished_at` for done and failed); (d) for working, waiting and done, when no time can be compared, the chat has nothing unread and no unread mention. A failure needs (a) to (c). | "Seen follows the existing read state per person": (c) and (d) carry it to every device. A read is written only when there is something new to read, so opening a chat whose run failed without a message writes nothing; (b) covers that on the device the person used. (d) holds because working, waiting and done come with a message (the live box anchor, the question card, the answer before `run.finish`, 09 5); a failure can come without one. |
| D-M4-52-3 | 2026-10-31 | The seen mark is the local-only table `thread_seen_states(thread_id, run_id, run_state)` of `local_store` (schema version 13), written by `ChatSeenMarker` while the history of a chat shows (the history column wraps itself in it, on the desktop and the phone) on every change of the newest run or its status, never synchronized, deleted with its thread. The migration keeps the cursor. | The read state cannot store "seen" without a new message (the server keeps the maximum and answers an equal position without an event), and a server-side seen record is outside the ticket ("use the state the client already syncs"). A mark held only in memory would bring a seen red dot back after a restart. |
| D-M4-52-4 | 2026-10-31 | The change time of working is `queued_at`, not `started_at`; a run that resumes after an answer has no change time of its own and is treated like waiting: seen through (a), (b) or (d). | `started_at` keeps its first value on the server (runs.sql), so it cannot date a resume; the live box anchor appears at `queued_at`. |
| D-M4-52-5 | 2026-10-31 | A row with a status mark shows no unread bar; the title stays bold while unread and the mention counter stays. A row without a mark keeps the bar, also in a chat with runs whose news is seen (a person wrote afterwards). | "The dot replaces the plain unread marker for chats with agent runs, so there are not two markers": the mark and the bar never show together, and a human message after seen agent news still needs a marker. |
| D-M4-52-6 | 2026-10-31 | A forum or channel row shows the most urgent unseen status of every stored chat of the channel, its main history included (failed > waiting > working > done), while the new personal setting `sidebar.show_project_status` (default `true`, 01 11, in the server's settings registry) is on; off, a channel row shows only the status of its main history, the chat the text channel row stands for. Space rows show none. | The owner asks for the aggregate on the forum or project row behind "Status auf Projekten anzeigen", default on; a text channel row is itself a chat, so turning the aggregate off must not hide that chat's own news. |
| D-M4-52-7 | 2026-10-31 | The mark is `DsChatStatusMark` of the design system at `size.status-dot`, at the trailing edge of the row before the mention counter: a dot in `category.moss.on-sidebar`, a ring in `category.gorse.on-sidebar`, a diamond in `category.loch.on-sidebar`, a triangle in `category.rowan.on-sidebar`. No new colour token. | The `on-sidebar` category steps are already paired with every sidebar surface for contrast (design-rules.json); four shapes keep the states apart without colour (01 8 "Color"); the trailing slot is where the counters stand. |
| D-M4-52-8 | 2026-10-31 | The tooltip and the end of the row label name the state: "New: run finished", "New: agent is working", "New: waiting for you", "New: run failed" (de: "Neu: Lauf beendet", "Neu: Agent arbeitet", "Neu: wartet auf dich", "Neu: Lauf fehlgeschlagen"); the mark has no screen reader node of its own. | One node per row (components.md 7); the words say both the state and that it is new. |
| D-M4-52-9 | 2026-10-31 | Known limits: a failure without a message that the person saw on one device stays red on another device until opened there or until the person reads something in the chat after the failure; a run that finishes without any message while the person has nothing unread and no read time is stored shows no green. | Both follow from using only the synced read state (D-M4-52-2); a server-side seen state would close them and is a separate decision. |
