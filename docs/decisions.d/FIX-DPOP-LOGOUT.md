# FIX-DPOP-LOGOUT A stale DPoP proof never ends the session

| No | Date | Ruling | Reason |
|---|---|---|---|
| FIX-DPL/1 | 2026-11-09 | A refresh answered with `401 invalid_dpop_proof` no longer signs out: only `session_revoked` (reason `sessionRevoked`), `unauthenticated` and `token_expired` (reason `refreshRejected`) end the session. The `DpopInterceptor` repeats every request with a proof, the refresh included, once on `invalid_dpop_proof` with a new proof (new `iat` and `jti`, the current nonce), like `use_dpop_nonce`; each of the two repeats happens at most once per request. A refresh that still fails keeps the stored refresh token and the state, emits `RefreshFailed(status: 401)` and throws `RefreshUnavailable`. Supersedes the `invalid_dpop_proof` part of D-M4-09-3. | Owner report: a macOS app signed the proof of a refresh during a short wake from sleep; the request was held through sleep and reached the server minutes later, older than `auth.dpop_proof_max_age` plus `auth.clock_leeway`. The server rightly answered `invalid_dpop_proof`, which it checks before the refresh token and for which it revokes nothing (08 7.3), but the client deleted the still valid refresh token and showed the login. Applies to every platform, since `packages/auth` is shared. |
| FIX-DPL/2 | 2026-11-09 | A refresh request gets connect, send and receive timeouts of 15 s each (`refreshRequestTimeout`), set by the `DpopInterceptor` from the request option `requestTimeoutExtra` in the same `onRequest` that signs the proof, the last of the auth slot. Other requests keep the timeouts of their client. A timed out refresh is a network error (`RefreshUnavailable`, state kept). | The sum stays below the default `auth.dpop_proof_max_age` of 60 s, so a refresh either arrives with a young proof or fails locally. A refresh whose answer is lost after the server rotated falls into `auth.refresh_reuse_grace` (08 7.4) on the next try. Uploads and long reads are not limited, because their duration is legitimately long. |
