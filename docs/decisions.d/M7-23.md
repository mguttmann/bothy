| D-M7-23-0 | 2026-10-26 | Built on `main` after M2-48 and M7-12 landed; changelog entries and these rulings are fragments. Names that differ from the brief, following the merged code: the release steps live in `tools/distribution/hostdist.py` next to the desktop steps whose keychain, test publisher and `signtool` functions they reuse, and `make -C services/host release-build`, `release-apple`, `release-windows` and `trial-apple` call it (the Windows jobs call it directly, Git Bash on the runner has no `make`); the control connection of M2-43 already stopped on `4114` without a reconnect and exited `78`, so this ticket adds only the update line (`control.Config.UpdatePath`, logged once in the client loop); the binary had no `version` command, so `bothy-host version` is new and `docs/spec/02-architecture.md` lists it; the CI trials are the new jobs `host trial (macOS)` and `host trial (Windows)` (ids `host-trial-macos`, `host-trial-windows`) in `ci.yml` and `build-verify.yml`; the signed set of all files comes from the new release job `host-signing`. | One PR per ticket on `main`; merged names win (D-W-100). |
| D-M7-23-1 | 2026-10-26 | Package tools and formats (Design note 1): Linux `.deb` and `.rpm` with nfpm 2.48.0 (pinned in `tools/bin/tools.lock.json`, MIT) from `infra/host/linux/nfpm.yaml`, for amd64 and arm64; macOS one `.pkg` per architecture from `pkgbuild` (one component installed below `/Library/Application Support`, `--ownership recommended`, so no existing system folder gets other owners or modes) and `productbuild`; Windows an MSI from `infra/host/windows/bothy-host.wxs` with the WiX Toolset 5.0.2 (the nupkg checked against its SHA-256 in `hostdist.py`, run with the runner's .NET; version 6 and later need a maintenance fee agreement, which is a cost, D-W-125). Each package ships the binary built with its package kind; the `.deb`, `.rpm` and `.pkg` also ship a reference copy of the service definition that `bothy-host install` writes for the default configuration path, in `share/` next to `bin/` (held byte for byte by `TestPackagedDefinitionsEqualInstall`), and the MSI registers the service (`TestMSIServiceEqualsInstall`). Everything is owned by root or the trusted owners, mode `0755` for binary and folders and `0644` for the reference. No package creates a user, writes the live definition, enables or starts a service or pairs: systemd and launchd never load the reference, and the MSI registers the service stopped with the start type demand. A first build put the definitions at the live paths; the review reproduced that a package upgrade then overwrote a unit that `install --config <file>` had written, so the live definitions belong to `install` alone and an upgrade replaces only binary and reference (the container check upgrades over such a unit and compares it). A removal of `.deb` or `.rpm` stops and disables the host service before it removes binary and reference, the MSI uninstall stops and removes the service; state folder, configuration, live definitions and what `install` created stay (16 4.4). The installation tests run in throwaway containers of Debian 13, Ubuntu 24.04, Fedora 43 and AlmaLinux 10 (pinned by digest, without network) for the architecture of the Docker host, and on the hosted macOS and Windows runners. | Nothing runs before its users and checks exist (24 2.2), and the package manager tracks what it installed; one recipe per format, no second definition that could drift from install. |
| D-M7-23-2 | 2026-10-26 | The limit of `spctl` with the test publisher (Design note 2, as D-M7-12-1): the macOS trial signs the binaries with the hardened runtime with a self-signed identity in a temporary keychain (the test publisher of M7-12), leaves the `.pkg` unsigned because `productbuild` refuses every installer identity that Apple did not issue (two CI runs: a self-signed certificate with the code signing usage and one with Apple's package signing usage `1.2.840.113635.100.4.13`, trusted for `pkgSign`, both "Could not find appropriate signing identity"), checks `codesign --verify --strict`, installs the `.pkg` with `installer` on the runner and records the answers of `pkgutil --check-signature` and `spctl --assess --type install` in `trial-host-apple.json`; Gatekeeper accepts only an Apple-issued Developer ID with notarization, so the package signature and the acceptance are not proven until the owner's accounts exist (OQ-08). The release job requires notarization, stapling and the acceptance of `spctl`. The Windows trial trusts a self-signed certificate in `LocalMachine\TrustedPeople` and `Root` for the run, so `signtool verify /pa` passes for binary and MSI; a certificate of a certificate authority is not proven. | D-W-127; no account and no cost (D-W-125). |
| D-M7-23-3 | 2026-10-26 | The `4114` exit code and the update line: the host service keeps the exit code `78` of a refused start for `4114` and for a `hello` without a common protocol version (24 2.2 "its own exit code", D-M2-42-14), so no service definition restarts it, and logs exactly one line at level error: `update the host service or the server` with `code=4114`, `update_path` and, for the missing protocol version, `reason`. `update_path` comes from `internal/buildinfo.PackageKind`, set at build time per package: `.deb`, `.rpm` and `.pkg` name "install the newer package of the same kind, then `bothy-host restart`" (the live definition stays as `install` wrote it); the MSI names `bothy-host install --config "<file>"` instead of the restart, with the configuration file the service runs with, because the major upgrade removes and registers the service again with its default command line and install restores command line, start type, recovery actions and DACL; a release binary without a package names download, verification and `bothy-host install --config "<file>"`. | The operator learns the one route that fits the installed package; a new exit code would need every service definition changed for the same behaviour. |
| D-M7-23-4 | 2026-10-26 | Release steps and checks: the release binaries keep no package kind and are signed only with cosign (not with a Developer ID; `install` signs them ad hoc on macOS as before); the binaries inside the `.pkg` and the MSI are signed for their platform. `host-signing` signs all twelve files (five binaries, four Linux packages, two `.pkg`, one MSI) after their SBOMs and stops when another number of files arrives. The host trials run in CI only when `services/host/`, `infra/host/`, `tools/distribution/` or `release.yml` change (`HOST_TRIAL_JOBS` in `tools/ci/components.py`), never on `main`; the desktop trials ignore `hostdist.py` and its test. Builds use `-trimpath -buildvcs=false -s -w`, so the binary depends on the source, the version and the Go toolchain only. | The brief asks for platform signatures in the platform jobs and one signed set; a host change of every kind can touch what the packages carry. |
