# RUNNER-LIVE-RELOAD Live channel reload and transcription in the Claude Code runner

Two gaps found in live operation on 2026-10-29. Normative text: 09 18.1, 18.2 "Input", 18.14,
21, R-AG-31, R-AG-32.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-RUNNER-LIVE-RELOAD-1 | 2026-10-29 | The runner reloads the whole list of served channels (`listServedChannels`) on `access.changed`, `channel.updated`, `space.updated`, `channel.archived` and `space.archived`, keeps `agent.config_changed` for a reload of one channel, and sends a heartbeat at once when a bound forum joined or left or a readiness changed. | The server writes `agent.config_changed` only to the effective operator at the time of the change, and an operator change writes only `access.changed` (04 8.2); a forum bound before the runner became its operator therefore stayed out of the cache and "not ready" until a restart. One list call per such event is cheap and needs no event payload interpretation. |
| D-RUNNER-LIVE-RELOAD-2 | 2026-10-29 | A timer reloads the list every `runner.channels_resync_interval` (default `5m`) as a fallback; a failed reload keeps the cache and logs `channels_resync_failed`. | `access.changed` is not written when the agent's visible targets do not change (for example a grant that already covered the channel), so an event alone is not a guarantee. |
| D-RUNNER-LIVE-RELOAD-3 | 2026-10-29 | `runner.transcribe_cmd` is an argument list without a shell; the runner appends the audio file path and reads the transcript from stdout, with the allow-list environment without any API key, its own process group and `runner.transcribe_timeout`. Default off. | Any local tool (a whisper.cpp binary or a wrapper that converts the format first) fits one contract; no shell means no injection through a file name; the audio stays on the host. |
| D-RUNNER-LIVE-RELOAD-4 | 2026-10-29 | The runner's transcript becomes the attachment's `transcript` in the run context, so the context helper renders it in the trigger part with the message's trust like a server transcript; it is then delivered with `submitTranscript`, best effort. | One rendering path for every transcript keeps the trust rules of ADR 0054; 09 13 says the agent delivers its transcript in mode `agent`, and a refusal in another mode must not end the run. |
| D-RUNNER-LIVE-RELOAD-5 | 2026-10-29 | Without a transcript the file entry gets `not transcribed: <code>` and the runner posts one message in the thread before the turn; the run continues. | The person learns why the agent did not understand the voice message instead of an answer that ignores it; Claude Code still sees the file. |
| D-RUNNER-LIVE-RELOAD-6 | 2026-10-29 | `capabilities.voice_input` is true exactly when `runner.transcribe_cmd` is set. | In mode `agent` the server routes a voice message only to an agent that reports it can transcribe (09 13); a runner without a transcriber keeps the visible `voice_unsupported` rejection. |
| D-RUNNER-LIVE-RELOAD-7 | 2026-10-29 | Only the attachments of the triggering message are transcribed, not those of context messages or follow-ups. | Only the trigger's attachments are downloaded (18.10); a follow-up line carries text only (18.5). Not covered by this change. |
