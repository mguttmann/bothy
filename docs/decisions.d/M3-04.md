# M3-04 Scan pass with clamd

| No | Date | Ruling | Reason |

| D-M3-04-1 | 2026-10-20 | A transient failure of the pass (PING failed, connection error, timeout, a reply the parser refuses, an object store error) returns no error to River: in a short unit of work that checks again that the file awaits the pass, the handler inserts the next `files.scan` with `Round + 1` at `now + NextScanDelay(Round, file.scan.health_interval, file.scan.retry_backoff_cap)` and returns `nil`. The delay doubles from `file.scan.health_interval` per round, never exceeds the cap and saturates for any round (no overflow; the round stops growing at the largest `int64`). Only a failed database unit returns its error to River. | 12 5.3 allows no upper limit of attempts while the file is not deleted; River's attempt limit would end the retries (brief design note 7). |
| D-M3-04-2 | 2026-10-20 | `files.scan` is registered without River job timeout: `platform/jobs.HandlerOptions` gains `Timeout` (zero: River's default, negative: none, mapped to River's per-worker timeout). The pass bounds itself with `file.scan.timeout`; PING uses `file.scan.health_interval` as deadline. | River's default job timeout (1 minute) is shorter than `file.scan.timeout` and would cut the unit of work that follows the scan. |
| D-M3-04-3 | 2026-10-20 | Outcome precedence (first row wins): size different, SHA-256 different, detected type denied (`failed` with `size_mismatch`, `checksum_mismatch`, `file_type_denied`, objects deleted), then `file.scan.mode = off` (`skipped`), then the clamd verdict: `clean`; `error` with `scan_limits_exceeded`; `infected` with `malware_detected`; `error` with `scan_stream_limit_exceeded`; `error` with `scan_engine_error`. The three failed rows decide also when the scan failed transiently, and a `FOUND` for such a file writes the malware audit entry as well. | Size, digest and type are known from the complete stream; `file_type_denied` is the reason of the early `415`; the audit on failed files closes the gap that a wrong checksum could hide a detection. |
