# I567 Red-team minors of the autonomous runs spec (issue 567)

Issue 567 collects the minors of the red team and of CodeRabbit on the AR-01 specification (PR
566). Normative text: [09-agents.md](../spec/09-agents.md) 5.8.2, 18.19.1, 18.19.6, 18.19.8 to
18.19.11; [01-product.md](../spec/01-product.md) 6.21; [16-operations.md](../spec/16-operations.md)
10.1; [17-observability.md](../spec/17-observability.md) section 3; [07-permissions.md](../spec/07-permissions.md) 4.1.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-I567-1 | 2026-11-08 | The backoff of failed wake-up checks is bounded by the new key `runner.wake_check_backoff_max` (default `10m`, at least `runner.wake_check_interval`) instead of "ten times `runner.wake_check_interval`"; this replaces that factor of D-AR-01-13. | Every limit is a named key (18.19.12); the default keeps the earlier bound for the default interval. |
| D-I567-2 | 2026-11-08 | `runner.turn_handover` goes off only after `claude-code-runner stop --turns` or while no turn runs. Enforced in the runner (merged AR-03 code): `run` with the key off refuses to start while a turn record that carries a phase is left (`StartError` `turn_handover_records_left`, exit 1, nothing touched), and `stop --turns` stops such records through the handover path also with the key off. | A runner without the key cannot continue a keeper turn or a record in `preparing` or `launching`; refusing the start makes the wrong order impossible instead of leaving an unwatched turn, and `stop --turns` stays the one way out. |
| D-I567-3 | 2026-11-08 | Rollback below AR-04 with ended wake runs: the older binary's `getRun` copies `trigger_kind` as stored (`RunREST`), and only the test build validates responses against the contract, so a wake run reads with `trigger_kind` `wake` and `200`; held by `TestRunREST_PassesATriggerKindItDoesNotKnowThrough`. Active wake runs end before the rollback, because an older server cannot deliver one. | Requirement 19 of AR-04 asks to decide and test the read path; the older code was read at the commit before AR-04, where `RunREST` has the same copy. |
| D-I567-4 | 2026-11-08 | `run.wake.recover` for a source run that ended `cancelled` or `completed` stores the wake-up `refused` with the new reason `run_not_failed` (note, `run.wake_changed`, notification `wake_ended`) and answers `409`; a run that has not ended still answers `run_not_ended` and stores nothing. The reason enters the closed list of 07 4.1. | Lost work of such a run must not end silently (18.19.9), and a stopped or completed run must not be continued by a recovery run; the stored refusal is the existing note path of 5.8.4, so the runner of AR-06 needs no new operation. |
| D-I567-5 | 2026-11-08 | `run.wake.recover` with `usage_limit` answers the pending `usage_limit` wake-up of an outage of an ended source run (`200`, nothing changed) when there is one, whatever end the run reached (also `cancelled` or `completed`, before the refusal of D-I567-4); only without one it goes on as before. A source run that has not ended still answers `run_not_ended`. | The partial unique indexes of `run_wakes` key create by outage and recover by reason, so they do not stop a second wake-up for one outage; the check in the same unit of work does. |
| D-I567-6 | 2026-11-08 | The thread scope of `bothy-wake --list` and `--cancel` is the runner's check (`wake_not_in_thread`), and `--pr` is validated by command and runner with the server's rule of `pr_checks` (`invalid_pr`), the repository passed to `gh` only as `--repo=<owner>/<repo>`; both are requirements of AR-05. | `run.wake.cancel` checks agent-self only (07 2.14); a joined option keeps a repository that starts with `-` from becoming an option of `gh`, and the number rule excludes a leading `-`. |
| D-I567-7 | 2026-11-08 | The runner log codes `wake_cancelled` and `wake_failed` name the ends of a wake-up; `wake_check_failed` stays the code of one failed check (17 section 3, R-OB-11). | Each end has its own code; a failed check is not an end. |
| D-I567-8 | 2026-11-08 | Obsolete or already held on main: item 10 (`run_wakes` and `run_autonomy` are in 20 section 2 with their participant and deletion paths since AR-04, `personaldata.go`); item 14 (the repeated create already recomputes the deadline from the new `not_before`, `WakeWindow`; a test of a move past the stored deadline now holds it); item 8's text (18.19.10 already says so; AR-06 gets the test); items 9 and 13 (the client already shows no end state without `end_state` and every note, tested in AR-08; the spec now says so). | The fix of each item stays where its behaviour lives; nothing is built twice. |
| D-I567-9 | 2026-11-08 | `services/server/internal/kernel/auditing/reasons.go` is out of the Sonar duplication measure (`sonar.cpd.exclusions`). | Its reason list is a deliberate copy of the list of `authz/domain`, held equal to 07 4.1 by `TestReasonsMatchChapter07`; each new reason duplicated its lines and failed the duplication condition of a small change. |
