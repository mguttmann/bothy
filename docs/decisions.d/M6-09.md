| D-M6-09-3 | 2026-10-23 | Login providers: the API stores secrets of providers only as references (`client_secret_ref`, `client_key_ref`, 08 2.6) and returns them in `config`. The rest of the stored configuration (members this form does not know too) is sent back unchanged with the form's members set or removed; a new client authentication needs its own reference, which the server names at its field when it is missing. "Test configuration" is not built: the API has no check of a provider configuration. The redirect URI is the server's callback (`<api base>/auth/oidc/callback`, 08 2.2 step 4) with a copy action. The proxy header form states the loopback rule (08 2.4 rule 1), and the server's `409 trusted_header_requires_loopback` is explained with its hint; disable and delete say that the sessions from the provider end at once (R-ID-12), and a `409 provider_in_use` shows the server's hint to disable instead. | Brief Design note 3; fixed requirements 15 and 16. |
| D-M6-09-4 | 2026-10-23 | Feature flags: the list shows key, description, kind, module, the state evaluated for the caller (`getInstance.features`), the stored global value with the default and the size of the rollout, version and who changed it.
