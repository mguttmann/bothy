# FIX-device-mirroring-2 The collapse of a space stays on its device

| No | Date | Ruling | Reason |
|---|---|---|---|
| FIX-DM2/1 | 2026-10-29 | Whether a space is collapsed in the sidebar is view state of the device, like the thread groups (D-SB-6) and the Done section: the new local-only table `space_view_states(space_id, collapsed)` in `local_store` (schema version 10) holds it, a tap on a space row writes only that table, and the sidebar reads the collapse from it. The client no longer writes `PUT /me/sidebar/spaces/{id}` for a collapse. The personal order stays synchronized. | Cause of the owner report of 2026-10-29: the collapse was synchronized (`putMySidebarSpace`, then `sidebar.updated`), so the space a device expanded to open a chat expanded on the other device of the person at the same moment. The server data showed four space toggles of the Mac mirrored on the iPhone while no route ever followed. A two-device test with the real client code (`apps/client/test/app/space_state_device_test.dart`) failed before the change with `Expected: true, Actual: <false>` (the desktop collapsed Team because the phone did). |
| FIX-DM2/2 | 2026-10-29 | The upgrade to version 10 fills `space_view_states` once from the stored `user_space_states.collapsed`, so every space keeps the state it showed. A new device or a reinstalled app starts with every space expanded. A `sidebar.updated` of an older app still updates `user_space_states` but no longer changes the sidebar. | Nothing changes visibly on the upgrade. Taking the server value for a space without a local row would let an older app on another device keep collapsing spaces here, which is the defect. |
| FIX-DM2/3 | 2026-10-29 | An order write (`moveSpace`) sends the `collapsed` the server holds for the space (`SidebarSpace.storedCollapsed`), not the state of this device. Server, API, `sidebar.updated` and the applier stay unchanged. | `SidebarStatePut` needs both fields; sending the device's state would write it to the server again and reach older apps. No server or API change is needed for a client-side view state. |
| FIX-DM2/4 | 2026-10-29 | The fake server needed no extension: it already answers `putMySidebarSpace` and appends `sidebar.updated` to the log of every device of the person, the live mechanism. The earlier tests (FIX-DM/3) checked the route, the selection and the columns, never the collapse state, and so could not find it. The new test waits for a setting the server writes after the tap on both devices, so any `sidebar.updated` of the tap is applied before the assertion (04 7.1, one ordered log). | Before the change the test failed on the first assertion; after it, it passes. |
