# ADAPTER-INTERIM Interim text of a Hermes turn is progress, not a message

Hermes posts the assistant text it writes in front of a tool call (commentary such as "Now I
remove the leftover line and run the tests.") with `send` on its own platforms. The adapter took
every `send` of a turn as the run's answer, so that text appeared as a normal agent message between
the real answers while the agent worked with tools (spec 09 section 17.3).

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-ADAPTER-INTERIM-1 | 2026-11-09 | A `send` that belongs to a turn of its thread (both cases of 17.3: `reply_to` names the turn's message, or the send is a turn send of the thread) is progress when Hermes marks it `_interim_send` or when Hermes' agent loop of the thread still runs (`pre_llm_call` seen, no `on_session_end` yet) and its last model reply asked for tools (`post_api_request` with `assistant_tool_call_count` > 0, the signal D-M2-33-8 already reads). Progress replaces `/last_text_excerpt` of the run, the same path as `send_draft` (D-HERMES-MAIN-5), and the send fails with a reason; it never becomes a message. Every other send of the turn stays the answer. A marked send of a thread without an active run fails too, an unmarked one stays a report (09 14). Place: `platform.py` (`send`), `handler.py` (`on_interim`), 09 17.3. Evidence: `tests/fake_hermes/test_turns.py` `test_interim_text_before_a_tool_call_is_no_message` (streamed and not streamed, against the pinned Hermes: one message equal to the answer, the interim text in `/last_text_excerpt`; both failed before the change with the interim text as a first message), `tests/unit/test_handler_runs.py` `test_interim_text_is_a_draft_and_only_the_answer_a_message` and `test_interim_text_without_a_run_is_not_shown`. | Read in the source of the pinned Hermes: not streamed, `GatewayStreamConsumer._send_commentary` sends the commentary with `metadata["_interim_send"] = True`, the marker Hermes also puts on heartbeats, inactivity warnings and other mid-turn notices ("not the turn-final", `gateway/run.py` `_interim_metadata`). Streamed with drafts, the consumer finalizes the text in front of a tool boundary with a plain `send` (`_send_or_edit(finalize=True, is_turn_final=False)` falls through `_draft_push` to `_first_send`), the same call as the final answer; only the loop state tells them apart. Hermes' own platforms show such text as a separate interim bubble; Bothy's equivalent is the live box, and a message would sit between the answers for good. The send fails rather than succeeds so that Hermes never records the text as delivered: a recorded commentary equal to the final answer would make Hermes skip the final send (`has_durably_delivered_text`). A failed first send only turns off edit previews for the rest of that turn; drafts and the final send are unaffected (proven by the Fake-Hermes test). The loop state is cleared by `on_session_end`, which Hermes fires at the end of the agent loop (`agent/turn_finalizer.py`) before the gateway sends a final it produced after a tool call (an error or limit text), so that final stays the answer. A `send_message` tool call into the turn's own thread during the loop would also count as progress; not reproduced, left as an open minor. |
