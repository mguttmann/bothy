# FEAT-hermes-channel-skills Channel skills, channel prompts and thread actions of the Hermes adapter

| No | Date | Ruling | Reason |
|---|---|---|---|
| FEAT-HCS/1 | 2026-11-02 | The adapter reads `channel_skill_bindings` and `channel_prompts` from the platform section's `extra` with Hermes' own resolvers (`resolve_channel_skills`, `resolve_channel_prompt` of `gateway.platforms.base`), keyed by Bothy channel or thread ID; a thread inherits its channel's entry. Hermes' config loader copies `channel_skill_bindings` from outside `extra` only for Discord and Slack, so the documented place is `extra` (or a root-level platform block, which Hermes promotes into `extra`). | Same semantics and the same reader as the Discord platform; no key of its own to learn. |
| FEAT-HCS/2 | 2026-11-02 | The profile's channel prompt is appended to the context the server delivers in the event's ephemeral channel prompt; it never replaces it. | The context carries the trust note and the data blocks (09 17.6); dropping it would remove the injection protection. |
| FEAT-HCS/3 | 2026-11-02 | The adapter loads the bound skills itself, with Hermes' `_load_skill_payload` and `_build_skill_message` and Hermes' auto-load note, before the person's text, once at the start of a thread's Hermes session (`TurnRequest.new_session`: session mode `new`, or no current session and no session to bind). It does not set the event's `auto_skill`. | Hermes' gateway applies `auto_skill` only when it sees a new session, and for this platform the admission registers the session's route before the turn, so the check never holds; the result is the same text Hermes builds for a Discord channel. Both private functions are in the stub of the pinned version, which the stub contract test holds equal. |
| FEAT-HCS/4 | 2026-11-02 | Thread actions run as the profile's agent without a run (`client.unbound()`), from the platform section like the standalone report sender: `bothy_hermes_adapter.threads.thread_action` and the command `python -m bothy_hermes_adapter thread close\|reopen\|title`, which prints one JSON line. The title uses `If-Match` of a fresh `getThread` and is cut to the report title length. | A skill runs a shell command, a support desk backend of the profile imports a function; both need the same credentials and no second configuration. |
| FEAT-HCS/5 | 2026-11-02 | No server change: the operator agent of a forum may already close and reopen posts and set their auto titles (`write` through the operator rule, 07 2.9), and a message in a closed thread is accepted, reopens it and triggers a run (01 6.1). `operator_done_test.go` proves it against the server. `thread.close` and `thread.reopen` stay without an audit entry (catalog `Audit: no`, as for a person); the durable `thread.closed` event and `closed_by` name the actor. | The brief asked for a fix with audit only if the server refused; it does not. |
| FEAT-HCS/6 | 2026-11-02 | The SDK FakeServer serves `closeThread` and `reopenThread` and reopens a done thread on a new message, as the server does. | The Fake-Hermes ticket flow test needs the server's behaviour. |
| FEAT-HCS/7 | 2026-11-02 | Not covered: the bindings are read once at the gateway start (a change needs a restart, as on Discord); a skill bound to a channel is not loaded again in a continued session after Hermes compresses it. | Hermes' Discord platform behaves the same. |
| FEAT-HCS/8 | 2026-11-02 | The adapter skips a bound skill that `skills.platform_disabled` disables for its platform key (Hermes' `get_disabled_skill_names`). | The adapter loads the skills before Hermes sets the turn's session platform, so Hermes' loader cannot apply the platform's list itself; Hermes' gateway loads them after it is set. |
| FEAT-HCS/9 | 2026-11-02 | A `bind` to a session ID Hermes' session store does not know returns `SessionSwitch.NEW` without `/resume`, and every switch that ends in a new session marks the turn as a new session. | Hermes keeps the new session of `/new` for an unknown ID; the turn has to load the bound skills then, and the report still carries `bind_failed` (09 9.5). |
| FEAT-HCS/10 | 2026-11-02 | The bound skills load on the gateway's event loop, before the turn is dispatched. | Hermes' gateway loads a Discord channel's bound skills the same way (`_hmwa_auto_load_skills`, synchronous in the turn's preparation); a worker thread would differ from Hermes without a reproduced stall. |
| FEAT-HCS/11 | 2026-11-02 | Not covered: a binding that names a skill by another identifier (a path) than the declared name `skills.platform_disabled` lists is caught only after Hermes' loader ran; the skill stays out of the turn, but the loader's own steps for it have run. | The profile's owner writes both the binding and the list; applying Hermes' policy before the load would need Hermes' private session context. |
