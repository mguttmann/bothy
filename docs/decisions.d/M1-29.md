| M1-29/1 | 2026-10-12 | `access.changed` is written only for an affected principal whose difference is non-empty; a change without visible effect still raises the rights version. | Ruling of the brief: later events carry the version in the envelope; an empty event would only make clients reload. |
| M1-29/2 | 2026-10-12 | I1 is checked for all active personal agents on every rights change. | Ruling of the brief: 10 section 5.1 names the minimum per action; the superset cannot miss a case, and 03 section 6.4 already asks the check for shrinking changes. |
| M1-29/3 | 2026-10-12 | The declaration of the brief is `txn.RightsChangeSpec` with the option `txn.DeclareRightsChange`; action and resource kinds are strings and `txn.Ref` names resources and targets. `txn.RightsChange(principals...)` stays and adds up with it; `Options.Covers` also requires the targets and the action of a nested unit. `RightsChangeOf` and `InRightsChange` read the declaration. | `RightsChange` is already the name of the option, and kernel ports never import each other (go-arch-lint: `kernel/txn` may not import `kernel/authorize`). |
| M1-29/4 | 2026-10-12 | The hooks of phase 1 and 3.1 are the method values `Begin` and `BeforeCommit` of `authzapp.RightsHook`, which also implements `authz.RightsChanges.AddAffected` and `VerifyInvariants`.
