# AUD-PKG-R2-06-host-platform-ci Platform suite of the host service green on Linux, macOS and Windows

Issue #622, plan row V1-13. Each cause was read from the log of a run of `host-platform.yml` on
the hosted runners (dispatch run 45770587799 on `main`, then the runs of the build branch of this
package), fixed where it lies, and the fix is held by a test.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-PKG-R2-06/1 | 2026-11-26 | `host-platform.yml` removes every ACL entry of `/opt` (`setfacl -b /opt`) before it gives the folder to root with mode 0755; `tools/ci/tests/test_host_platform_workflow.py` requires all three. | The hosted Ubuntu image gives `/opt` a default ACL (`default:other::rwx`, `default:user:runner:rwx`). Every new folder below inherits it as its access ACL, so `/opt/bothy-platform` came out with mode 0777 after the reset of the mode alone (run 45770587799 printed it), and HD10 and HD11 refused every start that used a program or working directory below it (`claude_bin_untrusted`, `program_location_untrusted`, `shared_location`). The product judged right. |
| AUD-PKG-R2-06/2 | 2026-11-26 | The HD3 probe runs `sudo -n /usr/bin/true` (`/bin/true` where only that exists), an absolute command, still with an empty environment. | Without `PATH` sudo finds a bare `true` only through `secure_path`, which the sudoers file of macOS does not set: `sudo -n true` answered "command not found" even for an account with a passwordless rule, so HD3 never saw one on macOS. Reproduced on a Mac with `env -i /usr/bin/sudo -n true`. `TestSudoProbeCommandIsAbsolute` holds the form. |
| AUD-PKG-R2-06/3 | 2026-11-26 | Windows `install` creates each of its folders in one call with owner Administrators and a protected DACL (SYSTEM and Administrators full, Users read and execute) and makes Administrators the owner of the files it writes or copies. | Windows gives a new object the default owner of the creating token: the group Administrators under UAC, the account itself without UAC or under the policy "object creator". The hosted runner has no UAC, so the program folder, the binary and the state directory belonged to `runneradmin`, which `hostos.TrustedOwner` rightly does not trust, and HD4, HD10 and HD11 refused every start (`state_dir_owner`, `helper_untrusted`, `program_location_untrusted`). The virtual account of the service cannot be made owner without a restore privilege; HD4 accepts Administrators. Creating the folder with its descriptor leaves no moment in which another account owns it or can write into it. |
| AUD-PKG-R2-06/4 | 2026-11-26 | Windows `install` refuses a folder or file of its plan that already exists as a junction or link, or with an owner other than SYSTEM, Administrators, TrustedInstaller, the virtual account of the service and the account that runs `install`. | With /3 alone, a folder that an unprivileged account created in advance (`C:\ProgramData` lets every user create folders) would have been handed to Administrators with that account's DACL and content, and HD4 would then trust it. `TestPlatform_SquattedStateDir` creates the state directory as a person first. |
| AUD-PKG-R2-06/5 | 2026-11-26 | `hostos.WindowsUsers.Groups` reads the local groups of an account that is no user of the account database (the virtual account `NT SERVICE\bothy-host`) by its SID over every local group; an unreadable group fails closed. | `NetUserGetLocalGroups` does not know a virtual account, Groups returned an error, and HD2 reported `forbidden_group` on every Windows host. `TestPlatform_ServiceAccountGroups` reads the groups and a membership in Administrators. |
| AUD-PKG-R2-06/6 | 2026-11-26 | Platform suite: it reads `last exit code = 78: EX_CONFIG` of `launchctl print`, types `echo BG=$!` without a quote after `!`, stages the replaced helper of TM-T26 on macOS as on Linux, creates and deletes the Windows profiles of its accounts, owns its own Windows files by Administrators, and prints the tail of `bothy-host.log` of a failed test on macOS and Windows. | Each was a cause of red tests that were not product defects: every refused start on macOS looked like another code; the zsh of macOS reads `!"` as a history mark and waited at `dquote>`; on macOS launchd owns the endpoint, so an unprivileged impostor tests nothing; `net user /delete` leaves the profile, and the profiles filled the system drive until `CreateProfile` failed with 80070070; the log of the service lay in the state directory, which the cleanup removed. |
| AUD-PKG-R2-06/7 | 2026-11-26 | HD10 reports `helper_unprotected` on macOS when System Integrity Protection is not reported as enabled (`csrutil status`); it refuses the start like a missing hardened runtime, except in the build of the platform suite (`buildinfo.PlatformSuite`), where it is a warning. TM-T26 checks that warning on a Mac with it off and the refused attach of `lldb` on a Mac with it on. | The hardened runtime keeps a debugger of the same user out only under System Integrity Protection: on the hosted runner, which has it off, `lldb` of the session user attached to its helper, and doctor said nothing. Refusing is the rule of 24 2.2 point 4 for a helper whose memory is not protected (as `ptrace_scope_low` on Linux); the suite build keeps measuring everything else on hosted runners, as it does for the peer check. A refused attach on a Mac with protection on is not proven by a hosted run (Open). |
| AUD-PKG-R2-06/8 | 2026-11-26 | On Windows the host service waits for a missing helper pipe within the bound of the check (`DialHelper`); the admin pipe does not wait. | A helper service reports itself running before it creates its pipe, and the service control manager starts the host service and the helpers in no fixed order (at boot, and `install` starts the host right after the helpers), so the first start of the host often met a missing pipe, reported `helper_unreachable` and was refused (run 45776803209). |
| AUD-PKG-R2-06/9 | 2026-11-26 | The platform suite is the required job `host-platform` of `ci.yml` and `build-verify.yml` (`components.HOST_PLATFORM_JOBS`): for changes of `services/host/` and of `host-platform.yml`, only in the public phase, never for a shared input alone, weekly on `main` through the schedule of the reusable workflow. | Plan row V1-13 and AUD-misc-testing-01 "Open" asked for the suite as a job of the plan once each system has a passing run; a weekly run alone let the suite stay red for weeks. The hosted macOS and Windows runners cost nothing only while the repository is public. |
