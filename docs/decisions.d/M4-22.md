| D-M4-22-1 | 2026-10-20 | Attach after completion: an upload entry is confirmed when `completeUpload` answered `200` (12 3.4), which releases the message; the message holds one slot `file:<key>` per attachment that the outbox fills from the upload's result (D-M4-15-6), and the wrapped `createMessage` executor turns the slots into `attachment_file_ids`. Parts: at most two in flight per upload (`UploadOps.parallelParts`), each read alone from disk with `Content-Digest`; after any failure the entry is retried by the outbox with the same `Idempotency-Key`, so `createUpload` returns the same session and only the parts `getUpload` did not confirm are sent. `completeUpload` uses a second key derived from the entry ID.
