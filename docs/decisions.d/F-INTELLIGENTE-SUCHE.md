# F-INTELLIGENTE-SUCHE Search assistant (2026-11-04)

Owner request of 2026-11-04: a search at the top of the apps that understands a question in the
person's own words and returns links to the matching chat and development sessions. Decision:
[ADR 0075](../adr/0075-search-assistant-through-an-agent-over-the-full-text-search.md). Design note:
[search-assistant.md](../design/search-assistant.md). Normative: [14-search.md](../spec/14-search.md)
4.10, [09-agents.md](../spec/09-agents.md) 10.6 and 18.16.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-IS-1 | 2026-11-04 | The server runs the search (terms, two full-text searches with the person's rights, fusion per thread) and asks one assistant agent once per question over the gateway; no model call in the server, no agent with tools, no embeddings. | B10 and I5 keep model credentials out of the server, ADR 0022 keeps runtimes outside; permissions stay in SQL; one call bounds cost and time; no local embedding model or vector extension ships. |
| D-IS-2 | 2026-11-04 | The candidates sent to the assistant are additionally filtered by the assistant agent's own `thread.read` and `message.read` (filter mode, fresh request scope); the payload carries opaque references and no ids; an answer may only name references it was sent. | The person may read more than the agent; neither the agent nor its operator may see content outside the agent's grants, and a model must not be able to name anything else. |
| D-IS-3 | 2026-11-04 | `search.assist` has the right `human` and the class `rl.trigger`; `search.assist.respond` is agent-self on the addressed agent; every other principal and an unknown request get `404`. Both have the effect `read` (05 2.7), and both count as writing for the read-only rule of "view as". | A question starts a model call on the agent's account like a trigger; the Authorizer hides another agent like an unknown resource (ADR 0017); nothing is stored, but "view as" must not spend another person's agent. |
| D-IS-4 | 2026-11-04 | Terms: runs of letters and digits, lower case, at least three letters, without the German and English stop words of `internal/search/domain/stopwords/` (including the words of asking for a search), at most `search.assist.max_terms`; the query is the terms joined with `or`, cut to `search.query_max_chars`. | A question as `websearch_to_tsquery` text is an AND of every word and finds nothing; the `simple` branch would match every function word. |
| D-IS-5 | 2026-11-04 | Fusion by reciprocal rank (`1/(60 + rank)`), the title list counting twice; the first message hit of a thread is its jump target and excerpt; equal scores order the newer first. | A title names the session; reciprocal rank needs no comparable scores across the two lists. |
| D-IS-6 | 2026-11-04 | The model may add terms; the server runs one more full-text pass with them and appends the new hits after the picks, without a reason. A question without candidates still goes to the assistant. | Synonyms and the other language find sessions the person's words miss, with one model call per question. |
| D-IS-7 | 2026-11-04 | The popup keeps its conversation; each request carries `history` (earlier questions, their terms and shown threads), at most `search.assist.max_turns`. The server stores nothing of a question; open requests live in memory like autocompletion. | Short-lived by construction: nothing to delete, no thread, no forum entry. |
| D-IS-8 | 2026-11-04 | The answer's `costs` are shown as `cost_estimate` (sum of `amount_micros` in one currency, else none), for information; no `cost_entries` row is written. | `cost_entries` requires a run, thread and channel (03); a question has none. The model call runs on the agent's account like its runs. |
| D-IS-9 | 2026-11-04 | Fallbacks: no agent configured, no relay or live connection, no valid answer within `search.assist.timeout` (below `http.request_timeout`, cross-check `search_assist_below_request_timeout`). A statement timeout of a search stays `503 search_timeout`. | The person always gets the best the server has; the request context must outlive the wait. |
| D-IS-10 | 2026-11-04 | No question, term, reference or reason is logged; one log line names mode, fallback reason and the counts. | Questions may contain anything (SEC-LOG-4); the canary test holds it. |
| D-IS-11 | 2026-11-04 | Runs are found through their thread; the run detail view of F-LAUFHISTORIE is not linked yet. | That view is not on `main`; the thread shows its runs. |
| D-IS-12 | 2026-11-04 | The web console gets no search assistant. | The console is the administration and statistics surface (ADR 0028); sessions open in the apps. |
