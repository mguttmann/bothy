# FIX-PUSH-RENEW The app renews a push registration the server disabled or no longer has

| No | Date | Ruling | Reason |
|---|---|---|---|
| FPR/1 | 2026-11-23 | With the same provider token and a stored registration ID, the app reads the state of that registration at every start (`signedIn`) and every return to the foreground (`PushPlatform.foreground`, driven by the app lifecycle in `pushPlatformProvider`): `getDevice` of the device of the session, member `push_registrations`. It registers the same token again when the registration is missing there or is disabled with `repeated_failures`, and leaves it for `logout`, `device_revoked`, `token_invalid`, `topic_mismatch` and `sender_mismatch`. A failed registration and a failed read are tried again at the next start or return to the foreground; nothing else changes (a new token still registers at once, the permission rule of D-M5-04-5 stays). The same code serves iOS, macOS and Android (`NativePush`); Windows has no push. Refines D-M5-04-5 and closes the item "a check of the registration by the app at its start" that AUD-SN01/1 left unbuilt. | Issue 618 (audit finding fn-push-notifications-2): the app registered only for a new token or a missing local ID (`_registerOnce` in `apps/client/lib/platform/push_platform.dart`) and never read its registration, so a row disabled with `repeated_failures` (rows of the former default `5`, or an instance that sets `push.max_consecutive_failures` above `0`) or removed on the server ended push for the device until logout, and a failed `registerPush` waited for the next start. `repeated_failures` says nothing about the token, so the same token is worth registering again; an ended session or device cannot register at all, and an answer of the provider about the token or the app would fail again with the same token, while a new token of the provider registers anyway. `getDevice` and `Device.push_registrations` exist (M3-22 design note 11), so no new API is needed; the read costs one `rl.read` request per start or return. |
| FPR/2 | 2026-11-23 | No server change: `registerPush` with the token of a disabled registration already renews it. The takeover of 13 13 deletes the row of `(provider, token)`, active or disabled, and inserts a new active row with `failure_count` `0`, a new ID and a new preview token; `disabled_at` and `disabled_reason` are not cleared on the old row, because the old row is gone. | Verified in `services/server/internal/notify/app/registrations.go` (`register`: `LockByProviderToken`, `Delete`, `Insert`) and held by `TestRegisterPush_RenewsADisabledRegistration`, which passed without a change. A new row also rotates the preview token, which the app stores with the new ID. |
