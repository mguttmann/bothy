# M4-32 Accessibility on the desktop

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M4-32-0 | 2026-10-25 | Built on main after M4-22, M4-24, M4-28, M4-29 and M4-33; the changelog entry and these rulings are fragments. Names that differ from the brief: the semantics tests of A1 to A6 live in `packages/admin_ui/test/a11y/` (the fakes of the administration are test code of that package and cannot be imported by `apps/client`); the screen harness and the audit are `dsAccessibilityTests` and `dsSemanticsProblems` in `package:design_system/testing.dart`, so the client and the administration share them; the macOS probe is `AccessibilityTreeProbe` in `apps/client/macos/Runner/MainFlutterWindow.swift` (debug builds only) instead of `RunnerTests/AXTreeProbe.swift`, because an XCTest target cannot run inside the integration test and the app's own hierarchy needs no project change; the Windows probe is the PowerShell script `apps/client/tool/uia_probe.ps1`. | Brief Boundaries (D-W-100, D-W-114): merged layout wins over the brief's names. |
| D-M4-32-1 | 2026-10-25 | Automated evidence per checklist item: per screen three tests of `dsAccessibilityTests` (roles, labels and states with the audit; contrast, labelled targets and the desktop target size in light and dark; text scale 2 in German and English without overflow and with every control reachable) plus assertions of the screen itself, and the platform tree test. The audit fails on a control without a name (also a disabled one), a tappable node without a role, an enabled button without a tap action, an empty or unlabelled image node, and a label that says one of its parts twice. The text contrast runs on macOS only (D-M4-07-10) and skips inactive controls by their merged state, which WCAG 1.4.3 excepts; the target size skips read-only text, which SC 2.5.8 excepts as inline text. | Brief Design note 1; WCAG 2.2 SC 1.4.3, 2.5.8, 4.1.2. |
| D-M4-32-2 | 2026-10-25 | The macOS probe runs inside the app: it turns the engine's accessibility on as VoiceOver does and walks the window's accessibility hierarchy through the attributes VoiceOver reads, so it needs no accessibility permission and works in the sandbox; the skip rule of the brief applies only where no probe exists (Linux), and the test then reports itself skipped. On Windows the probe reads UI Automation of the app's process from outside, as Narrator does. The probes compare names and roles of every button and text field and the live box container; the platform event of a live region or announcement is not read by them and stays in the manual pass. | Brief Design note 2; an out-of-process AX client needs a permission the CI runner does not grant to the sandboxed app. |
| D-M4-32-3 | 2026-10-25 | `tools/docs/tests/test_accessibility_checklist.py` reads every backticked test file and quoted test name of `docs/quality/accessibility-checklist.md` and fails when the file is missing or no test of it has the name (literal, templated with `$name`, or a screen name of `dsAccessibilityTests` with one of its three test names). | Brief Design note 3. |
| D-M4-32-4 | 2026-10-25 | Verdict rule: the ticket is done when every checklist item has its automated evidence green, every gap found is fixed with a test, and the manual section is written; the listening pass with VoiceOver and Narrator itself runs before each release (15 20) and is reported as not proven. | Brief fixed requirement 11. |
| D-M4-32-5 | 2026-10-25 | Gaps fixed at their class: `DsTappable` with its own label kept no tap action, so screen readers could not press buttons of cards or Stop (the child semantics are excluded, the tap and focus stay); `MenuItemButton` is a button only on the web, so every menu entry is a `DsMenuItem` with the button role and the selected state; Material controls without a visible focus get the ring of `DsFocusRing`; a control in a settings row and the level control of the notification tree are named by their row (`SettingRow.mergeSemantics`); names read twice (composer, waiting post, file tiles) are read once; raw `InkWell` rows of people, groups and the audit are `DsTappable` buttons; an empty spacer before the search filters is padding; the level state in the menu is readable text; the tray menu follows `users.locale`. | Brief fixed requirement 10: a gap is fixed in the member that has it, with a test that failed before. |
| D-M4-32-6 | 2026-10-25 | The macOS engine of Flutter presents a focused text field as its own `NSTextField` (`FlutterTextFieldCell`) without the semantics label: the platform tree has the field's role but no name (description, title, value and placeholder empty), measured with the composer of the thread view. The probe compares only the role of a text field on macOS (`namesTextFields`), the manual pass checks with VoiceOver that the field is named, and the report lists it as an engine limitation (01 8 "Known risk"). On Windows the name is compared. Two gaps of the client that the platform tree test found are fixed: the composer field is a node of its own (it took the history column with it before, and macOS presented the whole column as one text field), and in tests the engine only gets the semantics tree when the test enables it on the engine's dispatcher (flutter_test does not pass `setSemanticsTreeEnabled` on). | Brief Design note 2 and the known risk of 01 8; nothing in the client can set the name of the engine's own text field. |
