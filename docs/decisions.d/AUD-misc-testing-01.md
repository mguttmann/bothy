# AUD-misc-testing-01 Failed runs without a pull request, the phone terminal suite, the desktop E2E in CI

Work package of the audit of 2026-11-11 for the runs outside a pull request
(`.github/workflows/host-platform.yml`, `.github/workflows/e2e-mobile.yml`,
`.github/workflows/e2e-desktop.yml`, `.github/workflows/ci.yml`). Findings: `testing-1`,
`testing-3` and `testing-2` (one cause, rulings 1 to 4; `testing-1` also ruling 8), `testing-3`
(ruling 5), `testing-4` (rulings 6 and 7), `testing-9` (ruling 9). Rulings 10 and 12 belong to no
finding: two defects of the desktop E2E stack that the proof of ruling 6 ran into. Ruling 11 is the
switch of the alert of rulings 1 to 3: it is built and off, because AUD-CG1/7 of the work package
AUD-misc-ci-gates-01, merged while this one was built, puts the question to the owner.

| AUD-MISC-TESTING-01/10 | 2026-11-12 | The leaf certificate of the E2E stack names its subject and authority key identifiers (section `v3_leaf` of `test_ca` in `infra/compose/e2e.sh`). | No finding of the audit; the proof of ruling 6 ran into it. | AUD-MISC-TESTING-01/11 | 2026-11-12 | The alert of rulings 1 to 3 is built and switched off. `red-runs.yml` passes `--dry-run` unless the repository variable `BOTHY_RED_RUN_ISSUES` is exactly `true`: it reads the runs and the issues, writes nothing, and prints the red runs with the `gh` commands it would run to the log of its job. | AUD-MISC-TESTING-01/12 | 2026-11-12 | The driver of the Fake-Agent (`tools/ci/desktop_e2e_agent.py`) reads a patch that the Fake-Agent rebased as a patch that went through: a first answer `409 base_version_conflict` with `rebased` at status 200. A run document that changed since the agent read it answers `409 base_version_conflict`, and an adapter rebases on the current document (06 section 5). The Fake-Agent of the Python SDK does that and returns the first answer with the outcome of the rebase in `rebased`; the driver looked only at the first status and ended. The nightly phone run never showed it: none of its suites starts an agent run. `test_a_patch_the_fake_agent_rebased_is_no_failure` fails with that message without the change. |

## Open

For the next run in each area. None of these is a known wrong result of the product.

Red runs:

- The comment of a red run names jobs and steps, not the failed test (ruling 3).
- The switch of ruling 11 is off until the owner sets `BOTHY_RED_RUN_ISSUES`; AUD-CG1/7 holds
  the question. Until then the red runs are in the log of the hourly job only.
- A failed run of `red-runs.yml` itself is reported only by a later run of it that passes.
- An issue of a workflow whose file was removed stays open until someone closes it.

E2E in CI:

- The first hosted runs of this package's changes exist only after the merge: the phone terminal
  suite behind its first tap (ruling 5, proven on a local emulator of the same screen) and the
  job `headless` (ruling 6), which has no run on a Linux runner yet. `testing-4` is closed by
  the first night in which that job passes.
- The driver of the Fake-Agent prints nothing when it accepts a rebased patch (ruling 12), so a
  log cannot show that a conflict happened and was survived.
- The desktop E2E suites as a job of the plan for changes of the apps, the packages and the
  server (ruling 7), once the nightly run has shown how long it takes and how stable it is.
- iOS has no E2E run in CI (D-M5-11-5, unchanged).

Platform runs (V1-13, next to the list in docs/decisions.d/AUD-misc-misc-01.md):

- Windows unit tests (`testing-9`): run `go test ./...` of `services/host` once on
  `windows-2025`, read which tests fail, and remove their Unix path assumptions or mark the
  tests that belong to another system with a build constraint; then widen the step of
  `host-platform.yml` to every package.
- A run on Windows 11: add `windows-11-arm` to the matrix of `host-platform.yml` once the job on
  `windows-2025` passes. Windows 10 has no hosted runner.
- The platform suite as a job of the plan for changes of `services/host`, once each system has a
  passing run (ruling 8).
