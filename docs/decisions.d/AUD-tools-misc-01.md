# AUD-tools-misc-01 Deny-list scan of the files of every commit, push text of `wake_ended`, three findings recorded

Work package of the audit of 2026-11-11 for tools that share no other package
(`tools/denylist`, `tools/catalog`, `tools/configdoc`, `tools/arch-check`, `tools/pyproject.toml`).
Findings: `quality-tools-1` (rulings 1 and 2), `client-native-1` (rulings 3 and 4),
`architecture-1` (ruling 5), `privacy-4` (ruling 6) and `quality-tools-3` (ruling 7). Two are
fixed. Three are real and not built here, because each needs a design of its own; their rows
name the size.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-TM1/1 | 2026-11-12 | The default scan of `tools/denylist/denylist_scan.py` reads, for every commit it checks (`--range`, without a range every commit of `HEAD`), content and name of every file the commit adds or changes, from the commit itself: `git rev-list`, then `git diff-tree --stdin -r -c --root --no-renames`, then one `git cat-file --batch` (`scan_commit_files`). Both rule sets and the `@exclude-path` globs apply. The kinds are `commit-content` and `commit-path`; the location names the first commit of the range that holds the file under that name. A merge commit counts for what differs from all of its parents (the combined form of `-c`). A name and a content that the scan of the tracked files read are not reported a second time, compared by the bytes of the working file, so an edit that is not committed does not hide a commit. An output of git in another form and an object that the clone lacks end the scan with the configuration error (exit code 2). No workflow, no `make` target and no range changes. | The scan read the working tree plus message and identities of the range; file content of the commits between was read by `--history` only. A term that one commit added and a later commit of the same push removed passed the pre-push hook, the pull request job and `denylist-main`, although the repository is public from the first push (ADR 0039) and the earlier commit stays readable there. The files are read per commit and not, as `--history` does, from `git rev-list --objects`: that list shows every object once under one name, so a name that only an earlier commit used is not in it, and it names no commit to fix. A merge that takes a file unchanged from a parent outside the range would otherwise report what is published already and cannot be fixed in the branch. |
| AUD-TM1/2 | 2026-11-12 | Not built for the deny list: `--history` keeps its mechanism, and its limit is written into the README of the scanner (it reads every object once under the name `git rev-list --objects --all` lists it with, so a name that only an earlier commit used for an unchanged file is not read). No limit on the size of a range is added: a scan without a range reads the files of every commit of `HEAD`. The build branches keep the generic rules on the server. | The finding is about the default run, which every push goes through; `--history` is the step of the going-public checklist and no gate of a push, so a change of it is a change beyond the finding. The limit was reproduced on 2026-11-12 with a file that one commit names with a term of the example list and the next commit renames: `--history` ends clean, the default scan reports `commit-path`. It is recorded here for the next work package on the scanner (`quality-tools-12`). A scan without a range exists for the first push, where every commit is new to the remote. The private list needs the secret of the protected environment, which a push to a build branch does not get; such a push runs the pre-push hook, which reads the files of the commits with the private list. |
| AUD-TM1/3 | 2026-11-12 | The kind `wake_ended` gets its push text: the ARB key `pushBodyWakeEnded` in every language, the native key `PUSH_BODY_WAKE_ENDED` in `tools/catalog/apple_strings.py` (so in both `Localizable.strings` and both `strings.xml`), the entry in `PushTexts.bodies` of the Android push service, and the member in the lists `PushPreview.kinds` (Swift) and `PushPreview.KINDS` (Kotlin). The English text is "An agent did not continue on its own". Two tests in `tools/catalog/tests/test_apple_strings.py` hold the `PUSH_BODY_*` keys of the generator (in the order of the enum) and the three native lists to `NotificationKind` of `docs/api/openapi.yaml`. | The server sends `PUSH_BODY_<KIND>` for every kind since AR-04, and no file of the apps held the key of the ninth kind: iOS and macOS show the key itself for a missing key (the finding states this from the code, not from a device), Android fell back to the text of `message`. One text has to fit both causes of the kind (a wake-up that ended `refused`, `expired` or `failed`, and a run that ended `usage_limited`, 13 section 2), so it says what both have in common in the words of 01 6.21 ("continue on their own") and names no wake-up. The generated files were already held to the generator by `make codegen-check`; nothing held the generator and the hand-written lists to the contract, which is how the kind was missed. |
| AUD-TM1/4 | 2026-11-12 | Not built for the push text: the Notification Service Extension does not replace a `PUSH_BODY_` text the app cannot resolve; `PushPayload.previewKinds` (Swift) and `PushHint.PREVIEW_KINDS` (Kotlin) keep the six kinds of 13 6.4 check 1, so a `wake_ended` push shows its placeholder and fetches no preview; the list of keys in 13 6.1 is not edited here. | With the two tests the apps of a commit hold a text for every kind of the contract of that commit, which is what the finding found missing.
