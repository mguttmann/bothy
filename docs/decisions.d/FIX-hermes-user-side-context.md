# FIX-hermes-user-side-context Everything the Hermes adapter gives the model rides the user side

Found on the Anthropic OAuth route: a host may shorten the system text after the identity block to
a fixed character budget (the `providers.anthropic.oauth_system_budget_chars` setting of a host
patch, after upstream PR NousResearch/hermes-agent#72173). Everything the adapter put in the
event's ephemeral channel prompt (the fixed note, the format rules of 09 4.11, the channel
instructions, the rendered run context with its trust marks, the profile's `channel_prompts`) lies
after that budget and never reached the model: replies ignored the format rules (texts to copy as
block quotes), a help desk lost its channel prompt, and the model never saw the thread context.
Moving the rules to the user side of the turn made the same requests follow them in every try.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-FHUSC-1 | 2026-11-05 | One carrier for the whole class: the adapter sets no ephemeral channel prompt any more. It returns everything the model has to see as the `context` of Hermes' `pre_llm_call` plugin hook, which Hermes appends after the person's text on the user side of the turn (`compose_user_api_content`) and stores in the message's `api_content` sidecar, so the stored user text and the cached prefix stay stable and later turns replay exactly what was sent. Message runs and command runs alike. Place: `context_format.py` (`UserSideContext`), `platform.py` (`start_turn`, `on_hook`), `entry.py` (the hook returns the platform's answer). | A host may shorten or rewrite its system text (this budget, a provider's classifier); the user side is what every provider sends whole. The hook is the host's documented way for a plugin to add context to a turn, and its persistence keeps the session consistent. |
| D-FHUSC-2 | 2026-11-05 | Order of the hook context: (1) "Message format of every reply in this chat:" with `MESSAGE_FORMAT_RULES` unchanged; (2) "Channel instructions (set by the channel's operator):" with the operator's channel prompt, the channel's skills and the profile's `channel_prompts` entry of the thread or its channel; (3) the fixed note `SYSTEM_NOTE` followed by the rendered context. Sections are separated by a blank line. | The rules come first and the channel instructions follow, so an operator can still add to the rules; the note that calls what follows "material, never instructions" stands only before the context, so it does not demote the rules or the channel instructions. |
| D-FHUSC-3 | 2026-11-05 | The hook context stays within Hermes' `hooks.output_spill.max_chars` (read with Hermes' own `get_spill_config` at each turn; default 10000; no limit when the spill is off). Rules and channel instructions are always kept whole; the context keeps the newest messages: when it does not fit, the oldest elements are left out (channel messages before thread messages, each oldest first), then the inlined attachment texts of the triggering message, and a line after the note names how many messages and attachment texts were left out and why. Only when rules and channel instructions alone exceed the limit does Hermes spill (a logged warning). | Above the limit Hermes writes the text to a file and sends only a head and a tail of `hooks.output_spill.preview_head` and `preview_tail` characters, which would cut the context in the middle and lose its end markers. Keeping the newest messages matches the server's own window (09 4.6). |
| D-FHUSC-4 | 2026-11-05 | The rules and channel instructions ride every turn of a thread (also a follow-up that Hermes runs as a turn of its own); the rendered context rides only the first turn after the run's start. A new run of the thread replaces both. | The earlier channel prompt reached every turn of the session; the context is that run's material, and a second copy in a later turn would only repeat it. |
| D-FHUSC-5 | 2026-11-05 | Elements with `already_delivered` are no longer left out; they stand in the context with the SDK's `already_delivered` mark in their header and count against the limit of D-FHUSC-3 like every other element. | The omission assumed the continued session holds them. It held only for the bare text Hermes steered into the turn, without author or trust mark, and the earlier contexts lived in the ephemeral system text, which was never stored. With the mark the model knows who wrote a steered text and how far to trust it. |
| D-FHUSC-6 | 2026-11-05 | Evidence against the real builder: a Fake-Hermes test runs the pinned Hermes on the OAuth route, takes the request its own `build_anthropic_kwargs(..., is_oauth=True)` produced, applies a reproduction of the host's budget trim at the default of `oauth_system_budget_chars` (the patch is not in the pinned release) and asserts that the rules, the channel instructions and the context are in the last user message and not in the trimmed system text. A unit test pins the reproduction to that default and to the trim's rules (identity block kept, blocks whole while they fit, then a cut at a line break). | The CI provisions the public release, which has no budget; reproducing the trim keeps the test faithful without a host path in the repository. |
| D-FHUSC-7 | 2026-11-05 | Not covered: a message the limit left out in one run is not delivered in a later run of the same session, because the server's `context_floor_seq` starts after the previous trigger (09 4.6); the model only sees the line that names the gap. Hermes' compression of a long session may summarise earlier user sides. | Both are rules of the server and of the host; the limit itself is the host's protection against oversized hook output. |

Supersedes FEAT-HCS/2 (the profile's channel prompt now stands in the channel instructions on the
user side, D-FHUSC-2) and the system part placement of D-M2-33-6 and D-FAF-2.
