# F-KOPIER-FLIESSTEXT Copy a text block as running text

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-F-KOPIER-FLIESSTEXT-1 | 2026-11-04 | A code block offers a second copy, "Copy as text", when its fence has no language or one of `text`, `plaintext`, `txt`, `markdown`, `md` (any case, `dsIsProseBlock`); a block in any other language, also an unknown one, never does. An indented code block has no language either and offers it too: the renderer cannot tell it from a fence without a language, and the extra button changes nothing about "Copy code". | Owner report 2026-11-04: an agent sent a reply to forward in a fenced block without a language and broke its lines by hand after about 60 to 70 characters; "Copy code" copied those breaks, so a paste into a mail or another chat arrived as a packet of short lines. Agents choose that fence to make a text copyable; code is never changed, so the copy of a programming language block stays the exact copy of 01 6.12 item 3. `txt` and `md` are the short names of the same text languages. |
| D-F-KOPIER-FLIESSTEXT-2 | 2026-11-04 | `dsProseCopy` joins the lines of a paragraph with one space (the white space at the join collapses into it) and keeps a blank line as the break between paragraphs (several become one, a line of only white space counts as blank, leading and trailing blank lines and the trailing line break go). A list item (`-`, `*`, `+`, a number with `.` or `)`, each followed by a space or the line end) and an ATX heading start their own line, a heading also ends it, and a following line without such a start joins the item, so a broken list item stays one item and a nested item keeps its indentation. A line that ends in a Markdown hard break (two or more spaces or a backslash that is not itself escaped) and is followed by another line of its paragraph keeps its line break, the marker goes; a backslash at the end of a paragraph or an escaped one stays text. CRLF and a lone CR are line breaks. Every other character is kept, Unicode included. The copy is plain text only, no HTML form. | The brief: paragraphs and lists must survive, emoji, umlauts and dashes must not change. A heading line must not swallow the next line. A dash or a number inside a sentence (`-3`, `2.5`) is no list item because the marker needs a following space. The hard break marker is Markdown syntax, not text a mail should show. Running text has no formatting to carry. |
| D-F-KOPIER-FLIESSTEXT-3 | 2026-11-04 | The button is a text button like "Copy code" (D-M4-48-1), in `type.label` and `color.text.link`. On the desktop it sits between the toggle and "Copy code", and the keyboard reaches "Copy code" first, "Copy as text" second and the toggle last. On the phone, where a tap on the block copies it exactly, the header shows the toggle and "Copy as text"; a tap on the button is the button's and never also copies the block, like the toggle (01 6.14 item 1); on a narrow block both controls share the room the language label leaves and wrap their labels rather than run past the header's edge. | "Copy code" stays the first stop as M4-48 and M4-49 decided. On the phone the tap on the block has to stay the exact copy, so the running text copy needs its own target. |
| D-F-KOPIER-FLIESSTEXT-4 | 2026-11-04 | The toggle "Wrap lines" is renamed "Wrap display" ("Anzeige umbrechen") and gets a tooltip on the desktop, also its screen reader hint: "Changes only the display; the copy keeps the line breaks of the text". "Copy as text" has the tooltip "Joins the lines of each paragraph, for a mail or a message". The phone shows no tooltips, because a long press there opens the message menu; the hints stay for the screen reader. The behavior of the toggle is unchanged. | The owner read the toggle as broken: "Wrap lines" sounded like it would change the line breaks of the text, but on a text broken by hand it changed nothing visible and never affected the copy. Its job (making long lines readable on screen, 01 6.14) is still needed, so it stays and says what it does; the copy that removes the breaks is the new button. |
| D-F-KOPIER-FLIESSTEXT-5 | 2026-11-04 | Scope: the shared renderer of `packages/design_system` draws every code block of the four apps (macOS, Windows, iOS, Android), so the change applies to all of them in one place; the web console renders no messages and needs no change. The prompts of agents that break their lines are not part of this ticket. Follow-up list: names in docs and comments that describe the current toggle now say "Wrap display"; the briefs, the plan, the changelog fragments and the rulings of M4-48 to M4-50 keep "Wrap lines" as the record of their time, and the doc comments of `apps/client/lib/app/code_block_preference.dart` and `packages/local_store` (with their generated copies) keep it because changing them needs code generation in packages this ticket does not touch otherwise. | The renderer is the one place of code block rendering (01 6.12, 6.14). Historical records are not rewritten. |
| D-F-KOPIER-FLIESSTEXT-6 | 2026-11-04 | Tests: unit tests of `dsProseCopy` with the reported case rebuilt without personal data (two paragraphs broken by hand, emoji, umlauts, an en dash, typographic and straight quotes, a list with a broken item) and the edge cases (list markers, nested items, blank lines, CRLF and CR, a trailing line break, hard breaks, a heading, a dash or number inside a sentence); widget tests under macOS and Windows and under iOS and Android that the button exists only on text blocks and writes the joined text to the clipboard while "Copy code" stays exact, the keyboard order and the German labels; the golden of the long single-line block shows the new header. | The brief asks for exactly these tests; no GUI test runs on a maintainer's machine. |
