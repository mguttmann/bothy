# I570 Hide "Transcribe" where the server cannot transcribe

Issue 570: the client showed "Transcribe" for every voice message whose transcript is `none` or
`failed`, also with `voice.enabled` off or in transcription mode `agent`; the tap then answered
`feature_disabled`, which read as a fault.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-I570-1 | 2026-11-08 | `getInstance` gets the optional member `voice_transcription_mode` (`off`, `agent`, `service`): the effective mode of the caller, `voice.transcription_mode` with `service` reported as `off` while `voice.enabled` is off for the caller (the rule of `files.Transcripts.Mode`, applied by `instance` to the flags it already evaluates for `features`). | The client had no way to know the mode, which is process configuration. Optional, not required: a client or SDK model then keeps reading the answer of an older server, and hand-written instance payloads in other tests stay valid (the follow-ups of M5-08 show what a new required member breaks). `instance` gets no edge to `files`; it binds the same configuration key. |
| D-I570-2 | 2026-11-08 | The client offers "Transcribe" only while the stored flag `voice.enabled` (instance row, refreshed by `getInstance` and every snapshot) is on and `getInstance` reports `service`. With the switch off it asks nothing; a change of the switch asks `getInstance` again. A server without the member counts as "no Transcribe". The answer is read through `FileTranscripts.serverMode` and kept for the session (`serverTranscribesProvider`), not stored in the local database. | The stored flag follows a change of `voice.enabled` without a new request, and the mode only changes with a server restart. Not storing the mode avoids a schema migration of the local database for one value. In mode `service` the server starts the transcript of every voice message by itself, so hiding the button from an older server loses only the retry of a failed transcript. |
| D-I570-3 | 2026-11-08 | No text explaining that the agent transcribes: in mode `agent` a transcript in state `none` shows nothing until the agent submits it. | The issue allows either hiding or explaining; a note under every voice message of an agent-mode instance would be noise, and the transcript appears on `file.updated` when the agent delivers it. |
