# FLAKE-client-golden-timeout A drift stream that ends in fake time holds the close of the database

| No | Date | Ruling | Reason |
|---|---|---|---|
| FCGT/1 | 2026-11-01 | `openInMemoryForTests` of `local_store` takes `closeStreamsSynchronously` (default off), passed to drift's `DatabaseConnection`. A test file that shares one database across widget or golden tests and closes it in `tearDownAll` opens it with the option; `new_chat_golden_test.dart` does, and its first test ends an outbox stream in fake time and holds that no timer stays behind. `packages/local_store/test/close_test.dart` holds both sides: without the option the close waits for the timer of a watch that ended, with it a watch that ends starts no timer and the close completes. The default stays off, because the other tests open a database per test and `close_test.dart` relies on drift's timer. | Issue #238, run 40975481761 (PR of M4-47, commit 6a6869e): the new chat view watched `Outbox.watchThread` in `initState`, so the goldens ended a drift query stream in fake time. drift stops such a stream on `Timer.run` (`drift` 2.35.2, `stream_queries.dart:156`), made in the fake time of the test, which never fires once that test is over; four goldens failed with "A Timer is still pending", and `StreamQueryStore.close` waits for every such timer (`stream_queries.dart:191`), so `db.close()` in `tearDownAll` hung until the 12-minute timeout and `tools/ci/flakes.py` recorded the passing retry of `(tearDownAll)` as a flake. Reproduced locally: the new test without the option fails with the pending timer and `tearDownAll` hangs (no end within ten minutes with `--timeout 60s`); with it the file passes 50 runs in a row under load. The view on main opens the stream only while the post has files, so the goldens no longer trigger it, but nothing held the shared database to that. |
