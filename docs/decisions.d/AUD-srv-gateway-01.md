# AUD-srv-gateway-01 Gateway findings of the audit of 2026-11-11

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-SG1/1 | 2026-11-11 | A hint that crosses processes gets its preview fields on the receiving node: `Cluster.applyHint` asks the new port `HintPreviews` of the gateway, which `internal/wire` implements with the preview builder of `notify`. The rule is one function for both callers, `PreviewBuilder.HintFields` (the job `notify.gateway_send` and the receiving node): the recipient's `notify.preview_mode` of that moment, only a kind that points at a message, nothing for a deleted, run or system message, never an image. The signal keeps its members, IDs and codes only. The node builds the fields first and its hub then checks `push.deliver` for every connection, on the thread the signal names; the fields are those of a message in that thread only (AUD-SG1/9). A failed read of these fields sends the hint with its IDs and logs `gateway hint sent without its preview` with the signal kind and the error kind. This closes the second gap of D-M4-34-3. | With separate `api` and `worker`, the layout of the Compose stack, every desktop toast showed the placeholder: the worker's job built the fields and the signal dropped them (`TestDesktopHintWithSeparateWorker`, red before with a payload of IDs only). Text in `NOTIFY` is ruled out by R-Stack (02 11.6). No frame leaves without the hub's check, and the fields belong to the thread it checks (AUD-SG1/9), so a reader who lost access gets no name (13 6.3). A signal is at most once and has no retry, so a hint without text is better than no hint. |
| AUD-SG1/2 | 2026-11-11 | The desktop E2E flow of the notification (`apps/client/e2e_test/flows/session_flows.dart`) is not changed here: it still asserts tag, route and a title, and its comment still names the gap of D-M4-34-3. | The suite needs a desktop session and the Compose stack and runs before a release (D-M4-34-7), not in the checks of this change; an assertion nobody ran would prove nothing. The texts are proven on the server path by `TestDesktopHintWithSeparateWorker` (api nodes and a separate worker on PostgreSQL) and in the app by `toast_content_test.dart`. The next run of the desktop E2E adds the assertion on title and text and corrects the comment. |
| AUD-SG1/3 | 2026-11-11 | `decodeFocus` hands `background_thread_ids` on to the handler. `TestDecode_EveryPropertyReachesTheFrame` holds the class: for every op of `gateway_ops.enabled` every top-level property of the body schema changes the frame of `app`, and a property without a sample fails. The use case tests of `app` keep their own JSON decoder. | The member was added to the schema, the frame and the handler (M2-51), and the only test ran through the test decoder, so the codec of production dropped it and the control room cards got no `run.updated` (`TestLiveBoxBackgroundFocusGetsRunUpdated` against a started server, red before). The class test sits where the fault was, at the codec; running the `app` tests through the adapter would make the use case tests depend on the contract file. Members of nested objects are not covered by it. |
| AUD-SG1/4 | 2026-11-11 | The failed-credentials rule of 02 9.1 applies to the gateway: before the credentials of `identify`, `resume` or `reauth` are checked, one token of `rl.public_auth` of the client address is reserved; it is kept for a rejected token or proof, a session the authenticator reports revoked, a credential it reports inactive without an error (`actor.Actor.CredentialInactive`: a revoked or expired API token, a revoked session, device or device key) and a device or session that is not the token's, and given back otherwise (valid credentials, `token_expired`, `use_dpop_nonce`, an error of identity, a refusal of `authorize` for an active credential). With the bucket empty, `identify` and `resume` close with `4008` and `retry_after=<seconds>` before any check, and `reauth` answers `error` with `rate_limited`, the same text as `detail`, and keeps the connection. `rl.gateway_connect` still counts after the check, per device or token. | 05 section 3 says that `rl.public_auth` counts every failed check of presented credentials; REST and the terminal channels did (D-M2-46-11), the gateway did not, so a client could have any number of signatures checked. The counted outcomes are those of the REST chain, so one address has one budget on every path. That includes the inactive credential: the authenticator returns its actor without an error and only `authorize` refuses it, with `4012`, so a settlement that looked at the error alone gave the token back for every check of a revoked credential (`TestGatewayFailedCredentialsCountPublicAuth` with the access token of a revoked session, red before). Reserving before the check keeps parallel connections from passing on one token. `reauth` keeps its contract of answering `error` (M1-64). |
| AUD-SG1/5 | 2026-11-11 | `Gateway.Open` reads the sync epoch of `hello` from the instance row until one read succeeded and keeps it for the life of the process. | The threat model (5.5) promised that the upgrade reads no database, and the code read the instance row on every upgrade, before anybody was authenticated. The epoch of a running server cannot change: only `bothy restore finalize` sets a new one, and it refuses while a server process is connected (M7-04). |
| AUD-SG1/6 | 2026-11-11 | No bound on the connections one client address holds without `identify` is built. | 04 6.3 fixes that the upgrade checks nothing but the origin, and `sync.identify_timeout` ends every such connection. A bound needs a new configuration value, a refusal at the upgrade that every client and SDK has to handle, and a rule for many people behind one address; the audit reproduced no damage. Threat model 5.5 now says that the server does not bound that number. |
| AUD-SG1/7 | 2026-11-11 | `detail` of the frame `error` stays machine data, with the forms listed in 04 6.2. The first field error has one form on every op, `<pointer>: <code>`: `command.autocomplete_result` follows `run.update`, which replaces the form of D-M2-17-9. `GatewayError` gets no new members (`reason`, `errors`, a wait in milliseconds, a correlation ID), and the schema text of `detail` and `ref` in `openapi.yaml` and the client action of `4008` in `asyncapi.yaml` stay as they are. | The audit found three forms and no rule in 04. The Python and the TypeScript SDK read `detail` of `run.update` today (`run_not_active`), so `detail` is contract already and cannot turn into prose; the wait is readable as `retry_after=<seconds>`, the form clients parse for `4008`. New members change the schema that the generated clients and the fakes are built from, which is a contract change of its own. The contract files are embedded in those clients; their texts follow with the next contract change, and 04 is the rule until then. |
| AUD-SG1/8 | 2026-11-11 | The interview of the agent builder and the search assistant stay on the api node of the request, like command autocomplete; this is now written down in 02 11.6, 26 6.1, 14 4.10 and `docs/operations/multi-node.md` (sections 4 and 6). No path across nodes and no edge rule is built. | Both go to one connection of their agent in the process of the request and keep the open request in its memory, so with several api nodes they answer only what reaches the agent's node; the guide listed only autocomplete. A path across nodes would have to carry the interview or the question, and signals carry no text (02 11.6); it is the open design of D-M7-17-5. No edge rule keeps the person's request, the agent's connection and the agent's answer on one node: the gateway upgrade names no principal, so the edge cannot tell the agent's connection from any other. |
| AUD-SG1/9 | 2026-11-11 | `PreviewBuilder.HintFields` and the port `HintPreviews` take the thread of the hint beside the message and give no field unless the message lies in that thread; a hint without a thread gets none, and `Cluster.applyHint` does not ask the port for it. Such a hint still goes out with its IDs, as it did before AUD-SG1/1. The rule sits in the one function of both callers, so the job `notify.gateway_send` follows it with the thread and the message of its arguments. `gateway.hint` keeps its shape: `thread_id` and `message_id` stay optional members. | The hub admits a hint on the thread its signal names, or on the recipient alone when it names none, and the preview of AUD-SG1/1 was read from the thread of the message. The two are a checked pair only in a signal of the job. PostgreSQL has no privilege on `NOTIFY`, so every role that may connect, also one without a right on the schema of the tables such as the monitoring role, can send a signal that names a message of a thread the recipient may not read, without a thread or with a thread the recipient reads; the recipient's node then sent the names of the place, the author and the excerpt of that message (`TestHintSignalPreviewNeedsTheThreadOfTheMessage`, red before with both signals). The IDs alone are what the sender of such a signal already knows. Dropping the hint instead would change what a node did with such a signal before this ticket, for no gain. |
