# M4-42 Desktop thread layout: hide the channel column, drag every border

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M4-42-1 | 2026-10-28 | The "channel column" next to an open thread is the main history of a text channel (D2) or, for a forum post, the pinned forum overview (D15). One device state hides it for both: "Hide channel" in the thread header, Cmd+Shift+H (Ctrl+Shift+H) and the item of the Thread menu. The button shows only where such a column exists (a thread beside its main history, a post with the overview pinned); the main history alone and a post with an unpinned overview have nothing to hide. Hiding the overview leaves its pin as it is, so "Show channel" brings it back. | Owner feedback 2026-10-28: the thread where the person writes stayed small next to its channel; the brief names threads and forum posts. One switch keeps the keys and the button predictable. |
| D-M4-42-2 | 2026-10-28 | The state is the column `shell_view_state.channel_column_hidden` of `local_store` (schema version 7, false in the kept row), read through `channelColumnHiddenProvider`; it is not synchronized, because 01 11 has no key for it and it is a view preference like the pin of the overview (D-SB-6). It is one value for all threads, so opening another thread from the sidebar or a link keeps it. | Brief requirement (3); the other layout state of the shell (pin, collapsed groups) is kept the same way. |
| D-M4-42-3 | 2026-10-28 | The existing header button "Column" keeps showing and hiding the session column; the new state gets its own button "Hide channel" / "Show channel" next to it. Its icon is the existing `action.back` (hide, the thread grows to the left) and `action.collapse` (show); no new glyph. | "Column" already has one meaning in D1 and its own shortcut (Cmd+Shift+I); folding a second column into it would make one button toggle two things. A new glyph would need the icon pipeline of the design system for a header action. |
| D-M4-42-4 | 2026-10-28 | The border between the main history and the thread is a drag handle like the other column borders (`ColumnDragHandle`, now public in `column_layout.dart`). Its width is the column name `main_history` in `layout.column_widths`; the thread takes the rest, so a wider window gives the room to the thread. Without a stored width the two share the room as before. A drag keeps both at least `DsLayout.columnMin`; one drag is one `putMySetting` at its end, and the dragged width stays until the stored setting comes back. | 01 D1 says every border can be dragged; `layout.column_widths` accepts any column name (01 11), so no new setting key. |
| D-M4-42-5 | 2026-10-28 | While the channel column is hidden the thread keeps its place in the widget tree (a keyed `Expanded`), so its scroll position and its input survive hiding and showing. The labels of the header actions are cut with an ellipsis instead of overflowing when a column is at its minimum width. | A thread at `DsLayout.columnMin` overflowed its header by 20 pixels in the drag test. |
