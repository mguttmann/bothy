# FIX-operator-upload-grant Operators may upload, and the attachment notice follows the instance language

| No | Date | Ruling | Reason |
|---|---|---|---|
| FIX-OUG/1 | 2026-11-02 | Cause: the operator rule (05 2.3 point 4, 07 2.9, R-AZ-13) gave the effective operator of a channel and the fixed operator of a thread `write` without a grant row, but no capability. `file.upload` needs `write` and `+upload`, so every operator that sends files (answer attachments of the Claude Code runner, media of an adapter) was refused with `403 forbidden`, `capability_missing` until the owner added a grant with `upload` by hand. | Reported from operation (an answer ended with `upload_refused (forbidden, capability_missing)`); reproduced with `TestOperatorRuleUpload` (authz, fakes) and `TestOperatorRuleGivesUpload` (integration, real Postgres): both answered `forbidden/capability_missing` for the operator Texter before the change. |
| FIX-OUG/2 | 2026-11-02 | The operator rule now gives `write` and `upload`, computed in `domain.Effective` like `write`, with no grant row. Assigning an operator, `space.operator.set`, `channel.operator.set`, the inheritance of a space's default operator and the import switch-over all set the operator and so give `upload` with it; a change of operator takes it away with `write`. `access.changed` of the old and new operator carries the capability; `access.explain` shows it under the source `operator`, also for a space's default operator. | The rule exists so that no second, separately maintained grant is needed and nothing remains after a change (R-AZ-13); an `upload` grant created on assignment would be exactly such a second grant, would have to be found and revoked on every change of operator or inheritance, and would need a marker column to tell it from a grant the owner gave. |
| FIX-OUG/3 | 2026-11-02 | No migration and no startup reconciliation: the rule is evaluated on every decision, so every existing operator holds `upload` as soon as the new server runs. Grants with `upload` that owners added by hand stay as they are; revoking one no longer takes `upload` from an operator. | Nothing stored needs re-deriving: the access views before and after a rights change are computed in the same transaction, never persisted. The spec models no owner removal of operator rights; an owner who wants no files from an agent switches `supports_files_out` off. |
| FIX-OUG/4 | 2026-11-02 | `upload` comes with the operator rule whatever `supports_files_out` says; the owner's switch stays the gate where 09 2.2 puts it, at the acceptance of a message with attachments (`403 feature_disabled`). | `supports_files_out` lives in `agents.operator_config`, and `agent.update` is no rights change (05 4); capabilities are part of the rights snapshot, `access.changed` and the cached decisions keyed by `permission_version`, so tying the capability to the switch would make every `agent.update` a rights change. The switch already stops files from reaching a channel; an upload alone attaches nothing and is removed by the cleanup of unattached files. |
| FIX-OUG/5 | 2026-11-02 | The runner's notice follows `locale_default` of `getInstance` (the read it already makes for the limits): German (`de`, `de-*`) gets a German heading, a German last line and a readable German text per code (the texts stand in 09 18.10 point 5 and in the runner), with fixed texts for the common problems (`forbidden` with `capability_missing` reads as "upload not allowed (right missing)") and the problem code and reason in brackets for any other; every other or unknown locale keeps the English notice with codes. The locale is stored in the set's record, so a notice rebuilt by an adopting runner speaks the same language; a record of an older runner has none and stays English. Place: `reply_attachments.build_notice`, `notice_language`; `reply_upload.AttachmentSetRecord.locale`. | The runner has no thread or person language as data: its prompt is English, and guessing the language from the request text would be a heuristic. The instance locale is the owner's choice for the instance and is read anyway. A failed `getInstance` (`limits_unavailable`) leaves the locale unknown, so that notice is English. |
| FIX-OUG/6 | 2026-11-02 | Out of scope: a fixed thread operator that is not the channel's operator still cannot upload, because `file.upload` is decided on the channel (`scope_channel_id`), where only the channel's operator holds the rule; English notices keep the codes (the format of 09 18.10 point 5); the Hermes adapter's own texts are unchanged. | The reported case is the channel's operator; the thread case needs `createUpload` to name the thread, an API change. These are minors for the next change in this area. |
