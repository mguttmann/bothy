# FLAKE-pgtest-watchdog-usr1 The stub server of the watchdog tests keeps an early SIGINT

| No | Date | Ruling | Reason |
|---|---|---|---|
| FPWU/1 | 2026-11-01 | The stub entry point of the watchdog tests blocks SIGINT before it writes `ready`, then waits in `sigsuspend` (unblock and wait in one step) instead of a long `sleep`; an `alarm` keeps its bounded life. With `STUB_PAUSE` it stops itself (SIGSTOP) between `ready` and the wait, and `TestWatchdogStubKeepsAnINTAfterReady` sends SIGINT there. No product change, no retry, no longer sleep. Refines M1-72/14. | Run 41308492022 (shard 2 of 6) failed `TestWatchdogScriptRestartsOnUSR1` after 9.31s at `watchdog_test.go:216` (no `stopped` file when the second start was seen); a pass takes about 5.5s. Perl runs a `%SIG` handler only at an op boundary, and `sleep` does not look for a signal that arrived before it blocked. A SIGINT the watchdog sends (`pgtest.go:148`) after the stub's last check and before its `sleep 60` (old `watchdog_test.go:24`) therefore waits the full minute; `halt` gives up after `PGTEST_STOP_WAIT` (5s in the tests, `pgtest.go:150`) and `restart` starts the next stub, which matches the extra 4s of the failing run. The test sends SIGUSR1 as soon as it sees `ready`, so a host that preempts the stub between writing `ready` and `sleep` opens the gap. Reproduced with the gap widened by a slow operation in the `sleep` statement: the same failure message in 3 of 3 runs, about 9.1s each, on Linux (bash 5.2, Perl 5.40) and macOS; with the fix 3 of 3 pass with the same widening. |
