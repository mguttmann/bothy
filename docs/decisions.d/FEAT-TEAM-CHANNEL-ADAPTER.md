# FEAT-TEAM-CHANNEL-ADAPTER Hermes adapter slice of the team channels

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-TCA-1 | 2026-11-21 | The Python SDK's token check compares the `message_id` of a `team` token with the payload (`expectation_for`); the FakeServer serves `team` runs (`trigger(..., team=, authority=)`), agent-written follow-ups and names the run of an accepted `Invocation-Token` header (`FakeServer.token_run`). | Before, `expectation_for` knew no `team` row, so the SDK answered every team run `invalid_invocation_token` before the adapter saw it (checked on the base 0fce26bd4: the run failed, nothing crashed). The Claude Code runner uses the same SDK and needs the same row. |
| D-TCA-2 | 2026-11-21 | An input is the owner's word exactly when its message has origin `human` and the server's `source` is `owner`; any other combination (an agent's message with `source = owner`, a person's message with `source = member`) is treated as a member's request. | 09 3.9.9 "Owner authority": never from `triggered_by`, the token's `sub` or the member `team`. Failing closed on a mismatch keeps a member's text from ever reading as the owner's. |
| D-TCA-3 | 2026-11-21 | A member's text reaches Hermes behind the line `[von Mitglied @x: ...]` (the brief's marker with an English sentence for the model) in every place a text enters a turn: the first turn, a steered follow-up, a follow-up's own turn while the run holds work, and a typed answer to an open card. Every follow-up whose message is not of origin `human` gets it, also in a run that is not a `team` run; the handle comes from the run's member list by the author's agent, else from the agent's own handle, and any handle not in the form of 09 3.9.1 prints as `unknown`. | A member's input may reach any running run of the work thread, also one a person started there (09 3.9.8), whose invocation carries no member list; outside team channels no agent message is a follow-up (07 SR4), so the rule labels only team inputs. Cleaning the handle keeps instructions out of the label. |
| D-TCA-4 | 2026-11-21 | Hermes takes every turn of a run, a member's own follow-up turn included, from the run's person (the token's `sub`, which for a `team` run is the authority); the label, not the sender, names the member. | Hermes' admission checks the sender against its allow list (09 17.7); the source member's agent is no triggerer and would be refused, ending the run `failed`. The authority is the principal the server checked (09 3.9.5), and steered texts already reach Hermes as the run's person. |
| D-TCA-5 | 2026-11-21 | A member's typed answer to an open card goes the way of any text (09 17.5): a clarify gets the labelled text, an approval is denied and a slash confirmation cancelled. Nothing is added for members. | A text never approves a Hermes prompt; a member's text therefore cannot either. The denial is the safe side, and the server disables the card when it accepts the follow-up (09 11.6). |
| D-TCA-6 | 2026-11-21 | A `team` run without its member `team` (or with a handle not in the server's form) is refused before the start (`failed`, `adapter_error`); every other trigger kind the adapter does not know is refused as before. | Without the facts the turn could not say who wrote the input; refusing is the failure 09 3.9.9 names for an adapter that cannot serve a team run. |
| D-TCA-7 | 2026-11-21 | The run-token binding needs no change in the adapter: answers, cards and files go through the SDK outbox, which binds each entry to its run's newest token, and every other request of a turn runs inside `RunHandle.bound`, also when Hermes reports on a task of another run. A test runs a team run beside a concurrent run whose Hermes task reports for the team thread, with stage steps, a steered follow-up and an edit, and checks with `FakeServer.token_run` that every request about a run carries a token of exactly that run; removing the binding of `_bound` makes it fail. | The brief asks to verify every request path; the paths were read in `handler.py` (live box, steps of background work and stage files, edits, uploads, cards, finish), and the registries of external jobs and stages are local files that send nothing. |
