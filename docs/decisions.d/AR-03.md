| D-AR-03-1 | 2026-11-07 | File layout of a launch: `<runner.state_dir>/turns/<run_id>.<attempt>.<try>` with `.stdin` (named pipe), `.inputs`, `.spec`, `.keeper`, `.cli`, `.fed`, `.exit`, all mode `0600`; the run's input lines in `turns/<run_id>.lines`. `.spec` carries the CLI's argument list, environment, folder, stream and stderr files and lock descriptors; the keeper reads it once and removes it at its start, and a relaunch removes every file of the earlier try. | D-AR-03-2 | 2026-11-07 | The keeper relays the named pipe into an anonymous pipe that is the CLI's stdin, writes the initial inputs into that pipe before any relayed line, and closes it once every write end of the named pipe is closed; 09 18.19.4 items 2 and 3 and 18.19.12 changed accordingly. | Captured with the pinned CLI 2.1.288 against a local stand-in (`tests/real_cli/test_named_pipe.py`): with a named pipe directly as stdin the CLI reads every line but does not end on macOS when the last writer closes, while it ends at once on an anonymous pipe. Without the relay "close stdin" would never end a turn. The relay keeps every promise of 18.19.4 (the keeper holds no lock descriptor, its SIGKILL ends the input, the runner's write gets `ENXIO` or `EPIPE` once the keeper is gone). |

The SDK heartbeat accepts the capabilities `turn_handover` and `wakes` (`true` only).
