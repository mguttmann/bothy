# FEAT-markdown-viewer Document viewer of attachments

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-FEAT-MDV-1 | 2026-11-02 | One renderer: the viewer draws Markdown with `DsMarkdown` of the design system, the renderer of messages. It gained what the viewer needs and messages share: `DsMarkdownDocument` (parse once, the top-level blocks and the headings with GitHub anchors), `DsMarkdown.block` (one block, so a `ListView.builder` renders a long document lazily), `search` (marks of a `DsTextSearch`) with `DsMarkdown.countMatches`, which runs the renderer's own builder so the count always equals what is drawn, and `resolveLink` for links the message policy leaves inactive. A second renderer (a package such as `flutter_markdown`) was rejected. | Owner brief: "fix there, not a second one"; one renderer keeps the security rules of SEC-OUT-1 and SEC-OUT-2 in one place. |
| D-FEAT-MDV-2 | 2026-11-02 | Syntax colors come from a small lexer in the design system (`dsCodeTokens`: keywords, strings, numbers, comments, capitalized type names of the common languages, diff lines) colored with existing tokens (category, success, danger and muted text colors). They apply to code blocks of messages too. No highlighting package and no new color tokens. | A dependency would need a license and supply chain review for a display feature; the category tokens are already contrast checked in both themes. |
| D-FEAT-MDV-3 | 2026-11-02 | Kinds and bounds: by extension first, then MIME type (`.md`, `.markdown`, `.txt`, `.log`, `.json`, `.yaml`, `.yml`, `.csv`; `text/markdown`, `text/plain`, `application/json`, `text/csv`, YAML types). The viewer reads at most 8 MB; above 1 MB a document opens raw with a notice and "Show formatted"; JSON is pretty-printed up to 1 MB; a CSV of at most 500 rows and 40 columns renders as a Markdown table whose cells are escaped. Raw text renders in rows of 100 lines. | A whole file in memory is bounded; the lazy list keeps both forms responsive; escaping keeps CSV cells as their text. |
| D-FEAT-MDV-4 | 2026-11-02 | Security: only a file in the state `ready` (scan passed, upload complete) opens, through the same checked download as "Open" (`Repr-Digest`, 12 9.3); a blocked or unchecked file has no viewer. Raw HTML stays text. Images resolve only to attachments of the same message (thumbnail from the server); a web image is a button that loads it on a click. Relative links activate only when they name an attachment of the message, `#anchor` links only jump; every other relative or unknown link stays text. | Brief: no HTML execution, no remote content without a click, respect `scan_status`. |
| D-FEAT-MDV-5 | 2026-11-02 | The tile of a viewable file opens the viewer on a tap of the tile and on "Open"; "Open in another app" in the viewer keeps the system path (with its refusal of programs, D-M4-22-14). "Download/share" is "Save as" on every platform: the client has no share-out port to the system share sheet, and adding one is outside this ticket. | One way to reach the viewer from history and the files section; the existing save path works on all four platforms. |
| D-FEAT-MDV-6 | 2026-11-02 | Selection: on the desktop the viewer's list sits under `DsListSelection`, so a drag beyond the edge scrolls (FIX-drag-select-autoscroll); `DsListSelection.separator` joins rows with an empty line for Markdown blocks and a line break for raw rows. The phone uses a plain `SelectionArea`. | Reuse of the history's selection; raw rows are pieces of one text. |
| D-FEAT-MDV-7 | 2026-11-02 | Search counts per row; a match across two rows of raw text (a row boundary is a line break, which the search field cannot contain) cannot occur, and in rendered Markdown a match is found within one text run (a paragraph's words between inline elements), not across bold or link boundaries. Raw mode finds everything. The jump goes to the row of the current match, by an estimate first and then `Scrollable.ensureVisible` once the row is built. | Exact counts without a second text model; raw mode stays the complete search. |
| D-FEAT-MDV-8 | 2026-11-02 | Tests: unit tests of the kinds, bounds, JSON and CSV; design system tests of syntax runs, search marks against `countMatches`, link resolution and the document; widget tests from the history (a tap on a `.md` opens the viewer and not the system app, a blocked file does not open, relative links and images, Open in another app, Esc, phone layout with the sheet) and of the view (raw toggle, search with Cmd+F, Enter, buttons and Esc, scroll to a far match, contents panel, reading keys, copy all, large file, JSON, CSV); goldens of the sample with every element on desktop and phone in light and dark. No build on a device, so the feel with a real trackpad and screen reader on the phone is not proven by them. | Brief: tests first for every behavior. |
