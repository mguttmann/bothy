# sidebar-sessions Sessions in the sidebar (design of 2026-10-27)

Owner feedback of 2026-10-27 after the first use of the desktop app: the sessions of a project
should be visible and startable in the sidebar, as in Discord; the post list column takes too much
space; the difference between `#` and the forum icon is unclear. Design note:
[sidebar-sessions.md](../design/sidebar-sessions.md). Tickets: M2-52, M4-40, M4-41, M5-15.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-SB-1 | 2026-10-27 | Open forum posts and open threads of text channels appear nested under their channel in the sidebar; the post list column is closed by default; a forum row opens the forum overview D15 in the content column, which can be pinned as its own column (R-PR-17 replaces R-PR-01). | The owner works from the sidebar as in Discord; a fixed list column costs a quarter of a laptop screen; the overview keeps search, tags and Done. |
| D-SB-2 | 2026-10-27 | A thread row shows when the thread is open and selected, has an active run, waits for the person, is unread or had activity within `ui.sidebar_thread_window`; at most `ui.sidebar_threads_per_channel` rows per channel, chosen by selected, waiting, active run, unread mentions, unread, newest activity (01 6.8). | The sidebar shows what is going on now; a bound keeps a busy forum from pushing other channels away; everything that needs the person stays visible. |
| D-SB-3 | 2026-10-27 | Thread rows are ordered by creation, newest first; a row that no longer qualifies leaves only while the pointer is outside the sidebar and the focus is not in it. | Ordering by activity would move rows under the pointer while agents write. |
| D-SB-4 | 2026-10-27 | An expanded forum group ends with "All posts" (opens the overview) carrying unread and mentions of the posts not shown; no total count; text channels have no such row. | A count would be wrong without loading every page; text channels have no list view. |
| D-SB-5 | 2026-10-27 | Thread rows carry the channel row states and the run state icon; an expanded channel row counts only threads not shown below it, a collapsed one all; the run dot aggregates all threads. | No number twice on screen, nothing unread out of view. |
| D-SB-6 | 2026-10-27 | Group collapse (default expanded) and the pinned overview column (default not pinned) are kept per device in the local database, not synchronized. | 01 11 has no key for them and a new setting key would need a server change for a view preference (as D-M4-19-4). |
| D-SB-7 | 2026-10-27 | Thread and channel rows are not draggable; moving a thread stays the dialog. | Thread order is derived, channel order is global; an accidental drop must not move a session. |
| D-SB-8 | 2026-10-27 | The sidebar is one tree with thread rows; channel navigation and next unread include thread rows; Cmd+N or Ctrl+N starts a new chat in the forum of the focused or selected row; Cmd+Shift+O or Ctrl+Shift+O pins or unpins the overview column (01 7). | The sessions are the main navigation targets; existing shortcuts keep their meaning. |
| D-SB-9 | 2026-10-27 | "+" at every forum row and Cmd+N open a new chat view in the content column without a dialog; the title is optional where an operator agent names the chat (09 12) and required otherwise; the draft row is the existing new post draft of the forum (one per person and forum); sending creates the post through the outbox. | The most frequent action in a dev forum needs one step; the auto-title already removes the title. |
| D-SB-10 | 2026-10-27 | Icons `channel.text`, `channel.forum` and new `channel.project` with tooltip, screen reader text, header subtitle and empty state that explain the kind; project forums say "New chat", others "New post". | The owner asked the question at first sight; showcase standard 01 1 item 8. |
| D-SB-11 | 2026-10-27 | The snapshot carries `active_threads` (per channel every open thread with an active run, plus open threads active within `sync.snapshot_thread_window`, up to `sync.snapshot_threads_per_channel`); `Channel.project_bound`; creating or deleting a project binding raises `channels.version` and writes `channel.updated` (04 6.3, R-SY-28). | One snapshot instead of one list request per channel on every connect; a derived flag instead of exposing the binding, which needs `manage`. |
| D-SB-12 | 2026-10-27 | No git worktree per post; the runner and its working folder per turn stay unchanged; an agent with tool class `host` may create a worktree on the person's request (09 18.1, R-AG-28). | Owner clarification of 2026-10-27; a worktree per post would change readiness, cleanup and the working folder contract for an unwanted feature. |
| D-SB-13 | 2026-10-27 | On iPhone and Android, M1 shows the same groups with the same rules and the "+" action; a thread row opens M3, the forum name opens M2; no pinned column. | The same model on every device; on the phone the list is a page anyway. |
