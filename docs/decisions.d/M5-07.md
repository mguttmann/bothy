| D-M5-07-1 | 2026-10-25 | Recorder parameters: AAC-LC (`AudioEncoder.aacLc`), one channel, `client.voice.bitrate`, the sample rate of the package default for AAC-LC (44.1 kHz), into `<temporary folder>/voice/voice-<ms>.m4a`. The recording stops `voiceStopMargin` before `voice_max_duration_ms`: three AAC frames of 1024 samples at the sample rate (about 70 ms: the frame in progress and two frames of encoder priming that the `mvhd` duration can count) plus `voiceStopAllowance` (500 ms) for a stop timer that fires late on a busy phone and for the stop call; the recording time counts from before the start call, so a slow start counts against the limit as well. The brief asked to compute the margin from the bitrate; an AAC frame is a fixed number of samples, so its length follows from the sample rate, not the bitrate. The duration of a finished recording is its `mvhd` duration read like the server (`mp4Duration`, whole milliseconds rounded down, `mehd` for a fragmented file); a recording longer than the limit is never sent and shows `voicePhoneTooLong`. The notice comes `client.voice.limit_notice_lead` (new App key, default `30s`) before the stop, at once when the limit is shorter; its text is fixed when it appears, so it is announced once. The desktop controller of M4-22 uses the same stop margin and duration. | Brief Design note 1; 12 8.1 (`voice_too_long`, a duration equal to the limit passes). |
| D-M5-07-2 | 2026-10-25 | States and the background: `idle`, `recording`, `locked`, `stopping`, `ready`, `discarded`, plus `denied` and `failed` for the notices. Release in `recording` sends; a release while the system asks for the microphone records nothing (the finger left to answer the dialog). A recording stopped by the limit waits in `ready` even with the finger still down, and lifting the finger does not send it. When the app is no longer `resumed` (inactive, hidden, paused: a call, the app switcher, the background) or the system cancels the touch, a running recording stops and waits in `ready` with play, Send and Discard; "keeps it as locked" of the brief becomes this preview, because the recorder cannot continue in the background. Nothing is ever sent without the person. | Brief Design note 2. |
| D-M5-07-3 | 2026-10-25 | Button mode: the microphone shows it while `MediaQuery.accessibleNavigation` is true (VoiceOver, TalkBack, Switch Control and other services the person turns on in the system settings); a tap starts in `locked`, the microphone then reads "Stop recording", and Stop, Send and Discard are buttons. In the gesture mode the microphone's semantic tap action also records in `locked`, so an assistive technology that does not set `accessibleNavigation` still records without a gesture. The remaining time is a live region whose text changes at most once per `a11y.live_announce_min_interval` of recording time; the visible time still ticks every second. A separate in-app setting for the button mode was not added: the brief's "turns it on in settings" is read as the system's accessibility settings, and a new synced setting is outside this ticket's scope. | Brief Design note 3; 01 8. |
| D-M5-07-4 | 2026-10-25 | Photos: `image_picker` 1.2.x (BSD-3-Clause, flutter.dev) for the system photo picker (`PHPickerViewController` on iOS; the Android photo picker through `useAndroidPhotoPicker`) and the camera, chosen over own Pigeon code because it is maintained by the Flutter team and passes the license gate. It is asked for quality `photoJpegQuality` (90) and no full metadata: below 100 both platforms re-encode a photo that is neither PNG nor GIF (HEIC included) as JPEG, and the library needs no photo permission, so Android declares no storage permission; iOS still declares `NSPhotoLibraryUsageDescription` (a text that says the app reads only the photos the person chooses), because App Store review requires the key once the picker package links the photo library API, although the system never asks for it. `MediaPicker` keeps a JPEG as it is and encodes any other image `package:image` 4.x (MIT) can decode (PNG, GIF, WebP, BMP, TIFF) as JPEG at the same quality in a background isolate, transparency on white and the first frame of an animation; a file it cannot decode is refused (`photoUnsupported`). The name gets `.jpg`. The size check is the composer's (`file_max_upload_bytes`, refusal before the outbox); the local preview of the chip shows the outgoing copy until the upload deletes it; the chip is shared with the desktop composer, so an image attached there shows the same preview. Permission texts: `NSMicrophoneUsageDescription`, `NSCameraUsageDescription` and `NSPhotoLibraryUsageDescription` in `Info.plist` (English) and `InfoPlist.strings` per language, generated from the ARB messages `permissionMicrophoneUsage`, `permissionCameraUsage` and `permissionPhotoLibraryUsage` by `tools/ci/info_plist_strings.py` and checked in `make codegen-check`; Android declares `RECORD_AUDIO` and `CAMERA` (camera and microphone not required features). A denied permission shows the platform's path to the settings. | Brief Design note 4; 15 14; 12 7.1; ADR 0047. |
| D-M5-07-5 | 2026-10-25 | Temporary files: recordings and photos are written into the app's temporary folder (`getTemporaryDirectory`, private to the app); the outbox takes them by moving the recording (copying a photo) into `<instance folder>/outgoing/<key>/` and deleting the temporary file, so an upload that waits offline survives the system emptying the temporary folder; the outbox deletes the outgoing copy after the upload. A discarded recording is deleted at once, a refused file the app wrote itself (a photo over the limit, a pasted image) at the refusal, the picker's own file right after the conversion, and a finished recording that was never sent when the composer goes. | Brief requirement 16. |
