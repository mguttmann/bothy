# HERMES-MEDIA Hermes adapter: files, images, voice and video, and voice input

The Hermes adapter answered `send_document`, `send_voice`, `send_video` and `send_image` with a
failure and reported neither `files_out` nor `voice_input` (spec 09 section 17.3). This ticket
builds both directions.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-HERMES-MEDIA-1 | 2026-10-29 | Each local file Hermes sends (`send_document`, `send_image_file`, `send_voice`, `send_video`) becomes one message of the run with the caption as text and that file attached, in the order Hermes calls; images that Hermes batches come one per message through the base `send_multiple_images`. Place: `platform.py`, `handler.py` (`on_file`). | Hermes calls one method per file after its text; one message per call keeps Hermes' order and its own failure notice per file, without buffering the answer. |
| D-HERMES-MEDIA-2 | 2026-10-29 | Before the upload the adapter applies Hermes' `validate_media_delivery_path` again and passes on the resolved path; `media.read_local_file` opens it with `O_NOFOLLOW`, accepts only a non-empty regular file within `file_max_upload_bytes` (`getInstance`, once per run), hashes it and uploads through the same descriptor. Upload in mode `direct` only, with a fresh `Idempotency-Key` per create and complete, and `abortUpload` after any failure. No record survives a crash; an open session expires on the server. Place: `media.py`, `platform.py`. | Hermes checks `MEDIA:` paths, but other callers of `send_document` do not; the policy is Hermes' own (credential files, system paths, strict mode). A changed file fails the server's digest check instead of sending other bytes. A crash mid upload loses only that file, Hermes' notice is not sent then; a persisted record (as in M3-12) is not worth it for a file the model can send again. |
| D-HERMES-MEDIA-3 | 2026-10-29 | Every file, `send_voice` audio included, goes as `kind = text` with the file attached; the adapter sends no `kind = voice`. `send_image` with a web address sends the address as a message; the adapter downloads nothing from the web. Place: `handler.on_file`, `platform.py`. | The server refuses `kind = voice` with `409 file_not_ready` until the scan job after `completeUpload` has made the file final and written its detected type (12 3.4, 8.1); waiting for `file.updated` would hold the turn for a scan of unknown length, and the SDK outbox treats the 409 as final. An attached audio file still plays in the thread. The FakeServer refuses a voice message with an unscanned upload, so a test catches a return to `kind = voice`. A download would make the adapter host fetch addresses from model output. |
| D-HERMES-MEDIA-4 | 2026-10-29 | Voice input: the adapter transcribes the trigger's audio attachments without a transcript (scan `clean` or `skipped`) after `startRun` with the gateway's own `_enrich_message_with_transcription` on a copy in Hermes' audio cache, sets the transcript on the attachment (trust of the message) and submits it with `submitTranscript`; without a transcript Hermes' own note goes before the person's text. The turn's event stays a text event. `voice_input` is reported while `stt.enabled` holds and `_get_provider` finds a provider (connect and every heartbeat). `files_out` is always reported. Place: `handler.py` (`_transcribed`), `platform.py` (`transcribe`, `voice_input`), stubs `tools/transcription_tools.pyi`, `gateway/run_inbound_transcription.pyi`. | A voice event would let Hermes transcribe inside the turn, where the adapter cannot read the transcript for the server (09 13) and Hermes would echo it as an extra message. The same Hermes function gives the same provider, fallback and notes as Hermes' other platforms. The owner switch `supports_files_out` decides about files on the server. |
| D-HERMES-MEDIA-5 | 2026-10-29 | No recording scenario for files and voice; the Fake-Hermes tests (`tests/fake_hermes/test_media.py`) run the pinned Hermes with `MEDIA:` tags and a command speech to text provider and are the evidence; the stub contract holds the new private surfaces. | The recording measures surfaces before a build (17.10); adding a point would re-record every fixture. The Fake-Hermes tests run the same pin in the normal test run and check the effect at the server. |
