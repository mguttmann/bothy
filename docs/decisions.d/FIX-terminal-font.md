# FIX-terminal-font The terminal font and its cell width

| No | Date | Ruling | Reason |
|---|---|---|---|
| FIX-TF/1 | 2026-11-02 | Cause: the terminal view passed xterm the plain family `Atkinson Hyperlegible Mono` of `DsType.code` with its fallback list (`ui-monospace`, `SF Mono`, `Cascadia Mono`, `Consolas`, `monospace`). The apps register the font of `design_system` only as `packages/design_system/Atkinson Hyperlegible Mono`, so the plain name resolved nowhere, and on macOS none of the fallbacks did either (`ui-monospace` is a CSS keyword, `SF Mono` is not a system font). xterm 4.0.0 measures its cell as the width of `m` in the first font that resolves (`calcCharSize`) and draws every character at column times that width, so on macOS the cell came from the wide `m` of the proportional system font while each glyph kept its own narrow advance: the letter-spaced lines of the owner's report. | Proven by `packages/terminal_ui/test/terminal_font_test.dart` and `test/goldens/terminal_line_golden_test.dart`, which fail with the former style (cell 12.0 instead of 7.2 at size 12, 14.0 instead of 8.4 at size 14; both golden variants differ). |
| FIX-TF/2 | 2026-11-02 | The terminal draws with its own bundled font, JetBrains Mono 2.304 (OFL-1.1, tag `v2.304`, commit `cd5227bd1f61dff3bbd6c814ceaf7ffd95e947d9`), in `packages/terminal_ui/fonts/`: the static regular, bold, italic and bold italic files and the OFL text, recorded in `fonts/MANIFEST.json`. Not Atkinson Hyperlegible Mono: it has no box drawing (U+2500 to U+257F), no block elements and no powerline symbols, which shells, `tmux` and prompts draw; JetBrains Mono has all 128 box drawing and 32 block characters and the powerline symbols U+E0A0 to U+E0A2 and U+E0B0 to U+E0B3, and one advance (600 of 1000 units) for every glyph. Static files instead of the variable file, because xterm selects bold and italic only through `FontWeight` and `FontStyle`, without a `wght` variation. | Owner feedback 2026-11-02 after the first real session from the macOS app; the brief asks for a bundled open-licensed monospace font with powerline and box drawing coverage. |
| FIX-TF/3 | 2026-11-02 | `terminalTextStyle(fontSize)` is the only text style of the grid: family `packages/terminal_ui/JetBrains Mono` (the name every app, desktop, phone and web console, registers), xterm's line height 1.2, no letter spacing, and system monospace and emoji fonts only as fallback for characters the bundled font lacks. The marks painter (cursor and selection) uses the same style. The PTY size needs no change of its own: xterm derives the columns from the view width and the measured cell and the controller sends them as `resize`; the test holds that path for three font sizes. | One measured font on every platform; a family that resolves in the app is the precondition of a correct cell. |
| FIX-TF/4 | 2026-11-02 | Tests: the test setup of `terminal_ui` loads the package's own fonts under the plain and the package name, so the tests resolve `packages/terminal_ui/JetBrains Mono` like the apps. The goldens that show terminal text change with the cell width: `terminal_connected`, `terminal_detached`, `terminal_ended`, `terminal_blocked`, `terminal_extra_keys` of `terminal_ui` and `phone_m8_detached_*` of the client, CI and macOS variants; the new `terminal_line` golden shows a text line, box drawing, block elements and a powerline prompt. | A test of the cell against the advance read from the font file does not depend on xterm's own measurement. |
