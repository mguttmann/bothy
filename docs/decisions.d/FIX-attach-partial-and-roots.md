| FIX-APR/1 | 2026-11-02 | Cause: an answer of the Claude Code runner announced two files; one lay outside the allowed roots (`outside_allowed_roots`), and the all-or-none rule of 09 18.10 point 4 (D-M3-12-5) then refused the valid file too (`set_not_sent`), so the answer arrived without any file. | FIX-APR/2 | 2026-11-02 | Best effort replaces all or none. Every file that passes its checks is staged, uploaded and sent with the answer; a file refused at any step (its own checks, the limits, a change after the check, its upload) is named in the notice with its reason, and the others go on. The limits count only files that pass: the first `message_max_attachments` go, later ones get `too_many`. A failed upload aborts only that file's session; the next file starts. When no file is left, or the server refuses the attachments of the message, the answer goes out without files and with the notice under a new `client_msg_id`, as before. `set_not_sent` is no longer given; it stays in the closed set for records of an older runner. Place: `reply_attachments.check_set`, `reply_upload.stage_files`, `upload_set`, `_send_attached`. Supersedes the set rule of D-M3-12-5, the "no further file starts" of D-M3-12-6 and "the set stays all or none" of D-M4-47-6. | A file the person asked for is worth more than the symmetry of the set; the refused files are still named, so nothing is lost silently. The rule protected nothing: every file that goes out passed all its own checks. |
| FIX-APR/3 | 2026-11-02 | The crash-safe record stays: it stores each refused file with the position of its `ATTACH:` line, each file's state, and the body of the answer is rebuilt from the record only, so an adopting runner sends the same text under the same `client_msg_id`, uploads each file once, does not retry a file that already failed, and the answer appears once. The notice names refused files in the order of their lines. Place: `reply_upload.AttachmentSetRecord.refuse`, `notice`. | Same guarantees as D-M3-12 notes 10 and 11; a record of an older runner (no positions) still loads and renders. |
| FIX-APR/4 | 2026-11-02 | The roots stay as they are (project, thread inbox, run `TMPDIR`; no absolute roots). Place: `prompts/runner_prompt.md`. | An absolute root would be shared by every forum the runner serves and could reach the state directory (09 18.10 "Roots"); a copy into the run's temporary directory is the agent's own act under its own rights (T-DEV-01) and passes the denied patterns like any other file. |
