# M4-49 Readable code blocks

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M4-49-1 | 2026-10-31 | A code block wraps its long lines by default on every platform (01 6.14 item 1); this replaces the rule of 01 6.4 that code blocks scroll horizontally instead of wrapping. The toggle "Wrap lines" sits in the header of every block, left of the copy button on the desktop and alone on the phone, as a small text button with the screen reader's toggled state; the copy button stays the first stop of the keyboard. A tap on the toggle on the phone is the toggle's, never a copy. | Owner decision 2026-10-31: a long sentence sent as a fenced block "to copy" showed as one cut-off line on macOS, so the owner could not read what he would copy. A text button needs no new glyph, like the copy button of M4-48 (D-M4-48-1). |
| D-M4-49-2 | 2026-10-31 | The wrap choice is one value per device, applied to every code block: the column `shell_view_state.code_blocks_unwrapped` (local_store schema version 11, false in the kept row), never synchronized. The design system stores nothing; `DsCodeBlockScope` hands down the value, a callback and the limit, and the app provides it at its root (`CodeBlockPreferenceScope`). A block shows its own toggle at once and follows the device again when the stored value catches up; without a local database (before the sign-in) or without a callback the toggle switches only its own block. | The owner asked for the choice to be "remembered per device"; one value per device is what a reader expects after switching once, and the local view state is where M4-42 and M4-45 keep the columns of the shell (01 11 has no key for view preferences, and a new personal setting would need a server change). |
| D-M4-49-3 | 2026-10-31 | Without wrap the block brings its own `Scrollbar` on its own controller, always visible on the desktop (`thumbVisibility`), shown while scrolling on the phone; the room below the text keeps the thumb off the last line. Shift and the mouse wheel and a sideways trackpad gesture are handled by the scroll view itself; a plain vertical wheel goes on to the history. | The default scroll behavior of Flutter draws a scrollbar only on vertical scroll views, which is why the live block showed none. Widget tests hold the thumb drag, shift and the wheel, the trackpad and the drag on the phone; how a real Mac trackpad feels is not proven by them. |
| D-M4-49-4 | 2026-10-31 | The collapse limit is the new App key `ui.code_block_collapse_lines` (default 20). The block measures its rendered height (wrapped lines count) against the limit times the line height of `type.code` at the current text scale; above it, the block shows that height with a fade of two lines and "Show all" below it, which expands it in place, and "Show less" collapses it. The expanded state lasts while the block is on screen. `DsClipToHeight` is the clip of the long message collapse (`DsCollapsible`), now shared. | The ticket asks for a configurable height; limits come from named keys, as `ui.message_collapse_lines` does for messages. A message longer than `ui.message_collapse_lines` still collapses first; its "Show more" then shows a long block in its own collapsed form. |
| D-M4-49-5 | 2026-10-31 | Hanging indent: Flutter's paragraph has none, so a wrapped line that starts with spaces or tabs is drawn as its indentation beside a box with the rest of the line (`DsCodeLines`); the indentation takes at most `DsCodeLines.maxIndentColumns` (16) columns of the code font and is cut, not dropped, beyond. Code blocks have no line numbers, so none are added. The width bound is computed from the font, not from the layout, because a message may sit in a layout that asks for intrinsic sizes. | 01 6.14 item 3. Deep indentation must not squeeze the text into a narrow strip on the phone. |
| D-M4-49-6 | 2026-10-31 | Display only: the copy of a block is `dsCodeBlockText` of the parse tree as before (D-M4-48-2), whatever the block shows; the M4-48 tests are unchanged except the former horizontal scroll test, which now holds the new default. Under a system selection the wrapped lines join with a line break and an indented line stays one piece, so a selection keeps the text. The code is its own semantics node, so the phone block's label stays "Copy code". Platform coverage: every behavior has widget tests under macOS and Windows and under iOS and Android and a golden of a long single-line block (light, dark, comfortable, touch); no GUI test runs on a maintainer's machine. | 01 6.12 items 3 and 6, 01 6.14 item 4. |
