| No | Date | Ruling | Reason |
|---|---|---|---|
| D-A1-03-1 | 2026-11-06 | The migration of `agents.hosted_by` is three expand steps: 00094 counts the rows with `adapter_kind = 'claude_agent'` and fails with their ids before it adds the nullable column, its foreign key and the two checks `NOT VALID`; 00095 validates them; 00096 builds the partial index concurrently. No step changes data. | The brief names one file; `docs/operations/upgrade.md` rules M4 (indexes concurrently, outside a transaction) and M5 (new constraints `NOT VALID`, validated in a later migration) need the split, as 00046/00047 and 00091 did. A `NOT VALID` check still holds for every new and changed row at once. |
| D-A1-03-2 | 2026-11-06 | The name of a hosted token is `hosted by <runner handle>`. | The token list of the agent then says who holds it, without a new column (design note 3 of the brief). |
| D-A1-03-3 | 2026-11-06 | `agent.host.set` and `agent.hosted_token.issue` run their write as a declared rights change, although 07 2.13 gives them the column "Permissions" no; the rights hook admits them like `host.pair` (`writesRightsState`). | Both revoke API tokens, and the Authorizer caches the state of a token by rights version; a revocation outside a rights change would leave the revoked token valid until the next one (the rule identity enforces for every revocation). |
| D-A1-03-4 | 2026-11-06 | A calling token without `dpop_jkt` gets `409 conflict` with `reason` `dpop_required` for `issueHostedAgentToken`. | A hosted token must be bound to the runner's key (26 3.3 item 2); with `auth.dpop_required_for` without `agent` a runner could hold an unbound token, and issuing an unbound hosted token would make a copy usable without the key. |
| D-A1-03-5 | 2026-11-06 | The cascade query revokes the active tokens whose `created_by` is the agent of a revoked agent token and whose `principal_id` is another principal, with the same `dpop_jkt`; `agent.disable` revokes all tokens the agent created for another principal; a host change those of the agent created by the old runner. A person's revoked token never cascades. | Only a hosting runner creates tokens for another agent (people create tokens through `token.create`, agents cannot), so `created_by` names the hosted tokens without a new column (D-A1-01-4); limiting the token cascade to agent tokens keeps the agent tokens an owner created alive when the owner's own token ends. |
| D-A1-03-6 | 2026-11-06 | A hosting runner whose last stored heartbeat reports no `hosts_agents` admits only `chat` for its hosted agents in `agent.tool_class.set`; `agent.host.set` to it is `host_not_capable`. A change of `hosts_agents` in a heartbeat is stored at once, not with the delayed flush. | Design note 5: the ceiling is the stored report; without one there is no ceiling to allow more than the class every new agent starts with. Storing at once lets an owner raise a class right after the runner raised its ceiling. |
| D-A1-03-7 | 2026-11-06 | `listHostedAgents` lists the active agents whose `hosted_by` is the caller and does not ask for `hosts_agents`; for any other agent the list is empty. | 26 3.2 item 1: the runner lists at start, possibly before its first heartbeat is stored; the list reveals nothing an agent does not host, and the token issue keeps the capability check. |
| D-A1-03-8 | 2026-11-06 | `agent.enable` of a built-in agent also writes `agent.hosting_changed` to its runner. | The runner then serves the agent again at once instead of after `runner.channels_resync_interval`; the payload is only the agent id. |
| D-A1-03-9 | 2026-11-06 | The audit entry of `agent.hosted_token.issue` names the agent (resource), the runner (`hosted_by`), the token id, the expiry and the number of revoked older tokens; it carries no token prefix. | The audit schema allows lower-case codes only, and the prefix is mixed case; the token id names the row that holds the prefix, as `token.create` does (SEC-AUD-5). |
| D-A1-03-10 | 2026-11-06 | The billing rule of 10 10.3 is one function (`checkHostedBilling`) that runs after the write, in the same unit, for `agent.billing_mode.set` (single, `set_all` and the guided switch), `agent.credential_holder.set` and `agent.host.set`; it locks the hosting runner's row. A personal built-in agent also needs a runner that reports `personal` in `billing_modes_supported`. | Design note 6; checking the stored rows after the change covers a runner and its agents switched together in one `set_all`; the row lock serializes a change of an agent with one of its runner, so neither can slip past the other. 10 10.3 item 2 names the reported mode. |
| D-A1-03-11 | 2026-11-06 | `setAgentHost` takes `If-Match` and a `reason` like the other owner changes of an agent; an agent that is not built in is `409 conflict` with `reason` `not_a_builtin_agent`. | 07 2.13 gives `agent.host.set` audit and step-up like `agent.tool_class.set`, which takes both; the reason code is the one of 26 4.1 item 4 for the same case. |
| D-A1-03-12 | 2026-11-06 | `agent.hosting_changed` names the receiving runner as its resource (kind `agent`) and the built-in agent in the payload. | Its receive action `agent.hosted.list` is agent-self, so the admission of delivery and catch-up decides on the runner itself; with the built-in agent as resource no runner could receive it. |
