# AUD-PKG-P06-server-runs-chat Server findings of the audit of 2026-11-11 in runs, chat, messaging, search, sync and agents

Work package of the audit of 2026-11-11 for the modules `runs`, `chat`, `messaging`, `search`,
`sync` and `agents` of the server. Each finding was read again on the current `main` first;
findings already fixed or decided since the audit are closed with their evidence and have no row
here.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-P06/1 | 2026-11-23 | A restore of a space or channel takes the order lock first (the space order for a space, the space row for a channel, as move does) and, when a live sibling holds its sort key, moves the restored item right after it with a free key; `SaveSpaceDeletion` and `SaveChannelDeletion` write `sort_key`. Not built: a partial unique index on `(space_id, sort_key)`. Test: `TestRestore_KeepsTheOrderUnique`. | createChannel and createSpace gave the deleted item's key away during the undo window; a unique index would fail the migration on instances that already hold twins (srv-chat-1). |
| AUD-P06/2 | 2026-11-23 | Deleting a draft blanks `content_md` of its stored `draft.updated` events inside `PersonalRepository.DeleteDraft` and `DeleteDraftsOf`, through the existing `Redactor` in the same transaction; this covers the delete, the empty put, the clear on send and the erasure in one place. Test: `TestDeletedDraftLeavesNoTextInTheLog`. | 20-privacy promises redaction on deletion for `event_log`; unsent texts of a deleted account stayed until `sync.event_retention` (srv-gateway-sync-12). Older `draft.updated` events of a draft that is still alive keep their text, like edited messages. |
| AUD-P06/3 | 2026-11-23 | A stored online or degraded presence that no process tracks is offline once its heartbeat is `agent.presence_timeout` plus `agent.heartbeat_persist_interval` old (inclusive), one rule `domain.StoredState` for `getAgent`, `listAgents`, `Statuses` and the status page; the unused `StateAt`, `PresenceView`, `ReportedDetailsFromStore` and the agents copy of `EffectiveToolClass` are removed (the rule lives in `authz/domain`). Tests: `TestStatuses_StaleStoredRowIsOffline`, `TestStoredStateBoundary`. | Two api nodes showed the same agent online and offline (srv-agents-8, srv-agents-13). The status page boundary moves from exclusive to inclusive by one instant. |
| AUD-P06/4 | 2026-11-23 | The tracker builds `agent.presence_changed` under the entry lock and publishes it after the release (`presenceEvent`, `send`); the class test of D-M2-21-11 parks the publisher too. Not built: a counter for failed flushes or publishes, own deadlines for the background calls, a flush that isolates one failing row. The three error lines carry `error.type` from the new `errs.Type`. | The hub may read the database while admitting a receiver, so the lock was held across a database wait (srv-agents-3, srv-agents-4). The other copies of the error class helper in jobs, pg, sync and files stay; moving them to `errs.Type` is a minor. |
| AUD-P06/5 | 2026-11-23 | `OperatorConfigFromStore` ignores keys it does not know and stays strict for the known keys; a write stays strict. upgrade.md rule M8 names stored JSON documents with a closed schema. Test: `TestOperatorConfigFromStore_IgnoresUnknownKeys`. | A rollback by one release after a new key would have made every agent list an internal error (srv-agents-6). An ignored key is dropped on the next write of the agent row (`UpdateAgent` writes `operator_config` with every agent update). |
| AUD-P06/6 | 2026-11-23 | The thread list gets two partial indexes in its keyset orders, `threads_channel_created_idx` (00120) and `threads_channel_activity_idx` (00121), both `WHERE kind = 'thread' AND deleted_at IS NULL`. Not built: an index on `reactions (principal_id)` and a change of the export paging of own messages. Test: `TestThreadListIndexes`; `TestActiveThreads_QueryPlan` accepts either activity index. | A page of a forum sorted all its threads (data-layer-11); the personal data reads run once per export or erasure, and an index there would cost every reaction write. |
| AUD-P06/7 | 2026-11-23 | The hosting rule keeps its order (hosted agent row, then the runner row) and the module README names the exception to 03 section 6.3 and the `40P01` retry. | Locking both rows ahead needs a change of the generic change frame of the agents module (srv-agents-5). |
| AUD-P06/8 | 2026-11-23 | 09 section 2.2 states that `supports_title` and `supports_voice` have no effect yet and that the adapter's `components` report is not checked; 4.4 marks `capabilities_effective` as not built. Enforcing the title switch is not built. | Where the server enforces the switch (title update of an operator agent versus the invocation) is a product decision across runs, chat, the runner and the SDK (fn-agents-runs-9). |
| AUD-P06/9 | 2026-11-23 | A list item that `message.read` refuses is first checked against its thread: when the thread is deleted (or, in search, no longer a live thread of the hit's channel), the item is dropped silently; only a refusal for a live thread is logged and counted as `filter_mismatch`. The search coordinator asks `chat.SearchReads.HitThreads`, messaging asks `chat.Threads.Info`, both only on a refusal. Tests: `TestCoordinator_PageCheckDeletedThreadIsSilent`, `TestListMyMentions_DeletedThreadIsSilent`. Not built: excluding deleted threads in the SQL of search, mentions and export. | authorize answers `not_found` for every message of a deleted thread (D-DEL-SRV-1) while the statements filter by channel only, so each such hit paged `BothyAuthzError` until the purge, and the export for good (fn-search-6, srv-messaging-search-1). The refusal path is rare, so one read there costs less than a thread exclusion list in three statements of two modules. |
| AUD-P06/10 | 2026-11-23 | A failing second pass of the search assistant (any error) adds no hits; the answer keeps the picks, the first pass and the cost, and a warn line names only the error kind. An earlier question in `history` longer than `search.query_max_chars` is `400 validation_failed` with `too_long` on `/history/<i>/q`, documented in the operation description and 14 4.10; the schema `SearchAssistTurn` gets no `maxLength`. Tests: `TestAssist_FailedSecondPassKeepsTheAnswer`, `TestAssist_ValidatesTheQuestion`. Not built: a time budget for the second pass from the rest of the request time. | The model answer is paid for and a retry asks the model again (fn-search-5, srv-messaging-search-5); an oversized history made the payload builder fail with `500` (srv-messaging-search-4). A `maxLength` on a request member would be a contract tightening for G6. |
| AUD-P06/11 | 2026-11-23 | The fixed numbers `assistMinTermChars` (3), `TermMaxChars` (64), `rrfK` (60), `headlineShortWord` (3) and `personalBatch` (500) stay named constants, not configuration keys. The comment of `AssistTerms` and the design note name three letters as 14 4.10 point 2 does. | The term length is a rule of the specification, 60 is the standard constant of reciprocal rank fusion, and the batch of the personal data export and deletion is an internal read size with no effect a person or operator sees; none is an operator limit of SPEC rule 3 (srv-messaging-search-14). |
| AUD-P06/12 | 2026-11-23 | `agent.invocation` names the person of the run in `triggered_by` (`runs.triggered_by`, as the token's `sub` and `run.state_changed`); it reads that person only when it differs from the author of the triggering message (a `retryRun` by another person). 09 5.7 point 3 says so. Test: `TestRetry`. | The adapter took the user id from the token and the name from the payload, so a retry by Sam ran with Sam's id and Alex's name (srv-runs-app-4). |
| AUD-P06/13 | 2026-11-23 | `createRunWake` and `recoverRunWake` refuse a `not_before` later than now plus `run.wake_max_wait` for every reason but `usage_limit` (`400 validation_failed`, `invalid` on `/not_before`, 09 5.8.1) instead of clamping the deadline to it. Test: `TestWakeWindow`. | Such a wake-up held a place of `run.wake_max_pending` and could only expire at its first fire (srv-runs-app-6); moving `not_before` silently would fire it at another time than the agent asked. |
| AUD-P06/14 | 2026-11-23 | The live box documents stay read in one READ COMMITTED unit of work; the comments of `Documents` and `Deps.UoW` say so, and the next `run.updated` corrects a document that paired a run version with the steps of a later patch. | A snapshot reader for every live box read is a change of the read path for a short and self-healing case (srv-runs-app-12); the comment claimed a snapshot that did not exist. |
| AUD-P06/15 | 2026-11-23 | `bothy.run.tokens` stays in the signal catalogue and the dashboard but is marked as not built in signals.md and 17. | Counting tokens needs a token model of `runs.metrics` that the server does not have; removing the row would also remove the dashboard panel that a later producer fills (srv-runs-core-9). |
| AUD-P06/16 | 2026-11-23 | Not built in this package: SQL truncation of `content_md` for list reads (srv-messaging-search-6, second part), a bound on the thread id list of the search thread filter (srv-messaging-search-8, the quadratic channel cut is fixed), the reactions index by `principal_id` for the personal data export (srv-messaging-search-7, second part). | Each needs a measured limit or a statement redesign; none has a reproduced harm. |
