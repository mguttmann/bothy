# M2-40 Terminal rights, fresh step-up and the guards SR10 to SR12

| No | Date | Ruling | Reason |

| D-M2-40-1 | 2026-10-14 | `terminal.read_own` is `All(HumanSession, ByKind{terminal_session: Any(Self, Owner), host: Auth})`: on a host, "self or owner" means "own sessions on a host you can see, owners all"; the list query of M2-44 restricts the rows to the caller's `user_id` for people who are not owners, so on the host only visibility counts. A `terminal_session` is visible to its person and to effective owners whatever the requirement (else `404` with `not_self`), so the Owner gets `forbidden` `not_self` on `terminal.attach` of a foreign session. | A host has no owner of its own sessions; the requirement can only gate the list, the rows are the use case's filter. |
| D-M2-40-2 | 2026-10-14 | Fresh step-up evaluates only its own branch in step 8: the quick reattach first (only `terminal.attach` of a `detached` session from the same device and login session within `terminal.quick_reattach_window`, equal allowed), else a fresh step-up (`terminal.step_up_max_age`, equal allowed, `passkey` or `device_key`, not consumed). A console session fails closed until M6-18 adds the passkey rule with `userVerification = required`. `identity.StepUp.ConsumeFresh` checks the freshness again on the locked session row (the first domain row lock of the action's transaction) with the rule of `authorize` (`authz.FreshStepUpCheck`), never on the actor of the request. | Two requests with one confirmation both pass `authorize`; only the lock orders them, so the second opening sees the consumption (08 6.3 point 4, 03 6.3). Console sessions do not exist before M6-01. |

| D-M2-40-8 | 2026-10-14 | `RecordSessionUserReport` compares a report with the stored one by the set of names and each name's ordered `workdirs`; an equal report writes nothing and raises no rights version.
