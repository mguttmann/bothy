# F-LAUFHISTORIE The run history next to the live topology

Owner request of 2026-11-04: an overview of finished runs to click, with tokens, duration and the
other figures, because a run disappears from the live topology with its tree, costs and duration
as soon as it ends.

| No | Date | Ruling | Reason |
|---|---|---|---|
| F-LH/1 | 2026-11-04 | A new operation `listRunHistory` (`GET /api/v1/run-history`) instead of a state filter on `listActiveRuns`. | `listActiveRuns` is "Running now": its keyset is `queued_at`, its schema `RunSummary` has no model, metrics, space or chat, and the sync snapshot shares its pipeline. The history needs the keyset `finished_at`, the end-state filter, a space filter and the figures of the list in one call. A filter on `listActiveRuns` would change the meaning, order and schema of an existing operation depending on one parameter. The path lies outside `/runs/{run_id}`, so no literal segment competes with the run ID. |
| F-LH/2 | 2026-11-04 | Permissions as in `listActiveRuns`: `run.overview.read` on the instance as the route action, `Scope(run.read)` for the channels, the threads of those channels (narrowed to the channels of `space_id`) through chat, the query over that thread set, then `chat.Threads.Locate` and `run.read` per row in filter mode; a refusal after the channel filter is a filter mismatch. An unknown or invisible space or agent gives an empty page. | The brief asks for the rights of `listActiveRuns` and the per-run check of `getRun`. Reading by the thread set (the form of the statistics queries) bounds the scan for a person with few channels; the per-row check stays the truth (07 7.4 rule 3). The SQL exception is `thread_scope`. |
| F-LH/3 | 2026-11-04 | Each entry names its chat (`StatsRunChat`) through the statistics reader of chat, restricted to the visible channels. | `run.read` on a run is the right `read` on the path of its thread, the same as `thread.read`, so the names are those the sidebar shows the same person (25 4 rule 6). |
| F-LH/4 | 2026-11-04 | The history shows the cost of a run as `getRun` does (`RunSummary.cost` under `run.read`), labelled "Estimate" or "information only"; TV mode never shows the view. | Like the run graph, the history is run content under `run.read`, not a statistics view (R-VZ-14); the cost is already part of every run summary a reader gets. |
| F-LH/5 | 2026-11-04 | Retention: runs and their steps go with their thread (20 2); there is no time-based deletion of runs. The view states this above the list ("Runs are kept as long as their chat") and ends the last page with "Start of the history"; no extra server field. | The honest statement of how far back the history reaches is the rule itself; a count or oldest date per caller would cost a query on every page for a figure the last page shows anyway. |
| F-LH/6 | 2026-11-04 | No new storage: an additive partial index `runs_finished_idx (finished_at DESC, id DESC) WHERE state IN ('completed', 'failed', 'cancelled')`, built `CONCURRENTLY`. | The keyset of the history; the existing `runs_agent_finished_idx` serves only one agent. |
| F-LH/7 | 2026-11-04 | Clients: a view `RunHistoryView` in `bothy_viz` with the registry entry `runHistory` right after the live topology (`inTvMode = false`), hosted by `LiveScreen` of `admin_ui`, so the desktop apps, the mobile apps and the web console get it at once. The detail reads `getRun` and draws the steps with `RunGraphView`; "Go to the triggering message" calls the new host callback `onOpenMessage` (`/t/{thread}?m={message}` in the apps, the note "Open in the app" in the console). The cache write figure adds the writes of five minutes and of one hour. | One view for every client that shows the live topology, as the brief asks. |
| F-LH/8 | 2026-11-04 | The web console shows the detail with the step tree too, although 01 5.5 keeps the run graph D14 out of the console. | The brief asks for the history on every client that shows the live topology, and the console's topology already shows the agent tree labels under `run.read`; the console still has no chat, so its jumps show "Open in the app". |
