| D-CU-02-3 | 2026-11-26 | Names and places: macOS app `bothy-computer-helper.app` with the executable `bothy-computer-helper` and the bundle ID and LaunchAgent label `com.example.bothy-computer-helper` (white label, brief rule 8; file, folder and value names carry the working name only in the lowercase prefix form of 02 section 6, which `tools/ci/tests/test_product_name_places.py` holds, and the bundle's display name is "Computer Helper"), installed to `/Library/Application Support/bothy-host/desktop/` (root-owned like the program folder, so the peer rule of 27 9.4 can trust the chain; `/Applications` is writable by the group admin), LaunchAgent `/Library/LaunchAgents/com.example.bothy-computer-helper.plist` (`LimitLoadToSessionType` `Aqua`, `RunAtLoad`, `KeepAlive`). | D-CU-02-4 | 2026-11-26 | State file of the enablement: macOS `~/Library/Application Support/bothy-computer-helper/state.json` (mode `0600`, folder `0700`), Windows `%LOCALAPPDATA%\bothy-computer-helper\state.json` (the user's profile folder, closed to other users); content `{"v": 1, "enabled": <bool>, "generation": <int>}`, written atomically (a temporary file in the same folder, then a rename). A missing or unreadable file reads as off with generation 0; the helper reads the file at start only and never treats a change of it as an order. A process of the same account can rewrite the file; the threat model accepts this as the residual risk of T-CU-06 ("only at the machine" means "only by the console user's account"). | 27 section 4 item 1 and brief item 15. |
| D-CU-02-5 | 2026-11-26 | The helper checks the host side of its channel before it sends `hello`, with the rule of 27 9.4 ("Host side"): macOS pins the peer to the service user `bothy-host` or root and checks the folder chain and the socket's owner (`PeerRule.check`); Windows accepts only a pipe server running as `NT SERVICE\bothy-host` or `LocalSystem`. A first draft trusted whoever owned the endpoint folder; review found that a user controlling that folder could pose as the host. A development build (no verified signature, `signature: development`) accepts the endpoint from the environment variable `BOTHY_COMPUTER_HELPER_CHANNEL` (a socket path or a pipe name) and then skips this check; a verified build ignores the variable. 27 9.4 names the check. | Without it any process could create the endpoint while the host service is not running (a named pipe name can be taken first) and drive the screen with the helper's grants (TCC on macOS, `uiAccess` on Windows); the CI jobs need a fake host on their own endpoint. |
| D-CU-02-6 | 2026-11-26 | Session rules of the helper: `show` while the enablement is off shows nothing and sends `state` with `enabled: false`, so the host service ends the session (`device_disabled`); `capture`, `do` and `position` outside a shown session answer `invalid_action` and inject nothing; while locked they answer `screen_locked`, on the secure desktop `secure_desktop`; an operating system error of capture or input answers `os_refused`. A real Esc, the stop button or a local switch-off end the session in the helper at once (release every key and button, hide the indicator, stop the Esc tap and the display assertion) before the `stop` or `state` frame goes out; `hide`, `disable`, a broken channel and the helper's start do the same. | 27 8.4 item 2: the person at the machine must not wait for the host service. |
| D-CU-02-7 | 2026-11-26 | Key names of `do key` (27 6.4): `+` joins the parts, case does not matter; modifiers `shift`, `ctrl` (`control`), `alt` (`option`), `cmd` (`command`, `super`, `meta`) and `win` (`windows`); `cmd` and `win` are the Command key on macOS and the Windows key on Windows; named keys `Return` (`Enter`), `Tab`, `Escape` (`Esc`), `BackSpace`, `Delete`, `Insert`, `space`, `Up`, `Down`, `Left`, `Right`, `Home`, `End`, `Page_Up` (`Prior`), `Page_Down` (`Next`), `F1` to `F24`, `CapsLock`, and every single character. A name the platform has no key for is `invalid_action`; no valid name or combination is refused. `type` sends every character as Unicode input (a line break as `Return`); `scroll` moves `amount` lines; clicks press the modifiers before and release them after the click. | The names of Anthropic's computer tool set (xdotool names) with the aliases models use; one table for both helpers, held by the shortcut tests (CU-T15). |
| D-CU-02-8 | 2026-11-26 | The longest channel frame is `host_service.computer_frame_max_bytes`, read from the host service's configuration file when the helper may read it, else the default of 27 section 18; a longer frame ends the connection (the helper reconnects). | Brief item 14; the helper has no configuration of its own. |
| D-CU-02-9 | 2026-11-26 | The indicator border has the fixed color sRGB `#FF6A00`, so the native CI jobs can check that no screenshot contains it. | Brief "Definition of done": the indicator is never in a screenshot. |
| D-CU-02-10 | 2026-11-26 | Signing and packages as D-CU-01-29: `make -C services/host helper-macos` builds the app bundle (development build); `helper-sign-macos` signs it with the Developer ID Application identity named by `SIGN_IDENTITY` and the hardened runtime, without notarization, verifies it and compares its designated requirement with the file `REQUIREMENT_FILE` of the previous signed build (writing it the first time); on the owner's Mac it runs as a one-shot job in the GUI session. `helper-package-macos` builds the host `.pkg` with the helper as an optional choice. `tools/distribution/hostdist.py helper-cert-windows` creates the self-signed code signing certificate once on the owner's Windows computer (key not exportable, in `LocalMachine\My`, the certificate also in `LocalMachine\Root` and `LocalMachine\TrustedPublisher`) and prints its thumbprint; `hostdist.py helper-sign-windows` signs `bothy-computer-helper.exe` with a certificate from the machine's store (`signtool sign /sha1`) and checks `signtool verify /pa`; `helper-package-windows` builds the host MSI with the feature `ComputerHelper` (off unless selected, `ADDLOCAL=ComputerHelper`). Selecting the component sets `host_service.computer_use: true` in the host service's configuration file, creating the file when it does not exist; `release.yml` stays without a helper. | Owner decision; the release chain of M7-23 is reused for the package steps. |
| D-CU-02-11 | 2026-11-26 | The probe and the native tests of the helpers run from `tools/ci/computer_probe.py` with the fixture window `tools/ci/computer_fixture.py` (Tk, from the Python that `uv` installs on the runner) and a fake host on the development endpoint, in the jobs `helper-macos`, `helper-macos-native`, `helper-windows` and `helper-windows-native` of `host-platform.yml`; the workflow also runs for a pull request that touches the helpers, their packages or the probe, while its platform suite stays manual and scheduled. The lock state is not probed: a hosted runner cannot lock its session and keep the job alive. | Brief item 25; the brief scope names the workflow tests in `tools/ci/tests`, and the probe is CI tooling held by the linters of `tools/`. |
| D-CU-02-12 | 2026-11-26 | `services/host/desktop/**` is out of Sonar's coverage measure (`sonar.coverage.exclusions`), like the native code of the plugin members and the apps; the code stays in the scan. | Its XCTest and CTest suites run on the macOS and Windows runners of `host-platform.yml` and write no report the Linux scan can read (D-M4-10-7). |
| D-CU-02-13 | 2026-11-26 | A long action never outruns a stop: a shared interrupt flag, set directly by the Esc tap, the stop button, the lock monitor and the channel reader (`hide`, `disable`, a broken channel) on their own threads, is checked before every input event of a `do`; when set, every key and button is released and the action ends (`screen_locked` for a lock, else `invalid_action` after the `stop`). `repeat` above the default of `computer.key_repeat_max` and a text longer than one frame of `host_service.computer_frame_max_bytes` are `invalid_action` before anything is injected. | Review of the first build: a large `repeat` ran as one block and ignored Esc; the host checks the same bound, the helper keeps its own because it is the last place before the input. |
| D-CU-02-14 | 2026-11-26 | Details of the macOS helper: `Del` is an alias of `Delete` (CU-T15 names `ctrl+alt+del`); every host `disable` switches off whatever its generation; a `hide` for another session is ignored; a protocol fault (an image frame from the host, an unknown or missing `op`, `show` or `hide` without their members, `capture`, `do` or `position` without `seq`) closes the channel, while bad arguments with a `seq` answer `invalid_action` and unknown members are ignored; coordinates must be finite and are mapped and checked by the host, a zoom `region` must lie inside the screen; `done` always carries `app` and `screen` (empty `app` while locked, as the vector "done locked"); an image too large for one frame answers `os_refused`; permissions are `granted` or `denied` (the preflight calls cannot tell "not asked"); `signature` is `verified` when the code satisfies the generic Developer ID requirement; a switch-on counts only once it is saved, a switch-off at once; screenshots leave out the pointer; `Insert` and `F21` to `F24` have no Mac key (`invalid_action`), a character without a key on the layout goes as Unicode input; the menu bar stop counts as `indicator_stop`; the menu bar title is "Computer Helper" ("Agent active" during a session). | Names and behaviour 27 leaves open, as built in `services/host/desktop/macos`. |
| D-CU-02-15 | 2026-11-26 | The helper reconnects to the host endpoint with a backoff fixed in code (it starts short and doubles to a cap), not through a configuration key. | It paces a local reconnect to a folder on the same machine, bounds nothing a person tunes, and the helper has no configuration of its own (the host's keys `host_service.reconnect_backoff_*` govern the control connection to the server). |
| D-CU-02-16 | 2026-11-26 | The stop contract of 27 9.6 is one rule for both helpers, held by the shared vectors `services/host/testdata/computer/stop-vectors.json`, which `HelperCoreTests` (Swift) and the CTest suite (C++) both run against their controllers; it replaces the per-helper fixes of D-CU-02-13. | The same class came twice in review (a long `repeat` that ignored Esc on macOS; on Windows an Esc filter state that survived a restart of the tap and swallowed the next real Esc, and a pending Esc that the first step did not check); one contract with one test set closes the class on both platforms. |
