# M4-44 Forums for existing folders and renaming a project

Follow-up of M4-43 after the owner's former setup (2026-10-29). Design note:
[new-project.md](../design/new-project.md) section 6. Normative text: 01 6.10, 6.11, R-PR-21; 03
`agents.reported_project_folders`, R-DM-56; 05 `agent.project_folders.read`; 09 4.8, 18.13, 21,
R-AG-30.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M4-44-1 | 2026-10-29 | The runner reports the names of the folders under its projects root in the heartbeat member `project_folders`; absent means unchanged, a different list is written at once. | The server never reads host files and only the runner sees the folders; the heartbeat already carries the runner's view of its projects. |
| D-M4-44-2 | 2026-10-29 | Only entries directly under the root with a one-segment name (`^[A-Za-z0-9][A-Za-z0-9._-]*$`, at most 255 characters) that resolve to a folder under the root and hold `.git`, in code point order, at most `runner.project_folders_max`. | Exactly the folders that a binding with `provision` `none` makes ready; no hidden or temporary clone folder; names only, no path; a bounded heartbeat. |
| D-M4-44-3 | 2026-10-29 | `listAgentProjectFolders` with the new action `agent.project_folders.read` (owner, no step-up, no audit, `rl.read`); `agents.reported_project_folders` stores the list; agents asks chat for the bound names through its readiness port. | No existing action reads a runner's folders; `agent.read` is too wide for host folder names; owner reads carry no step-up or audit; chat keeps its table. |
| D-M4-44-4 | 2026-10-29 | The list leaves out every folder whose name equals a `workspace_ref` without case; the unique index still refuses a folder bound meanwhile; "Try again" keeps the created forum. | The owner's rule: never a second forum for a folder with one. |
| D-M4-44-5 | 2026-10-29 | The dialog lists all folders without a binding, checked; nothing is created before "Add forums"; per folder forum, runner and binding with `provision` `none` in list order, then the readiness of all; per row state, failure sentence and resume. | The list is the dry run the owner wanted; one step-up for the whole run; one failure does not stop the others. |
| D-M4-44-6 | 2026-10-29 | "Rename project" in the menu of a bound forum (with `manage`) changes only the forum's name through `updateChannel` with If-Match; folder, binding and sessions stay. | `workspace_ref` names the folder the sessions work in; the runner never moves a folder it did not create. |
| D-M4-44-7 | 2026-10-29 | Desktop only. | As D-M4-43-12. |
