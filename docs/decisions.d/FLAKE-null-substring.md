# FLAKE-null-substring Tests find JSON null by decoding, not as text

| No | Date | Ruling | Reason |
|---|---|---|---|
| FNS/1 | 2026-11-01 | A test finds a JSON null (ADR 0053) by decoding the JSON and walking the values: `testkit.HasJSONNull`, `testkit.JSONNull` (the JSON pointer of the first null) and `testkit.NoJSONNull` in `services/server/internal/platform/testkit`. They read one JSON value or a sequence of them (NDJSON); empty text holds none; text that is not JSON holds no JSON null for `HasJSONNull`, while `NoJSONNull` fails on it. Every check of the server tests that looked for the letters `null` in a body, an event payload or a stored document (`strings.Contains(..., "null")`, `bytes.Contains(..., []byte("null"))` and lists of banned substrings with `"null"`) uses them. The Semgrep rule `bothy-go-test-null-substring` refuses the text check in a `_test.go` file and in the test helpers under `services/*/test/`; a check of text that is not JSON carries a `nosemgrep` with its reason. The local `noNull` helpers that already decoded stay. | Issue #238, run 41272251665 (push to main): `TestIdentityLink/TestIdentityLink_Success` failed with `oidc_test.go:675: JSON null in {"authorization_url":"...state=o0d5U1VIIudCJv79Zc96lNYHoZN8nZuZnullGnQNyHk",...}`. The helper `want` (`sessions_env_test.go:481`) reported a null because the random base64url `state` held the letters `null`; the response had none. A random base64url token of 43 characters holds them with a chance of about 40 / 64^4 (about 1 in 400 000), and the server tests check many bodies with three such tokens and other random values, so the class failed correct changes at random. Semgrep found 72 such checks in 63 files on main before this change, none after. |
