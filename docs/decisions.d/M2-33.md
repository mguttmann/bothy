| D-M2-33-8 | 2026-10-24 | Follow-ups: at `steer` the text is read from `getRunContext` and passed into the running turn as busy input, reported `delivered`, and `absorbed` at the end of the turn that received it (the pinned version reports no absorption). At `queue` nothing is passed for a running run. A follow-up for a run in `waiting_input` is the answer to the open card in both modes: the SDK resumes the run with its token, the adapter disables the card's components and answers the prompt once: a clarify with the text, an approval with `deny` and a slash confirmation with `cancel` (a text is no approval); at `steer` the text of an approval or confirmation answer first reaches the blocked turn. One place decides whether a person's text enters a turn: only at `steer` and only while the turn runs, because at `queue` (and after the end) Hermes would start a new turn that no run covers. A steer that misses the last tool batch is Hermes' next user turn inside the same processing, before `on_processing_complete`, so the run covers it (measured against the pin, `test_followup_during_the_final_answer_stays_in_the_run`); the installer turns Hermes' own busy notices off (`display.busy_ack_enabled: false` and `display.platforms.<key>.busy_steer_ack_enabled: false`), which would otherwise be posted as messages of the run. After a model reply without tool calls (`assistant_tool_call_count` of `post_api_request`, an unknown count counts as none) no text enters the turn any more: Hermes reports that reply before it drains its last steer, and the server's follow-on run takes the follow-up. A reply with tool calls opens the gate again, so text Hermes sends before a tool call (the same way as the answer) does not end steering (`test_followup_after_interim_commentary_is_steered`). A person's text (trigger and follow-up) reaches Hermes with `allow_gateway_control` off, so it never runs a Hermes command or answers a Hermes prompt by itself; the adapter's own commands (`/stop`, `/new`, `/resume`) go out from its control sender, the slash-command admin the installer lists. `interrupt` makes the adapter `degraded` with `busy_mode_invalid` and without the follow-up capability. Place: `handler.py`, 09 17.5. | 09 7, 10.4, 11.5, 11.6, 17.4, 17.5: a chat text starting with `/` must not bypass the server's command check or an approval card. |
