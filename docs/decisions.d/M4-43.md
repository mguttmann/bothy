# M4-43 New project from the app

Owner feedback of 2026-10-28 on the desktop app: a space had no way to add a project. Design note:
[new-project.md](../design/new-project.md). Normative text: 01 6.9, R-PR-20; 03
`project_bindings`, R-DM-55; 09 4.8, 18.1, 18.12, 21, R-AG-29.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-M4-43-1 | 2026-10-28 | The app composes existing actions: `createChannel` (forum), `setChannelOperator` when the runner is not inherited, `putProjectBinding` with `provision`, waiting on `getChannelBehavior`, and for an idea the first post; no new action and no composite endpoint. | Every step keeps its own permission, step-up, audit and event; a composite action would duplicate them and need a permission of its own; the steps are keyed, so a resume creates nothing twice. |
| D-M4-43-2 | 2026-10-28 | The serving runner creates the folder under `runner.projects_root` from the binding member `provision` (`none`, `init`, `clone`); the server never touches host files or fetches the URL; the host service is not involved. | The runner owns the projects root and works in the folder as its user (09 18.1); 03 principle 9 and SEC-OUT-1 forbid server fetches; the host service owns terminals only. |
| D-M4-43-3 | 2026-10-28 | With `init` or `clone` the `workspace_ref` is one segment of `^[A-Za-z0-9][A-Za-z0-9._-]*$` and `clone` needs an `https` URL without user information; the server and the runner both check; the runner runs `git` with an argument list, `--` before operands, no prompt, only the `https` protocol, a time limit, and clones into a hidden temporary folder in the root that it renames. | One segment keeps the target directly under the root; the runner does not trust the server for its own file system (T-DEV-01); no shell means no injection. |
| D-M4-43-4 | 2026-10-28 | `init` and `clone` never take over an existing folder: a target the runner did not create (record in its state directory) is `workspace_exists`; existing folders are bound with `provision` `none`. | The owner's former setup refused an existing folder for a new project; a silent takeover would aim a new project at someone else's work. |
| D-M4-43-5 | 2026-10-28 | `ProjectReadiness.reason` (code) from the runner, stored as `project_bindings.ready_reason` while not ready, shown in `ProjectBinding.ready_reason`; a reason change is applied like a readiness change (no event, audit or settings version). | The person must see why a project does not start; a code carries no content or path. |
| D-M4-43-6 | 2026-10-28 | A failed creation is retried for the same binding content only after `runner.provision_retry_after`, a binding change or a runner restart. | No clone loop on every heartbeat; short network failures still heal. |
| D-M4-43-7 | 2026-10-28 | "New project" shows only for owners; the step-up of the composed actions applies; the binding's audit reason is fixed text of the app. | No new permission; whoever may bind a project may create one. |
| D-M4-43-8 | 2026-10-28 | The dialog lists its steps with states, names a failed step with one sentence for its code, resumes at the failed step with "Try again" (kept IDs, keys and still editable fields), and after `ui.new_project_wait` without readiness says the runner has not finished and lets the person close. | Every step fails for its own reasons, and the person must know what exists and what is left. |
| D-M4-43-9 | 2026-10-28 | The idea is stored first as the person's new post draft of the forum and sent with `clear_draft` and an empty title when the binding is ready. | A post before readiness is refused with `project_not_ready`; an early close keeps the idea where "+" finds it. |
| D-M4-43-10 | 2026-10-28 | The name is suggested from the URL's last segment without `.git` or the first words of the idea, folded to lower case letters, digits and hyphens, at most `ui.new_project_name_max_chars`; it names forum and folder; after a refused folder only the folder name changes. | As the owner's former agent chose names; one name keeps forum and folder recognisable. |
| D-M4-43-11 | 2026-10-28 | The runner field lists the active agents with the space's default operator preselected; another choice sets the forum's operator. | Readiness counts only from the forum's effective operator (09 18.1). |
| D-M4-43-12 | 2026-10-28 | Desktop only; the phone shows the result. | Asked on the Mac; rare action that needs a keyboard. |
