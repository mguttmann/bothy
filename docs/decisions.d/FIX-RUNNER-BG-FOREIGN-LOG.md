# FIX-RUNNER-BG-FOREIGN-LOG Background sessions: an input of another sender is only logged

Reproduction condition: a background session whose inputs come only from the thread's person
and from Claude Code itself (a notification of a background agent, of a plugin, an input of a
subagent). Under the check "Whose input" of 09 18.5 (FIX-RUNNER-BG-INBOX-AUTH rulings 1, 9, 10
and 11, FIX-RUNNER-BG-SIDE-NOTICE) each such input that the runner could not attribute logged
`background_foreign_input` with the word `unattributed` and stopped the session; the next
message logged `session_not_continued`. Result: each stop ended the run, killed the session's
agents, and the next message started a new session without the conversation, a false alarm
every time. Ruling 1 replaces the rule.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-FIX-RUNNER-BG-FOREIGN-LOG-1 | 2026-11-17 | An input of another sender in a background session (rule 1 of 09 18.5, unchanged in what it counts as such) is logged and nothing else: the warning `background_foreign_input` with one of the words `peer`, `human`, `other` or `unattributed`, never a text of the record. The session is not stopped, the run goes on and ends as usual, the mapper treats the input as the start of a turn like the session's own input (a turn end after an input nothing attributed still ends the turn), and the answer is posted. A runner that adopts a turn logs the inputs in the part of the transcript it maps again. Nothing marks a session any more and no run takes a new session because of such an input: the mark `<runner.state_dir>/sessions/<session id>/foreign-input`, its check before an attempt, the judging of a released transcript (`background_foreign_input_unread`), `session_not_continued`, `session_mark_failed` and the cause `background_foreign_input` are removed; a mark an earlier runner wrote is read by no runner and goes with the retention sweep. This replaces the stop of D-FIX-RUNNER-BG-INBOX-AUTH-1 and all of D-FIX-RUNNER-BG-INBOX-AUTH-10. Evidence: `tests/scenarios/test_bg_inbox_auth.py` (each foreign input scenario ends `completed` with the answer and the warning; `test_the_next_run_continues_the_session_that_took_a_foreign_input`, `test_a_print_turn_continues_that_session_too`, `test_a_mark_an_earlier_runner_wrote_has_no_effect` and the adoption scenarios fail on the earlier version), `tests/unit/test_bgtranscript.py` (a foreign turn starts a turn; a turn end after an unattributed input still ends the turn), `tests/unit/test_statedir.py` (the sweep takes an old mark). | An input in the thread's chat comes from the thread's person, so discarding it throws away what the person said and nothing answers. Where only the person and Claude Code itself write into a session, every stop is a false alarm that costs the thread its conversation. What stays open is in 09 18.5 "What stays open": a program of the host user that writes to the inbox socket reaches the model, which acts on it with the rights of the tool class; the runner only logs it. |
