# FIX-RUNNER-BG-FOREIGN-LOG Background sessions: an input of another sender is only logged

On 2026-11-17 the check "Whose input" of 09 18.5 (FIX-RUNNER-BG-INBOX-AUTH rulings 1, 9, 10
and 11, FIX-RUNNER-BG-SIDE-NOTICE) stopped the session of the owner's steering thread seven
times in one day, each time a false alarm: a notification of a background agent, the
security review plugin of Claude Code, an input of a subagent (production runner log, event
`background_foreign_input` with the word `unattributed`, followed by `session_not_continued`
at the next message). Each stop ended the run, killed the session's agents, and the next
message started a new session without the conversation. The owner's ruling the same evening
replaces the rule.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-FIX-RUNNER-BG-FOREIGN-LOG-1 | 2026-11-17 | An input of another sender in a background session (rule 1 of 09 18.5, unchanged in what it counts as such) is logged and nothing else: the warning `background_foreign_input` with one of the words `peer`, `human`, `other` or `unattributed`, never a text of the record. The session is not stopped, the run goes on and ends as usual, the mapper treats the input as the start of a turn like the session's own input (a turn end after an input nothing attributed still ends the turn), and the answer is posted. A runner that adopts a turn logs the inputs in the part of the transcript it maps again. Nothing marks a session any more and no run takes a new session because of such an input: the mark `<runner.state_dir>/sessions/<session id>/foreign-input`, its check before an attempt, the judging of a released transcript (`background_foreign_input_unread`), `session_not_continued`, `session_mark_failed` and the cause `background_foreign_input` are removed; a mark an earlier runner wrote is read by no runner and goes with the retention sweep. This replaces the stop of D-FIX-RUNNER-BG-INBOX-AUTH-1 and all of D-FIX-RUNNER-BG-INBOX-AUTH-10. Evidence: `tests/scenarios/test_bg_inbox_auth.py` (each foreign input scenario ends `completed` with the answer and the warning; `test_the_next_run_continues_the_session_that_took_a_foreign_input`, `test_a_print_turn_continues_that_session_too`, `test_a_mark_an_earlier_runner_wrote_has_no_effect` and the adoption scenarios fail on the earlier version), `tests/unit/test_bgtranscript.py` (a foreign turn starts a turn; a turn end after an unattributed input still ends the turn), `tests/unit/test_statedir.py` (the sweep takes an old mark). | The owner, 2026-11-17 (translated): who else would send a foreign message, only he can put one into this chat; why discard anything, when he says something it is thrown away and nothing answers. On the runner host only the owner and Claude Code itself write into a session, so every stop was a false alarm that cost the thread its conversation. What stays open is in 09 18.5 "What stays open": a program of the host user that writes to the inbox socket reaches the model, which acts on it with the rights of the tool class; the runner only logs it. |
