# FIX-IMPORT-LEAD-FROM-STORE The lead of a posted thread comes from the stored thread

Follow-up to AUD-srv-importer-01: a security review of that change reported that the mirror gate
of a posted thread item read the lead from the request.

| No | Date | Ruling | Reason |
|---|---|---|---|
| FIX-ILS/1 | 2026-11-12 | The report holds and is fixed. Whether a posted thread item applies the mirror rules of 22 12.2 step 3 is decided by what is stored alone: the thread under its row lock (`chat.ImportThreads.Lock`, which now returns the channel of the thread and `moved_at`), the channel items of the source whose target that channel is (`Store.ItemsOfTarget`, new query) and the stored mapping (`domain.Mapping.SourceLeads`). The source leads only when there is such a channel item and the mapping gives every one of them the lead `discord`. Supersedes the two sentences of AUD-SIM1/5 that read the lead from the item's `channel_origin_key` and that let a channel the mapping does not name keep the mirror. | Before, `ledHere` took the channel from `channel_origin_key` of the request and `mirror` returned before the stored thread was read. `applyImportBatch` needs `import.apply` (an owner, no step-up; the session of the command line can never give step-up), while the ownership list needs `import.manage` with step-up. So a session without step-up could switch the mirror of a thread in a channel led here on by naming a channel the source leads, or any channel the mapping does not name (that case failed open): the thread was renamed, closed or reopened without `thread.reopened` and without an audit entry, against 22 12.1. Reproduced on a started server and held by `TestPostedThreadItemOfAnotherChannel`. No other check bound the item to its thread: a replay only compares the kind and the content hash of the item. |
| FIX-ILS/2 | 2026-11-12 | A posted thread item has to name the channel its thread lies in: `channel_origin_key` must be the origin key of one of those channel items, else `409 conflict` with `reason` `target_outside_source`, recorded as a denial; the batch writes nothing. The key decides nothing beyond that. | A replayed item that contradicts the store comes from a broken or forged client and shall be seen in the audit log, not ignored. The import tool builds the key from the Discord channel of the thread, which never changes, so its items always pass. |
| FIX-ILS/3 | 2026-11-12 | The item of a thread that was moved into another channel here (`thread.move`, `threads.moved_at` set) is answered without the check of FIX-ILS/2, and the channel the thread lies in now decides the mirror: none in a channel outside the source or led here, the mirror in a channel the source leads. Its messages are taken over as before. | A moved thread no longer lies where its item says, and the item cannot say anything else. A refusal would end every later full run at that thread, because the tool stops at a refused batch. Reading the lead of the channel the thread lies in, also here, keeps the decision free of the request: an item that named the new channel of a moved thread would otherwise switch its mirror. A thread moved into a channel the source leads follows its Discord thread again; that channel is read-only here, so nothing people work on is hidden (R-IM-11). Before, the lead of the channel named by the request decided, so a thread moved out of the mirror was still renamed and closed by the source. |
| FIX-ILS/4 | 2026-11-12 | When the mapping names one existing channel for several Discord channels, all of them count: one with the lead `bothy` is enough for no mirror in that channel. | The server does not store which of these Discord channels a thread came from, so the item could otherwise choose the entry that decides. A channel that one of its entries leads here is writable for the people working in it, which is the case 22 12.1 protects. |
| FIX-ILS/5 | 2026-11-12 | Not built: the `channel_origin_key` stored on the thread item. Not changed: `docs/api/openapi.yaml` and the fake server of the import tool. | A stored key needs a migration and a column in the core contract, and the thread items posted before it would have none, so the lookup through the stored thread would be needed anyway. The description of `applyImportBatch` already names `409 conflict` `target_outside_source` for a target outside the channels of the source and points to chapter 22 for the mirror rules; a changed description would regenerate every API client without a change of the contract. The fake of the tool does not model the mirror of a posted thread. |
