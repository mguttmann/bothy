# AUD-PKG-R2-owner-ops Owner decisions of the audit round 2: runner, CI, packaging, operations

Work package of the owner decisions of 2026-11-25 on findings of the audit of 2026-11-11 ("decide
it yourself": each row takes the recommended option). Each finding was read again on the current
`main` first.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-R2O/1 | 2026-11-25 | New runner key `runner.cli_telemetry` (bool, default `false`). While it is `false` the runner sets `DISABLE_TELEMETRY=1`, `DISABLE_ERROR_REPORTING=1` and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (`TELEMETRY_OFF` in `environment.py`) for every CLI it starts (turns, probes, control commands, the background supervisor) and in the `env` block of a background session's settings file; values of the runner's own environment never pass the allow list. The names come from the Claude Code documentation "Data usage" (retrieved 2026-11-25) and occur in the binary of the pinned CLI. The byte-equal baseline `tests/fixtures/baseline/turn_environment.json` gains exactly the three lines `"CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1"`, `"DISABLE_ERROR_REPORTING": "1"` and `"DISABLE_TELEMETRY": "1"`, because the default deliberately changes the environment of a turn without a key. Tests: `test_cli_telemetry_is_off_by_default_and_set_by_the_runner`, `test_cli_telemetry_on_sets_no_opt_out`, `test_cli_telemetry_is_a_bool`, the settings-file test of `test_bgsession.py`. | Issue #907 (privacy-13): the CLI's metrics and error reports go to the vendor and third parties and were neither switched off nor described. The CLI documents that the switches also turn off its feature-flag evaluation; the real-CLI background tests already run with them set. Not proven against a CLI signed in to a subscription. |
| AUD-R2O/2 | 2026-11-25 | No connection pooler is supported: the last mention of the lever "several api processes only with a pooler" (the lever text of `tools/load/capacity_run.py`) now names one pool per api process; 16-operations.md 13 already said so. | Issue #1359: `platform/pg` sets session parameters, caches statements and holds `LISTEN` connections, which a pooler in transaction mode breaks. |
| AUD-R2O/3 | 2026-11-25 | Response compression only at the TLS edge and only for the static web console under `/console/`; none in the server, none for API responses and WebSocket frames (16-operations.md 4.3, R-OP-22). install-compose.md 5.1 has a Caddy example with `encode` limited to `/console/*`; the example nginx edge says it does not compress. API lists are not split out by path: they carry user content next to fields an attacker controls. | Issue #881: BREACH leaks a secret through the length of a compressed response that also reflects attacker text. |
| AUD-R2O/4 | 2026-11-25 | The upgrade of an installation made from a bundle is a documented manual procedure (upgrade.md 2.1: copy, verify, unpack, copy over, compare `.env.example`, advance the marker, Compose upgrade, way back from the copy without `secrets/`). No upgrade mode of `install.sh` before version 1.0; supersedes the "not built" state of AUD-IC1/5. | Issue #1477: there is no release and no bundle yet; a tested upgrade step follows with the first releases. |
| AUD-R2O/5 | 2026-11-25 | The Windows package takes a missing Visual C++ runtime file from the redist folder of the build toolchain (`vc_redist`: the default redist version of the newest Visual Studio), never from `System32`, and prints folder and version; ADR 0078 records Microsoft's redistribution terms, docs/quality/licenses.md lists the files. | Issue #869: version and origin depended on the runner image, and the copies of `System32` are not on Microsoft's list of Distributable Code. |
| AUD-R2O/6 | 2026-11-25 | `make lint` checks `.coderabbit.yaml` against the vendor's `schema.v2.json` at commit `41993ea4a799` of `coderabbitai/awesome-coderabbit` (`CODERABBIT_SCHEMA_URL`), fetched once into `.cache/schemas/` and checked by its SHA-256 (`CODERABBIT_SCHEMA_SHA256`) before every use; no copy in the repository. That copy is older than the schema the vendor's website serves; the configuration passes both. The Semgrep run through `uvx` without a lock stays as it is (see "Open minors"). | Issue #734: a changed or unreachable vendor page turned the required job red for every pull request. The vendor's website has no fixed address; its own repository has. |
| AUD-R2O/7 | 2026-11-25 | `make commitlint` checks the pull request body, the rest of the squash commit, for a `Signed-off-by: Name <e-mail>` line as its last line outside HTML comments, where git reads trailers (`check_pr_body`, `PR_BODY` in the job `gates`), except in pull requests of `dependabot[bot]`, `renovate[bot]` and `github-actions[bot]` (`PR_BODY_BOTS`; the last opens the pull requests of `hermes-pin.yml`). Any identity counts: which one must sign stays OQ-25. It is part of `ci-ok` through the job `gates`, which already runs `commitlint`; no new job. The old commits of `main` without a sign-off stay as they are. Tests: `test_pull_request_body_needs_a_signoff`, `test_pull_request_body_of_a_bot_needs_no_signoff`, `test_commitlint_recipe_checks_the_pull_request_body`. | Issue #872: commitlint checked only the branch commits, and the squash commit on `main` takes title and body of the pull request. A check of tool trailers in the body is not part of the owner decision. |

ADR 0063 item 4, ADR 0032, 02 17, 14 7, 23 2, gates.md and PLAN P-07 say so instead of "in the release workflow". The chaos tests keep the tag `perf`. | Issues #1507, #1591, #1596: the texts claimed a release workflow step that does not exist. | AUD-R2O/11 | 2026-11-25 | G6 (`make api-breaking`): without a `server/v*` tag the baseline is the merge base of `HEAD` with the base of the pull request (`API_BREAKING_BASE` in the job `gates (docs and contracts)`, locally `origin/main`); a release tag, once there is one, stays the base (06 13 item 7). A deliberate break before 1.0 passes with the existing pull request label `breaking change` (`PR_LABELS`, `--allow-break`) while `info.version` of the working tree is below 1.0; from 1.0 on only the major step accepts a break. No N-1 compatibility gate before V1 (V3-37 stays after V1); upgrade.md 4 says that an older build is not tested against a newer schema. Tests: `test_check_without_tag_compares_with_the_merge_base`, `test_label_accepts_a_break_before_1_0`, `test_label_accepts_no_break_from_1_0_on`, `test_main_reads_base_and_label`. | Issues #1508, #1625: without a tag G6 compared nothing, and an N-1 run of the previous suite takes hours per change with no release to go back to. |

## Open minors

- Semgrep runs through `uvx --from semgrep==$(SEMGREP_VERSION)`: only the package is pinned, its
  dependencies resolve anew without hashes. A locked environment of its own (a `pyproject.toml`
  with `uv.lock`) is more than a line and waits for the next change of the security gates (#734).
