# A1-02 Server: agent definitions (2026-11-06)

Brief: [A1-02-agent-definitions.md](../briefs/A1-02-agent-definitions.md). Normative:
[26-builtin-agents.md](../spec/26-builtin-agents.md) 4, 9, 13 and 14; ADR 0076. The rulings settle
what chapter 26 leaves open; none is weaker than the chapter.

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-A1-02-1 | 2026-11-06 | Field codes: the codes of 26 4.3 (`unknown_member`, `skill_frontmatter`, `inline_shell`, `import_outside_folder`, `secret_value_not_allowed`, `env_name_reserved`, `mcp_command_not_allowed`, `mcp_package_unpinned`, `tool_class_too_low`, `too_long`, `too_many`, `invalid_name`, `duplicate_name`), for the shape the codes of the request validation of the API (`required`, `invalid_type`, `invalid_enum`, `invalid`, `too_large`, `too_small`) and for characters the codes of `kernel/textcheck` (`invalid_utf8`, `control_character`, `bidi_control`). One finding per pointer and code: a text with both inline shell forms is one `inline_shell`. | A finding has the same code whether the schema check of the API or the validator sees it first; every writer of the corpus can reproduce the list. |
| D-A1-02-2 | 2026-11-06 | Required members: `instructions` (may be empty), `skills`, `mcp_servers` (may be empty), `settings`, `origin`; in a skill `name`, `description` (not blank), `body`; in a file `name`, `content`; in a server `name`, `transport` and per transport `url`, or `command` and `package` (missing is `mcp_command_not_allowed` or `mcp_package_unpinned`); in `settings` only `tool_class_wish`; in `origin` only `kind`. `settings.model` absent means the runner's default model, `max_cost_usd_per_run` absent means no cap (26 5.3), `allowed_tools` absent means no narrowing and an empty list means no named tool (26 4.4 item 2, the helper `definition.Intersect`). | 26 4.2 marks only `files[]`, `headers[]`, `args[]`, `env[]` and the template members optional, while 5.3 reads model and cap as optional. |
| D-A1-02-3 | 2026-11-06 | Text rules on `instructions`, every skill `body` and every file `content`. Characters: valid UTF-8, no control or bidi character except line feed and carriage return (a tab is refused). Frontmatter (body and file content only): the first line, after an optional byte order mark and without trailing blanks, is `---`. Inline shell: an exclamation mark directly followed by a backtick, at least one character other than a backtick (line breaks included) and a closing backtick, at the start of the text or after white space of the JavaScript set (tab, line feed, vertical tab, form feed, carriage return, space, U+00A0, U+1680, U+2000 to U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF), which is the pinned CLI's pattern with its look-behind written as a group; and any occurrence of three backticks directly followed by an exclamation mark, inside other fences too. Imports: a token `@<path>` at the start of the text or after white space (so at the start of every line), path up to the next white space with a leading quote ignored, refused when it starts with `/`, `\`, `~` or a drive (`C:`) or has a `..` segment with `/` or `\` as separator. | At least the two patterns of 26 4.3 item 3; the stricter forms close look-alikes the CLI might read later (RK-14). Imports inside code are refused too, because the cost is a rephrased example. |
| D-A1-02-4 | 2026-11-06 | Names: skills, servers and the template slug `^[a-z0-9][a-z0-9-]{0,63}$`; files `^[a-z0-9][a-z0-9._-]{0,63}\.md$` and never `SKILL.md` in any case; environment entries `^[A-Z_][A-Z0-9_]*$`; headers `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`. `duplicate_name` on the second occurrence: skills, servers, files of one skill, environment entries (exact), headers (without case) and `allowed_tools`. | A case-insensitive file system would let `skill.md` replace the runner's `SKILL.md`; two headers that differ only in case are one header. |
| D-A1-02-5 | 2026-11-06 | Secrets: an entry carries exactly one of `value` and `secret_ref` (both: `invalid` on the entry, neither: `required` on the entry). A name whose upper-cased form contains `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `CREDENTIAL`, `AUTH` or `COOKIE` needs `secret_ref` (`Authorization`, `Cookie` and `Proxy-Authorization` are covered by these words); the plain value is `secret_value_not_allowed` on `/value`. `secret_ref` has the form of `runner.anthropic_api_key_ref`: `env:<NAME>` or `file:<clean absolute path>` other than `/`. The server checks only the form. | 26 4.3 item 5 and design note 3; the form is that of the runner's secret provider. |
| D-A1-02-6 | 2026-11-06 | MCP: `url` is `https` (any case) with a host, without user information, without `#`; query and port are allowed. `package` is `<name>@<version>` with an npm name (optional lower-case scope) or a Python package name and a SemVer 2.0.0 version without `v`, leading zeros, range operator, wildcard or tag. The runner places `package` directly after `command` and every `args` entry after it, so an argument may start with `-` (it reaches the server, not the command). `tool_class_too_low` once per `stdio` server on `/mcp_servers/<i>/transport`, checked against the agent's configured `tool_class`. | 26 4.2 forbids a dash only before the package; with the package first there is no argument before it. |
| D-A1-02-7 | 2026-11-06 | `allowed_tools` entries: a CLI tool name `^[A-Za-z][A-Za-z0-9_]*$`, optionally with a rule in parentheses (as `runner.scoped_allowed_tools` may name it), or `mcp__<server>` or `mcp__<server>__<tool>` of a server of the same definition with the tool part `^[A-Za-z0-9_-]+$`; otherwise `invalid`. `max_cost_usd_per_run` is a JSON number above zero (`too_small`) and at most `agents.definition.max_cost_usd_per_run` (`too_large`). `model` follows the pattern of `default_model` and does not start with `-` (`invalid`). | The intersection compares exact strings with the runner key, so a rule entry narrows exactly one runner entry. |
| D-A1-02-8 | 2026-11-06 | Corpus: `tests/agent-definitions/valid/<name>.json` and `invalid/<code>-<name>.json`, each `{"tool_class", "definition", "expect": [{"pointer", "code"}]}` compared order free, run with the limits of `tests/agent-definitions/limits.json`, which a wire test holds equal to the defaults of the configuration keys. | One conformance set for server, runner, template gate and interview; a changed default without a changed corpus fails. |
| D-A1-02-9 | 2026-11-06 | Versions and `If-Match`: absent only while no version exists; absent on an existing definition `428`; present without a stored version `412 version_conflict` without `current`; stale or malformed `412` with the current `AgentDefinitionVersion` (the owner passed `agent.update`). A body equal to the current definition stores nothing, raises nothing and audits `no_change`. The first version names every part as changed, later versions the differing parts of `instructions`, `skills`, `mcp_servers`, `settings`, `origin`. | 06 8 and R-API-29; undo of content equal to the current one changes nothing (06 2 "No effect"). |
| D-A1-02-10 | 2026-11-06 | `getAgentDefinition` takes an optional query `version` for undo (26 8.4); owners read every stored version, the agent itself only its current one, another version answers `404`. `listAgentDefinitionVersions` pages newest first with a keyset cursor bound to caller and agent and the page sizes `api.page_size_default` and `api.page_size_max`; a built-in agent without a definition lists nothing, another agent answers `404`. | 26 8.4 offers undo from the version list, and the list carries no text; the brief keeps the agent to its current version. |
| D-A1-02-11 | 2026-11-06 | `putAgentDefinition` for an agent that is no built-in agent answers `409 conflict` with `reason: not_a_builtin_agent` after authorize and the row lock; `getAgentDefinition` answers `404` for it. | 26 4.1 item 4 for the write; a read of a definition that cannot exist is an unknown resource. |
| D-A1-02-12 | 2026-11-06 | The refusal of `agent.tool_class.set` below `host` with a `stdio` server is recorded as an audit `deny` with the new reason `definition_needs_host` (07 4.1, "no `authorize` result") and the target class, through the aggregated denial path, in both units of the change; the second runs under the agents row lock that every definition write takes first. | 07 4.1 holds the closed list of reasons; a refusal after authorize is recorded like `trusted_header_requires_loopback`. |
| D-A1-02-13 | 2026-11-06 | The stored `definition` is the definition as the validator read it, encoded again: exactly the members of 26 4.2, optional members absent, never null. The handler encodes the decoded request body again; the API's schema check already refused unknown members and wrong types with the same codes. | Nothing outside the schema can be stored, also not through a member a decoder would drop. |
| D-A1-02-14 | 2026-11-06 | Every new version raises `agents.version` and appends `agent.updated` in the same transaction as the insert and `agent.definition_changed` (resource agent without version, audience the agent, receive action `agent.definition.read`, payload `definition_version`). The apps skip `agent.definition_changed` (no local table); it is no webhook event. | 26 9 keeps `agent.updated` following a new definition version; a built-in agent is served through its hosting runner's gateway connection. |
| D-A1-02-15 | 2026-11-06 | Configuration bounds: `agents.definition.instructions_max_bytes` and `agents.definition.skill_body_max_bytes` 1 to 1048576, `agents.definition.skill_description_max_chars` 1 to 4096, `agents.definition.max_skills` and `agents.definition.max_allowed_tools` 0 to 1024, `agents.definition.max_skill_files` and `agents.definition.max_mcp_servers` 0 to 256, `agents.definition.max_cost_usd_per_run` at least 0; zero for a count allows none. | The keys are read once at start; a bound keeps a definition well below the JSON body limit of a request. |
| D-A1-02-16 | 2026-11-06 | Names that differ from the brief: the worktree branch is `feat/A1-02-v4` (launcher); `Validate(raw, Limits, ToolClass)` takes the JSON text, `Parse` returns the typed definition and `Decode` reads a stored one without the limits; the use cases live in `app/definitions.go` over the new port `DefinitionStore`, and the check of `agent.tool_class.set` is `needsHost`, called from `SetToolClass` in `app/policy.go`. | D-W-100: follow the code; no dependency names differ. |
