# FEAT-terminal-admin-user Terminal in the owner's own account (2026-11-01)

Owner decision of 2026-11-01, changing the requirement of 2026-10-10 (ADR 0068): a terminal from the
apps on his own server machine, as his normal administrator account, set up remotely. Decision:
[ADR 0073](../adr/0073-terminal-in-the-owners-own-account.md). Design note:
[terminal-owner-account.md](../design/terminal-owner-account.md).

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-OA-1 | 2026-11-01 | `host_service.owner_account` names an existing account; the host service runs as it and `host_service.session_users` is exactly this name (empty is filled in). Default empty: the separate-user setup of ADR 0068 is unchanged. | Opt-in per host; one explicit key instead of a mode flag plus a name. |
| D-OA-2 | 2026-11-01 | `bothy-host install --owner-account` runs as the account itself and refuses root; it writes the binary, configuration and state directory under the account's home and a LaunchAgent (macOS, GUI domain of the account) or a systemd user unit (Linux). No user, group or system service is created. | The owner has no physical access; the steering session works over ssh as the account. |
| D-OA-3 | 2026-11-01 | Windows does not support the mode in this version: `host_service.owner_account` is a configuration error there and `install --owner-account` exits `2`. | A per-user background service without logon needs a stored password or an elevation, both need the owner at the machine. |
| D-OA-4 | 2026-11-01 | The PTY helper of the owner account is a child process of the host service on a socket in `<state>/run`; the peer check compares the account's uid and the child's PID. The child ends when its standard input closes. | Per-user services cannot socket-activate a helper under another identity, and there is no other identity; the existing helper code and peer check stay. |
| D-OA-5 | 2026-11-01 | The host service accepts a token for the owner account only with `own = true`, checked before the binding step; otherwise `session_user_mismatch` (`4104`). | The host enforces the owner rule even when the server is wrong; a non-owner token must never bind the account. A new close detail would change the closed list of 24 10.3 for a case that only a faulty server produces. |
| D-OA-6 | 2026-11-01 | The report carries `owner_account: true` for that name. An assignment needs `owner_account: true` exactly when the report says so (`400 validation_failed`, `owner_account_opt_in_required` or `owner_account_not_on_host`), and only an active owner may make one, only for himself (`403 forbidden`, `owner_account_owner_only`). The flag is stored in `host_session_users.owner_account`. | Explicit opt-in that names what it does; a second owner cannot put the first owner into an administrator shell. |
| D-OA-7 | 2026-11-01 | SR12 counts an assignment only while the reported flag equals the stored flag; an owner account assignment additionally needs an active owner at every `terminal.open` and `terminal.attach` (`403 terminal_denied`, `owner_account_owner_only`). Losing the owner role ends running sessions on owner accounts (`access_revoked`). | A host that later reports a name as the owner account does not silently turn an earlier assignment into an administrator shell; a demoted owner loses the shell at once. |
| D-OA-8 | 2026-11-01 | The audit entries of `terminal.open`, `terminal.attach` and of the assignment carry `owner_account = true` in this mode. | Every administrator shell is visible in the audit. |
| D-OA-9 | 2026-11-01 | In the mode, HD1 passes with the warning `owner_account_mode` and fails `owner_account_mismatch` when the service runs as another account; the findings of HD2, HD3, HD9, the helper part of HD8 and the HD10 codes `peer_check_unavailable`, `ptrace_scope_low` and `helper_unprotected` are warnings with the same code; HD6 findings in the owner account are warnings. The owner account counts as a trusted owner for HD10 and HD11, and "writable by a session user" there means writable by any other person account of the host or by everyone. HD4 and the service part of HD8 are unchanged. | These checks protect people from each other and the keys from a session; in this mode there is one person and he is the administrator. The checks that still protect against everyone else stay failures. |
| D-OA-10 | 2026-11-01 | The mode refuses `host_service.require_local_confirm = true` (configuration error). Step-up on every opening stays. | Nobody sits at the machine to answer the dialog (owner: no physical access). |
| D-OA-11 | 2026-11-01 | Host settings show the owner account with a warning and an explicit checkbox; the open dialog shows a warning before the step-up when the person's session user is an owner account. | The owner sees that he opens an administrator shell; nothing changes silently. |
| D-OA-12 | 2026-11-01 | The mode is allowed on the server host (16 4.4 item 4): SR10 already gives the server host only to owners, and the owner wants exactly this machine. | The owner's server machine is the target of the request. |
| D-OA-13 | 2026-11-01 | In the mode the helper skips the walk of the chain files below the places of HD11 (`.claude`, `.git`) and the entry scan of HD11 (request field `owner_account`). The objects of the places themselves are still checked. | Both walks only look for entries of other session users, and the mode has none; on a real home (a `~/.claude` with hundreds of thousands of entries) they ran into `helper_unreachable` and `entry_scan_timeout` and refused the start (red team of FEAT-terminal-admin-user). |
