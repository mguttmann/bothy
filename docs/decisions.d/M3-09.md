| D-M3-09-10 | 2026-10-24 | `submitTranscript` outside mode `agent` and `requestTranscription` outside mode `service`, and both for a file that is not a voice format (`IsVoiceFormat` with the uploader's kind), answer `409 conflict` with `reason` `transcription_unavailable`; a file that is not ready answers `409 file_not_ready` or `409 file_blocked` (12 8.2). | One reason for "no transcription for this file in this mode", as 12 8.2 names it for `file.transcribe`; an agent transcript would overwrite the service or contradict mode `off`. |
| D-M3-09-11 | 2026-10-24 | `requestTranscription` sets a transcript in state `none` or `failed` to `pending` and inserts the job; `pending` and `done` change nothing; the answer is always `202` with the current `Transcript` view, and the switch off for the caller gives `403 feature_disabled` before the mode check (12 8.2). | A repeated tap must not start a second transcription or overwrite a finished one; the idempotency stage of M1-20 replays a repeated `Idempotency-Key`. |
| D-M3-09-12 | 2026-10-24 | `ErrTranscriptionPermanent` from the adapter writes `failed` at once; any other error returns the error so the job retries, and the attempt that reaches `voice.transcription_max_attempts` writes `failed` instead; a database error never writes `failed`.
