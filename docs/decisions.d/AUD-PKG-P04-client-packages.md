# AUD-PKG-P04-client-packages Audit package of the client packages: REST timeouts and read retry, step-up and refresh, sync reconnect, gaps and outbox, terminal accessibility and end, design system semantics, time zones, test fake fidelity and statistics views

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-PKG-P04/A1 | 2026-11-24 | The read retry of `api_client` does not wait for a `Retry-After` above the cap of its policy (`client.outbox_retry_cap` in the apps); the refusal goes to the caller with `ApiProblem.retryAfter`. No overall deadline per read is added: with the cap every wait is bounded, and Dio already ends the wait of a cancelled request. | Clamping the wait to the cap would retry before the server's floor (06 9 item 3), and a wait of hours inside one awaited read blocked its caller. |
| AUD-PKG-P04/A2 | 2026-11-24 | The apps' REST client gets a connect timeout (`client.http_connect_timeout`) and a receive timeout (`client.http_receive_timeout`) and no send timeout. The receive timeout lies above the longest server deadline (`agents.interview.timeout` plus `http.request_timeout`). The discovery client, the object store uploads and the web console stay as they are (AUD-PKG-P03/C4). | Dio's receive timeout bounds the wait for headers and each pause between chunks, so long downloads pass; a send timeout would cut uploads of any length, which FIX-DPL/2 keeps unbounded. |
| AUD-PKG-P04/A3 | 2026-11-24 | A caller of `RefreshCoordinator` waits at most `refreshCallerDeadline` and then gets `RefreshUnavailable`; the running refresh keeps its single-flight slot until it ends. The Windows device key plugin that may drop a reply stays unchanged. | Freeing the slot would let a second refresh send the same refresh token while the first may still be answered, which the server takes as reuse and answers with revocation and a wipe. |
| AUD-PKG-P04/A4 | 2026-11-24 | `StepUpService.confirm` runs one step-up at a time; a call while one runs joins it, gets its result and shows no prompt of its own (its purpose text is not shown). `confirmFresh` never joins. | One confirmation counts for every request of the session for `auth.step_up_max_age`; the terminal's fresh step-up is consumed by its own request. |
| AUD-PKG-P04/A5 | 2026-11-24 | `SessionCore.signOut` emits `SignedOut` also when the `SecretStore` fails to delete, then rethrows the store's error; a store that cannot be read counts as holding a session. Failures of `secrets.write` in `adopt` keep their current behaviour (the refresh fails). | Without the event the app kept showing the signed-in state and did not delete local data after a revocation (R-SY-14). |
| AUD-PKG-P04/B1 | 2026-11-24 | A refused `putReadState`, `putThreadDraft` or `deleteThreadDraft` without dependents is deleted from the outbox and logged instead of kept as `failed` (addendum to 04 13.2 item 5). No grace period. | No view shows these entries (the thread view filters them), so a kept row only grew the outbox and kept draft text forever; the next read position or draft write carries the current state again. Dependency tables and indexed reads of the outbox stay open (#1631, architecture). |
| AUD-PKG-P04/B2 | 2026-11-24 | Interim fix for gaps after an app start: on focus the engine derives the gap from stored messages behind the newest loaded range (`GapFiller.recover`) and fills it. No timed retry, and a `gapAfter` known only from `threads.last_message_seq` gets no own load path. | Removes the user-visible harm (messages stored behind a forgotten gap stay hidden) without a new table; a backoff retry and a load path for `gapAfter` are a new mechanism and stay open (#865). |
| AUD-PKG-P04/C1 | 2026-11-24 | A handler of the fake server that throws anything but a `FakeProblem` answers `500 internal_error` and adds a line to `violations`; an operation without a handler keeps its `501` and is not added to `violations`. | A crash of the fake is always a defect of the fake, and every test that checks `violations` now fails on it. Tests and app tests that touch operations the fake does not serve would all turn red on a `501` violation; that list is a separate decision. |
| AUD-PKG-P04/C2 | 2026-11-24 | `vizProblemCode` reports only a Dart `Error` (with its stack) to `FlutterError.reportError`; an `Exception` without a problem body (a transport failure) keeps showing only the general text. No `onError` port is added to the views. | An `Error` is a defect of the app; a lost connection is an expected state that the banner already explains, and reporting it would flood the host's error handler. `FlutterError.reportError` reaches the host without a new API. |
| AUD-PKG-P04/C3 | 2026-11-24 | `VizTable` sorts a table with tree rows by blocks (a top row with the tree rows below it, ordered by the top row's cell) instead of switching sorting off for tree tables. | The live topology table stays sortable by run, and a flat table (every row on level 0) sorts as before. |
| AUD-PKG-P04/C4 | 2026-11-24 | `FakeServer.stop` waits at most `FakeServer.stopGrace` (2 seconds) for requests still being served; `DelayFault` keeps its `Future.delayed`. | The sockets are closed before the wait, so a held handler can no longer answer; a bounded wait ends the tear-down without changing how faults delay. |
| AUD-PKG-P04/D1 | 2026-11-24 | "Read screen" in the terminal also has keys: Cmd+Shift+S on Apple systems, Ctrl+Shift+S elsewhere, bound by `terminal_ui` for the apps and the console and named in the hint of the screen node (01 7 table "In the terminal"). The custom action stays. Lines of the screen are not exposed as semantics nodes. | Only iOS and Android offer custom actions to screen readers. Keys with the platform modifier keep every plain key with the shell (R-PR-10); S is free in both shortcut tables; readable line nodes would make running output reachable but change what a screen reader meets on every update. |
| AUD-PKG-P04/D2 | 2026-11-24 | The hardware-keyboard-only workaround of D-M4-36-10 applies only to the Windows app, not to a browser that runs on Windows (`!kIsWeb`). | The cause is the Windows embedder; in the browser the target platform is only the system of the browser, and its text input client works as on macOS and Linux. |
| AUD-PKG-P04/D3 | 2026-11-24 | `TerminalController.end` returns whether the session ended: a `200` or a `404` (the server no longer has it) ends the tab; any other failure leaves it detached with the problem code (`end_failed` without one). The apps close the tab only on success; the console keeps its End button for a detached tab. | The server answers an already closed session with `200`, so `404` is the only "already gone"; a swallowed failure left a session running on the host until `terminal.detach_grace` with the tab gone. |
| AUD-PKG-P04/D4 | 2026-11-24 | Only the primary button gets hover and pressed colors on its fill (`color.accent.bg-hover`, `bg-pressed`, its fill painted as ink). Success, danger and the other filled surfaces keep no visible hover until tokens for them exist. | Only the accent has hover tokens; the shared `color.surface.hover` is opaque and would cover the fill and its text contrast. |
| AUD-PKG-P04/D5 | 2026-11-24 | `L10nFormat` formats a time zone the bundled database lacks as UTC (`L10nFormat.knownTimeZone`) and never throws for a zone. The existing fallbacks of the callers stay as dead code until their area is next touched. | One rule in the package fixes the callers without a fallback; removing fifteen copies is a refactor outside the finding. |
| AUD-PKG-P04/D6 | 2026-11-24 | The run reason `user_cancelled` keeps "Canceled by a person" while the run carries no name of the person who stopped it. | Naming the person needs the field in the run contract. |
| AUD-PKG-P04/E1 | 2026-11-24 | A thread move writes `thread.moved` before `thread.moved_out` (consecutive `seq`), replacing ruling M1-62/1; the client moves the stored messages, attachments, run summaries, read state, drafts and search rows of a thread whose channel changes. Events of moves written before this change keep the old order and still remove the thread once on a device that catches up over them. | `thread.moved_out` does not name the target, so a client can only tell whether it sees the target when `thread.moved` came first; with the old order a reader of both channels lost the thread with its messages. Changing the server order needs no new payload or client state across pages; the old order stays only within `sync.event_retention`. |
