# FEAT-TEAM-CHANNEL-APP App slice of the team channels

| No | Date | Ruling | Reason |
|---|---|---|---|
| D-TEAM-APP-1 | 2026-11-21 | The app learns that a channel is a team channel from `getChannelTeam` (`404` for none), asked by an owner for a text channel when it opens, and reads the team again after every own change and when a new message arrives in the open thread of the team channel. No sync event for team changes and no `Channel` member that marks a team channel were added on the server (D-TEAM-10 left them to this slice). | Only owners read a team channel (readers rule, 09 3.9.1), and every owner may call `team.read`, so one read per opened text channel is exact for every reader; a person who is no owner never asks. Pauses and stops post a note in the team channel and the member states follow `run.state_changed` of the work threads, so the header stays current without a new event. What it does not cover: a member added or removed by another owner on another device shows after the next message in the open thread or the next opening of the channel, and an owner's message in another thread of the channel lifts a pause the header shows until then. A sync event `team.updated` and a `Channel` member stay open for a later slice if that delay matters. |
| D-TEAM-APP-2 | 2026-11-21 | The six team operations are online calls with an immediate answer, not outbox entries. An add and a stop carry an `Idempotency-Key`; a repeated add for the same agent, home channel and handle after a lost answer sends the same key. A refused add drops its key, so the next press is a new request (the server keeps a refusal under its key, 04 5.2). | The dialog must show the server's refusal reason at once (`team_readers_not_owners`, `team_home_not_operated`, ...), and a queued switch or member change would act long after the owner looked at the team. |
| D-TEAM-APP-3 | 2026-11-21 | `/team` is a built-in client command, offered to an owner in a text channel that is neither archived nor read-only; `add` opens the dialog with the handle filled in instead of taking agent and home channel as text. | The name is reserved on the server (09 10.1); choosing an agent and one of the channels it operates needs a picker, and the dialog holds the same rules as the switch. |
| D-TEAM-APP-4 | 2026-11-21 | A member's state in the header is "working" while its agent has an active run (queued, running or waiting) in its work thread, else "paused" while the channel is paused, else "idle". | The pause holds back new member inputs, not a running run; "Stop all" ends those. |
| D-TEAM-APP-5 | 2026-11-21 | "from @handle" is shown under a text message of a member's agent in the team channel; an agent that is a member twice names both handles. "to all members" is shown under every text message of a person there. The input copies in a member's work thread are not labelled in this slice. | A mirror carries no member ID (03 `team_mirrors` is server-side only), so the author's agent is the only link; every person who can write in a team channel is an owner. The work thread lies in the home channel, whose view does not know the team. |
| D-TEAM-APP-6 | 2026-11-21 | A menu entry that opens a dialog takes the `ProviderContainer` while the menu builds (`ProviderScope.containerOf`) and hands it on, never the menu's `WidgetRef`: the team entry (`showTeamDialog`, also `stopTeam` of the bar) and "Rename project" (`showRenameProjectDialog`), which had the same pattern. | A menu entry runs after its menu closed, when the `WidgetRef` of the menu overlay is unmounted; the review reproduced "Team channel..." throwing `Using "ref" when a widget is about to or has been unmounted` from the sidebar row (`test/menus/team_menu_test.dart`). |
