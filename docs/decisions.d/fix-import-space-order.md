# FIX-import-space-order Order of imported spaces and channels

| No | Date | Ruling | Reason |
|---|---|---|---|
| FIX-ISO/1 | 2026-10-29 | The import tool reads the last `sort_key` of the spaces of the server and of the channels of every live target space in the preflight; the new spaces get the next integer keys after the last space key, the channels of each target category the next integer keys after the last channel key of its space (none for a space the run creates). Each block keeps Discord order. | Found in an import into an instance that already had spaces: the keys started at `a0` and the imported spaces interleaved with the existing ones in the sidebar (key, then ID). |
| FIX-ISO/2 | 2026-10-29 | A re-run does not reorder: the server answers a posted origin key with its stored item and does not write the new key, and structure items carry no content hash, so a changed key is not counted as changed at the source. A category added to the mapping later lands after everything that exists at that run. | The keys of later runs differ from the first run's, which is harmless because only new items are written; `TestRerunKeepsPlacedOrder` holds it. |
| FIX-ISO/3 | 2026-10-29 | The tool has its own integer step of the fractional index (`nextKey`, the step of `fracindex.KeyBetween(k, "")`) instead of importing `internal/chat/domain/fracindex`, with the vectors of the chat module in its test. | The module register lets `cmd` depend only on the kernel, platform, wire, api and migrations, not on a module's domain; moving `fracindex` to the kernel would touch the chat module and its records for one step function. |
| FIX-ISO/4 | 2026-10-29 | The channel blocks are keyed by the live target space, not by the Discord category: all categories mapped to one existing space draw their keys from one sequence in Discord order. The sidebar order the tool sets is the shared one; personal sidebar keys stay with each person. | Two categories mapped to the same existing space started at the same last key and interleaved; `TestCategoriesSharingExistingSpaceKeepDiscordOrder` holds it. The tool cannot read or write the personal keys of other people. |
