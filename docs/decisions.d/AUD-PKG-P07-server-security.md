# AUD-PKG-P07-server-security Server findings of the audit of 2026-11-11 in identity, authz, audit, privacy, gateway and wire

Work package of the audit of 2026-11-11 for the modules `identity`, `authz`, `audit`, `privacy`,
`gateway` and `wire` of the server. Each finding was read again on the current `main` first;
findings already fixed or decided since the audit are closed with their evidence and have no row
here.

| No | Date | Ruling | Reason |
|---|---|---|---|
| AUD-P07/1 | 2026-11-23 | After a restore to an earlier point in time the operator moves `audit.checkpoint_sink` to a new location that holds a copy of the checkpoints up to the newest one of the restored database; the old location stays as evidence (backup-restore.md 8.1, runbook `BothyAuditChainBroken`). Test: `TestRestoreBreaksTheChainUntilTheSinkMoves`. Not built: a signed rollback marker written by `bothy restore finalize`. | The old checkpoints cannot be removed from a bucket in mode `COMPLIANCE`, and a rollback marker is a new concept of the checkpoint chain (verify, job and sink format); the copy needs no code and keeps every existing check unchanged (srv-kernel-audit-privacy-2). |
| AUD-P07/2 | 2026-11-23 | Without `audit.checkpoint_sink` the trim of `retention.audit` stays off; the start and job warning `audit_checkpoint_sink_not_configured`, the configuration reference, 20-privacy.md 4.5 and the ROPA template say so. No separate metric for a skipped trim. | Trimming without a checkpoint outside the database would let rows leave the log unsealed (M7-05); the existing warning already fires at every start and job run (privacy-5, srv-kernel-audit-privacy-4). |
| AUD-P07/3 | 2026-11-23 | A new IP key starts at the end of an older key that covers the aligned start of its period (`Keyring.periodStart`). Test: `TestKeyring_LongerPeriodStartsAfterTheLastKey`. | A longer `privacy.audit_ip_key_period` made the aligned start hit an expired key, so the insert was a no-op and every audited write with a client IP failed (srv-kernel-audit-privacy-3). No exclusion constraint: the walk keeps the existing table and query. |
| AUD-P07/4 | 2026-11-23 | The viewed person of "view as" is loaded like the principal of the check without a request (owner role from the owner list, own cache key); the check of the re-check marker sits in `principalOf`, so every path that loads a principal shares the R-AZ-29 bound. Tests: `TestViewAsOwnerShowsOwnerView`, `TestRecheckPrincipal_BoundOutsideAuthorize`. | 07 9.2 shows what the person sees; the intersection with the viewing owner keeps it from showing more (srv-authz-6, srv-authz-10). |
| AUD-P07/5 | 2026-11-23 | `grant.create`, `previewGrant`, `grant.revoke` and the privacy request and decision bound their reason by `audit.reason_max_chars` (`too_long`); the fixed 1000 of privacy is removed. The OpenAPI descriptions of these reasons are not changed here. | SEC-AUD-5 names the bound for every mandatory reason; a description change regenerates the three SDK clients and waits for the next contract change of these operations (srv-authz-3, srv-kernel-audit-privacy-16). |
| AUD-P07/6 | 2026-11-23 | The audit entry of a decision error and the `Fail` of a privacy job after the last attempt run with `context.WithoutCancel`, bounded by the unit of work; the export deletes a package its request did not take with the same detached context. Not built: aggregation of decision errors, a reconciliation of running privacy requests without a live job, a sweeper of `gdpr_export` files without a request. | The canceled request or job context made the very write fail that records the failure (srv-authz-9, srv-kernel-audit-privacy-6, -7); the rest is new machinery without a reproduced harm. |
| AUD-P07/7 | 2026-11-23 | A confirmed login (enrollment code or pairing) on a known `pending` device of the same person with the same key is `409 conflict` with reason `device_pending`; the unit rolls back, so the code stays unused (the refusal counts as a failed attempt like every rejected redemption with a matching code). Activating the device in the login unit is not built. Supersedes the third sentence of M1-37/12. Test: `TestRedeemOnKnownPendingDeviceKeepsTheCode`. | Approving the device is the rights change `device.approve`, whose hook must lock `permission_version` before any domain row; the login units lock the code row first, so an in-unit approval would break the lock order (srv-identity-app-5). |
| AUD-P07/8 | 2026-11-23 | `CountPairingDevicesOfUser` counts only active non-cli devices with an active DPoP key, which leaves out the keyless web devices of console logins. Not built: revoking the web device at console logout, or the app device at app logout. Test: `TestUnlink_LastMethod`. | A console device never approves a pairing (no device screens in the console), yet every console login left one active (fn-sign-in-devices-5). Revoking devices on logout changes the device list and is a product decision. |
| AUD-P07/9 | 2026-11-23 | The flush steps `audit_denials` and `stats_flush` each get the new key `shutdown.database_flush_timeout` (default `2s`), which `jobsWaitBudget` subtracts twice and the budget sum of the runner counts through `Runner.Reserve` (the steps register during the start of their components, after the check); the start refuses a sum above `shutdown.total_timeout` as before (exit 2). Not built: a cross-check in `bothy config check`, because `Serve` takes the role as an argument, not from `server.role`. With the defaults the role `all` keeps 6s for `jobs_wait` (10s before). Not built: budgets for the phases connections, event_tail and consumers. Tests: `TestJobsWaitBudgetLeavesTheLaterSteps`, `TestServeDatabaseFlushBudgetCountsAtWiring`, `TestReservedBudgetCountsAtWiring`. | A hanging job could spend the whole total, so the open denial aggregations were neither written nor reported as dropped (srv-wire-4); a fixed reserve without a key would be an unnamed limit (SPEC rule 3). |
| AUD-P07/10 | 2026-11-23 | The webhook routes of the internal listener answer `503 unavailable` with `Retry-After` equal to `shutdown.total_timeout` once readiness turned false (`shutdownGate`). The rate limit sweeper of that listener keeps its phase. Test: `TestShutdownGateRefusesWebhooksDuringTheShutdown`. | The listener closes after the pool (srv-wire-8); the start lock already leaves the routes unmounted, so only the shutdown needed a gate. The restart follows the shutdown, so its total is the honest retry hint. |
| AUD-P07/11 | 2026-11-23 | The challenge cleanup keeps the used step-up challenge whose `finished_at` equals `step_up_at` of a live session; storing the user verification fact on `auth_sessions` is not built. Test: `TestConsoleStepUpSurvivesChallengeCleanup`. | No migration and no new key: the kept row is at most one per live session and goes with the next step-up or the session's end (srv-identity-core-4). |
| AUD-P07/12 | 2026-11-23 | Step 6 of the account deletion rewrites `handle`, `display_name`, `locale` and `time_zone` of every stored `user.updated` event of the person to the pseudonymized values and drops `avatar_file_id`, through the `eventlog.Redactor` of sync passed to `identity/app.NewPersonalData`; status and the other members stay. Test: `TestPersonalDataErase`. | 20 section 2 promises redaction on deletion for `event_log`; identity did not use the redactor (privacy-9). Keeping the status keeps the history of the events readable for clients that catch up. |
| AUD-P07/13 | 2026-11-23 | Every gateway connection end writes one info line `gateway connection closed` with `bothy.close.code`, `bothy.outcome`, `bothy.principal.kind` and the new log attribute `bothy.connection.duration` (seconds), in signals.md 5.3 and the collector allowlist. Ending the span `gateway.connect` at ready is not built. Test: `TestConnectionEndLogsOneLine`. | Disconnects of a device were only visible as a metric without a principal kind or duration (fn-sync-offline-8); changing the span model would change the trace catalogue. |
