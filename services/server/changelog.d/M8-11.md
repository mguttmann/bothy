### Added

- Content items of the import interface (M8-11, 22 5.1.1, 6, 7.2, 8, 12.2, R-IM-05, R-IM-08,
  R-IM-11): `applyImportBatch` accepts thread batches with `thread_origin_key` (`thread:<id>` or
  `channel:<id>` for the main thread of a text channel) holding a thread item, message items and
  pin items. A thread gets its title (cut to `thread.title_max_chars`, `auto` for a placeholder
  name), the planned operator of the mapping, the times and the done state of the source, its
  starter message and forum tags; a posted thread only follows the mirror rules (title while
  `auto`, archive and reopen, later activity). Imported messages have `origin = import`, are
  silent, write no mentions, keep `created_at` and `edited_at` of the source, take the thread
  numbers in request order and may reply to and attach files of the same thread; pins name the
  importing owner. A batch never triggers a run, an invocation, a notification or a push and
  never appends `message.created`; it sets `threads.unread_floor_seq` to the end of the thread and
  appends one `thread.updated` and one `import.progress`.
- `createImportFile` reserves the file of a file item with an upload session without quota
  (`ImportFileCreate.sha256` is new and required); the new operations `uploadImportFilePart` and
  `completeImportFile` carry the parts and the completion under `import.apply`, so read-only
  mirror channels accept them, and post the item. A repeated call returns the same file ID, with a
  new session after an aborted or expired one. The scan and thumbnail jobs of import files run
  with the lowest job priority on the queue `files` (`platform/jobs` `InsertOptions.Priority`).
