### Added

- Interview of "New agent" (chapter 26 6.1): `POST /api/v1/agents/interview` (`interviewAgent`,
  action `agent.interview`: owners only, effect `write`, `rl.trigger`) sends the interview so far
  as the ephemeral event `agent.interview_requested` to one live connection of the builder agent
  named in `agents.builder_agent_id` and waits up to `agents.interview.timeout`; the route's
  deadline is that wait plus `http.request_timeout`. The answer is one or two questions, a draft
  checked with the definition rules and the template catalogue (`mcp_not_in_catalogue`), or a
  fallback (`builder_not_configured`, `builder_offline`, `builder_timeout`, `builder_invalid`),
  with the builder's cost estimate. Nothing of the interview is stored; every request writes one
  audit entry `agent.interview` and one log line with counts only.
- `POST /api/v1/agent-interview-requests/{request_id}/answer` (`answerAgentInterview`, action
  `agent.interview.respond`) takes the builder's answer once; a draft that reaches a surface of
  the Claude Code CLI is refused and ends the request with `builder_invalid`.
- Configuration keys `agents.builder_agent_id` (empty: no interview), `agents.interview.timeout`,
  `agents.interview.max_turns` and `agents.interview.answer_max_chars`. Nothing changes for an
  installation that sets none of them.
