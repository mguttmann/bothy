### Added

- Several api nodes (M7-17, 02 11.6 and 16 level 2, 13 12 point 4, 16 4.5): with
  `cluster.mode = multi` the gateway sends typing, live box updates, agent presence, the
  replacement of a device connection, the takeover of an agent consumer and hints between the
  processes as signals on `NOTIFY ephemeral` with IDs, versions and codes only; the receiving node
  rebuilds the event from its own state and the database. A second `identify` of a device on
  another node closes the older connection with `4017`, a second connection of an agent
  consumer closes the older one with `4015` at once. The new table `gateway_presence` (`UNLOGGED`,
  R-DM-51) holds the live connections of every api node, written every
  `cluster.presence_flush_interval` and ignored after `cluster.presence_ttl` (new keys); the
  worker's push decision reads it and sends `notification.created` to the node of the
  connection, so desktop hints and the delayed mobile push work with separate roles and several
  api nodes. New counter `bothy.gateway.presence.write_failures`. One `LISTEN ephemeral`
  connection per process (`ephemeral_listener`, application name `bothy-ephemeral`) now serves
  the gateway and the terminal. The load test `perf/gateway_fanout_multi` measures
  `perf.fanout_cross_node_p99`; the guide `docs/operations/multi-node.md` describes the setup,
  including one signing key store for all nodes.

### Changed

- Role `worker` no longer falls back to push only for desktops (M3-23): it reads
  `gateway_presence`. Role `api` holds the `LISTEN ephemeral` connection in every
  `cluster.mode`, because a separate worker sends its hints through it.
- `command.autocomplete_requested` reaches only an agent connection on the node of the request;
  without one the request ends with an empty result at once.
