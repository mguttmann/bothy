### Added

- Timeline, SLO traffic light and backend view of the visualizations (M6-14,
  docs/spec/25-visualization.md 6.2, 6.4, 6.5): the operations `getStatsTimeline`,
  `getStatsSlo` and `getStatsBackends` are enabled. All three read the own measurement
  (`stats_minutes`) with the authorization and the channel set of the statistics queries.
  `getStatsTimeline` returns the minute rows and the run intervals of a range on full minutes of
  at most `stats.timeline_max_range` inside `retention.stats_minutes` (`400 validation_failed`
  otherwise): rows of the visible channels, rows without a channel only for an owner on the
  instance, `cost` rows only with `cost.read.aggregate`; runs ordered by `queued_at`, at most
  `stats.timeline_max_runs` with `runs_truncated`. `getStatsSlo` returns one entry per SLO of the
  Sloth files with ratio, remaining error budget and the state `green`, `amber`, `red` or
  `insufficient_data` by `stats.slo_warn_budget_ratio` and `stats.slo_min_events`, owner only,
  `measured_by` `own`, cached for `stats.cache_ttl`. `getStatsBackends` returns per agent of the
  visible channels the configured and reported billing mode, the supported modes, the switches,
  the I2 and I3 denials, costs per mode as estimates (only with `cost.read.aggregate`, mode
  `personal` only with `billing.show_personal_estimates`) and the reported rate-limit state,
  never a runtime name, version, evidence, subscription or credential. New keys
  `stats.timeline_max_range`, `stats.timeline_max_runs`, `stats.slo_warn_budget_ratio` and
  `stats.slo_min_events`.
- The agent heartbeat accepts `rate_limit` (`state`, optional `resets_at`) and stores exactly
  these two members in `agents.reported_details.rate_limit`; a heartbeat without it clears the
  stored one. It is never audited on its own.
