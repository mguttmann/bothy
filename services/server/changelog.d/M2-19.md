### Added

- Agent answers and announcements (M2-19, AG-01, AG-26): `MessageCreate.run_id` is enabled. An
  agent may name an active run (`queued`, `running`, `waiting_input`) of its own in the target
  thread; a person or app, an unknown run, a run of another thread or of another agent answer
  alike 400 `validation_failed` with `errors[].code` `run_mismatch`, an ended own run 409
  `conflict` with `reason` `run_not_active`, and `first_message.run_id` of `createThread` is
  always `run_mismatch`. `run_id` is checked in the acceptance subscriber of runs under a shared
  row lock, so an answer with `run_id` commits before the end event of its run; it is never
  stored and not part of the request hash. `MessagePosted` carries `RunID`. Agent messages never
  trigger, and agents write only with `write` from a grant or the operator rule, proven by the
  tests of AG-01 and AG-26.
