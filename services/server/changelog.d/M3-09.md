### Added

- Voice messages and transcript (M3-09, 12 section 8, 09 section 13, R-FI-10, R-AG-16):
  `createMessage` and `createThread` (`first_message`) accept `kind = voice` (no longer `400
  validation_failed` with `errors[].code` `not_enabled`). A voice message has exactly one ready
  attachment, MP4 audio (`audio/mp4`, `.m4a`) for every author and MP3 (`audio/mpeg`) also for
  agents; another format, an MP4 with a video track or without an `mvhd` duration answer `400
  validation_failed` with `errors[].code` `voice_format_unsupported`, a duration above
  `voice.max_duration` `voice_too_long`, a file not ready `409 file_not_ready` or `409
  file_blocked`, and nothing is stored. MP4 audio becomes `complete` together with its duration in
  the container phase of `files.thumbnail`. The transcription mode `voice.transcription_mode`
  decides the transcript: in mode `agent` the operator agent of the thread stores it with
  `submitTranscript` (`If-Match` with the derived transcript `ETag`, which `getFile` and
  `getTranscript` now send; an agent that cannot read the file gets the unknown-id `404`); in mode
  `service`, only while `voice.enabled` is on for the author, the send queues the new job
  `files.transcribe`, which sends the audio through the egress client to the OpenAI-compatible
  service at `voice.transcription_url` and stores `done` or, after
  `voice.transcription_max_attempts` attempts or a permanent error, `failed`;
  `requestTranscription` starts it again. Every change of the transcript writes `file.updated`
  without the text. A voice message that triggers an agent without a transcription path gets
  `trigger_state = failed` with `voice_unsupported`; in mode `service` its `agent.invocation`
  waits for the transcript, at most `voice.transcript_hold_max`. The run context lists the
  transcript of a voice message with the trust of its message. New configuration keys
  `voice.transcription_model` and `voice.transcription_max_attempts`.
