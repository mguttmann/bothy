### Added

- Terminal conformance and chaos suite (M2-48): `test/terminal/catalogue.yaml` names for every
  ID TM-T01 to TM-T29, AZ-M54 to AZ-M61, ID-T28 and SEC-T05 where it runs; the data-driven
  scenario files under `test/terminal/scenarios` run with the packages `suite`, `stack` and
  `device` in `test/terminal/e2e/conformance`, `hostpolicy`, `limits`, `twonode`, `restart` and
  `hostplatform` against the installation Compose file with test overlays, the server image built
  from the worktree, a test-only TLS front, real `bothy-host` services in Linux containers with
  systemd and a Go test device that speaks Noise through the host service's own packages.
  `test/chaos` gains `TestChaosTMT16` for `make perf`. No product behaviour, configuration key,
  operation or event is added.

### Fixed

- Terminal (M2-48): the ready that `confirmHost` and `setHostLlmCredentials` send again to a
  connected host service runs after the outermost commit, so it carries the committed
  declaration also inside the unit of work of the Idempotency-Key stage; a host that logged in
  while `confirming` no longer keeps `llm_credentials` `none` and offers the profile `claude`.
  Every ready of a control connection is read and queued in one order, so the ready of the login
  can no longer overtake a newer one.
- Terminal (M2-48): a denied `listTerminalSessions` of an agent, app or personal token writes its
  deny entry like the other four session operations (R-AZ-04, TM-T17).
- Terminal (M2-48): when the host side of a started session ends because the session ended (a
  revocation, a `session.close` from another node, 4110 to 4112 at the control connection), the
  relay closes the device stream with the code and reason of that end (`RelayHostLost`) instead
  of `4102`, also when the close of the data connection arrives before
  `terminal_session.changed`.
