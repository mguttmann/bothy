### Added

- Hosted agents (A1-03): an agent with `adapter_kind` `claude_agent` is a built-in agent and names
  its hosting Claude Code runner in the new member `hosted_by` of `createAgent` and `Agent`
  (column `agents.hosted_by`, migrations 00094 to 00096; the first refuses to run while an agent
  of that kind exists and names it). The runner must be active, not hosted itself and report the
  new heartbeat capability `hosts_agents` (`chat`, `scoped` or `host`), else `400` with
  `host_not_capable` on `/hosted_by`.
- `setAgentHost` (`PUT /api/v1/agents/{agent_id}/host`, `agent.host.set`, owner with step-up)
  moves a built-in agent to another runner and revokes the tokens the old runner holds;
  `listHostedAgents` (`GET /api/v1/agents/me/hosted`, `agent.hosted.list`) lists the active agents
  a runner hosts; `issueHostedAgentToken` (`POST /api/v1/agents/me/hosted/{agent_id}/token`,
  `agent.hosted_token.issue`) gives the hosting runner a token bound to its DPoP key that expires
  after the new key `agents.hosted_token_ttl` (default `24h`, at most `auth.api_token_max_ttl`);
  every other caller gets `404`. The durable event `agent.hosting_changed` tells the old and the
  new runner.
- The tool class of a built-in agent stays at or below its runner's `hosts_agents`
  (`409 conflict` with reason `host_tool_class_ceiling`), and `personal` needs the runner's credential holder
  (`409 conflict` with reason `hosted_holder_mismatch`, BR-14).

### Security

- The tokens of a built-in agent go only to its hosting runner and end with the agent, a host
  change, the runner and every runner token with the same key, in the same transaction;
  `createToken` for a built-in agent is `409 conflict` with reason `hosted_agent_token`. Agents and tokens created before
  this version are unchanged.
