### Added

- Run document, patches and live box (M2-10, ADR 0025, R-SY-05): the operation `patchRun` and the
  gateway op `run.update` are enabled and call one use case (`run.update`, agent-self,
  `rl.agent_runtime`, no `Idempotency-Key`). The agent of an active run changes its live box with
  RFC 6902 `add`, `replace` and `remove` on the paths of 09 section 5.3 with `base_version` as
  compare-and-swap: a path outside the table gives 400 `validation_failed` with `errors[].code`
  `patch_path_forbidden`, an ended run 409 `conflict` with `reason` `run_not_active`, a stale base
  409 `base_version_conflict` with the document in `current`; `add` and `replace` set absent
  members, `remove` of an absent member is a no-op. A stored patch raises `runs.version` by one,
  clears `stall_warned_at` and writes no durable event, no `event_seq`, no `audit_seq` and no
  `NOTIFY`. `last_text_excerpt` keeps its last `run.excerpt_max_chars` runes, a step `detail` is
  cut to `run.step_detail_max_bytes`, its numbers stored in plain decimal form, and above `run.max_steps_persisted` older finished steps
  merge into one summary step. Clients get the ephemeral `run.updated` only on connections that
  focus the thread and pass `run.read`, coalesced per run and connection for
  `sync.run_patch_coalesce_interval`; a newly focused thread, a resumed focus, a gap and a full
  outbound queue get the whole document as `snapshot` instead (never `4014`). New configuration
  keys `sync.run_patch_coalesce_interval`, `run.excerpt_max_chars` and `run.max_steps_persisted`,
  the counter `bothy.run.steps` and the reason `patch_replaced_by_snapshot` of
  `bothy.gateway.outbound.dropped`; follow-up states go through the port `FollowupStates`, empty
  until M2-11. ADR 0025's Confirmation now names 400 `validation_failed` instead of 422.
