### Added

- Costs: booking, price table and display (M2-22, BR-09, BR-11 server part, D-BR-01, R-DM-23):
  the module `billing` keeps the tables `price_table` (migration `00072`, with the extension
  `btree_gist` and an exclusion constraint against overlapping validities of one provider, model
  and unit; `bothy_app` may update only `valid_to`) and `cost_entries` (migration `00073`, append
  only, with the foreign key of `agent_session_id`), and enables `getThreadCosts`, `listPrices`,
  `createPrice` and `closePrice`. `finishRun` books its `costs` (the `errors[].code` `not_enabled` of
  M2-09 is gone): one estimate entry per model in the unit of work of the finish, `computed` from the price
  set of provider, model and the end of the run when it has one currency and every consumed unit
  (exact integer arithmetic, one half-up rounding per entry), else `adapter_reported` with the
  adapter's amount, else `unpriced` with `0`; the entries copy agent, thread, channel, space,
  session and the actual billing mode, `occurred_at` equals `finished_at`, and currencies are
  never converted. A repeated finish books nothing, invalid reports and reports for a run that
  never started are 400, the run columns take the sum in the currency of the first entry, and the
  session sum grows per currency (`agents.Sessions.AddCost`, no `agent_session.changed`).
  `getThreadCosts` answers per run and per billing mode and currency (new schemas `CostTotal` and
  `TokenCounts`, `CostBreakdown` and `RunCost` reshaped), with token counts always and with the
  amounts of `personal` runs only when the new key `billing.show_personal_estimates` is on; an
  invisible thread is the 404 of an unknown one. Price changes need an owner with step-up, are
  audited with row, source and retrieval time (new audit value kind `auditing.SourceURL` under
  `source_url`), are refused with `409 conflict` and the reason `price_overlap`, `price_currency_mismatch`,
  `price_closed` or `price_in_use`, and never change a used row except its end. The port `billing.Costs` offers
  the valid sums per run, thread, session, agent, space and instance for the statistics. The
  product ships the start file `internal/billing/domain/startprices/start_prices.json` (schema
  `start_prices.v1`, base prices with source and retrieval time, checked by tests, not loaded by
  the server; the owner enters prices with `createPrice`). The counter `bothy.run.cost` records
  each booked entry after the commit. No new event type, job, action or problem code.
