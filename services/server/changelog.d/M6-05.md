### Added

- Statistics in the server (M6-05, admin-statistics.md, R-OB-08): `getUsageStats`,
  `getRunStats`, `getToolCallStats`, `getErrorStats` and `getCostStats` are enabled and answer from
  the server's own tables through new `StatsSource` ports of the owning modules (`chat`,
  `messaging`, `runs`, `billing`, `files`, `apps`, `notify`), never from telemetry. Each
  operation authorizes `stats.read` (`getCostStats`: `cost.read.aggregate`) on the instance or, with
  `space_id`, on that space, and counts only the channels the caller may read
  (`Scope(message.read)`); webhook, push and scan figures, which have no channel, appear only for an
  owner on the instance. No figure is grouped by person; `active_people` exists only for weeks and
  months and is withheld below `privacy.stats_min_group_size` and named in the new member
  `below_min_group` of `StatsBucket`. `getCostStats` keeps `personal` and `organization` apart,
  marks estimates, applies `billing.show_personal_estimates` and answers in one currency: the new
  parameter `currency`, or the one currency of the range, else `400 validation_failed` with
  `errors[].code` `currency_required`. Ranges are bounded by `stats.max_range` and
  `api.stats_max_buckets`; day, week and month buckets start at local midnight of `stats.time_zone`.
  Results are cached per process for `stats.cache_ttl`, keyed by the caller's rights version and
  channel set and bounded by the new key `stats.cache_max_entries`. The keys `stats.cache_ttl`,
  `stats.max_range`, `stats.time_zone`, `api.stats_max_buckets`, `privacy.stats_min_group_size` and
  `privacy.per_person_stats_enabled` become active. The module `stats` may now use the ports of
  `files`, `apps` and `notify`; the SQL visibility gate gains the category `system_aggregate`. No
  new table, migration, action, event or problem code.
