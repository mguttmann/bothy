### Added

- Maintenance mode (M7-08, ADR 0065, 05 rule 1.9, 16 section 11): with
  `server.maintenance_mode = read_only`, read at the start of `api` and `worker`, every action with
  effect `write` gets `503 maintenance` with `Retry-After` (`server.maintenance_retry_after`) after
  the rate limit and before `authorize`, never audited and counted in
  `bothy.maintenance.rejected`. Reading, search and downloads continue. Exceptions: the token
  refresh, the emergency actions `auth.step_up`, `session.revoke`, `device.revoke`, `token.revoke`
  and `user.disable`, `run.cancel`, and for an agent with a running run `run.update`, `run.finish`,
  `agent.heartbeat`, `agent.events.consume` and its answer (`message.create`, `file.upload`) in the
  run's thread; `run.start` is refused, so queued and waiting runs wait.
- Second line: in the mode every unit of work that is no exception begins `READ ONLY`; a write
  PostgreSQL refuses there (`25006`) answers `503 maintenance` whatever the use case made of the
  error (`txn.WithWriteInMaintenance`, `txn.ExemptInMaintenance`, `pg.UnitConfig.ReadOnly`).
- `auth.token.refresh` in the mode returns a new access token and the presented refresh token
  without a write; a reuse still revokes the family.
- The `worker` in the mode runs only the consumers `push` and `webhooks`, the queue `delivery` and
  `runs.cancel_timeout`; other jobs of the queue `maintenance` wait without using an attempt, other
  queues and periodic jobs pause until a restart without the mode.
- Agent deliveries in the mode: the invocation of a queued or waiting run (and every
  `command.invoked`) is held, so the agent's consumer, on the gateway and over REST, stops before it
  without closing and receives it after the mode.
- The status page shows every component of the instance and the overall state as `maintenance`
  in the mode, derived from the configuration.
- The port `runs.RunningRuns` (the running runs of an agent) and the configuration key
  `server.maintenance_retry_after`; `server.maintenance_mode` is active.

### Changed

- In maintenance mode `last_seen_at` of app sessions and devices, `last_used_at` of API tokens and
  the own measurement in `stats_minutes` are not written.
