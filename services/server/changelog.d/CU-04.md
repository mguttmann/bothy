### Added

- Computer sessions in the module `terminal` (docs/spec/27-computer-use.md, ADR 0078): an agent in
  an active `host` run that an active owner started with an own message lists the owner's
  desktops (`GET /api/v1/computer/desktops`, `computer.desktops.list`) and opens a computer
  session on one of them (`POST /api/v1/computer/sessions`, `computer.open`), bound by the header
  `Invocation-Token` (SR9) and guard rule SR13; refusals `403 forbidden` with
  `computer_not_owner_run`, `computer_tool_class` or `computer_not_enabled`, `409 conflict` with
  `computer_busy` or `computer_run_busy`, `409 host_unavailable`, `404 not_found`. The answer
  carries a single-use attach token (`typ = computer-session+jwt`).
- The attach connection of `bothy-computer-mcp` (`/api/v1/computer/sessions/{session_id}/attach`,
  `computer.attach`) and the computer data connection of the host service
  (`/api/v1/hosts/computer-sessions/{session_id}/stream`), paired in the relay; the relay forwards
  ciphertext only and counts lengths (`bothy.terminal.computer.relay.size`, `.messages`).
- Host ops `computer.open`, `computer.close`, `computer.disable` (server to host) and
  `computer.started`, `computer.state`, `computer.ended` (host to server); `report` gains the
  object `computer`, stored in `hosts.reported_computer`, a change audited under `host.connect`.
- Every active owner stops any computer session (`POST /api/v1/computer/sessions/{session_id}/stop`,
  `computer.stop`) and switches the enablement of a host off
  (`POST /api/v1/hosts/{host_id}/computer/disable`, `computer.device.disable`); the owner lists the
  own sessions (`GET /api/v1/computer/sessions`, `computer.session.read`).
- A computer session ends with its run (`run_ended`), a lost owner role or a disabled person
  (`access_revoked`), a host state change, a lost connection and the open timeout; every end is
  audited as `computer.terminate` without screen content, and the event `computer_session.changed`
  goes to the triggering owner. The end of a run that opened a computer session ends the thread's
  agent session with `end_reason = computer_use`.
- While a run holds a computer session, follow-ups of other people stay queued and interactions of
  other people with its components are refused (SR13 item 5).
- Tables `computer_sessions` and the columns `hosts.reported_computer` and
  `hosts.computer_disabled_generation` (migrations `00124` to `00127`), retention class
  `security`; configuration keys `computer.*` of chapter 27 section 18. Nothing changes until a
  host reports an enabled helper.
