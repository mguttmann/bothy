### Added

- Push registration and preview endpoint (M3-22, 13 sections 6.3, 6.4, 7.3, 13 and 17, ADR 0031):
  the operations `registerPush`, `unregisterPush` and `getPushPreview` are enabled. A
  registration binds a push target of the caller's own active device to the person, the device
  and the session, and returns a preview token of the new kind `pvw` (`bothy_pvw_...`, ADR 0061)
  exactly once as a one-time secret (schema `PushRegistrationCreated`; a replay answers
  `409 conflict` with `reason` `one_time_secret`); only its HMAC is stored. A known
  `(provider, token)` is taken over by deleting its row, the other active registrations of the same
  app installation end with `token_invalid`, and a registration that loses a concurrent
  registration of the same token runs once more and answers `409 conflict` only when it loses
  again. Provider and field rules answer `400 validation_failed` (`not_enabled`, `invalid`,
  `pattern_mismatch`, `too_long`) or
  `403 feature_disabled` with `reason` `push_provider_disabled`; a principal without a session gets
  `403 forbidden` with `reason` `step_up_not_possible`. The preview fetch takes the new security
  scheme `pushPreviewToken` (the route flag `OwnCredential` hands the credentials to the use case
  instead of the authenticator) with a DPoP proof of the session's device key, checks token,
  registration, session, device and person (`401`), then `message.read` and `push.deliver` with
  the rights of the moment (`404`, identical to an unknown message), and answers by
  `notify.preview_mode`: `full` with names, a plain-text excerpt, the attachment count and a fetch
  ticket of the first image, `names` with names only, `none` with `kind`, `thread_id`,
  `message_id` and `badge`. The required query parameter `kind` selects the labels. The same
  preview builder fills the preview fields of `notification.created` (without `image_url`).
  `auth.logout`, `device.revoke` and `user.disable` deactivate the registrations in their own
  transaction (`logout` or `device_revoked`). The schema `Device` lists the registrations of a
  device without tokens through the new source port `identity.PushTargets`. New: the configuration
  key `push.registration_field_max_bytes`, the schema entries of `notify.default_preview_mode` and
  `notify.preview_max_chars` (no longer planned), the metric `bothy.push.fetch` per provider, the
  edge `notify -> files`, the kind `pvw` in the gitleaks rule `bothy-api-token`, and a push token
  and a preview token in the canary scenario.
