### Added

- Personal channel and post order of the sidebar (M4-51): `putMySidebarSpace` takes the optional
  member `channel_order`, the personal order of the channels and forums of the space (absent
  keeps the stored list, an empty list returns to the default order); `SidebarState` carries it
  in the answer, in `sidebar.updated`, in the snapshot member `sidebar` and in `getMySidebar`,
  absent for the default order. The new operation `putMySidebarChannel`
  (`PUT /api/v1/me/sidebar/channels/{channel_id}`, action `sidebar.update`, people only, a channel
  the caller cannot read is 404) stores the personal order of the posts of a channel
  (`thread_order`) with version + 1, last write wins, and writes the personal event
  `sidebar_channel.updated`. The snapshot member `sidebar_channels` and the `getMySidebar` member
  `channels` carry these rows for the channels the person may read that are not archived. Both
  lists take unique IDs only, at most `sidebar.order_max_items` (new configuration key, default
  1000, at least 1); the server does not check whether an ID names a row the caller can see.
  Migration 00085 adds `user_space_states.channel_order` and the table `user_channel_states`
  (retention `personal_sync`), which the personal data export writes as the section
  `sidebar_channels` of `personal.json` and the account deletion erases.
- Personal settings `sidebar.auto_arrange_spaces`, `sidebar.auto_arrange_channels` and
  `sidebar.auto_arrange_chats` (M4-51, 01 section 11): booleans that arrange spaces, channels and
  posts of the sidebar by last activity instead of the personal order.
