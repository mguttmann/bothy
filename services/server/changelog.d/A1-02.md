### Added

- Definitions of built-in agents (chapter 26 4, ADR 0076): `PUT /api/v1/agents/{agent_id}/definition`
  (`putAgentDefinition`, part of `agent.update`: owner, step-up, audit, `If-Match` of the current
  definition version) stores a new version of the closed schema `agent_definition.v1` for an
  agent of `adapter_kind` `claude_agent`, raises `agents.version` and sends the durable event
  `agent.definition_changed` with `definition_version` only to the agent.
  `GET /api/v1/agents/{agent_id}/definition` (`getAgentDefinition`, optional `version` for owners)
  and `GET /api/v1/agents/{agent_id}/definition/versions` (`listAgentDefinitionVersions`, newest
  first, without the text) are the new action `agent.definition.read` (owner or the agent itself).
  Every refusal of 26 4.3 answers `400 validation_failed` with one field error per finding
  (JSON Pointer and field code), and nothing is stored; a definition never appears in an event,
  an audit entry, a log line or telemetry.
- Table `agent_definitions` (migration `00093`), one row per version, never updated.
- `agent.tool_class.set` below `host` is refused with `409 conflict`, reason
  `definition_needs_host`, while the current definition has a `stdio` MCP server (R-BA-06), and
  recorded as an audit `deny` with that reason.
- Configuration keys `agents.definition.instructions_max_bytes`, `agents.definition.max_skills`,
  `agents.definition.skill_description_max_chars`, `agents.definition.skill_body_max_bytes`,
  `agents.definition.max_skill_files`, `agents.definition.max_mcp_servers`,
  `agents.definition.max_allowed_tools`, `agents.definition.max_cost_usd_per_run` and
  `agents.mcp_stdio_runners`. Nothing changes for an existing agent.
