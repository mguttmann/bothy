### Added

- Live stream `stats.live` and `getStatsLive` (M6-15, docs/spec/25-visualization.md 5, R-VZ-05,
  R-VZ-06): the gateway ops `stats.subscribe {space_id?}` and `stats.unsubscribe` are enabled. A
  subscription needs `stats.read` on the instance or the space (people only) and answers `error`
  (`feature_disabled`, `not_found`, `forbidden`, `rate_limited`) without closing the connection;
  one subscription per connection, a new one replaces it, `resume` restores it after the same
  check. While a subscription exists, or `getStatsLive` was polled within the last
  `stats.live_interval`, each api node builds one base frame per interval from the active runs
  (`runs.LiveSource`: step kind and name, approval flag, cost so far), the channel places of chat
  (`chat.ChannelPlaces`), the agents' configured mode and presence, the last full and the current
  minute of `stats_minutes` and the SLI totals over `stats.live_sli_window`, and filters it per
  receiver in memory: the visible channels (one space for a space subscription), cost members
  only with `cost.read.aggregate`, `sli` and `connections` only for the instance, `connections`
  only with `cluster.mode = single`, runs cut to `stats.live_max_runs` and below
  `sync.event_payload_max_bytes` with `runs_truncated`. Each frame goes to its one connection
  after `sync.Admit` with `stats.read`; a revocation ends the subscription with one `error`
  `forbidden`. `getStatsLive` returns the node's base frame of the current interval filtered for
  the caller, built once in a single flight on an idle node. New keys `stats.live_enabled`,
  `stats.live_interval`, `stats.live_max_runs`, `stats.live_max_subscribers` and
  `stats.live_sli_window`; new gauge `bothy.stats.live.subscribers`.
