### Added

- Run context (M2-13, AG-20 server part, AG-21, SEC-AI-1, ADR 0054): `getRunContext`
  (`run.context.read`, agent-self, `rl.agent_runtime`) is enabled and returns `run_context.v1` of an
  own run in `queued`, `running` or `waiting_input`: the triggering message whole and never
  counted, `thread_context` above the session floor and, in session mode `new`, `bind` and for
  guests, `channel_context` from the main thread before the parent message when that lies in the
  thread's current channel. Every element carries `channel_id` (new, required in `RunContextMessage`),
  author, origin, kind, `role` and `trust`, computed at request time through the new kernel port
  `authorize.TriggerHolders`, which authz implements. Contents are cut per element at
  `agent.context_message_max_bytes` and in sum at `agent.context_max_bytes` from old to new
  (`truncated`, `truncated_before_seq`); `already_delivered` marks follow-ups the session received.
  Unknown, invisible and inactive runs answer the same 404; other agents get 403 `not_self`, people
  and apps 403 `subject_kind_not_allowed`. New port methods `messaging.Messages.ContextWindow` and
  `ContextMessage`, `agents.CurrentSessions`, `chat.ThreadInfo.ParentMessageID` and
  `chat.TriggerChannel.HistoryBackfillLimit`; configuration keys `agent.context_max_bytes` and
  `agent.context_message_max_bytes`. No migration, no metric.
