# Module `status`

Status: skeleton (M1-05) plus the backup service (M7-02): the port `BackupRuns`, the table `backup_runs`, schedules, manifest and the backup use cases; the automatic restore test (M7-03); the status page with its components, incidents, automatic checks and the job `retention.ops` (M7-09).
The normative source is [docs/spec/02-architecture.md](../../../../docs/spec/02-architecture.md); where they differ, the chapter applies.

## Purpose

Status page, components, incidents, automatic checks, backup runs.

## Code

- `internal/status` (`doc.go`, `backup.go`, `page.go`): the port as root package; since M7-02 `BackupRuns` with `BackupKind`, `FinishedRun` and `ErrNoBackupTable`; since M7-03 `LatestSucceeded`, `BackupRun` and `FinishedRun.Checks`; since M7-09 `Status`, the inbound port of the seven operations of the status page, with `Page`, `Component`, `Incident` and the inputs.
- `domain/` (M7-02, M7-03): the backup kinds and their slots with `KindRestoreTest` (`kind.go`), `restore_test_checks.v1` with its validation (`restorecheck.go`), the five-field cron parser (`cron.go`), the due kinds of a window (`plan.go`), `backup_manifest.v1` with its validation (`manifest.go`, `manifestcheck.go`), the form of an error code (`errcode.go`) and the off-site target (`offsite.go`).
- `app/` (M7-02, M7-03): the backup use cases (`service.go`), the restore test (`restoretest.go`), the scheduler (`scheduler.go`) and the outgoing ports `Executor`, `ManifestSource`, `Metrics` (`ports.go`), `Scratch` and `ScratchDB` (`restore_ports.go`).
- `adapters/postgres/` (M7-02, M7-03): sqlc queries of `backup_runs`, `Runs` (implements `BackupRuns`), `ManifestSource` and `ScratchDB` (the queries over the restored copy); `adapters/scratch/` (M7-03): the scratch area of the restore test (restore, scratch PostgreSQL on a Unix socket, object fetch, clearing, the test hook of the build tag `restoretesthook`); `adapters/executor/`, `adapters/s3mirror/` and `adapters/otelmetrics/`: the external steps, the object mirror of the driver `s3` and the instruments `bothy.backup.*` and `bothy.storage.volume.*`.
- Status page (M7-09): `domain/page.go` (states, health sources and their groups, the standard components, the closed values, the order) and `domain/probe.go` (outcomes, the measurement window, the state machine `Step`, the incident decision); `app/page.go` (`Page`, the read model with its visibility and the owner operations), `app/probe.go` (`Probe`, the job `status.probe`), `app/subscribers.go` (`agents.AgentDisabled`), `app/pageports.go` (`PageStore`); `adapters/postgres` (`Page`, the store, and `Retention`, the participant of `retention.ops`), `adapters/checks` (the checks over the ports of `stats`, `files`, `search` and `agents`), `adapters/httpapi` (the REST handlers) and `adapters/jobs` (`status.probe`).
- Further layers and adapters come with their use cases. Their components are generated by `tools/archgen` from `architecture/modules.yaml`; a package outside these layers fails `make arch`.

## Port (root package `internal/status`)

- Inbound: `Status` (M7-09), `BackupRuns` (for `bothy-backupd`).
- Emits in-tx events: none.
- Subscribes to in-tx events: `agents.AgentDisabled`.
- Implements source ports and cross-cutting ports: none.

## Backup service (M7-02)

Normative: [16-operations.md](../../../../docs/spec/16-operations.md) sections 7.1, 8.1, 8.2 and 10, [03-data-model.md](../../../../docs/spec/03-data-model.md) 4.12, [backup-restore.md](../../../../docs/operations/backup-restore.md) sections 2 and 3, the rulings D-M7-02-1 and following in [docs/decisions.d/M7-02.md](../../../../docs/decisions.d/M7-02.md).

- **Port.** `BackupRuns` (`Start`, `Finish`, `LastSuccess`) is the only way to `backup_runs`. `bothy-backupd` records its runs through it with the role `bothy_backup`, which may select, insert and update this table and nothing else; `bothy migrate up` reads the last success of `pg_full`, `pg_diff` or `logical` through `wire.LastBackupSuccess`. `LastSuccess` returns `ErrNoBackupTable` for a schema migrated before M7-02.
- **Table.** `backup_runs` exactly as 03 4.12 (migration `00050`): a row is `running` exactly while `finished_at` is NULL; `error` holds a code without content (`domain.ValidErrorCode`); a failed run keeps the empty manifest. Retention class `ops` (the job follows with M7-09).
- **Schedules.** `domain.ParseSchedule` reads the five-field cron expressions of `backup.pg.full_schedule`, `backup.pg.diff_schedule`, `backup.logical.schedule` and `backup.objects.schedule` (numbers, ranges, steps and lists; no names or macros), evaluated in UTC. `domain.DueKinds` returns the kinds due in a window; a full and a differential due together run only the full. `app.Scheduler` covers the window from its previous tick, so a minute starts at most once and a time missed while the process was down is not caught up.
- **One run per kind.** `app.Service.Run` takes the slot of its kind (`pg_full` and `pg_diff` share one) and returns `app.ErrBusy` without a row when it is taken. A run writes a `running` row, runs its steps through `Executor` (pgBackRest into repo1 and, with an off-site target, repo2, then `expire` on repo1 only; `pg_dump` into a file that is removed in every case, stored with restic; restic over `file.fs.root` or the mirror of the driver `s3`), builds the manifest and stores it twice: as a restic snapshot of stdin with the tags `manifest`, the kind and the run id, and as `backup_runs.manifest`. Without an off-site target the local restic snapshots of `logical`, `objects` and the manifests are forgotten after `backup.logical.retention` and `backup.objects.retention`; with one only the owner's `ExpireOffsite` forgets or expires off-site (R-OP-09). The row is finished even when the run is canceled (code `canceled`).
- **Manifest.** `backup_manifest.v1` has exactly the fields of 03 4.12 and backup-restore.md 3; `Validate` admits only closed forms (UUIDs, version characters, table names, lowercase hex, pgBackRest labels, restic ids), so message text fails, and `ParseManifest` rejects unknown keys. `ManifestSource` reads the facts as `migrate.bootstrap_user` in one `READ ONLY` transaction with `REPEATABLE READ`: exact `count(*)` per table of schema `public` (partitions through their parent), the bounds of `event_log`, the last `audit_events` row, the instance row and the totals of the files that are not deleted.
- **Error codes.** `app.ErrorCode` takes the code of an `ExecError` (`<tool>_exit_<n>`, `<tool>_not_found`, `<tool>_output_invalid`, `s3_mirror_failed`) or a fallback per step; the manifest steps record `manifest_failed` and `manifest_store_failed`. No output text reaches the row or the log.
- **Metrics.** `Prime` reads the last success per metric kind (`physical`, `logical`, `objects`) at start; `RunFinished` after each run; `Sample` reads `pg_stat_archiver.last_archived_time` and the volumes. A sample that fails is logged and skipped.
- **Tests.** Unit tests in `domain` (`TestCronDue`, `TestManifestSchema`, `TestParseOffsiteTarget`) and `app` (fakes and a fake clock, no sleeping: `TestRunWritesRowAndManifest`, `TestRunFailureRecordsCode`, `TestOneRunPerKind`, `TestOffsiteEmptyWarns`); integration tests in `adapters/postgres` with `pgtest` (`TestBackupRunsRole`, `TestManifestCounts`, the tests of `Runs`) and `migrations` (`TestMigrationBackupRuns`).

## Restore test (M7-03)

Normative: [16-operations.md](../../../../docs/spec/16-operations.md) 8.3 (with "As built"), [backup-restore.md](../../../../docs/operations/backup-restore.md) 4, [03-data-model.md](../../../../docs/spec/03-data-model.md) 4.12 `backup_runs.checks`, the rulings D-M7-03-1 and following in [docs/decisions.d/M7-03.md](../../../../docs/decisions.d/M7-03.md).

- **Use case.** `app.Service.RestoreTest` runs once in the slot `restore_test` (`ErrBusy` while one runs); `app.Scheduler` starts it on `backup.restore_test.schedule`. It writes a running `restore_test` row, restores the newest succeeded `pg_full` or `pg_diff` by the label of its manifest through `Scratch`, runs the seven checks of 8.3 each with its own result and duration, clears the scratch area in a deferred call, and finishes the row with `restore_test_checks.v1` in `checks` (`failed` with `checks_failed` or `scratch_cleanup_failed`, or with `canceled` when the process stops during the test, which records no failed check in the metrics).
- **Checks.** `pgbackrest` (restore, `pgbackrest verify`, start of the copy; a copy that cannot be restored or started skips the next five with `restore_failed`), `manifest` (schema version, instance, sync epoch, tables; the row counts of `event_log` and `audit_events` when the copy reached the event and audit heads of its manifest), `event_log` (`count(*) = max(seq) - min(seq) + 1` per partition, `event_seq` and `audit_seq` not behind), `audit_chain` (`audit.RowsVerifier` over the rows of the copy), `thread_sample` (`thread_seq` without gaps up to `last_message_seq`), `file_sample` (SHA-256 of the objects from the newest object backup against `files.sha256`), `duration` (the whole test against `dr.rto_target`). A check that panics fails with `check_panicked`; the others still run.
- **Scratch area.** `adapters/scratch` in `/var/lib/bothy-backup/restore`: `pgbackrest restore --type=immediate --target-action=promote --archive-mode=off` from repo1 as the database host (`--reset-pg1-host`), PostgreSQL with `listen_addresses` empty and its socket in the directory (mode `0700`), a pool over that socket as `migrate.bootstrap_user`, `restic restore` of the sampled objects, and `SIGINT`, then `SIGKILL`, then an empty directory. It never connects to the production database.
- **Test hook.** Only with the build tag `restoretesthook` (`hook_restoretesthook.go`), which no release build sets: `RESTORE_TEST_HOOK` names one manipulation of the copy (`event_log_gap`, `audit_hash`, `object_bytes`), and every run writes the TCP sockets of the container to `restore-test-tcp` next to the scratch directory. Production builds compile the empty hooks of `hook.go`.
- **Metrics.** `bothy.backup.restore_test.duration`, `bothy.backup.duration{restore_test}`, `bothy.backup.restore_test.last_success.timestamp` (also primed at start) and `bothy.backup.restore_test.failures` per failed check with `bothy.reason`.
- **Tests.** `domain` `TestRestoreChecksSchema`; `app` `TestRestoreTestAllPass`, `TestRestoreFailureSkipsDependentChecks`, `TestRestoreChecksDetectDamage`, `TestRestoreManifestWindow`, `TestDurationOverRTOFails` (fake clock), `TestSampleSizes`, `TestRestoreTestScheduleAndSlot`; `adapters/postgres` with `pgtest` `TestScratchDBEventLogAndCounters`, `TestScratchDBThreadSample`, `TestScratchDBFilesAndAudit`, `TestRunsLatestSucceededAndChecks`; `adapters/scratch` `TestScratchRestoreFetchClear`, `TestScratchFailures`; the image test `TestRestoreTest` in `test/postgresimage` (clean copy, three manipulated copies, no TCP listener, empty scratch directory, the `restore_test` row).

## Status page (M7-09)

Normative: [16-operations.md](../../../../docs/spec/16-operations.md) 12 (with "As built") and 14, [03-data-model.md](../../../../docs/spec/03-data-model.md) 4.12, [05-actions.md](../../../../docs/spec/05-actions.md) (`status.read`, `status.manage`, `status.public.read`, `status.updated`), the rulings D-M7-09-1 and following in [docs/decisions.d/M7-09.md](../../../../docs/decisions.d/M7-09.md).

- **Tables.** `status_components`, `status_incidents`, `status_incident_updates`, `status_incident_components` exactly as 03 4.12 (migration `00077`); `bothy_app` may also delete old rows of `backup_runs` for `retention.ops`.
- **Operations.** `getStatus` (`status.read`), `getPublicStatus` (`status.public.read`, `404` unless `status.public_enabled`), `createStatusComponent`, `updateStatusComponent`, `deleteStatusComponent`, `createStatusIncident`, `addStatusIncidentUpdate` (`status.manage`, owner, audited with the operation and the id, never a text). Every writer locks all components first, so the owner and the job never interleave. A name another component has, an unknown `health_source`, `agent.presence` without `agent_id` or `agent_id` with another check, an unknown agent or an unknown `after_component_id` give `400 validation_failed` with the field. `sort_key` holds fixed-width numbers; a create or a move numbers the list again.
- **Visibility.** Components of an agent only with `agent.read` on it, never on the public page and never in `overall_state` (the worst state of the other components); an incident only with at least one visible component (with only the visible ones) or, for an incident of the owner, with none; an automatic incident whose component is gone is shown to nobody; resolved incidents for `status.history_window`.
- **Standard components.** `status.probe` creates every standard component whose group key no component carries (`api`, `push`, `files`, `search`) and one `agent.presence` component per active agent (name: the display name, description: the handle). The owner may rename, describe, reorder and delete them; **a deleted standard component comes back with the next round**, because 16 12 makes the four parts the minimum. A disabled agent's component goes in the transaction of `agent.disable` (`Subscribers.OnAgentDisabled`) and by the next round for any agent that is no longer active.
- **Checks** (`adapters/checks`, the keys of 16 12). `api.http`, `push.apns`, `push.fcm` and `sync.fanout` read the own measurement of every process in `stats_minutes` through `stats.SLIWindows` over the window of `domain.Window`; `files.storage` writes, reads and deletes the probe object `status-probe/<process id>`; `files.scan` reads the last `PING` of the health monitor; `search.query` runs `search.Probe`; `agent.presence` reads `agents.StatusAgents`. A round runs all checks at once, each bounded by `status.check_interval`, then applies `domain.Step` and `domain.DecideIncident` in one unit of work.
- **Automatic incidents.** One per outage (`created_by` NULL, impact `major`, title `<name>: major outage`, `started_at` the start of the outage) after `status.incident_after` of `major_outage` while none is open and the outage had none yet; resolved after `status.resolve_after` of `operational`. The timers read the memory of the job (`domain.Track`), never `updated_at`, which an owner's edit moves. The automation never changes an incident of the owner or anyone's update.
- **Events.** One `status.updated` per change (`overall_state`, `changed_component_ids`, `changed_incident_ids` without agent components and their incidents); nothing for a round without a change or an update without effect.
- **Retention.** `adapters/postgres.Retention` (class `ops`, `retention.ops`): incidents resolved before the cutoff with their updates and links, backup runs started before it except the latest succeeded run of each kind. The components carry no end time.
- **Tests.** `domain` `TestStateMachine`, `TestIncidentAutomation`, `TestOutcomes`, `TestWindow`, `TestPlace`; `adapters/checks` `TestMeasuredChecks`, `TestProbedChecks`; `migrations` `TestMigrationStatusPage`; the integration tests in `services/server/test/status` (`TestProbe_SimulatedOutages`, `TestProbe_RealSources`, `TestVisibility`, `TestPublicStatus`, `TestStatusUpdatedOnlyOnChange`, `TestProbe_OneIncidentPerOutage`, `TestRetentionOps`, `TestHandlers_Components`, `TestHandlers_Incidents`).

## Dependencies

May use the ports of these modules: `agents`, `audit`, `stats`, `files`, `search`.

Reason: agent presence as a status component (`agents.StatusAgents`, `agents.AgentDisabled`); the restore test verifies the audit chain of the restored copy through `audit.RowsVerifier`, the verification of `audit.verify` (M7-03); the checks of the status page read `stats.SLIWindows`, `files.StorageProbe`, `files.ScannerHealth` and `search.Probe` (M7-09).

In addition, for all modules: `internal/kernel`; `internal/platform` and `api/` only in `adapters/`.
Checked by go-arch-lint (ADR 0008).
