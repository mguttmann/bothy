# Modul `files`

Status: Gerüst (M1-05) plus object storage port and file system driver (M3-01), the S3 driver (M3-02) and the upload sessions in mode `direct` with `getFile` (M3-03). Scan, downloads and the other use cases follow with the tickets of stage M3.
Normativ ist [docs/spec/02-architektur.md](../../../../docs/spec/02-architektur.md); bei Abweichung gilt das Kapitel.

## Zweck

Upload-Sitzungen in Teilen, Objektspeicher-Treiber, Scan, Metadaten-Entfernung, Vorschaubilder, Anhänge, Transkripte, Dateitext.

## Code

- `internal/files` (`doc.go`, `uploads.go`): the port as root package: `Uploads`, `Files`, their DTOs and `Register` (M3-03).
- `domain/` (M3-01): key schema and key grammar (`objectkey.go`); M3-03: part plan, name cleaning, `Content-Digest`, session states, the ETag of a file system part, missing ranges.
- `app/` (M3-01): the outgoing port `ObjectStore` with its value types and errors (`objectstore.go`); M3-03: the use cases, the outgoing ports, the part strategies and the builder of `file.updated`.
- `adapters/fs/` (M3-01): the file system driver; `adapters/filestest/`: the conformance suite, imported only by tests.
- `adapters/s3/` (M3-02): the S3 driver, the only package that imports the AWS SDK.
- M3-03: `adapters/postgres/` (sqlc queries and the repository), `adapters/httpapi/` (the six REST operations), `adapters/unicode/` (NFC, `golang.org/x/text`), `adapters/mimetype/` (extensions of denied types, `github.com/gabriel-vasile/mimetype`), `adapters/otelmetrics/` (`bothy.file.upload.size`), `adapters/channels/` (the space of a channel over the chat port); `adapters/fs` gains `FreeBytes`.
- Further layers and adapters come with their use cases. Their components are generated by `tools/archgen` from `architecture/modules.yaml`; a package outside these layers fails `make arch`.

## Port (Wurzelpaket `internal/files`)

- Eingehend: `Uploads` (Sitzungen, Teile), `Files` (Lesen, Öffnen, Vorschau, Abruf-Tickets, Löschen), `Attachments`, `Transcripts`, `TextExtracts`; deklariert `AttachmentLocator`.
- Gibt In-Tx-Ereignisse aus: `FileFinalized` (Scan und gegebenenfalls Transkript endgültig).
- Abonniert In-Tx-Ereignisse: keine.
- Implementiert Quellen-Ports und Querschnitts-Ports: `identity.AvatarFiles`, kernel `personaldata.Participant`.

## Upload sessions (M3-03)

Normative: [12-dateien.md](../../../../docs/spec/12-dateien.md) sections 2, 3 and 6, the rulings D-M3-03-1 to D-M3-03-27 in [docs/DECISIONS.md](../../../../docs/DECISIONS.md).

- **Port.** `Uploads` (`Create`, `PutPart`, `State`, `Complete`, `Abort`) and `Files` (`Get`); the actor comes from `kernel/actor`. An unknown and a foreign file answer the same `404`. `Register` declares `file.updated`.
- **Tables.** `files` (retention class `content`), `file_upload_sessions` and `file_upload_parts` (retention class `transient`), exactly as 03 4.7; `files.search_vector` of 03 5; the foreign key `principals.avatar_file_id -> files(id) ON DELETE SET NULL`, added `NOT VALID` and validated by the next migration. The retention jobs are M7-05.
- **Actions.** `createUpload`, `uploadPart`, `getUpload` and `completeUpload` authorize `file.upload` on the scope channel; `abortUpload` authorizes `file.delete`, `getFile` `file.read`, both on the file with `authorize.FileFacts` (before attachment only the uploader sees the file).
- **Event.** Only `abortUpload` and the abort after a lost read right write `file.updated` (receive action `file.read`, payload `FilePayload`), with `audience_principal_id` = uploader; create and completion write none. `app.FileUpdated` is the builder for M3-04 to M3-10.
- **Part strategies.** `app.PartStore`, chosen in `internal/wire` from `file.storage.driver`: `fs` keeps part `n` as `uploads/<file_id>/<n>` (ETag derived from its SHA-256), `s3` as part `n` of a multipart upload of the final key, created at the first part with its id in `storage_upload_id`. Completion calls no object store; the verify pass of M3-04 joins the parts or runs `CompleteMultipart`. No object store call runs inside a unit of work (02 8.5).
- **Outgoing ports.** `Repository` (adapters/postgres), `PartStore`, `FreeSpace` (the file system driver), `NameNormalizer` (adapters/unicode), `TypeExtensions` (adapters/mimetype), `ChannelLocator` (adapters/channels over `chat.Structure.NotificationPath`), `Metrics` (adapters/otelmetrics).
- **Query exceptions (AZ-P12).** Every read is keyed by the file id or the uploader and stands with this reason in `tools/lint/sql_visibility.yaml`: `files.GetFile` and `files.GetSession` resolve one file for authorize, `files.QuotaUsedBytes` and `files.CountOpenSessions` count the caller's own files and sessions, `files.LockSessionForUpdate` and `files.LockSessionForShare` lock the caller's own session. The writes touch only rows of a session the use case authorized.
- **Logs and metrics.** Lines carry at most `bothy.file.id`, never a name, digest, declared type or channel name (the file name is a canary value, SEC-T10). `bothy.file.upload.size` has no attributes.
- **Tests.** Unit tests in `domain` and `app` (fakes; the fake object store fails any call inside a unit of work); integration tests in `test/uploads` through the real server (`go test -tags contract_validate ./test/uploads/`); the paths of `test/canary`, `test/leak` and the G7 hook of `tools/contract`.

## Object storage (M3-01)

Normative: [12-dateien.md](../../../../docs/spec/12-dateien.md) sections 4.1, 4.2 and 4.4, [ADR 0010](../../../../docs/adr/0010-objektspeicher-hinter-s3-schnittstelle-lokaler-treiber-als-standard.md), rulings M3-01/1 to M3-01/19 in [docs/DECISIONS.md](../../../../docs/DECISIONS.md).

- **Port.** `app.ObjectStore` is an outgoing port of the application layer with exactly `Put`, `Get` (whole object or one byte range), `Head`, `Delete`, `CreateMultipart`, `UploadPart`, `CompleteMultipart`, `AbortMultipart` and `PresignUploadPart`. Other modules never see it. Every operation checks the key first (`ErrInvalidKey` before any storage call). Sentinel errors: `ErrNotFound`, `ErrInvalidRange`, `ErrSizeMismatch`, `ErrUploadNotFound`, `ErrInvalidPart`, `ErrNotSupported`; every other error is a storage failure that callers answer with `503`. `Delete` of a missing object and `AbortMultipart` of an unknown upload succeed.
- **Key schema.** `domain.OriginalKey` (`f/<aa>/<bb>/<file_id>/orig-<n>`), `domain.VariantKey` (`small`, `medium`, `large`, `poster`) and `domain.UploadPartKey` (`uploads/<file_id>/<n>`) take only an `ids.ID`, an `int` and the closed type `Variant`, so no name, channel ID or space ID can reach a key (`TestObjectKeysCarryNoContext`, `TestKeyBuildersTakeOnlyIDsAndNumbers`). `domain.ValidateKey` is the one grammar of all drivers: segments of `[a-z0-9-]` joined by single `/`.
- **File system driver.** `fs.Open(fs.Config{Root})` refuses a root that is not an absolute, clean path of an existing directory (not a link) owned by the server user with mode `0700`; errors name `file.fs.root`, not the path. It creates `<root>/.tmp` and never the root itself. All operations go through an `os.Root`; no symbolic link is followed at any level (`Lstat` of every component before an operation and before a rename; because `os.Root` follows a link inside the root even with `O_NOFOLLOW`, a read checks the path again when the opened file is not the one it checked), and a link is a storage failure. An existing `.tmp` must also be a directory of the server user with mode `0700`. A new directory is synced in its parent. Directories get mode `0700`, files `0600`.
- **Writes.** Temporary file in `<root>/.tmp` (no key can address it, keys have no dot), exactly `size` bytes with a bounded buffer, `fsync`, rename, `fsync` of the directory. A directory sync that the platform refuses as "not supported" counts as success (Linux and macOS support it). A reader never sees half an object; a failed write leaves nothing. `Put` on an existing key replaces it atomically; the module, not the driver, never overwrites an object (next revision).
- **Delete.** Removes the file and then the file directory (`f/<aa>/<bb>/<file_id>` or `uploads/<file_id>`) if it is empty; writers create a vanished directory again. `Delete` of an original key also removes `uploads/<file_id>/`, so parts that a completion could not remove go with the file.
- **Multipart.** `CreateMultipart` takes only original keys and returns the upload ID `""`; parts lie at `uploads/<file_id>/<n>` with the ETag `"<sha256 hex>"` of their bytes and are readable objects while the upload is open. `CompleteMultipart` reads each listed part once, checks it against its ETag and removes the upload directory; `AbortMultipart` removes it. `PresignUploadPart` gives `ErrInvalidPart` for a part number below 1, `ErrSizeMismatch` for a size below 1 (M3-02) and otherwise `ErrNotSupported`.
- **Conformance suite.** `filestest.RunObjectStoreConformance(t, newStore, filestest.Options{PartSize: ...})` runs the cases of 12 "15. Tests" against a fresh store per case. A new driver calls it from its own `_test.go` with the smallest part size it accepts (the file system test passes a small size, the S3 driver the S3 minimum).
- **Configuration.** `file.storage.driver` (`fs` or `s3`, default `fs`) and `file.fs.root` (default `/var/lib/bothy/files`); cross-check `file_fs_root_absolute`. `wire.FilesObjectStore(ctx, values, wire.FilesDeps{Secrets, Egress})` opens the driver.
- **Observability.** None: the driver logs nothing and adds no metric or span; callers log.
- **Open points.** A temporary file left in `.tmp` by a crashed process stays (no rule in the specification yet; proposed for M3-08). The readiness check "Objektspeicher antwortet" (16 "4.2") has no ticket yet. Since M3-03 every role opens the store in the start step `files`, and the server image holds the directory `/var/lib/bothy/files` (D-M3-03-24).

## S3 driver (M3-02)

Normative: [12-dateien.md](../../../../docs/spec/12-dateien.md) sections 3.3 and 4.3, [ADR 0010](../../../../docs/adr/0010-objektspeicher-hinter-s3-schnittstelle-lokaler-treiber-als-standard.md), ADR 0048, rulings M3-02/1 to M3-02/14 in [docs/DECISIONS.md](../../../../docs/DECISIONS.md).

- **Core S3 only.** `s3.Store` holds the interface `coreAPI` (`PutObject`, `GetObject`, `HeadObject`, `DeleteObject`, `CreateMultipartUpload`, `UploadPart`, `CompleteMultipartUpload`, `AbortMultipartUpload`) and `presignAPI` (`PresignUploadPart`), nothing else of the SDK. No request sets encryption, ACL, tagging, object lock, storage class or conditional headers.
- **Vendor rule.** The vendor group `awssdk` is granted to the adapters of `files` in `architecture/modules.yaml`; depguard in `.golangci.yml` narrows it to `internal/files/adapters/s3` (production and test files), forbidigo forbids `s3.Client.DeleteObjects` and `s3.PresignClient.PresignGetObject`, and `TestS3SDKOnlyInAdapter` checks the imports with `go list`.
- **Keys.** `file.s3.endpoint` (required, absolute `http` or `https` URL without path), `file.s3.region`, `file.s3.bucket` (required), `file.s3.prefix` (optional, key grammar, joined with `/`), `file.s3.use_path_style`, `file.s3.checksum_mode` (`when_required` or `when_supported`, the latter only with an `https` endpoint), `file.s3.access_key_ref` and `file.s3.secret_key_ref`; cross-check `file_s3`. `file.s3.presigned_upload` and `file.s3.presign_ttl` follow with the presigned mode.
- **Egress and secrets.** One egress client with purpose `objectstore`, the host policy of exactly the request host and port, no redirects, the time limit `http.transfer_timeout` and the body limit `file.max_upload_bytes`; an `http` or private endpoint needs an `egress.allowed_hosts` entry with `allow_private`. The keys come only from the secret provider and are resolved again on every refresh of the SDK credential cache, so a rotation works after `secrets.cache_ttl`; the SDK default configuration and credential chain are never used. No SDK retries.
- **Bodies.** `Put` and `UploadPart` stream the reader as `UNSIGNED-PAYLOAD` and hold back the last byte until the reader ends, so a body of another length gives `ErrSizeMismatch` and stores nothing.
- **Errors.** `files/s3: <operation> <key>: <detail>` with the S3 code, the status or a fixed text; never a URL, query, presigned URL, endpoint or credentials. `Head` on a missing bucket reads as `ErrNotFound` (a HEAD answer has no body).
- **Tests.** Unit tests run against an `httptest` fake behind the real egress client and secret provider. The conformance suite and the integration tests (`TestS3Conformance`, `TestS3RequestsAreCoreS3`, `TestPresignedPartBindsLength` and others) run against SeaweedFS in a throwaway container from the image of the Compose service (`seaweedImage`, pinned by digest; `TestSeaweedImagePinned` holds the version equal to `BOTHY_SEAWEEDFS_VERSION`). They need a Docker-compatible runtime and fail without one: `cd services/server && go test ./internal/files/adapters/s3/`. A container left by a killed test binary carries the label `org.bothy.test=seaweedfs`.
