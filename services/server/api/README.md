# services/server/api

Status: generated from the contract (M1-17). The REST layer of the server is generated from
[docs/api/openapi.yaml](../../../docs/api/openapi.yaml) (spec-first, ADR 0013); the server
generates and registers only the operations that the enable list [operations.yaml](operations.yaml)
names (PLAN P-04). The normative sources are [06-api.md](../../../docs/spec/06-api.md), section
"Code generation", and [05-actions.md](../../../docs/spec/05-actions.md), rule 3.

## Layout

| Path | Content | By hand? |
|---|---|---|
| `operations.yaml` | enable list: `enabled` and `later` with milestone | yes |
| `generate.go` | the two `go:generate` lines (real surface and fixture) | yes |
| `rest/oapi-codegen.yaml` | settings of oapi-codegen (`std-http-server`, `strict-server`, `models`, `skip-prune`) | yes |
| `rest/rest.gen.go` | Go types of all schemas and the server of the enabled operations | generated |
| `rest/openapi.gen.yaml` | byte-identical copy of `docs/api/openapi.yaml`; `rest.Spec` (`rest/spec.go`) embeds it for the request validator of the HTTP chain (M1-18) | generated |
| `routes/routes.go` | types, `Table`, `Recorder`, `Verify`, `Build`, lookup | yes |
| `routes/routes.gen.go`, `catalog.gen.go`, `build.gen.go` | operation table, action catalogue, link to the generated server | generated |
| `routes/gen/` | generator with tests and `testdata/` (fixture and negative fixtures) | yes |
| `routes/internal/fixture/` | fixture with three operations, generated by the same generator | generated, except `fixture.go` |
| `routes/routestest/` | fixture surface with a stub for tests outside `api/routes` | yes, only for `_test.go` |

Component in the module register: `api` with the vendor groups `oapi` (runtime of oapi-codegen),
`openapi` (kin-openapi, loader of the generator) and `yaml` (generator). Tool: oapi-codegen
v2.8.0, pinned as a `tool` in [go.mod](../go.mod), runtime `github.com/oapi-codegen/runtime`
v1.7.0.

## Generate again

```sh
cd services/server
go generate ./api/...      # or: go generate ./... (everything that make codegen-check generates)
make -C ../.. codegen-check
```

`make codegen-check` generates everything again and fails when a file changes (R-API-18). After
a change to `openapi.yaml`, `actions.yaml` or `operations.yaml`, the regenerated files belong in
the same commit.

The generator ([routes/gen](routes/gen/main.go)) reads spec, catalogue and list, reports every
finding with file and operation and then writes nothing. Otherwise it writes a copy of the spec in
which `paths` keeps only the methods of enabled operations (paths without a method are dropped),
`webhooks` is missing and `components` stays complete, into a directory from `os.MkdirTemp`, runs
oapi-codegen on it and removes the directory on every path. Why a pre-filtered copy instead of
`include-operation-ids`: see [DECISIONS.md](../../../docs/DECISIONS.md), M1-17/1.

Flags: `-spec`, `-catalog`, `-list`, `-codegen-config`, `-rest-dir`, `-routes-dir`, `-rest-pkg`
(import path of the package in `-rest-dir`) and `-core-pkg` (import path of `api/routes`; empty
when `-routes-dir` is `api/routes` itself). Exit codes: 0, 1 on findings or errors, 2 on a wrong
call.

## Enable list

```yaml
version: 1
enabled: []          # operationIds with a handler; sorted ascending
later:               # every other operationId under paths; sorted by operation_id
  - operation_id: addOwner
    milestone: M1
    ticket: M1-31    # optional
```

The generator rejects and names every entry: `version` other than 1, unknown keys, an operation
under `paths` in no section, an entry in both sections, twice in one or not in `openapi.yaml`, a
section not ascending in byte order, `milestone` not `M1` to `M8` or `V1` to `V3`, `ticket` not
of the form `<milestone>-<two digits>` or of another milestone. Operations under `webhooks:` are
not in the list: the server sends them, it does not serve them. How `later` was filled:
DECISIONS.md, M1-17/4.

For every operation under `paths`, enabled or not, the generator also checks: `x-authz-action`
and `x-rate-limit-class` present, the action in the catalogue, the class equal to the class of the
action and not `none`, no action with the permission `system` (05, rule 10), exactly one server
`/api/v1` (W6), no health operation (L2), and forms that the route table could not describe
(DECISIONS.md, M1-17/13). An enabled operation must not have security requirements of its own
(M1-17/19). Every object schema that the request body of an operation under `paths` reaches must
reject unknown members (`additionalProperties: false`, with `allOf` `unevaluatedProperties: false`;
except `JsonObject` and maps), otherwise the generator names the schema (W7, DECISIONS.md M1-18/12).
Checks and metadata come from the document that the loader of oapi-codegen
(kin-openapi) reads, so that the table and the generated server see the same (M1-17/18).

## Add an operation to openapi.yaml

Every new operation under `paths` gets an entry under `later` in the same commit, with the
milestone (and the ticket that builds it); otherwise the generator fails in `make codegen-check`.

## Enable an operation (handler ticket)

1. Move the operationId from `later` to `enabled` (sorted) and run `go generate ./api/...`.
   `rest.gen.go` gets the method in the `StrictServerInterface`, `routes.gen.go` the row of the
   table; from the first operation on, `routes.Server` is `rest.StrictServerInterface`.
2. In the module, implement the method of the interface in `internal/<module>/adapters/httpapi`
   and embed the handler of the module in `wire.Handlers` (02 "Layers within a module", rule 3).
   If a method is missing or two modules implement the same one, the package does not build. The
   compiler checks only the methods: the start (`wire.Serve`, M1-11) builds every module handler
   with its dependencies and passes the filled composite to `wire.MountRoutes`.
3. Change the tests that hold the number of operations (`TestRealTable_Enabled` in `api/routes`)
   along with it; `make codegen-check` and `make arch` green.

## Start check

`wire.MountRoutes(role, mux, handlers, cat, log)` is step 7 of the start (02 "Start"): for the
roles `api` and `all` it calls `routes.Build(handlers, routes.Options{}, cat)`; since M1-25 `cat`
is the closed catalogue of `authz` (`authz/app.Catalog`), and the start step checks the route
bindings against it first (`internal/authz/README.md`). `routes.SpecCatalog()` remains for the
tests of this package. `Build` lets the generated std-http and strict server register on a
`routes.Recorder` and compares with `Verify` every registered pattern with the table, every
action with the catalogue and every class with the class of the action (05 rule 3, AZ-P1). On a
finding, `MountRoutes` logs `route check failed` at level error with all findings, mounts nothing
and returns the error. Otherwise it mounts every route under `Route.Operation.Pattern` on the
public mux. M1-11 builds the command `bothy serve` and the public listener; the contract with
this ticket: `bothy serve` calls the step before opening the public listener and ends with exit
code 1 on an error, before it reports ready (until then the abort is tested at the level of the
step, `TestServe_AbortsOnUnknownAction`). The catalogue is a parameter; M1-25
passes the closed catalogue of `authz`.

`routes.Options` carries the error handlers of the generated server; `nil` means the default of
oapi-codegen, which writes the error text with 400 or 500. M1-18 puts in the problem writers.

## Metadata per route

`routes.Operation` names per enabled operation `ID`, `Method`, `Path` (with the base URL),
`Pattern` (exactly as the generated code registers it), `Action`, `RateLimitClass`, `Public`
(`security: []`), `IdempotencyKey` (header `Idempotency-Key`, in the spec
`#/components/parameters/IdempotencyKey`), `IfMatch` (header `If-Match`: `IfMatchRequired` with
`required: true`, otherwise `IfMatchOptional`), `RequestBody` and `BodyRequired` as well as
`ETagStatuses` (2xx statuses whose response names `ETag`). Lookup through `routes.ByPattern` (the
value of `http.Request.Pattern`) and `routes.ByID`; the HTTP chain (M1-18 to M1-20) reads from it.

## Limits

- Generated code does not count in the Go coverage (`*.gen.go`, DECISIONS.md M1-17/10); the
  golden test of the generator and `make codegen-check` hold it.
- `rest.gen.go` grows with every enabled operation. If the file exceeds `repo.max_file_kb` (hook
  `check-added-large-files`), `make lint` fails; the ticket that reaches the limit decides on the
  split (DECISIONS.md, M1-17/16).
