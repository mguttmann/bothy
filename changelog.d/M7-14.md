### Added

- Portability test (M7-14, docs/spec/16-operations.md 11.1): `make portability` with
  `PORTABILITY_TAG` installs a product release with `install.sh` and the options of
  `tests/portability/install-options`, once with `--storage fs` and once with `--storage s3`. It
  verifies the signature of every server image digest with cosign in a container pinned by digest
  before `install.sh` runs, checks that the containers run exactly these images, drives the smoke
  scenario of M1-73 and a new scenario through the public API (a run of a test adapter on the
  Python SDK, an upload clean and with the EICAR test file, the search, the status page), runs a
  backup and the restore test, receives telemetry through the overlay `local` without finding a
  canary, checks the tailnet case without an account and reports the digests. On a failure it
  prints the state and the logs of its installation before the cleanup. `make portability-trial`
  proves it end to end against the local trial release on the build host; without
  `PORTABILITY_TAG`, `make portability` stays the Compose smoke test.

### Fixed

- Installation with `--storage s3` (M7-14): the server of the Compose installation aborted its
  start because the `http` endpoint of the in-stack SeaweedFS lacked its `egress.allowed_hosts`
  entry; `compose.yaml` now sets it through the new variable `BOTHY_EGRESS_ALLOWED_HOSTS` (default
  `seaweedfs:8333;allow_private`).
- `secrets-init` generates `s3_access_key` and `s3_secret_key` (M7-14): without them the server
  of an installation with `--storage s3` stopped at its start.
