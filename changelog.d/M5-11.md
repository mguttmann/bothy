### Added

- Mobile device E2E and performance (M5-11): `make e2e-mobile` runs the `patrol` suites of
  `apps/client/e2e_test/phone` (login with address, password and TOTP and the device confirmed by
  a second session, the push permission dialog, a push from another person whose text the
  Android service fetches from the real server, tapping it to the thread, sharing an image from the system share sheet, sending offline with delivery
  after the reconnect) on an iOS simulator and an Android emulator against the Compose stack. The
  stack runs a test build of the server (Go build tag `e2e`) whose push goes to fake APNs and FCM
  providers in the stack; the runner hands each captured push to the device. The Android debug
  build gains switches for the E2E push backend and the trust of the run's test CA; release builds
  are unchanged. The workflow `e2e-mobile` runs the Android suites every night. `make perf`
  measures the phone targets `client.perf.*` in a profile build on an attached physical reference
  device and prints a SKIP line without one.
