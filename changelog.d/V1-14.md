### Added

- Settings, Sign-in in the desktop and phone apps and the page Sign-in of the web console: the own
  linked login services, passkeys and the state of the password and the one-time code; a password
  with a one-time code in two steps (the password typed twice, then a QR code of the one-time code
  with its key as text and a code to confirm); a passkey where the platform can create one (the
  browser in the console, Windows Hello in the Windows app, the system in a phone build with a
  public domain); a link with a further login service (V1-14, issue #1426).
- The Windows app creates and uses passkeys over Windows Hello (the Win32 WebAuthn API behind the
  runner's channel `bothy/webauthn`). A step-up on a device without a step-up key takes the
  person's passkey when there is one, and so does the fresh step-up of the terminal: the Windows
  app opens the terminal after a passkey confirmation (V1-14, issue #677).

### Changed

- The hints of the console without a step-up method and without a passkey for the terminal, and of
  a terminal tab on a device that cannot give the fresh step-up, name the real way: Settings,
  Sign-in in the app and the page Sign-in of the console (V1-14).
- E3 keeps its three ways; the password with the one-time code is set after the first login under
  Settings, Sign-in (01 5.6, V1-14).
