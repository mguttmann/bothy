### Added

- Push on Android (M5-05): a Kotlin `FirebaseMessagingService` without the Flutter engine posts
  the localized placeholder of an FCM data message at once into the channel of its kind, tagged
  with the thread so a later push replaces it (silently for quiet hints), and an expedited
  WorkManager job per `nid` replaces it with "<channel> · <thread title>" and
  "<sender>: <excerpt>" fetched from `GET /api/v1/push/preview` with the preview token and a DPoP
  proof of the `dpop` device key within `client.push.fetch_timeout`; "Message not available" on
  `404`, the placeholder without network, after the timeout, with `notify.preview_mode = none`
  (nothing is fetched) or when a newer push of the thread arrived. `k = "sync"` removes the
  notifications of the cleared threads and sets the badge. The app asks for the notification
  permission (API 33 and later) when a thread is first opened after the login, registers the FCM
  token with `registerPush` (provider `fcm`), keeps the preview token only in the runner's
  Keystore-encrypted store, registers again on a new token, unregisters on logout, opens the
  thread at the message on a tap and submits the service's display counters as client metrics.
  Only a build with a Firebase configuration (`android/app/google-services.json`) links Firebase
  and has push (ADR 0072); `make apple-strings` also writes the Android push strings.
