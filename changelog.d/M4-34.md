### Added

- Desktop E2E suite and performance level (M4-34): `make e2e-desktop` starts the server from the
  `bothy-server` image with the installation Compose file, the smoke overlay and the E2E overlay
  (a TLS front on `127.0.0.1` with a free port, the world job, the Fake-Agent of the Python SDK
  for `support-agent` and `stream-agent`), prepares the world (Alex, Sam, the space Support with
  `general` and the forum `requests`) and runs the suite `apps/client/e2e_test` against it: the
  enrollment login, a waiting device confirmed from the first, sending online and offline through
  the outbox, a run with live box, follow-up and approval card, upload and download, search, the
  channel menu, the keyboard walkthrough, a notification while hidden in the notification area
  and the revocation with `4012`. On macOS and Windows through `flutter drive`, headless with
  `E2E_DEVICE=flutter-tester`. `make perf-desktop` measures the desktop targets
  `client.perf.*` in a profile build and fails when one is missed; the summary goes to
  `apps/client/build/perf/summary.json`. The workflow `e2e-desktop` compiles both suites on
  macOS and Windows every week.

### Fixed

- A text channel opened on a device that signed in after the channel was created showed nothing:
  the history now loads a thread the device never received (`getThread`) when it opens (15 11).
- After a short network loss without missed events the app stayed "catching up" and held back
  every later live event: a `resumed` or `ready` whose `head_seq` equals the stored cursor now
  goes live at once, as the server sends no `catchup.complete` then.
