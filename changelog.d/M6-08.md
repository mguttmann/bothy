### Added

- Apps and webhooks in the administration of the desktop app and the web console (M6-08, 01 5.2
  and 5.5, 11 4 to 8): owners install an app from a manifest file (JSON or YAML, never a URL)
  after the server validated it, with a consent in plain text that names the scopes with their
  meaning, the events, the hosts data go to, commands, components, the requested grants with a
  concrete target each and the data outflow; the server's preview of each grant is shown before
  it is created, and the app token appears exactly once with the key ID for receivers. An update
  shows the diff of the new manifest and asks a new consent for new scopes and events; suspend,
  resume and uninstall state their effects before the confirmation. Outgoing subscriptions take
  only granted events and `https` addresses, show their state, a disabled one with its reason,
  and their deliveries with result and next attempt, with "Redeliver". Incoming webhooks are
  managed per channel, with the composed "incoming app" for owners and the address with its token
  shown once. Every change goes through the step-up the server asks for. One dialog shows every
  secret that the server returns once. `make console-e2e` runs the `patrol` web flows of the
  install, an outgoing delivery to a receiver in the Compose network and an incoming webhook.
